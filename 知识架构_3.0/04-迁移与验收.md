# 04 · 迁移与验收

> 这份文件回答三个问题：现有 2.0 内容怎么迁到 3.0、先改哪几章、改到什么程度算达标。

## 一、变与不变

### 不变（硬约束）

| 项 | 说明 |
| --- | --- |
| 26 章、26 课次 | 章号与课次对应关系不变 |
| 80 学时（理论 12 / 实践 68） | 不增加课时，不靠加学时消化新内容 |
| 三段式题目骨架 | 概念讲解 → 示范例题 → 独立习题 |
| 实训六段（第 2 批起） | 任务目标、课前准备、操作步骤、排错清单、提交验收、课后扩展（复习任务并入此段） |
| 纯纸质 | 无二维码、无折叠、无数字挂载点 |
| 代码事实 | 以 `项目参考/` 为准，不因改写而改代码 |
| 答案位置 | 示范例题解答在章内，独立习题答案在 `98-参考答案.md` |

### 变（知识架构）

| 项 | 2.0 | 3.0 |
| --- | --- | --- |
| 组织依据 | 项目施工顺序 | 12 个核心概念 + 项目实例 |
| 章内结构 | 知识点平铺（9–10 节） | 六段式，3–5 个理解台阶 |
| 概念 | 用到才出现，不命名 | 显式命名、定义、复现、迁移 |
| 术语 | 无预算，第 8 章 11 个 | 每章 ≤5，每节 ≤2，三层制 |
| 取舍 | 单一正确解 | 每章至少一个反例/取舍 |
| 图表 | 每章一张流程图 | 按知识需要配置 ER/时序/状态/组件/部署图 |
| 习题 | 记忆/分析为主 | 增加“换场景”的迁移题 |
| 呼吸章 | 无 | 第 15、17、18、21、22、24、25 章不新增核心概念 |

## 五、验收标准

### 全书级（6 条）

1. 12 个核心概念全部有完备卡（定义/现象/机制/边界/反例/迁移）。
2. 26 章全部有章首三行桥。
3. 每章新术语 ≤5，每节 ≤2；第 5 章必学 4 个计入预算，选读 2 个不计。
4. 每章至少一个反例或取舍，至少一个迁移题。
5. 第 15、17、18、21、22、24、25 章无新核心概念。
6. `01-概念矩阵.md` 的“引/用/深/迁”与正文实际一致，抽查 12 个概念全部命中。

### 章级（12 项检查表）

改写每一章后逐项打勾：

- [ ] 章首写清“本章工程问题”，不是“本章内容”。
- [ ] 章首三行桥齐全：已会 / 只加 / 关系。
- [ ] 本章核心概念不超过 1 个，支撑概念不超过 2 个。
- [ ] 新术语不超过 5 个；每节不超过 2 个。
- [ ] 每个抽象词在同一段内有 duty/页面/终端锚点。
- [ ] 六段式齐全：问题、概念、机制、应用、边界与取舍、迁移。
- [ ] 至少一个反例，且反例可见（页面/请求/日志）。
- [ ] 至少一个取舍，说明替代方案与代价。
- [ ] 长代码有阅读路径，不要求一次读懂。
- [ ] 有 ◇ 选读部分，且明确“跳过不影响后续”。
- [ ] 迁移题换场景，答案不能照抄本章代码。
- [ ] 章末小结回扣核心概念，不是结论清单复述。

### 试读验收（每批 2 名学生）

读完一章后问三个问题：

1. 这一章解决什么问题？
2. 哪个概念是新的？它落在哪个具体东西上？
3. 换一个业务场景，你会先做什么？

两名学生中至少一名能完整回答三题，且没有人答“不知道这章在讲什么”，才算通过。若失败，先改章首桥与锚点，不要先怪学生基础。

## 六、风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 概念反弹 | 改写时又加回一堆术语 | 每章改写前先填“术语预算表”，超了就删 |
| 架构空转 | 文档很漂亮，正文还是施工步骤 | 章级 12 项检查表；每节必须回答“推进哪个 K” |
| 呼吸章被填满 | 第 15/22 章又加新框架 | 呼吸章写“本章不引入”并进验收 |
| 教案脱节 | 教材变了，教案还是老流程 | 同批补“概念桥”两栏，不改学时 |
| 考核脱节 | 考试仍考工具细节 | 迁移题进平时成绩；表现性任务与 K 对齐 |
| 学员更怕 | 概念命名后显得更“学术” | 每个概念先落地再命名；前 3 章零代码；◇ 选读 |
| 工期失控 | 26 章一次铺开 | 按 5 批推进，每批试读通过再继续 |
| 纸质限制 | 选读框、概念图印不清 | 选读用统一符号与灰度；图不超过半页 |

## 七、待作者拍板的 5 件事

1. **是否保持 26 章不变？** 建议保持。改章界会牵动 80 学时、26 课次、教案、答案与所有回链，收益不抵成本。
2. **是否在正文前加一页“全书概念地图”？** 建议加，放在前言之后、目录之前，用一张 DAG 图 + 12 个概念一句话。纯纸质可行。
3. **“概念讲解”这个部分名是否保留？** 建议保留，避免动 C13 三段式与所有交叉引用；但内容按六段式重写。
4. **核心概念是否只保留 12 个？** 建议是。每增加一个核心概念，就要增加一次定义、复现与考核，直接推高负荷。
5. **是否同批修改教案？** 建议正文先行，教案在后一批补“概念桥”和“本章不引入”，不改教学流程。

## 八、完成定义

3.0 不是“改完 26 章”就结束。完成定义是：

- 学生只看目录与概念地图，能说出全书在讲哪五条线。
- 任取一章，学生能说出“本章只解决一个问题”和“它落在哪个具体东西上”。
- 任取一个核心概念，学生能在新场景里判断“该不该用、为什么”。
- 教师换一个业务项目，仍能用同一套概念讲，不必重写教材。

做到这四条，才算从“施工日志”变成了“教材”。
