## 一句话结论

2.0 的知识组织是“把 duty 项目按开发顺序做一遍”；3.0 改成“**用 duty 项目承载 12 个工程概念，每个概念在 3 个以上章节里由浅入深地复现**”。

## 三条不变

1. **26 课次、80 学时（理论 12 / 实践 68）不变；章数按 C21 为 24。** 章仍是教学单元，课次号 1–26 不动，章号按 v3.0 重排（原 4、5 章并入新第 3 章，原 6–26 章各 −2）。
2. **三段式题目骨架不变。** 概念讲解 → 示范例题 → 独立习题；示范例题承担应用层，独立习题保留思考题与自习题。
3. **纯纸质、无 AI 主线、代码事实以 `项目参考/` 为准不变。** 不新增二维码、折叠交互或数字挂载点。

## 新架构要解决的四个学员风险

| 学员风险 | 表现 | 对应机制（详见 03） |
| --- | --- | --- |
| 知识点不完备 | 学完会做 duty，换场景就不会 | 核心概念完备卡：定义 / 现象 / 机制 / 边界 / 反例 / 迁移 |
| 跨度过大 | 前一章还懂，后一章突然全是新词 | 概念依赖图 + 章首三行桥 + 跨章回顾 |
| 新概念太多 | 一节课十来个新术语，记不住 | 术语三层制 + 每章 ≤5 / 每节 ≤2 的预算 |
| 抽象不落地 | 听得懂字面，不知道在说什么 | 三选一锚点：duty 文件 / 页面元素 / 终端输出 |
