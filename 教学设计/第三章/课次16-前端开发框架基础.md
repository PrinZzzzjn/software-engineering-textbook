## 二、教学目标

**知识与技能**

- 能说清前端三件事：结构（HTML）、样式（CSS）、交互（JS）各做什么。
- 能说清 Streamlit“用 Python 写界面”的含义与代价。
- 能说清 Streamlit 的架构：脚本运行器、会话、WebSocket、前端渲染。
- 能说清事件模型：交互 → 脚本重跑 → 差量更新。
- 能说清 `st.session_state` 在“重跑”中的作用（只要求知道）。
- 能说出 Streamlit 的适用场景与局限。
- 能读一个计数器脚本，标出触发重跑的位置和需要跨重跑保存的值。

**过程与方法**

- 经历“改一行 → 保存 → 页面变化”的过程，建立“页面重跑”的直觉。
- 学会用架构图和事件链理解框架，而不是只记组件名。

**情感态度与价值观**

- 建立“框架是取舍”的意识：简单换来的是限制。
- 养成“先理解运行模型、再写页面”的习惯。

## 教学内容

> 对应教学计划：专题三基本内容第 1 条“前端开发框架基础”。
> 本课次只讲“一个页面怎么组成、怎么运行、状态放在哪里”；组件怎么用是课次17，布局与多页面/导航是课次18。

1. **前端在系统里的位置**：后端返回 JSON，前端负责展示和交互；前后端分离。
2. **前端技术栈**：HTML 管结构、CSS 管样式、JS 管交互；Streamlit 用 Python 把这些“包起来”。
3. **Streamlit 的架构**：脚本运行器（ScriptRunner）、会话（Session）、WebSocket、前端渲染层。
4. **事件模型**：用户操作 → 触发重跑 → 脚本从上到下重新执行 → 差量更新页面；`st.session_state` 用来跨重跑保存状态（只要求知道）。
5. **状态放在哪里**：普通变量每次重跑重新初始化，`st.session_state` 跨重跑保留；登录态、分页、筛选是同一类问题，具体用法在课次19–20。
6. **适用与局限**：适合内部工具/数据应用；不适合精细排版、高并发公网、复杂动画。
7. **读脚本练习**：打开计数器脚本，标出触发重跑的位置、被框架托管的值、放进 `session_state` 的值。

## 三、重点与难点

**重点**

- Streamlit 的架构与事件模型。
- 普通变量与 `session_state` 的分工。
- “用 Python 写界面”的取舍。

**难点**

- 理解“每次交互重跑脚本”。
- 理解“差量更新”和 `session_state` 的作用。
- 理解“用 Python 写界面”的取舍。

## 四、学情分析与教学策略

学生几乎零基础，没有 HTML/CSS/JS 经验。Streamlit 降低了门槛，但“重跑”和“差量更新”与直觉不同。

策略：

- **先演示，再解释**：改一行看页面变化，再讲重跑；
- **用架构图**：画出“浏览器—WebSocket—脚本运行器—会话”；
- **用事件链**：操作 → 重跑 → 更新，画成三步；
- **只用一个案例**：从头到尾用计数器，不切换到登录页或布局示例；
- **读脚本**：把概念落到一段十几行的代码上，不写完整项目。

## 五、教学准备

- 投影/白板；教材第16章。

- 最小计数器示例（标题 + 文字 + 按钮 + 计数），教师提前跑通。

## 六、教学过程

### 环节1：导入——点一下，数字为什么不变（10 分钟）

**教师演示**

打开计数器页面，连续点击“点我 +1”。

**提问**

> “页面上的标题、文字、按钮，是谁写出来的？”
>
> “代码里明明写了 `count += 1`，为什么数字永远显示 1？”

**引导学生说出**

- 页面是用代码写出来的；
- 点按钮会触发一段程序；
- 程序运行后，页面重新显示。

**教师点明本课边界**

> 今天不写业务功能，只搞清楚三件事：
>
> 1. 一个页面由什么组成；
> 2. 一次点击之后发生了什么；
> 3. 要留下的值该放在哪里。
>
> 组件怎么用是课次17，布局与多页面怎么组织是课次18。

---

### 环节2：前端三件事（15 分钟）

**教师讲授**

| 技术 | 管什么 | 在页面上的表现 |
|---|---|---|
| HTML | 结构 | 标题、文字、按钮 |
| CSS | 样式 | 颜色、字号、间距、边框 |
| JavaScript | 交互 | 点击后发生了什么、数据怎么变 |

**用计数器页面对照**

- 标题、数字、按钮的“位置关系”是结构；
- 数字的字号、按钮的颜色与圆角是样式；
- 点“点我 +1”后数字加一是交互。

**讲清 Streamlit 的位置**

> 原生前端要分别写 HTML、CSS、JS。
>
> Streamlit 让你只写 Python：你写 `st.title(...)`、`st.write(...)`、`st.button(...)`，框架替你生成 HTML、CSS 和 JS。

**强调取舍**

- 换来的是：几行 Python 就能出一个页面；
- 代价是：能精细控制的东西少，复杂动画、像素级布局做不了。

---

### 环节3：Streamlit 的架构与事件模型（25 分钟）

**教师画架构图**

```
浏览器（负责显示）
    │  WebSocket 长连接
Streamlit 服务端
    ├─ Session（会话）：保存这个用户的状态
    └─ ScriptRunner（脚本运行器）：执行 app.py
```

**讲清四层**

1. **浏览器**：只负责显示和收集操作；
2. **WebSocket**：浏览器和服务端保持一条长连接，操作和页面更新都走它；
3. **Session**：每个访问者一个会话，`st.session_state` 就存在这里；
4. **ScriptRunner**：每次交互，把脚本从头到尾再执行一遍。

**事件链（板书三步）**

```
用户操作 → 脚本从头重跑 → 生成新的页面树 → 差量更新到浏览器
```

**关键句**

> 页面不是被“修改”的，而是被“重新算了一遍”。
>
> Streamlit 比较新旧两次结果，只把变化的部分发给浏览器，这叫“差量更新”。

**现场演示重跑**

```python
import streamlit as st

st.title("重跑演示")

if "count" not in st.session_state:
    st.session_state.count = 0

if st.button("点我 +1"):
    st.session_state.count += 1

st.write("当前计数：", st.session_state.count)
```

**演示步骤**

1. 先去掉 `session_state`，只写 `count = 0`，点按钮，数字不动；
2. 再加上 `session_state`，点按钮，数字累加；
3. 解释：普通变量每次重跑都会重新初始化，`session_state` 才能跨重跑保留。

**只要求知道**

> 今天不要求会用 `session_state`，只要知道“重跑会丢普通变量，跨重跑要用它”。
> 具体用法在课次19–20 登录态和分页状态里再练。

### 环节4：状态放在哪里（20 分钟）

**先分析普通变量为什么丢**

> 每次点击都会把脚本从头执行一遍，`count = 0` 也就每次都被执行一次：先清零，再 `+= 1`，所以永远是 1。

**几种直觉修法为什么不成立**

- 把 `count = 0` 挪进 `if`：会连 `count` 是否定义都说不清；
- 改用 `global`：变量仍然在脚本里，重跑时照样重新初始化；
- 写进文本文件：能行，但两个人同时打开会互相覆盖，每次点击还要读磁盘。

**给出正解**

```python
import streamlit as st

if "count" not in st.session_state:
    st.session_state.count = 0

if st.button("点我 +1"):
    st.session_state.count += 1

st.write("当前计数：", st.session_state.count)
```

**讲清三处**

1. `if "count" not in ...` 只在第一次设初始值，重跑时该判断为假；
2. `st.session_state.count` 可以按属性写，也可以按字典写；
3. 加减与显示的写法，和普通变量完全一致。

**迁移一句**

> 登录态、页码、筛选条件，都是同一类问题：值要跨重跑保留，就放进 `st.session_state`，不要放在普通变量里。具体做法在课次19–20。

**学生跟做（5 分钟）**

把上面两版代码各跑一次，观察点击后的差别，并指出 `if "count" not in ...` 为什么只在第一次执行。

### 环节5：适用边界（10 分钟）

**适用场景**

- 内部工具、管理后台；
- 数据查询与统计展示；
- 原型验证、课程项目。

**局限**

- 不适合精细排版、复杂动画；
- 不适合高并发公网产品；
- 对 SEO 不友好；
- 复杂交互仍需要自定义组件。

**讲清两条原因**

- 它只按比例划分区域，不能指定像素坐标；
- 它每次交互都重跑整个脚本，页面复杂、并发上来以后，代价会越来越明显。

**结论**

> 框架没有好坏，只有取舍。选 Streamlit，是用“控制力”换“开发速度”。
>
> 界面设计与布局原则不在这里展开，课次18 会在具体页面上讲。

**教师总结**

> 一个页面 = 结构 + 样式 + 交互。
>
> Streamlit 用 Python 把这三件事包起来，代价是控制力有限。
>
> 每次交互都会重跑脚本；跨重跑保存状态用 `session_state`。

## 七、板书设计

```
前端三件事：HTML 结构 / CSS 样式 / JavaScript 交互
Streamlit：用 Python 写界面 = 框架替你生成三件事

架构：浏览器 ⇄ WebSocket ⇄ Session + ScriptRunner

事件：操作 → 脚本重跑 → 新页面树 → 差量更新
状态：普通变量重跑即丢；st.session_state 跨重跑保留

取舍：开发快 ⇄ 控制力弱
```
