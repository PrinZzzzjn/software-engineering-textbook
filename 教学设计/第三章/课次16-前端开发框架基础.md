| 项目 | 内容 |

## 二、教学目标

**知识与技能**

- 能说清前端三件事：结构（HTML）、样式（CSS）、交互（JS）各做什么。
- 能说清 Streamlit "用 Python 写界面"的含义与代价。
- 能说清 Streamlit 的架构：脚本运行器、会话、WebSocket、前端渲染。
- 能说清事件模型：交互 → 脚本重跑 → 差量更新。
- 能说清 `st.session_state` 在"重跑"中的作用（只要求知道）。
- 能用 `st.columns`、`st.container` 摆一个单页布局。
- 能说出界面设计的一般原则：简洁、一致、可预测、以用户为中心。
- 能说出 Streamlit 的适用场景与局限。
- 能读一个真实页面，标出标题、表单、按钮、布局容器。

**过程与方法**

- 经历"改一行 → 保存 → 页面变化"的过程，建立"页面重跑"的直觉。
- 学会用架构图和事件链理解框架，而不是只记组件名。

**情感态度与价值观**

- 建立"框架是取舍"的意识：简单换来的是限制。
- 养成"先理解运行模型、再写页面"的习惯。

## 教学内容

> 对应教学计划：专题三基本内容第 1 条"前端开发框架基础"。
> 本课次只讲"一个页面怎么组成、怎么运行"；多页面、导航、项目结构在课次18。

1. **前端在系统里的位置**：后端返回 JSON，前端负责展示和交互；前后端分离。
2. **前端技术栈**：HTML 管结构、CSS 管样式、JS 管交互；Streamlit 用 Python 把这些"包起来"。
3. **Streamlit 的架构**：脚本运行器（ScriptRunner）、会话（Session）、WebSocket、前端渲染层。
4. **事件模型**：用户操作 → 触发重跑 → 脚本从上到下重新执行 → 差量更新页面；`st.session_state` 用来跨重跑保存状态（只要求知道）。
5. **单页布局**：`st.columns`、`st.container`；`st.sidebar`、`st.tabs` 作为容器（导航在课次18）。
6. **界面设计的一般原则**：简洁、一致、可预测、以用户为中心。
7. **适用与局限**：适合内部工具/数据应用；不适合精细前端、高并发公网、复杂动画。
8. **读页面练习**：打开 `duty_frontend` 登录页，标出标题、表单、按钮、布局容器。

## 三、重点与难点

**重点**

- Streamlit 的架构与事件模型。
- 单页布局（columns/container）。
- 界面设计原则。

**难点**

- 理解"每次交互重跑脚本"。
- 理解"差量更新"和 `session_state` 的作用。
- 理解"用 Python 写界面"的取舍。

## 四、学情分析与教学策略

学生几乎零基础，没有 HTML/CSS/JS 经验。Streamlit 降低了门槛，但"重跑"和"差量更新"与直觉不同。

策略：

- **先演示，再解释**：改一行看页面变化，再讲重跑；
- **用架构图**：画出"浏览器—WebSocket—脚本运行器—会话"；
- **用事件链**：操作 → 重跑 → 更新，画成三步；
- **只讲单页**：多页面/导航留到课次18；
- **读真实页面**：把概念落到登录页，不写完整项目。

### 环节2：前端三件事（15 分钟）

**教师讲授**

| 技术 | 管什么 | 在页面上的表现 |
|---|---|---|
| HTML | 结构 | 标题、段落、输入框、按钮 |
| CSS | 样式 | 颜色、字号、间距、边框 |
| JavaScript | 交互 | 点击后发生了什么、数据怎么变 |

**用登录页对照**

- 标题和输入框的"位置关系"是结构；
- 按钮的颜色、圆角、间距是样式；
- 点"登录"后页面变化是交互。

**讲清 Streamlit 的位置**

> 原生前端要分别写 HTML、CSS、JS。
>
> Streamlit 让你只写 Python：你写 `st.title(...)`、`st.text_input(...)`，框架替你生成 HTML、CSS 和 JS。

**强调取舍**

- 换来的是：几行 Python 就能出一个页面；
- 代价是：能精细控制的东西少，复杂动画、像素级布局做不了。

### 环节3：Streamlit 的架构与事件模型（25 分钟）

**教师画架构图**

```
浏览器（负责显示）
    │  WebSocket 长连接
Streamlit 服务端
    ├─ Session（会话）：保存这个用户的状态
    └─ ScriptRunner（脚本运行器）：执行 app.py
```

**讲清四层**

1. **浏览器**：只负责显示和收集操作；
2. **WebSocket**：浏览器和服务端保持一条长连接，操作和页面更新都走它；
3. **Session**：每个访问者一个会话，`st.session_state` 就存在这里；
4. **ScriptRunner**：每次交互，把脚本从头到尾再执行一遍。

**事件链（板书三步）**

```
用户操作 → 脚本从头重跑 → 生成新的页面树 → 差量更新到浏览器
```

**关键句**

> 页面不是被"修改"的，而是被"重新算了一遍"。
>
> Streamlit 比较新旧两次结果，只把变化的部分发给浏览器，这叫"差量更新"。

**现场演示重跑**

```python
import streamlit as st

st.title("重跑演示")

if "count" not in st.session_state:
    st.session_state.count = 0

if st.button("点我 +1"):
    st.session_state.count += 1

st.write("当前计数：", st.session_state.count)
```

**演示步骤**

1. 先去掉 `session_state`，只写 `count = 0`，点按钮，数字不动；
2. 再加上 `session_state`，点按钮，数字累加；
3. 解释：普通变量每次重跑都会重新初始化，`session_state` 才能跨重跑保留。

**只要求知道**

> 今天不要求会用 `session_state`，只要知道"重跑会丢普通变量，跨重跑要用它"。
> 具体用法在课次19–20 登录态和分页状态里再练。

### 环节4：单页布局（20 分钟）

**教师演示最小布局**

```python
import streamlit as st

st.set_page_config(page_title="值班数据统计系统", layout="wide")

st.title("🗂️ 值班数据统计系统")

left, right = st.columns([2, 1])

with left:
    with st.container(border=True):
        st.subheader("系统状态")
        st.write("后端服务正常")

with right:
    with st.container(border=True):
        st.subheader("快速开始")
        st.write("先看列表，再试新增")

with st.sidebar:
    st.caption("当前用户：admin")
```

**讲清四个容器**

| 容器 | 作用 | 本课要求 |
|---|---|---|
| `st.columns([2, 1])` | 把页面横向分成几列，数字是宽度比例 | 会写 |
| `st.container(border=True)` | 把一组内容装进一个框，形成"卡片" | 会写 |
| `st.sidebar` | 左侧边栏 | 知道 |
| `st.tabs` | 同一区域分页签 | 知道 |

**强调**

- Streamlit 的布局是"分区"，不是"定位"；
- 不能像 CSS 那样指定"距左边 137 像素"；
- 列比例会随窗口宽度自适应，窄屏时会自动堆叠。

**学生跟做（5 分钟）**

把上面的最小示例敲一遍，改成"标题 + 两列卡片"，观察窗口变窄时的变化。

### 环节5：设计原则、适用与局限（10 分钟）

**四条原则**

| 原则 | 含义 | 反例 |
|---|---|---|
| 简洁 | 一屏只放当前任务需要的东西 | 首页堆满十张表 |
| 一致 | 同类操作用同样的位置和样式 | 有的页面按钮在左、有的在右 |
| 可预测 | 点了会发生什么，用户能预期 | 按钮叫"确定"，却执行删除 |
| 以用户为中心 | 按用户的任务顺序组织页面 | 先让用户填十个无关字段 |

**适用场景**

- 内部工具、管理后台；
- 数据查询与统计展示；
- 原型验证、课程项目。

**局限**

- 不适合精细排版、复杂动画；
- 不适合高并发公网产品；
- 对 SEO 不友好；
- 复杂交互仍需要自定义组件。

**结论**

> 框架没有好坏，只有取舍。选 Streamlit，是用"控制力"换"开发速度"。

## 七、板书设计

```
前端三件事：HTML 结构 / CSS 样式 / JavaScript 交互
Streamlit：用 Python 写界面 = 框架替你生成三件事

架构：浏览器 ⇄ WebSocket ⇄ Session + ScriptRunner

事件：操作 → 脚本重跑 → 新页面树 → 差量更新
状态：st.session_state 跨重跑保存

布局：st.columns / st.container / st.sidebar / st.tabs

原则：简洁 / 一致 / 可预测 / 以用户为中心
取舍：开发快 ⇄ 控制力弱
```
