## 二、教学目标

**知识与技能**

- 能完成前端整体联调：登录 → 部门管理 → 数据统计。
- 能排查常见问题：401/403/404/422/500、页面不渲染、数据不更新、样式异常。
- 能统一处理接口错误：错误提示、401 清登录态、重试、空数据。
- 能区分 401（没登录）、403（没权限）、404（找不到）、422（参数错）、500（后端错）。
- 能复用参考实现扩展页面：人员、工位等。
- 能整理前端成果并做 3 分钟展示。

**过程与方法**

- 经历"整合 → 排查 → 修复 → 展示"的收尾过程。
- 学会用"状态码 → 日志 → 定位步骤"的顺序排查问题。

**情感态度与价值观**

- 建立"交付"意识：能跑、能说清、能交接。
- 养成"错误也要给用户看得懂"的习惯。

## 教学内容

> 对应教学计划：专题三基本内容第 7 条"前端开发综合实践"。

1. **常见问题排查**：401/403/404/422/500、页面不渲染、数据不更新、样式异常。

6. **成果整理与展示**：代码、截图、联调记录、已知问题。

## 三、重点与难点

**重点**

- 整体联调。
- 常见问题排查（状态码 → 定位）。
- 统一错误处理。

**难点**

- 多页面联调时定位问题。
- 401/403/500 的区分与处理。

### 环节3：常见问题排查（35 分钟）

**教师给出诊断顺序**

```
现象 → 状态码 → detail / 返回体 → 后端日志 → 定位到页面/接口/字段
```

**五类状态码**

| 状态码 | 含义 | 先查什么 | 页面怎么提示 |
|---|---|---|---|
| 401 | 没登录/登录过期 | token 是否存在、请求头 | 清登录态，重跑回登录 |
| 403 | 登录了但没权限 | 当前角色、接口权限 | "当前账号没有权限" |
| 404 | 资源不存在 | 路径、编码是否已被删除 | "数据不存在，可能已被删除" |
| 422 | 参数校验失败 | 字段名、类型、必填 | 显示具体字段问题 |
| 500 | 后端异常 | 后端日志/堆栈 | "服务器开小差了" |

**非状态码问题**

| 现象 | 先查什么 |
|---|---|
| 页面不渲染 | 是否有未捕获异常；`st.stop()` 位置 |
| 数据不更新 | 是否 `st.rerun()`；取数是否在操作之前 |
| 样式异常 | `config.toml` 是否重启；是否重复注入 CSS |
| 图表空白 | 数据结构/字段名是否与接口一致 |
| 页面卡顿 | 是否在循环里发请求；是否一次取太多 |

**故障卡活动（15 分钟）**

教师提前在参考实现上制造 3 个故障（学生拿到的是"坏"版本）：

1. 部门列表路径少写 `/api/v1` → 404；
2. 登录成功后没把 token 写进 `session_state` → 后续全部 401；
3. 新增成功后没有 `st.rerun()` → 列表不更新。

学生分组排查，填写"现象 → 原因 → 改法"，教师公布答案。

**强调**

- 不要凭感觉改代码，先确认"请求发到哪、返回了什么"；
- 401 和 403 要分清：一个是"没证件"，一个是"证件不够级别"；
- 500 先看后端日志，不要在前端反复改。

### 环节4：统一错误处理（35 分钟）

**教师说明**

> 每个页面都写一套 `try/except` 会重复，而且提示不一致。
> 把"错误 → 提示"的映射收拢到一个函数里。

**统一处理函数**

```python
import streamlit as st


def show_api_error(exc) -> None:
    """把接口错误转换成用户看得懂的提示。"""
    if exc.status_code == 401:
        st.session_state.clear()
        st.warning("登录已过期，请重新登录")
        st.rerun()
    elif exc.status_code == 403:
        st.error("当前账号没有权限执行该操作")
    elif exc.status_code == 404:
        st.error("数据不存在，可能已被删除")
    elif exc.status_code == 422:
        st.error(f"提交内容有误：{exc.detail}")
    elif exc.status_code == 500:
        st.error("服务器开小差了，请稍后重试或联系管理员")
    elif exc.status_code == 0:
        st.error(f"无法连接后端服务：{exc.detail}")
    else:
        st.error(exc.detail)
```

**页面里统一调用**

```python
try:
    data = api.get("/departments/", params=params)
except api.ApiError as exc:
    show_api_error(exc)
    st.stop()
```

**讲清四种处理策略**

| 情况 | 策略 |
|---|---|
| 401 | 清登录态，提示重新登录，停止渲染 |
| 403 | 提示没权限，不重试 |
| 404 | 提示数据不存在，刷新列表 |
| 422 | 显示具体字段问题，让用户改 |
| 500 | 提示稍后重试，记录时间与操作 |
| 空数据 | `st.info("暂无数据")`，不当作错误 |
| 网络失败 | 提示检查后端，允许重试 |

**强调**

- 错误提示要"说人话"，不要把堆栈直接给用户；
- 401 必须在统一入口处理，不要每个页面各写一遍；
- 空数据不是错误，不要弹红色错误框；
- 提示里不要泄露 token、密码、服务器路径。

**学生任务（15 分钟）**

- 建 `show_api_error`，在三个页面的取数处统一调用；
- 分别制造 401、404、422，确认提示正确；
- 把 500 的提示改成"请稍后重试，并联系管理员"。

### 环节5：参考实现的复用与扩展（30 分钟）

**教师演示"照抄一页"**

人员管理页可以照部门页改，主要改三处：

| 位置 | 部门页 | 人员页 |

**注意后端差异**

> 部门列表的排序参数是 `sort_order`，人员列表是 `order`。

**扩展步骤**

1. 复制 `1_部门管理.py` 为 `3_人员管理.py`；

3. 改接口路径和字段；
