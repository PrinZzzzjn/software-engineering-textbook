- 经历"登录 → 拿 token → 调列表 → 显示"的联调过程。

**情感态度与价值观**

- 建立"前后端按契约对接"的意识。

## 教学内容

> 对应教学计划：专题三基本内容第 4 条"数据读取与展示"。

### 环节2：`requests` 基础（25 分钟）

**教师先不写 Streamlit，只在 Python 里调**

```python
import requests

BASE_URL = "http://127.0.0.1:8000"
PREFIX = "/api/v1"

# 1. 登录
resp = requests.post(
    f"{BASE_URL}{PREFIX}/auth/login",
    json={"username": "admin", "password": "admin123"},
    timeout=10,
)
print(resp.status_code)
print(resp.json())

token = resp.json()["access_token"]

# 2. 带 token 查部门
resp = requests.get(
    f"{BASE_URL}{PREFIX}/departments/",
    params={"page": 1, "page_size": 10},
    headers={"Authorization": f"Bearer {token}"},
    timeout=10,
)
print(resp.status_code)
print(resp.json())
```

**讲清四件事**

| 要素 | 写法 | 说明 |
|---|---|---|
| 地址 | `BASE_URL + PREFIX + path` | 端口、前缀不能漏 |
| 方法 | `requests.get/post` | 查用 GET，登录用 POST |
| 参数 | `params=` / `json=` | 查询参数用 `params`，请求体用 `json` |
| 请求头 | `headers={"Authorization": ...}` | token 放这里 |

**强调**

- 先看 `status_code`，再看 `json()`；
- 不要说"返回了数据"就完事，要确认状态码是 200；
- 后端地址和前缀来自 `config.py`，不要散落在代码里。

**学生任务（10 分钟）**

在脚本里跑通登录 + 部门列表，把 `token` 前 20 个字符和 `total` 打印出来。

**常见问题**

| 现象 | 原因 |
|---|---|
| `ConnectionError` | 后端没启动、端口不对 |
| 404 | 路径少了 `/api/v1`，或部门路径写成单数 |
| 401 | 没带 token，或 token 抄错 |
| 422 | 请求体字段名/类型不对 |

### 环节3：封装 `api_client`（35 分钟）

**教师说明**

> 如果每个页面都写一遍 URL、超时、请求头、错误处理，迟早会不一致。
> 统一封装成一个入口，页面只关心"调哪个接口、传什么"。

**`config.py`**

```python
import os

API_BASE_URL = os.getenv("DUTY_API_BASE_URL", "http://127.0.0.1:8000").rstrip("/")
API_PREFIX = "/api/v1"
REQUEST_TIMEOUT = 10
DEFAULT_PAGE_SIZE = 10
```

**`api_client.py`（最小版）**

```python
import requests
import streamlit as st

from config import API_BASE_URL, API_PREFIX, REQUEST_TIMEOUT


class ApiError(Exception):
    """接口调用失败的统一异常。"""

    def __init__(self, status_code: int, detail: str):
        self.status_code = status_code
        self.detail = detail
        super().__init__(detail)


def _url(path: str) -> str:
    return f"{API_BASE_URL}{API_PREFIX}{path}"


def _headers() -> dict:
    token = st.session_state.get("access_token")
    return {"Authorization": f"Bearer {token}"} if token else {}


def _request(method: str, path: str, **kwargs):
    try:
        resp = requests.request(
            method,
            _url(path),
            headers=_headers(),
            timeout=REQUEST_TIMEOUT,
            **kwargs,
        )
    except requests.RequestException as exc:
        raise ApiError(0, f"无法连接后端服务：{exc}") from exc

    if resp.status_code == 401:
        st.session_state.pop("access_token", None)
        raise ApiError(401, "登录已过期，请重新登录")

    if not resp.ok:
        try:
            detail = resp.json().get("detail", resp.text)
        except ValueError:
            detail = resp.text
        # FastAPI 的 422 是一个列表，压平成一句话
        if isinstance(detail, list):
            detail = "；".join(str(item.get("msg", item)) for item in detail)
        raise ApiError(resp.status_code, str(detail))

    return resp.json() if resp.content else None


def get(path: str, params: dict | None = None):
    return _request("GET", path, params=params)


def post(path: str, json: dict | None = None):
    return _request("POST", path, json=json)
```

**讲清封装带来的四个统一**

1. 地址统一：`config.py` 改一处，全局生效；
2. 请求头统一：token 自动带上；
3. 超时统一：不会某个请求一直挂着；
4. 错误统一：页面只捕获 `ApiError`。

**强调**

- `_request` 是唯一入口，不要在页面里直接 `requests.get`；
- 401 统一清登录态，避免拿着过期 token 反复请求；
- 后端 `detail` 可能是字符串，也可能是列表（422），显示前要处理。

### 环节4：登录与 token（40 分钟）

**教师演示登录表单**

```python
import streamlit as st

import api_client as api

# 未登录：只显示登录表单，登录后脚本重跑，进入下面的页面内容
if "access_token" not in st.session_state:
    st.title("🗂️ 值班数据统计系统")

    with st.form("login_form"):
        username = st.text_input("用户名", value="admin")
        password = st.text_input("密码", type="password")
        submitted = st.form_submit_button("登录")

    if submitted:
        if not username or not password:
            st.error("请输入用户名和密码")
        else:
            try:
                with st.spinner("正在登录..."):
                    data = api.post(
                        "/auth/login",
                        json={"username": username, "password": password},
                    )
            except api.ApiError as exc:
                st.error(exc.detail)
            else:
                st.session_state["access_token"] = data["access_token"]
                st.session_state["current_user"] = data["user"]
                st.rerun()

    st.stop()

user = st.session_state.get("current_user", {})
st.success(f"欢迎，{user.get('username', '用户')}（{user.get('role', '-')}）")
```

**退出登录**

```python
with st.sidebar:
    if st.button("退出登录"):
        st.session_state.clear()
        st.rerun()
```

**讲清 token 的三个动作**

```
登录成功 → 取出 access_token → 存进 st.session_state
之后的请求 → _headers() 自动读出 → Authorization: Bearer <token>
退出登录 → 清空 session_state → st.rerun()
```

**演示三种情况**

| 操作 | 结果 |
|---|---|
| 正确账号密码 | 200，拿到 token，页面刷新 |
| 错误密码 | 401，显示"用户名或密码错误" |
| 不带 token 调列表 | 401，`api_client` 清登录态并提示 |

**强调**

- token 是"通行证"，不要打印到页面上；
- 密码输入框必须 `type="password"`；
- 登录成功后 `st.rerun()`，让页面带着登录态重新渲染；
- 删掉课次18 的"模拟登录"按钮，换成真实登录表单；
- `session_state` 只在当前会话有效，刷新浏览器会丢。

**学生任务（20 分钟）**

- 完成登录表单；
- 登录成功后显示用户名和角色；
- 退出登录按钮清空 `session_state`；
- 用错误密码登录，确认提示是 401 的内容。

### 环节5：部门列表与加载状态（30 分钟）

**教师演示**

```python
import pandas as pd
import streamlit as st

import api_client as api

try:
    with st.spinner("正在加载部门列表..."):
        data = api.get(
            "/departments/",
            params={"page": 1, "page_size": 10, "sort_by": "create_time", "sort_order": "desc"},
        )
except api.ApiError as exc:
    st.error(exc.detail)
    st.stop()

items = data.get("items", [])
if not items:
    st.info("暂无部门数据")
else:
    df = pd.DataFrame(items)
    st.dataframe(
        df[["dept_code", "full_name", "address", "create_time"]],
        width="stretch",
        hide_index=True,
    )
    st.caption(f"共 {data.get('total', 0)} 条")
```

**讲清三件事**

1. 列表响应结构是 `{"items": [...], "total": ...}`，先取 `items`；
2. 表格只显示需要的字段，不要把整个 JSON 全铺出来；
3. `st.spinner` 包住请求，让用户知道"正在加载"。

**字段对照（后端 → 前端）**

| 后端字段 | 前端表头 | 说明 |
|---|---|---|
| `dept_code` | 部门编码 | 唯一 |
| `full_name` | 部门名称 | 搜索字段 |
| `address` | 地址 | 可空 |
| `create_time` | 创建时间 | 日期时间 |
| `parent_dept_code` | 父部门编码 | 可空 |

**强调**

- 字段名以后端 `/docs` 为准，不要凭印象写；
- 空数据要提示，不要显示一个空表格；
- 请求失败后 `st.stop()`，避免后面的代码继续执行。

**学生任务（15 分钟）**

- 把列表显示出来，字段用中文表头（可直接用 `column_config`，也可先用英文）；
- 加 `st.spinner`；

### 环节6：联调排查（25 分钟）

**教师给出排错顺序**

```
先看状态码 → 再看 detail / 返回体 → 再对照 /docs → 最后查代码
```

**常见问题清单**

| 现象 | 先查什么 |
|---|---|
| 连不上 | 后端是否启动；地址是否是 `127.0.0.1:8000` |
| 404 | 路径前缀 `/api/v1`；部门是复数 `/departments/` |
| 401 | 是否登录；请求头是否是 `Bearer <token>`；token 是否过期 |
| 422 | 请求体字段名、类型；查询参数格式 |
| 返回空列表 | 数据库是否有数据；分页参数是否超出范围 |
| 页面白屏 | 是否有未捕获异常；`st.stop()` 是否放对位置 |
| 页面反复刷新 | 是否在表单外调用了会触发重跑的组件 |

**现场演示两个故障**

1. 把 `API_PREFIX` 改成 `/api`，看 404；
2. 把 token 手动改一个字符，看 401 和登录态清除。

**强调**

- 不要一看到报错就改代码，先确认"请求发到哪、返回了什么"；
- 在 `_request` 里临时打印 URL 和状态码，是最快的定位方法；
- 401 不是"代码坏了"，是"没登录/登录过期"。

**学生任务（10 分钟）**

两人一组，互相制造一个故障（改路径、改 token、关后端），对方按排错顺序定位并记录。

## 七、板书设计

```
链路：登录 → token → 带 token 请求 → 显示

requests：
  get(url, params=..., headers=..., timeout=...)
  post(url, json=..., headers=..., timeout=...)
  先看 status_code，再看 json()

api_client：
  config：BASE_URL + PREFIX + TIMEOUT
  _headers()：Authorization: Bearer <token>
  _request()：超时、401 清登录态、错误转 ApiError

登录：
  POST /auth/login → access_token → st.session_state
  登录成功 st.rerun()

列表：
  GET /api/v1/departments/
  data["items"] → DataFrame → st.dataframe
  st.spinner 包住请求

排错：状态码 → detail → /docs → 代码
```
