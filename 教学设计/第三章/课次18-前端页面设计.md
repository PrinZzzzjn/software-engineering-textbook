## 二、教学目标

**知识与技能**

- 能说清 Streamlit 项目的标准结构：`app.py`、`pages/`、`components/`、`config.py`、`requirements.txt`。
- 能使用 `pages/` 目录创建多页面，并说明侧边栏导航如何生成。
- 能规划一个页面的区域：标题区、筛选区、内容区、操作区。
- 能说出"页面访问守卫"的概念：未登录不能进子页面。
- 能在多页面中应用列比例做基本响应式布局。
- 能搭出 duty_frontend 的页面骨架：登录页、部门管理页、数据统计页的空壳。

**过程与方法**

- 经历"建目录 → 建页面 → 排页面区域 → 加导航"的过程。
- 学会先把"页面地图"画出来，再写代码。

**情感态度与价值观**

- 建立"结构先于细节"的意识。
- 养成"页面分工清楚、导航可预测"的习惯。

## 教学内容

> 对应教学计划：专题三基本内容第 3 条"前端页面设计"。
> **边界**：课次16 已讲框架/运行模型/状态，课次17 已讲组件；本课次不重复，只讲"多个页面怎么组织"，单页布局在本课次展开。

1. **Streamlit 项目结构**：`app.py`（入口）、`pages/`（页面）、`components/`（复用组件）、`config.py`（配置）、`requirements.txt`。
2. **多页面与侧边栏导航**：`pages/` 目录、文件名排序、页面切换、导航命名。
3. **页面区域规划**：标题区、筛选区、内容区、操作区；信息层级与页面地图。
4. **页面访问守卫与登录态入口**：概念上"未登录不能进子页面"；具体 `session_state`/token 放在课次19–20。
5. **响应式布局（多页面中的应用）**：`st.columns` 比例、宽屏/窄屏、表格/图表自适应；不重新讲 columns 基础。
6. **案例**：搭出 duty_frontend 的页面骨架——登录页、部门管理页、数据统计页三个**空壳页**，不接后端。

## 三、重点与难点

**重点**

- `pages/` 多页面与侧边栏导航。
- 页面区域规划。
- 项目结构组织。

**难点**

- 多页面的文件组织与顺序。
- "页面访问守卫"的概念（实现放到 19–20）。
- 多页面中列比例的选择。

## 四、学情分析与教学策略

学生已经会写单个页面和组件，但没有组织过多页面项目。零基础学生容易把所有代码堆在 `app.py` 里。

策略：

- **先画页面地图**：登录、部门、统计三页，各放什么；
- **先搭空壳**：每页只放标题和占位内容；
- **导航自动生成**：用 `pages/` 目录，不手写导航；
- **守卫只讲概念**：不展开 token/session_state；
- **不重复基础**：框架、布局、组件直接引用课次16/17。

## 五、教学准备

- `duty_frontend` 目录结构（投影）。
- 页面地图模板（三页 + 区域）。
- 页面骨架模板：`app.py` + `pages/` 两个空页。

### 环节2：项目结构（20 分钟）

**教师展示目录树**

```
duty_frontend/
├── app.py                  # 入口：首页 + 登录门禁
├── pages/
│   ├── 1_部门管理.py       # 子页面 1
│   └── 2_数据统计.py       # 子页面 2
├── components/
│   └── table.py            # 可复用表格/分页
├── config.py               # 后端地址、超时、分页大小
├── requirements.txt        # 依赖
└── .streamlit/
    └── config.toml         # 主题配置（课次21）
```

**讲清每个位置的作用**

| 位置 | 作用 | 谁负责 |
|---|---|---|
| `app.py` | 入口、首页、登录门禁 | 每个项目一个 |
| `pages/` | 每个文件就是一个页面 | 按功能拆分 |
| `components/` | 跨页面复用的组件 | 第二次用到时再抽 |
| `config.py` | 配置集中管理 | 只改一处 |
| `requirements.txt` | 依赖清单 | 部署和换机时用 |

**强调**

- 不要把页面代码全写进 `app.py`；
- 不要每个页面各写一份后端地址；
- `components/` 不要提前造，出现重复再抽。

**学生任务（10 分钟）**

按上面的结构建目录，先建空文件；`requirements.txt` 写三行：

```text
streamlit>=1.50,<2
requests>=2.31
pandas>=2.0
```

import streamlit as st

**讲清导航规则**

1. `pages/` 下的每个 `.py` 文件自动成为一个页面；
2. 文件名前的数字决定排序：`1_`、`2_`；
3. 文件名去掉数字前缀后成为导航名称；
4. 不需要手写导航菜单；
5. 每个页面都是独立脚本，进入时从上到下执行。

**强调**

- `st.set_page_config` 必须是页面里第一个 Streamlit 调用；
- 页面文件名不要用空格和特殊符号；
- 页码前缀用 `1_`、`2_`，不要用 `01-`，避免排序意外。

部门管理页

- 同一类信息放在同一区域；
- 操作区不要压在表格中间；
- 筛选区不要和标题混在一起；
- 页面地图先画在纸上，再写代码。

### 环节6：页面访问守卫的概念（20 分钟）

**教师说明**

> 多页面带来一个新问题：用户可以直接输入地址进入子页面，绕过登录。
>
> 解决办法是"每个页面进门先查证件"。

**演示最小守卫**

```python
import streamlit as st

def require_login():
    """未登录时提示并停止渲染当前页面。"""
    if "access_token" not in st.session_state:
        st.warning("请先登录后再访问该页面")
        st.stop()
```

在每个子页面顶部调用：

```python
require_login()
```

**讲清三件事**

1. `st.stop()` 会立即停止当前脚本，后面的内容不再渲染；
2. 守卫要写在页面**最上面**，不能写在表格后面；
3. 登录态从哪来、`access_token` 怎么存，是课次19 的内容，今天只留占位。

**强调**

- 前端守卫只是"体验"；真正的权限仍由后端校验；
- 守卫不能只写在首页，每个子页面都要写；
- 今天只检查"有没有 token"，token 是否有效由课次19 的接口验证；
- 今天不实现登录，只保证"没登录进不去"。

**课次18 的过渡做法**

子页面加了守卫后，未登录就看不到内容。为了让骨架能打开，先在首页放一个临时的"模拟登录"按钮：

```python
# app.py 底部：课次18 临时用，课次19 换成真实登录
if st.button("模拟登录（课次18 用）"):
    st.session_state["access_token"] = "demo-token"
    st.rerun()
```

> 这只是让骨架页能打开，不代表已经登录成功；课次19 会用真实登录替换它。

**学生任务（10 分钟）**

把 `require_login` 放进 `components/` 或单独的 `auth.py`，在两个子页面顶部调用；在首页加"模拟登录"按钮；清空 `session_state` 后访问子页面，确认被拦住；点"模拟登录"后再访问，确认能进入。

### 环节7：响应式布局（20 分钟）

**教师演示**

```python
left, right = st.columns([2, 1])
with left:
    st.info("主内容区")
with right:
    st.info("辅助区")
```

**讲清三条规则**

1. 列比例 `[2, 1]` 表示"主区占 2 份、辅区占 1 份"；
2. 窗口变窄时，列会自动堆叠，不需要写媒体查询；
3. 表格、图表用 `width="stretch"` 填满所在容器。

**对比**

| 写法 | 宽屏 | 窄屏 |
|---|---|---|
| `st.columns([2, 1])` | 左右两栏 | 自动上下堆叠 |
| 固定像素布局 | 可能溢出 | 需要自己处理 |
| `width="stretch"` | 填满容器 | 填满容器 |

**强调**

- Streamlit 做不到像素级响应式，只能做"比例 + 自动堆叠"；
- 不要为了响应式引入大量自定义 CSS；
- 验收时至少拖动一次窗口宽度。

**学生任务（10 分钟）**

把部门页的"列表 + 操作"改成两列 `[3, 1]`，观察窄屏时的堆叠效果。

## 七、板书设计

```
项目结构：
  app.py          入口 / 首页 / 门禁
  pages/          每个 .py 一个页面，文件名数字排序
  components/     复用组件（第二次用到再抽）
  config.py       配置集中管理
  requirements.txt

页面区域：
  标题区 → 筛选区 → 内容区 → 操作区

守卫：
  每个子页面顶部 require_login()
  未登录 → st.warning + st.stop()

响应式：
  st.columns([2, 1]) + width="stretch"
  窄屏自动堆叠
```
