## 二、教学目标

**知识与技能**

- 能实现列表刷新：新增/编辑/删除后，列表显示最新数据。
- 能实现新增表单：字段、必填、提交、刷新。
- 能实现编辑表单：回填当前值、保存、刷新。
- 能实现删除：二次确认、删除后刷新。
- 能给出操作反馈：成功/失败提示。
- 能用 `st.session_state` 保存当前用户、页码、筛选条件。
- 能处理表单级基本错误：422 缺字段、400 重复。

**过程与方法**

- 经历"列表 → 新增 → 编辑 → 删除 → 状态保持"的 CRUD 过程。
- 学会用 `session_state` 让翻页、筛选在操作后不丢。

**情感态度与价值观**

- 建立"操作要有反馈、危险操作要确认"的意识。
- 养成"一次只做一个操作、做完就测"的习惯。

## 教学内容

> 对应教学计划：专题三基本内容第 5 条"数据编辑与页面状态"。

1. **列表刷新与分页/筛选状态**：新增/编辑/删除后怎么刷新；页码、筛选条件怎么保持。
2. **新增表单**：字段、必填、提交、刷新列表。
3. **编辑表单**：回填当前值、保存、刷新。
4. **删除**：二次确认、删除后刷新。
5. **操作反馈**：成功/失败提示；表单级 422/400 的基本提示。
6. **页面状态**：用 `st.session_state` 保存当前用户、页码、筛选条件，跨 rerun 保持；状态的生命周期（初始化、读取、重置/清理）。
7. **深度错误处理不在此课**：401/403/500、统一错误提示放课次22。

## 三、重点与难点

**重点**

- 新增/编辑/删除三个操作。
- 列表刷新与分页/筛选状态保持。
- `session_state` 的使用。

**难点**

- 编辑表单的回填。
- 操作后页码/筛选不丢。
- 删除的二次确认与失败提示。

## 四、学情分析与教学策略

学生已经完成登录和列表展示，知道怎么调接口、怎么显示数据。本课次从"读"转到"写"：

- 一次只做一个操作：列表 → 新增 → 编辑 → 删除；
- 每做完一个就测一次；
- 状态放 `session_state`，不要放局部变量；
- 不深入 401/403/500，避免和课次22 重复。

策略：

- **先刷新，再新增**：先理解"为什么改完要重跑"；
- **表单先做新增，再做编辑**：编辑多了"回填"和 `key` 两个坑；
- **删除必须二次确认**：把"危险操作"变成习惯；
- **反馈用 toast**：成功提示跨 rerun 保留，体验更顺。

### 环节2：列表刷新与分页/筛选状态（25 分钟）

**教师讲清"刷新"的本质**

> Streamlit 每次交互都会重跑脚本。
> 只要"取列表"的代码在脚本顶部，操作后调用 `st.rerun()`，列表自然重新取一遍。

**分页与筛选状态**

```python
import streamlit as st

if "dept_page" not in st.session_state:
    st.session_state.dept_page = 1
if "dept_page_size" not in st.session_state:
    st.session_state.dept_page_size = 10

params = {
    "page": st.session_state.dept_page,
    "page_size": st.session_state.dept_page_size,
    "sort_by": "create_time",
    "sort_order": "desc",
}
```

**配合翻页按钮**

```python
left, middle, right = st.columns([1, 2, 1])
with left:
    if st.button("上一页", disabled=st.session_state.dept_page <= 1):
        st.session_state.dept_page -= 1
        st.rerun()
with right:
    if st.button("下一页"):
        st.session_state.dept_page += 1
        st.rerun()
```

**讲清三条规则**

1. 页码、每页条数、筛选条件都放 `session_state`；
2. 临时输入（正在编辑的文本框）不要放 `session_state`，除非确实要跨页面保留；
3. 切换筛选条件时，页码要重置为 1，否则可能停在一个不存在的页。

**强调**

- `st.rerun()` 不是"刷新浏览器"，是"让脚本再跑一遍"；
- 列表请求要放在操作代码**之前**，否则刷新后拿不到新数据；
- 状态初始化用 `if "dept_page" not in st.session_state`，不要每次重跑都覆盖。

**学生任务（10 分钟）**

- 把页码、每页条数放进 `session_state`；
- 加"上一页/下一页"，验证翻页后状态保持；
- 加一个搜索框，切换关键字时把页码重置为 1。

### 环节3：新增表单（35 分钟）

**教师演示**

```python
with st.form("create_dept", clear_on_submit=True):
    col1, col2 = st.columns(2)
    with col1:
        dept_code = st.text_input("部门编码 *", placeholder="例如 1001")
    with col2:
        full_name = st.text_input("部门名称 *")
    address = st.text_input("地址")
    parent_dept_code = st.text_input("父部门编码（可空）")
    submitted = st.form_submit_button("提交", type="primary")

if submitted:
    if not dept_code.strip() or not full_name.strip():
        st.error("部门编码和部门名称不能为空")
    else:
        try:
            api.post(
                "/departments/",
                json={
                    "dept_code": dept_code.strip(),
                    "full_name": full_name.strip(),
                    "address": address.strip() or None,
                    "parent_dept_code": parent_dept_code.strip() or None,
                },
            )
        except api.ApiError as exc:
            st.error(exc.detail)
        else:
            st.session_state["_flash"] = "部门新增成功"
            st.rerun()
```

**讲清"提交"的三步**

```
前端校验（必填） → 调 POST → 成功：提示 + 重跑；失败：显示 detail
```

**表单级错误处理（本课只做这两类）**

| 状态码 | 含义 | 页面怎么做 |
|---|---|---|
| 422 | 参数缺失/类型不对 | 显示"请检查必填项和格式" |
| 400 | 业务规则不满足（编码重复、父部门不存在） | 直接显示后端 `detail` |

**强调**

- 前端校验只是"第一道关"，后端校验才是最终依据；
- 提交成功后不要手动 `append` 列表，交给 `st.rerun()` 重新取；
- `clear_on_submit=True` 让表单提交后自动清空，避免重复提交。

**学生任务（15 分钟）**

- 完成新增表单；
- 新增成功后列表多一条；
- 用重复编码提交，确认显示 400 的提示；
- 把必填项留空，确认前端提示，不发出请求。

### 环节4：编辑表单（40 分钟）

**教师演示选择要编辑的部门**

```python
options = {f"{d['dept_code']} - {d['full_name']}": d for d in items}
selected_label = st.selectbox("选择部门", list(options.keys()))
selected = options[selected_label]
```

**回填表单**

```python
key_suffix = selected["dept_code"]

with st.form("edit_dept"):
    st.text_input(
        "部门编码",
        value=selected["dept_code"],
        disabled=True,
        key=f"edit_code_{key_suffix}",
    )
    full_name = st.text_input(
        "部门名称",
        value=selected.get("full_name", ""),
        key=f"edit_full_name_{key_suffix}",
    )
    address = st.text_input(
        "地址",
        value=selected.get("address") or "",
        key=f"edit_address_{key_suffix}",
    )
    save = st.form_submit_button("保存修改", type="primary")

if save:
    try:
        api.put(
            f"/departments/{selected['dept_code']}",
            json={
                "full_name": full_name,
                "address": address or None,
            },
        )
    except api.ApiError as exc:
        st.error(exc.detail)
    else:
        st.session_state["_flash"] = "部门修改成功"
        st.rerun()
```

**讲清三个坑**

1. **回填**：`value=` 只在组件第一次创建时生效，之后用户输入会覆盖它；
2. **切换对象**：从部门 A 切到部门 B 时，如果 `key` 不变，组件会沿用 A 的输入；
3. **解决办法**：`key` 加上当前对象的唯一标识（如 `dept_code`），切换时相当于新建组件，值会重新取 `value`。

**为什么编码要 `disabled=True`**

- 部门编码通常是主键/业务唯一键；
- 允许修改会牵连人员、父部门等关联；
- 本课程约定：编码创建后不可改，只改名称、地址等字段。

**强调**

- 编辑不是"先查详情再填"，列表里已有字段可以直接回填；
- 如果字段较多，再单独调 `GET /departments/{code}`；
- 保存成功后同样用 `st.rerun()` 重新取列表。

**学生任务（20 分钟）**

- 完成"选择部门 → 回填 → 保存"；
- 切换两个不同部门，确认表单值跟着变；
- 故意把 `key` 的 `key_suffix` 去掉，观察"切换后还是上一个值"的现象，再改回来；
- 验证保存后列表显示新名称。

### 环节5：删除与二次确认（25 分钟）

**教师演示**

```python
st.divider()
with st.expander("删除部门（危险操作）"):
    st.caption(f"将删除：{selected['dept_code']} - {selected['full_name']}")
    confirm = st.checkbox(
        "我确认要删除该部门",
        key=f"dept_delete_confirm_{selected['dept_code']}",
    )
    if st.button("删除", type="primary", disabled=not confirm):
        try:
            api.delete(f"/departments/{selected['dept_code']}")
        except api.ApiError as exc:
            st.error(exc.detail)
        else:
            st.session_state["_flash"] = "部门删除成功"
            st.rerun()
```

**讲清三个设计点**

1. 删除放在 `expander` 里，默认收起，减少误触；
2. 必须勾选"我确认"才启用按钮，把"二次确认"落到实处；
3. 删除失败要显示原因（如 404 已被删除、400 有关联数据不能删）。

**强调**

- 不要用一个"删除"按钮直接删，危险操作必须确认；
- 删除后如果当前页空了，页码要回退一页；
- 本课只处理 400/404 的表单级提示，401/403/500 放课次22。

### 环节6：操作反馈与页面状态（25 分钟）

**教师演示 `flash` 模式**

```python
def set_flash(message: str) -> None:
    """把提示暂存起来，等 rerun 之后显示。"""
    st.session_state["_flash"] = message


def show_flash() -> None:
    """显示并清除上一次操作留下的提示。"""
    message = st.session_state.pop("_flash", None)
    if message:
        st.toast(message, icon="✅")
```

**页面顶部调用一次**

```python
show_flash()
```

**讲清"为什么不能直接 `st.success` 再 `st.rerun()`"**

- `st.success` 画在当前这次渲染上；
- 紧接着 `st.rerun()` 会丢掉这次渲染；
- 所以要先把消息存进 `session_state`，重跑后再显示。

**状态的生命周期**

| 阶段 | 做法 |
|---|---|
| 初始化 | `if "dept_page" not in st.session_state: ...` |
| 读取 | 请求参数、当前用户从 `session_state` 取 |
| 修改 | 翻页、筛选、登录时写入 |
| 清理 | 退出登录时 `st.session_state.clear()` |

**强调**

- 只把"跨 rerun 需要保留"的东西放 `session_state`；
- 不要把所有变量都塞进去，否则状态会越来越乱；
- 退出登录必须清空，避免下一个用户看到上一个用户的状态。

**学生任务（10 分钟）**

- 给新增、编辑、删除都加上 `flash` 提示；
- 退出登录清空 `session_state`；
- 检查操作后页码、搜索条件是否保持。

## 七、板书设计

```

  前端校验 → 调接口 → 成功 st.rerun() / 失败显示 detail

  value= 回填 + key 加对象唯一标识

删除：
  expander + 勾选确认 + disabled 按钮

  set_flash → st.rerun → show_flash → st.toast
```
