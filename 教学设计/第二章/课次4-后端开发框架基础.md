# 课次4：后端开发框架基础——后端到底在做什么

## 一、课次基本信息

| 项目 | 内容 |
|---|---|
| 所属专题 | 专题二：后端服务开发 |
| 学时 | 2 学时（理论，约 90 分钟） |

## 二、教学目标

**知识与技能**

- 能说出前端、后端、数据库各自负责什么。
- 能说出一个接口由四部分组成：URL、方法、参数、返回。
- 能打开 `/docs`，看懂一个接口，并点 "Try it out" 试一次。
- 能写一个最简单的 FastAPI 接口：收到请求，返回一段 JSON。
- 能区分路径参数和查询参数。
- 知道"参数不对会返回 422"。

**过程与方法**

- 经历"点一个按钮 → 看请求 → 看返回"的过程，建立"请求—响应"的直觉。
- 学会用 `/docs` 验证接口，而不是靠猜。

**情感态度与价值观**

- 建立"接口是前后端约定"的意识。
- 不怕英文报错，知道先看状态码和提示。

## 教学内容

> 对应教学计划：专题二基本内容第 1 条"后端开发框架基础"。

1. **前端、后端、数据库的分工**：谁负责显示、处理、存储。
2. **请求—响应模型**：前端发请求，后端返回数据；JSON 格式。
3. **一个接口的四要素**：URL、方法、参数、返回。
4. **常用 HTTP 方法**：GET 查、POST 增、PUT 改、DELETE 删。
5. **常用状态码**：200 成功、201 新增、404 没找到、422 参数不对。
6. **FastAPI 的最小用法**：`@app.get`、返回 JSON、启动服务。
7. **路径参数与查询参数**：`/hello/{name}` 与 `/hello?name=...` 的区别。
8. **接口文档 `/docs`**：看懂接口、点 "Try it out" 测试。
9. **参数校验与 422**：参数缺失或类型不对时的提示。

> **边界说明**：本课次只要求"看懂一个接口、试通一个最小接口"；
> "一个模块需要设计哪些接口、URL 怎么命名、参数来源怎么选"是课次5 的内容，本课次不展开。

## 三、重点与难点

**重点**

- 前端、后端、数据库的分工。
- 接口四要素：URL、方法、参数、返回。
- 写一个最小接口，并在 `/docs` 里试通。

**难点**

- 理解"请求—响应"这个过程。
- 区分路径参数和查询参数。
- 第一次写接口时的语法和环境问题。

## 四、学情分析与教学策略

学生几乎零基础，英文术语多、抽象概念多，容易听不懂、跟不上。

本课次只讲**一个核心问题**：

> 后端到底在做什么？——接收请求，返回数据。

教学策略：

- **少讲术语**：先讲"做什么"，再给术语；
- **一个例子讲到底**：用"查部门"贯穿全课；
- **只写一个接口**：`/hello`，不写完整项目；
- **多演示、多重复**：每个概念配一个可见的结果；
- **不要求当堂独立完成**：先看懂、再模仿。

## 六、教学过程

### 环节1：导入——点一个按钮，发生了什么（10 分钟）

**教师展示**

打开 duty 前端，点"查询部门"，展示部门列表。

**提问**

> "你点了按钮，屏幕上出现了数据。数据是从哪里来的？"

**引导学生说出**

- 页面上没有这些数据；
- 数据在服务器/数据库里；
- 页面向服务器"要"数据，服务器把数据"送"回来。

**教师总结**

> 这个过程就叫"请求—响应"。
>
> 前端负责"显示"，后端负责"给数据"，数据库负责"存数据"。

---

### 环节2：前端、后端、数据库（15 分钟）

**教师画三个框**

```
浏览器（前端）  →  服务器（后端）  →  数据库
   显示              处理              存储
```

**用"查部门"讲一遍**

1. 前端：用户在页面上点"查询"；
2. 后端：收到请求，去数据库查部门；
3. 数据库：把部门数据返回给后端；
4. 后端：把数据整理成 JSON，返回给前端；
5. 前端：把 JSON 显示成表格。

**讲清两个词**

- **请求**：前端发给后端的话；
- **响应**：后端回给前端的话。

**强调**

> 后端不负责"画页面"，它负责"按要求取数据、处理数据、返回数据"。

---

### 环节3：一个接口的四个部分（20 分钟）

**教师用"查部门"举例**

| 部分 | 例子 | 说明 |
|---|---|---|
| URL | `/api/v1/departments/` | 找谁 |
| 方法 | `GET` | 做什么（查/增/改/删） |
| 参数 | `page=1`、`page_size=10` | 带什么条件 |
| 返回 | `{"items": [...], "total": 5}` | 给什么结果 |

**四种常见方法（只讲最常用的）**

| 方法 | 意思 | 例子 |
|---|---|---|
| GET | 查 | 查部门列表 |
| POST | 新增 | 新增一个部门 |
| PUT | 修改 | 修改部门名称 |
| DELETE | 删除 | 删除部门 |

**状态码（只讲 4 个）**

| 状态码 | 意思 |
|---|---|
| 200 | 成功 |
| 201 | 新增成功 |
| 404 | 没找到 |
| 422 | 参数不对 |

**强调**

> 一个接口 = 找谁（URL）+ 做什么（方法）+ 带什么（参数）+ 给什么（返回）。

---

### 环节4：写一个最小接口，并在 `/docs` 里试通（25 分钟）

**教师演示（一步一步，不粘贴整段）**

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")
def hello():
    return {"message": "你好，后端"}
```

**运行**

```bash
uvicorn main:app --reload --port 8000
```

**打开**

- `http://127.0.0.1:8000/hello` → 看到 `{"message": "你好，后端"}`
- `http://127.0.0.1:8000/docs` → 找到 `/hello`，点 "Try it out"，点 "Execute"

**学生任务**

- 跟着教师，把 `/hello` 跑起来；
- 在 `/docs` 里点一次 "Try it out"；
- 把返回结果截图或抄下来。

**只讲三件事**

1. `@app.get("/hello")`：告诉程序"有人访问 `/hello` 时，执行下面的函数"；
2. `return {"message": ...}`：返回一个 JSON；
3. `/docs`：自动生成的使用说明书。

**常见问题**

- 端口被占用：换 `--port 8001`；
- 找不到 `uvicorn`：检查是否装了 FastAPI 和 uvicorn；
- 改了代码没反应：看是否加了 `--reload`。

---

### 环节5：路径参数、查询参数和 422（15 分钟）

**路径参数**

```python
@app.get("/hello/{name}")
def hello(name: str):
    return {"message": f"你好，{name}"}
```

访问 `/hello/张三` → `{"message": "你好，张三"}`

**查询参数**

```python
@app.get("/hello")
def hello(name: str = "同学"):
    return {"message": f"你好，{name}"}
```

访问 `/hello?name=张三` → `{"message": "你好，张三"}`

**对比**

| 类型 | 位置 | 例子 | 适合 |
|---|---|---|---|
| 路径参数 | URL 路径里 | `/hello/张三` | 定位"某一个" |
| 查询参数 | `?` 后面 | `/hello?name=张三` | 筛选、带条件 |

**422 演示**

- 把 `name` 改成必填的数字：`def hello(name: int)`；
- 访问 `/hello/abc` → 返回 422；
- 告诉学生：**422 就是"你给的参数不对"**，看返回里的 `msg`。

**强调**

> 不用背所有状态码；先记住 200 成功、404 没找到、422 参数不对。

---

### 环节6：小结与出口题（5 分钟）

**教师总结**

> 后端 = 接收请求，返回数据。
>
> 一个接口 = URL + 方法 + 参数 + 返回。
>
> 今天只写了一件事：一个最小的 `/hello` 接口，并在 `/docs` 里试通。

**出口题（口头或纸条，3 分钟）**

1. 前端、后端、数据库各负责什么？
2. `/hello/张三` 和 `/hello?name=张三` 有什么区别？
3. 422 是什么意思？

**布置作业**

1. 把 `/hello` 跑起来，在 `/docs` 里试一次，截图。
2. 把 `/hello` 改成 `/hello/{name}`，访问 `/hello/你的名字`。
3. 预习课次5：表怎么建、接口怎么定。

## 七、板书设计

```
前端（显示） → 后端（处理） → 数据库（存储）
       请求  →         响应

接口四要素：
  URL     找谁      /api/v1/departments/
  方法    做什么    GET / POST / PUT / DELETE
  参数    带什么    page=1
  返回    给什么    {"items": [...]}

状态码：200 成功 / 201 新增 / 404 没找到 / 422 参数不对
```
