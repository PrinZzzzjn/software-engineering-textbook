### 环节2：用户列表与详情（15 分钟）

**教师演示**

```python
@router.get("/", dependencies=[Depends(get_current_admin_user)])
def list_users(db: Session = Depends(get_db)):
    users = (
        db.query(User)
        .order_by(User.id)
        .limit(50)
        .all()
    )
    return {
        "items": [
            {"id": u.id, "username": u.username, "role": u.role, "is_active": u.is_active}
            for u in users
        ],
        "count": len(users),
    }
```

```python
@router.get("/{user_id}", dependencies=[Depends(get_current_admin_user)])
def get_user(user_id: int, db: Session = Depends(get_db)):
    user = db.query(User).filter(User.id == user_id).first()
    if not user:
        raise HTTPException(status_code=404, detail="用户不存在")
    return {"id": user.id, "username": user.username, "role": user.role, "is_active": user.is_active}
```

### 环节3：修改角色与启用/禁用（25 分钟）

**教师演示**

```python
class UserUpdate(BaseModel):
    role: str | None = None
    is_active: int | None = None
```

```python
@router.put("/{user_id}")
def update_user(
    user_id: int,
    data: UserUpdate,
    db: Session = Depends(get_db),
    current_user: dict = Depends(get_current_admin_user),
):
    user = db.query(User).filter(User.id == user_id).first()
    if not user:
        raise HTTPException(status_code=404, detail="用户不存在")

    # 安全规则：不能禁用自己
    current_user_id = int(current_user["sub"])
    if current_user_id == user_id and data.is_active == 0:
        raise HTTPException(status_code=400, detail="不能禁用自己")

    if data.role is not None:
        user.role = data.role
    if data.is_active is not None:
        user.is_active = data.is_active
    db.commit()
    db.refresh(user)
    return {"id": user.id, "username": user.username, "role": user.role, "is_active": user.is_active}
```

**学生任务**

- 加修改接口；
- 把普通用户改成 `admin`，再改回 `normal`；
- 禁用普通用户，再用它登录，观察 401。

**强调**

- 角色只允许 `admin` / `normal`，不要接受任意字符串；
- 禁用后不能登录（登录时检查 `is_active`）；
- 不能禁用自己，避免把自己锁在外面。

### 环节4：权限测试（20 分钟）

**测试步骤**

1. 管理员登录，拿 token；
2. 普通用户登录，拿 token；
3. 分别调用 `GET /users/`、`PUT /users/{id}`；
4. 记录结果。

**预期**

| 接口 | 管理员 | 普通用户 |
|---|---|---|
| GET `/users/` | 200 | 403 |
| GET `/users/{id}` | 200 | 403 |
| PUT `/users/{id}` | 200 | 403 |
| GET `/users/me` | 200 | 200 |

**讲清 401 与 403**

- 401：没登录、token 错、token 过期；
- 403：登录了，但角色不够（普通用户访问管理员接口）。

**强调**

- 权限加在后端，不能只靠前端隐藏按钮；
- 普通用户也应该能访问 `/users/me`（看自己）。

---

### 环节5：完整闭环演示（20 分钟）

**教师带学生走一遍**

1. 管理员登录；
2. 创建普通用户 `zhangsan`；
3. 用 `zhangsan` 登录，访问 `/users/` → 403；
4. 管理员把 `zhangsan` 改成 `admin`；
5. 用 `zhangsan` **重新登录**，再访问 `/users/` → 200；
6. 管理员把 `zhangsan` 禁用；
7. 用 `zhangsan` 再登录 → 401。

**重点解释**

> 修改角色后，旧 token 里还是旧角色；要重新登录，才能拿到新角色。
> 这不是 bug，是 token 的工作方式：token 在登录时签发，过期或重新登录才更新。

**学生跟做（10 分钟）**

- 用自己的两个账号走一遍 1–7 步；
- 记录一次 403、一次 401，各截一张图；
- 确认"改角色后不重新登录，权限不变"。
