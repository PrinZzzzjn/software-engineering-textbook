## 二、教学目标

**知识与技能**

- 能说清 `users` 表的作用和四个核心字段：`username`、`password_hash`、`role`、`is_active`。
- 能创建用户，密码用哈希存储，不存明文。
- 能实现登录：用户名 + 密码 → 校验 → 发 token。
- 能用 `Authorization: Bearer <token>` 访问一个受保护接口。
- 能处理 401：密码错、没带 token、token 过期。

**过程与方法**

- 经历"建用户 → 登录 → 拿 token → 访问受保护接口"的完整闭环。
- 学会用 `/docs` 的 "Authorize" 测试需要登录的接口。

**情感态度与价值观**

- 建立"密码不明文、token 要保密"的安全意识。
- 养成"先看 401 提示、再排查"的习惯。

## 教学内容

> 对应教学计划：专题二基本内容第 4 条"用户模块：登录认证"。
> 本课次把 JWT 当"黑盒"：只讲"登录发 token、请求带 token"，不展开三段结构、刷新、登出。

1. **`users` 表**：账号、密码哈希、角色、状态；`username`、`password_hash`、`role`、`is_active`。
2. **创建用户**：输入用户名、密码、角色；密码哈希后存；用户名不能重复。
3. **登录**：用户名 + 密码 → 查用户 → 校验密码 → 发 token。
4. **token 的使用**：登录成功后拿到 token；之后请求带 `Authorization: Bearer <token>`。
5. **当前用户**：用 token 查到"我是谁"（`/users/me`）。
6. **401 的三种情况**：密码错、没带 token、token 过期。
7. **user 模块的最小结构**：model、schema、service、controller 四个文件（crud 在课次9 再拆）。

## 三、重点与难点

**重点**

- `users` 表与创建用户。
- 密码哈希存储与校验。
- 登录流程与 token 的使用。

**难点**

- 理解"密码只存哈希"。
- token 放在请求头里传递。
- 区分 401 的三种原因。

## 四、学情分析与教学策略

学生几乎零基础，JWT、哈希、依赖注入这些词都很陌生。本课次**不深讲原理**，只讲"怎么用"：

- 密码：用教师提供的 `get_password_hash` / `verify_password`；
- token：用教师提供的 `create_access_token` / `decode_token`；
- 当前用户：用教师提供的 `get_current_user` 依赖；
- 学生只写：`users` 表、创建用户、登录、`/users/me`。

策略：

- **先跑通，再理解**：先让创建用户和登录跑通；
- **只做两个接口**：`POST /users/`、`POST /login`，再加一个 `/users/me`；
- **用 `/docs` 的 Authorize 测试**；
- **排错清单**：401 先看密码、token、请求头。

> 3. `GET /users/me`：带 token 拿到当前用户。

**验收标准**

### 环节2：`users` 表（20 分钟）

**教师展示表结构**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 整数 | 主键，自增 |
| username | 文本 | 用户名，唯一，不能重复 |
| password_hash | 文本 | 密码哈希，不是明文 |
| role | 文本 | `admin` / `normal` |
| is_active | 整数 | 1 启用，0 禁用 |

**讲清三件事**

1. `username` 唯一：不能有两个同名账号；
2. `password_hash` 存哈希：数据库泄露也拿不到原密码；
3. `role` 决定权限，`is_active` 决定能不能登录。

**学生任务**

- 写 `model.py`；
- 在数据库里建表（`Base.metadata.create_all`）；
- 用工具查看表结构，确认字段。

**参考代码**

```python
class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True)
    username = Column(String(100), unique=True, nullable=False)
    password_hash = Column(String(255), nullable=False)
    role = Column(String(20), default="normal")
    is_active = Column(Integer, default=1)
```

### 环节3：创建用户（35 分钟）

**教师演示（一步一步）**

1. `schema.py`：定义输入和输出模型；
2. `service.py`：查重、哈希密码、写入数据库；
3. `controller.py`：`POST /users/`。

**参考代码**

```python
class UserCreate(BaseModel):
    username: str = Field(..., min_length=3, max_length=100)
    password: str = Field(..., min_length=6, max_length=50)
    role: str = "normal"
```

```python
def create_user(db, data: UserCreate):
    if db.query(User).filter(User.username == data.username).first():
        raise HTTPException(status_code=400, detail="用户名已存在")
    user = User(
        username=data.username,
        password_hash=get_password_hash(data.password),
        role=data.role,
    )
    db.add(user)
    db.commit()
    db.refresh(user)
    return user
```

**学生任务**

- 写 schema、service、controller；
- 在 `/docs` 里创建一个用户；
- 用数据库工具查看 `password_hash`，确认不是明文。

**常见错误**

- 忘记哈希，直接把 `password` 存进 `password_hash`；
- 用户名重复没有返回 400；
- 响应里返回了 `password_hash`（不应返回）。

### 环节4：登录（45 分钟）

**教师演示**

1. `service.py`：按用户名查用户 → `verify_password` → 发 token；
2. `controller.py`：`POST /login`。

**参考代码**

```python
def login(db, username: str, password: str):
    user = db.query(User).filter(User.username == username).first()
    if not user or not verify_password(password, user.password_hash):
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    if not user.is_active:
        raise HTTPException(status_code=401, detail="账号已禁用")

    token = create_access_token({"sub": str(user.id), "role": user.role})
    return {
        "access_token": token,
        "token_type": "bearer",
        "user": {"id": user.id, "username": user.username, "role": user.role},
    }
```

**学生任务**

- 写登录 service 和 controller；
- 在 `/docs` 里用正确密码登录，拿到 token；
- 用错误密码登录，确认 401。

**强调**

- 错误提示统一写"用户名或密码错误"，不要泄露账号是否存在；
- token 是一串字符串，客户端保存，之后请求带上；
- 不展开 token 内部结构，知道"能解析、会过期"即可。

---

### 环节5：带 token 访问受保护接口（30 分钟）

**教师演示依赖**

```python
# dependencies.py（教师提供）
def get_current_user(token: str = Depends(oauth2_scheme)):
    payload = decode_token(token)
    if not payload:
        raise HTTPException(status_code=401, detail="登录已过期")
    return payload
```

**学生任务**

1. 在 `controller.py` 写 `GET /users/me`，依赖 `get_current_user`；
2. 在 `/docs` 里先登录拿 token，点 "Authorize" 填入；
3. 调用 `/users/me`，看到当前用户；
4. 不带 token 再调用一次，观察 401。

**参考代码**

```python
@router.get("/me")
def me(current_user: dict = Depends(get_current_user)):
    return current_user
```

**强调**

- 受保护接口加 `Depends(get_current_user)`；
- token 放在请求头 `Authorization: Bearer <token>`；
- 401 不是"服务器坏了"，是"没登录/登录过期"。

### 环节6：测试与排错（30 分钟）

**测试清单**

- [ ] 创建用户 → 201；
- [ ] 用户名重复 → 400；
- [ ] 密码太短 → 422；
- [ ] 正确密码登录 → 200，返回 token；
- [ ] 错误密码 → 401；
- [ ] 不带 token 访问 `/users/me` → 401；
- [ ] 带 token 访问 `/users/me` → 200；
- [ ] 改一个字符的 token → 401。

**排错清单**

| 现象 | 先查什么 |
|---|---|
| 401 密码错 | 用户名是否存在、是否用 `verify_password` |
| 401 令牌错 | 请求头是否 `Bearer <token>`、token 是否过期 |
| 400 用户名重复 | 查重逻辑、数据库唯一约束 |
| 500 | 字段名、数据库查询、`user` 是否为空 |
| `/docs` 没有 Authorize | 是否配置了 `OAuth2PasswordBearer` |
