## 二、教学目标

**知识与技能**

- 能说清一个标准 CRUD 模块的六个文件及各自职责。
- 能实现部门模块：列表、新增、详情。
- 能给字段加校验：必填、长度、类型、唯一。
- 能用统一异常处理返回 404、422、400。
- 能按对照表把部门模块复制成人员模块，课内完成人员列表，新增课后完成。
- 知道更新、删除、搜索放课后。

**过程与方法**

- 经历"建表 → 校验 → CRUD → 异常 → 复制"的完整模块开发过程。
- 学会用 `/docs` 和错误响应排查问题。

**情感态度与价值观**

- 建立"数据要校验、错误要统一"的意识。
- 养成"先做主链路、再补细节"的习惯。

## 教学内容

> 对应教学计划：专题二基本内容第 6 条"数据模块：增删查改"。

1. **标准 CRUD 模块的六个文件**：model、schema、param、crud、service、controller。
2. **部门表字段**：`dept_code`、`full_name`、`address`、`longitude`、`latitude`、`parent_dept_code`。
3. **数据校验**：必填、长度、类型、唯一。
4. **部门 CRUD**：列表、新增、详情（更新/删除放课后；分页/过滤/排序在课次10）。
5. **统一异常处理**：404 没找到、422 参数不对、400 业务错误（如名称重复）。
6. **人员模块复制**：复制部门结构，增加 `dept_code` 关联；课内只做列表示范，新增放课后。
7. **测试**：正常、重复、缺字段、找不到。

## 三、重点与难点

**重点**

- 六个文件的职责。
- 部门模块的列表、新增、详情。
- 数据校验与统一异常。

**难点**

- 六文件之间的调用关系。
- 唯一校验（名称/编码重复）。
- 复制部门到人员时，外键 `dept_code` 的处理。

## 四、学情分析与教学策略

学生已经在课次7–8 做过 user 模块，但还没有完整写过一个 CRUD 模块。零基础学生容易被六个文件绕晕，所以本课次：

- **先画调用关系**：controller → service → crud → model；
- **部门模块做透**：列表、新增、详情三个接口，课内给足时间；
- **人员模块只做列表示范**：新增放课后，避免两套模块都半生不熟；
- **每完成一个接口就测**：不攒到最后。

策略：

- **一个文件一个文件改**：不一次打开六个；
- **用对照表**：dept → personnel 改哪些；
- **错误驱动**：先制造 404/422/400，再讲异常处理。

## 五、教学准备

- duty 后端可运行；`/docs` 可用。
- dept 模块脚手架（六个文件空壳）。
- personnel 模块的复制对照表（见附录 A）。
- 统一异常处理代码：`app/core/exceptions.py`。

---

### 环节2：六个文件与调用关系（20 分钟）

**教师画调用关系**

```
前端请求
  ↓
controller   接请求、返回结果
  ↓
service      业务规则（重复校验、关联校验）
  ↓
crud         读写数据库
  ↓
model        表结构
```

**六个文件**

| 文件 | 一句话职责 |
|---|---|
| model.py | 表长什么样 |
| schema.py | 输入/输出长什么样 |
| param.py | 查询参数 |
| crud.py | 增删改查 SQL |
| service.py | 业务规则 |
| controller.py | 接口 |

**强调**

- controller 不写 SQL、不写业务；
- service 不直接拼 SQL，调 crud；
- crud 不写业务规则；
- schema 决定"哪些字段能进、哪些字段能出"。

---

### 环节3：部门表与校验（25 分钟）

**教师给出部门表**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| dept_code | 文本 | 是 | 部门编码，唯一 |
| full_name | 文本 | 是 | 部门名称 |
| address | 文本 | 否 | 地址 |
| longitude | 数字 | 否 | 经度 |
| latitude | 数字 | 否 | 纬度 |
| parent_dept_code | 文本 | 否 | 父部门编码 |

**schema 校验**

```python
class DepartmentCreate(BaseModel):
    dept_code: str = Field(..., min_length=1, max_length=20)
    full_name: str = Field(..., min_length=1, max_length=100)
    address: str | None = Field(default=None, max_length=500)
    longitude: float | None = None
    latitude: float | None = None
    parent_dept_code: str | None = None
```

**讲清三种错误**

| 情况 | 返回 | 原因 |
|---|---|---|
| 缺 `dept_code` | 422 | 校验失败 |
| `full_name` 超长 | 422 | 校验失败 |
| `dept_code` 已存在 | 400 | 业务规则（唯一） |
| 查不到部门 | 404 | 资源不存在 |

**学生任务**

- 写 model 和 schema；
- 在 `/docs` 里试一次缺字段，观察 422。

---

### 环节4：部门 CRUD（60 分钟）

> 分两段推进，每段 30 分钟，中间停一次做检查，避免学生闷头写到下课。

**第一段（30 分钟）：crud + service**

**学生任务**

1. **crud.py**：`get_by_code`、`list_departments`、`create`；
2. **service.py**：
   - 新增前查重，重复抛 400；
   - 列表先做简单查询（分页/过滤/排序在课次10）。

**第一段检查点（停 2 分钟）**

- [ ] `get_by_code` 能按编码查到/查不到；
- [ ] `create` 能写入一条部门；
- [ ] 重复编码会抛 400。

**参考代码（新增）**

```python
def create_department(self, db, data):
    if self.crud.get_by_code(db, data.dept_code):
        raise HTTPException(status_code=400, detail="部门编码已存在")
    return self.crud.create(db, data)
```

**第二段（30 分钟）：controller + 联调测试**

**学生任务**

- `GET /departments` 列表；
- `GET /departments/{dept_code}` 详情；
- `POST /departments` 新增；
- 按下面的测试清单逐条验证。

**测试清单**

- [ ] 新增成功 → 201；
- [ ] 重复编码 → 400；
- [ ] 缺字段 → 422；
- [ ] 列表 → 200；
- [ ] 详情 → 200；
- [ ] 不存在的编码 → 404。

**教师巡视**

- 常见错误：`dept_code` 大小写、重复校验漏掉、404 写成 400；
- 提醒：今天先做简单列表；数据量大了怎么分页，是课次10 的内容。

---

### 环节5：统一异常处理（20 分钟）

> **边界**：本课次只做到“会用 400/404/422、知道有全局处理器”。全局处理器的实现细节、错误格式统一与事务边界放到课次14，不在本课次展开。

**教师展示 `app/core/exceptions.py` 的用法**

- 业务错误：`raise BadRequestException("部门编码已存在")`；
- 404 / 422 由框架处理，业务错误用 400；
- 全局处理器负责把异常转成统一的 `{"detail": "..."}`（实现细节课次14 讲）。

**学生任务**

- 制造三种错误：缺字段、重复编码、查不到；
- 观察返回的状态码和 `detail`；
- 确认错误格式一致。

**强调**

- 不要把数据库报错直接返回给前端；
- 不要所有错误都返回 500；
- 错误提示要让人看懂；
- 事务边界不在本课次，课次14 统一讲。

### 环节7：代码评审与排错（20 分钟）

**评审清单**

- [ ] 六个文件职责是否清楚？
- [ ] 部门新增是否做了重复校验？
- [ ] 人员列表是否正确关联部门（`dept_code`）？
- [ ] 响应是否泄露了不该返回的字段？
- [ ] 404/422/400 是否用对？
- [ ] 人员模块是否残留 dept 字段？

**排错清单**

| 现象 | 先查什么 |
|---|---|
| 422 | 请求体字段名、类型、必填 |
| 400 重复 | 查重逻辑、数据库唯一约束 |
| 404 | 路径参数、查询条件 |
| 500 | 字段名、表名、外键、`None` |
