# 课次15：后端开发综合实践（二）——全流程联调与成果整理

| 项目 | 内容 |

| 学时 | 2 学时（实践，约 90 分钟） |

## 二、教学目标

**知识与技能**

- 能按清单完成一次全流程联调：登录 → 建用户 → 建部门/人员 → 建执勤记录 → 查统计 → 权限验证。
- 能根据 401/403/404/422/500 快速定位常见问题。
- 能整理专题二成果：代码、接口文档、测试、Git 记录、成果清单。
- 能做 3 分钟小组展示，说清"做了什么、能跑什么、还有什么问题"。

**过程与方法**

- 经历"排查 → 联调 → 整理 → 展示"的收尾过程。
- 学会用清单证明"系统真的能用"，而不是"代码写完了"。

**情感态度与价值观**

- 建立"交付"意识：能跑、能说清、能交接。
- 养成"记录问题、总结经验"的习惯。

## 教学内容

> 对应教学计划：专题二基本内容第 12 条"后端开发综合实践（二）"。

1. **常见问题排查**：启动失败、端口占用、依赖缺失、401/403/404/422/500、空数据库、外键不存在。
2. **全流程联调**：管理员登录 → 建普通用户 → 建部门/人员 → 建执勤记录 → 查统计 → 普通用户 403。
3. **成果整理**：代码、接口文档、测试、Git 提交记录、成果清单。
4. **小组展示**：3 分钟，说清做了什么、能跑什么、还有什么问题。
5. **专题二回顾**：user → dept/personnel → duty_record → analytics 的知识地图。
6. **学习资源与后续**：FastAPI/Streamlit/Docker 官方文档；预告专题三。

## 三、重点与难点

**重点**

- 全流程联调清单。
- 常见错误的定位。
- 成果整理与展示。

**难点**

- 多步骤联调时，定位是哪一步出错。
- 说清"能跑什么、不能跑什么"。
- 把问题记录下来，而不是改完就忘。

## 四、学情分析与教学策略

学生已经完成 user、dept、personnel、duty_record、两个统计。本课次不写新功能，只做"跑通 + 整理 + 展示"。

策略：

- **一张清单走到底**：每步都有"请求 → 期望结果"；
- **出错先定位步骤**：不要从头重来；
- **成果清单**：让学生知道"交付"不只是代码；
- **3 分钟展示**：每组说清"做了什么、能跑什么、还有什么问题"。

## 六、教学过程

### 环节1：导入与任务说明（5 分钟）

**教师说明**

> 今天不写新功能，做三件事：
> 1. 按清单把整条链路跑一遍；
> 2. 整理成果（代码、文档、测试、Git）；
> 3. 每组 3 分钟展示。

**验收标准**

- 清单上的步骤至少跑通 8 步；
- 能说清哪一步失败、为什么；
- 有一份成果清单。

---

### 环节2：常见问题排查（20 分钟）

**教师讲五类问题**

| 现象 | 先查什么 |
|---|---|
| 服务起不来 | 端口占用、依赖缺失、语法错误 |
| 401 | 密码、token、请求头 |
| 403 | 角色、权限依赖 |
| 404 | URL、路径参数、资源是否存在 |
| 422 | 请求体字段、类型、必填 |
| 500 | 日志/堆栈、字段名、空值、外键 |

**排查顺序**

1. 看状态码；
2. 看 `detail`；
3. 看服务日志；
4. 定位到具体接口/字段；
5. 改完重跑。

**强调**

- 不要一上来就改代码；
- 先确认"哪一步、什么错"；
- 改完跑测试/重跑清单。

---

### 环节3：全流程联调（30 分钟）

**学生任务**

按清单一步一步走，每步记录"通过/失败 + 原因"。

**清单（节选）**

| 步骤 | 请求 | 期望 |
|---|---|---|
| 1 | 管理员登录 | 200，拿到 token |
| 2 | 创建普通用户 | 201 |
| 3 | 普通用户登录 | 200 |
| 4 | 普通用户查用户列表 | 403 |
| 5 | 管理员建部门 | 201 |
| 6 | 管理员建人员（带 dept_code） | 201 |
| 7 | 管理员建执勤记录 | 201 |
| 8 | 再建一条时间重叠的记录 | 400 |
| 9 | 查年度统计 | 200，数字正确 |
| 10 | 查时段分布 | 200，24 项 |
| 11 | 不带 token 访问 `/users/me` | 401 |
| 12 | 缺字段新增部门 | 422 |

**教师巡视**

- 优先处理"卡在某一步"的组；
- 提醒：先看状态码，再看 detail；
- 提醒：失败步骤记下来，不要跳过。

**常见卡点**

- 步骤 3：普通用户被禁用（`is_active=0`）；
- 步骤 4：普通用户也能访问（权限没加）；
- 步骤 6：`dept_code` 不存在；
- 步骤 8：时间重叠条件写错；
- 步骤 9：没有数据（年份/人员不对）。

---

### 环节4：成果整理（15 分钟）

**学生任务**

按成果清单整理：

- [ ] 代码在 Git 仓库，提交记录完整；
- [ ] 接口文档（Swagger 或 Markdown）；
- [ ] 测试文件，能运行；
- [ ] 一份"我们组做了什么"的清单；
- [ ] 已知问题列表（没做完/有 bug 的）。

**强调**

- 交付不只是代码；
- 已知问题要写出来，不要藏；
- 文档要能让别人照着跑。

---

### 环节5：小组展示与互评（15 分钟）

**展示要求（每组 3 分钟）**

1. 我们做了哪些模块；
2. 演示 1–2 个能跑的接口；
3. 遇到的最大问题 + 怎么解决；
4. 还有什么没做完。

**互评表**

- [ ] 能跑通主流程；
- [ ] 权限正确；
- [ ] 错误处理清楚；
- [ ] 展示说清了"做了什么、没做什么"；
- [ ] 有已知问题记录。

**教师点评**

- 表扬"能跑 + 能说清"的组；
- 指出"能跑但说不清"的问题；
- 提醒专题四答辩会看"能不能解释"。

---

### 环节6：专题二回顾与预告（5 分钟）

**教师画知识地图**

```
user（登录/角色）
   ↓
dept / personnel（数据管理）
   ↓
duty_record（业务规则）
   ↓
analytics（统计）
```

**回顾三个关键词**

- 数据：表、字段、主外键；
- 规则：service 层、400/422；
- 质量：测试、安全、分页。

**预告专题三**

> 后端接口已经有了，下一步是让用户"看得到、用得上"——Streamlit 前端。
