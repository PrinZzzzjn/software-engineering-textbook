## 二、教学目标

**知识与技能**

- 能说清执勤记录的业务：谁、什么时间、在哪个工位、状态、备注。
- 能说清 `duty_record` 表的字段，以及它和人员、工位的关系。
- 能实现执勤记录的列表和新增。
- 能实现一条核心业务规则：开始时间必须早于结束时间；同一人员同一时间段不能重复。
- 能按规则返回 400（时间冲突/人员不存在）；知道 422 由框架处理；统一异常与事务放课次14。
- 知道"业务规则放 service，不放在 controller"。

**过程与方法**

- 经历"读表 → 读模块 → 写接口 → 加规则 → 测试"的过程。
- 学会用"正常、边界、冲突"三类数据测试业务规则。

**情感态度与价值观**

- 建立"业务规则要能被验证"的意识。
- 养成"先想清规则，再写代码"的习惯。

## 教学内容

> 对应教学计划：专题二基本内容第 8 条"业务模块：规则描述"。
> 本课次只做**执勤记录**；查勤记录移到扩展，不在此讲。
> 本课次只讲"规则本身"；统一异常处理、事务边界放到课次14。

1. **执勤记录业务**：谁值班、什么时间、在哪个工位、状态（正常/异常）、备注。
2. **`duty_record` 表字段**：`personnel_certificate_number`、`successor_certificate_number`、`workstation_id`、`start_time`、`end_time`、`status`、`remark`。
3. **业务规则**：开始时间 < 结束时间；人员必须存在；工位必须存在；同一人员同一时间段不能重复。
4. **service 层**：业务规则写在 service，controller 只接请求、返回结果。
5. **列表与新增**：列表按人员/时间筛选；新增时校验规则。
6. **规则违反时的返回**：400（时间冲突/人员不存在）；422 参数格式由框架处理；统一异常与事务边界放课次14。
7. **批量处理（选讲/扩展）**：批量导入值班记录，放课后。

## 三、重点与难点

**重点**

- `duty_record` 表与关联关系。
- 列表与新增。
- 时间冲突校验。

**难点**

- 时间重叠的判断。
- 关联校验（人员、工位是否存在）。
- 业务规则放在哪一层。

## 四、学情分析与教学策略

学生已经做过 dept、personnel 两个数据模块，知道六个文件和 CRUD。本课次第一次遇到"有业务规则"的记录：不是填进去就行，还要检查时间是否冲突、人员/工位是否存在。

策略：

- **先读表，再读规则**：先看字段和关系，再看规则；
- **一条规则讲透**：只做"时间冲突"这一条，不堆规则；
- **用三类数据测试**：正常、边界、冲突；
- **业务规则放 service**：controller 只做转发。

## 六、教学过程

### 环节1：导入与任务说明（10 分钟）

**教师提问**

> "排班时，如果同一个人在同一时间被排了两次，会怎样？"

**引导学生说出**

- 冲突、无法执行、需要系统检查。

**任务**

> 今天做执勤记录：
> 1. 列表：按人员/时间查；
> 2. 新增：填人员、工位、开始/结束时间；
> 3. 规则：开始 < 结束；同一人员同一时间段不能重复。

**验收标准**

- 能新增一条正常记录；
- 开始时间晚于结束时间 → 400；
- 同一人员时间重叠 → 400；
- 人员不存在 → 400；
- 缺字段 → 422。

---

### 环节2：执勤记录表与关系（20 分钟）

**教师展示表结构**

| 字段 | 说明 |
|---|---|
| id | 记录编号（主键） |
| personnel_certificate_number | 值班人员证件号（外键） |
| successor_certificate_number | 接班人员证件号（可选） |
| workstation_id | 工位编号（外键） |
| start_time | 开始时间 |
| end_time | 结束时间 |
| status | 状态（normal / abnormal） |
| remark | 备注 |

**画关系**

```
personnel 1 ─── N duty_record N ─── 1 workstation
```

**讲清**

- 一条记录属于一个人员、一个工位；
- 人员、工位必须先在各自表里存在；
- 时间是这条记录的核心。

---

### 环节3：业务规则（30 分钟）

**教师列三条规则**

1. **时间合法**：`start_time < end_time`；
2. **人员/工位存在**：查一下有没有；
3. **时间不冲突**：同一人员的记录不能重叠。

**时间重叠怎么判断**

```python
# 已有记录：start1 ~ end1
# 新记录：  start2 ~ end2
# 重叠条件：start1 < end2 且 end1 > start2
```

**教师举例**

| 已有 | 新记录 | 是否冲突 |
|---|---|---|
| 08:00–12:00 | 10:00–11:00 | 冲突 |
| 08:00–12:00 | 12:00–14:00 | 不冲突（首尾相接可以） |
| 08:00–12:00 | 13:00–15:00 | 不冲突 |

**强调**

- 规则写在 service，不写在 controller；
- 规则要能说清"什么情况拒绝、返回什么错误"；
- 边界情况（首尾相接）要明确。

---

### 环节4：读 duty_record 模块（25 分钟）

**教师展示目录**

```
duty_record/
├── model.py      # 表结构
├── schema.py     # 输入/输出
├── param.py      # 查询参数
├── crud.py       # 数据库读写
├── service.py    # 业务规则
└── controller.py # 接口
```

**带学生看三处**

1. `model.py`：字段和表名；
2. `service.py`：新增时做了哪些校验；
3. `controller.py`：列表、新增的接口。

**强调**

- controller 只接请求、调 service；
- service 里做"开始<结束、人员存在、时间冲突"；
- crud 只负责查和写。

---

### 环节5：写列表与新增（45 分钟）

**学生任务（按顺序）**

1. `schema.py`：`DutyRecordCreate`（人员、工位、开始、结束、备注）；
2. `service.py`：
   - 校验开始 < 结束；
   - 校验人员、工位存在；
   - 写库；
3. `controller.py`：
   - `GET /duty-records` 列表；
   - `POST /duty-records` 新增；
4. 在 `/docs` 里测试。

**参考代码（新增）**

```python
def create_duty_record(db, data):
    if data.start_time >= data.end_time:
        raise HTTPException(status_code=400, detail="开始时间必须早于结束时间")

    person = db.query(Personnel).filter(
        Personnel.certificate_number == data.personnel_certificate_number
    ).first()
    if not person:
        raise HTTPException(status_code=400, detail="人员不存在")

    workstation = db.query(Workstation).filter(
        Workstation.workstation_id == data.workstation_id
    ).first()
    if not workstation:
        raise HTTPException(status_code=400, detail="工位不存在")

    record = DutyRecord(**data.model_dump())
    db.add(record)
    db.commit()
    db.refresh(record)
    return record
```

**强调**

- 先校验，再写库；
- 错误提示要具体；
- 不要把所有错误都写成 500。

---

### 环节6：时间冲突规则（30 分钟）

**教师演示**

```python
conflict = db.query(DutyRecord).filter(
    DutyRecord.personnel_certificate_number == data.personnel_certificate_number,
    DutyRecord.start_time < data.end_time,
    DutyRecord.end_time > data.start_time,
).first()

if conflict:
    raise HTTPException(status_code=400, detail="该时间段已存在值班记录")
```

**学生任务**

- 加冲突校验；
- 测试三种情况：
  - 完全重叠 → 400；
  - 首尾相接 → 成功；
  - 不重叠 → 成功。

**强调**

- 重叠条件是两个区间"有交集"；
- 首尾相接（12:00 结束、12:00 开始）不算冲突；
- 冲突校验只查同一人员的记录。

---

### 环节7：测试与排错（15 分钟）

**测试清单**

- [ ] 正常新增 → 201；
- [ ] 开始晚于结束 → 400；
- [ ] 人员不存在 → 400；
- [ ] 工位不存在 → 400；
- [ ] 时间重叠 → 400；
- [ ] 首尾相接 → 201；
- [ ] 缺字段 → 422；
- [ ] 列表能按人员查。

**排错清单**

| 现象 | 先查什么 |
|---|---|
| 422 | 字段名、时间格式、必填 |
| 400 时间 | `start_time < end_time` |
| 400 冲突 | 重叠条件、是否只查同一人员 |
| 500 | 外键、表名、字段名 |
