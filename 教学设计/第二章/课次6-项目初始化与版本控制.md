# 课次6：项目初始化与版本控制

## 一、课次基本信息

| 项目 | 内容 |
|---|---|
| 所属专题 | 专题二：后端服务开发 |
| 学时 | 4 学时（实践，约 180 分钟） |
| 教材对应 | 第4章 版本控制与工程协作；第6章 6.1–6.2；第8章 8.1 |
| 主线案例 | duty 后端项目结构、`main.py`、`app/core/`、`.gitignore` |
| 教学形态 | 概念导入 + 教师演示 + 学生动手 + 故障排查 |

> **理论—实践衔接**：本课次把课次4/5 的概念落到项目——标准结构对应分层与模块化，
> 虚拟环境对应可复现，Git 对应协作与变更管理。

## 二、教学目标

**知识与技能**

- 能按标准结构创建一个 FastAPI 项目。
- 能创建并激活虚拟环境，安装项目依赖。
- 能配置 `.env`、数据库连接与应用入口。
- 能运行项目，访问 `/health` 与 `/docs`。
- 能初始化 Git 仓库，完成提交、分支、合并。
- 能使用 `.gitignore` 排除虚拟环境、数据库、日志和密钥。

**过程与方法**

- 经历"建目录 → 配环境 → 写入口 → 跑服务 → 提交代码"的完整初始化过程。
- 学会用日志和错误信息定位环境问题。

**情感态度与价值观**

- 养成"环境即代码、提交即记录"的工程习惯。
- 建立"可复现"的意识：换一台机器也能跑起来。

## 教学内容

> 对应教学计划：专题二基本内容第 3 条"项目初始化与版本控制"。

1. **FastAPI 项目的标准结构**：app/api、app/core、app/config、tests 各放什么。
2. **虚拟环境与依赖管理**：venv、requirements.txt。
3. **配置文件与环境变量**：`.env`、settings。
4. **数据库连接与建表**：SQLite、engine、Base。
5. **应用入口与第一个路由**：`main.py`、`/health`、`/docs`。
6. **Git 基本操作**：init、add、commit、branch、merge。
7. **`.gitignore` 与不提交的内容**：venv、`*.db`、`.env`、logs。
8. **团队协作的基本流程**：分支、提交信息、代码评审。
9. **常见环境问题的排查**：端口、依赖、路径、数据库文件。

## 三、重点与难点

**重点**

- FastAPI 项目的标准结构。
- 虚拟环境与依赖管理。
- Git 基本操作与 `.gitignore`。

**难点**

- 环境配置与依赖冲突。
- 模块导入路径（`ModuleNotFoundError`）。
- 数据库文件路径与端口占用。

## 四、学情分析与教学策略

学生可能第一次独立搭项目，环境问题会占掉大量时间。策略：

- 教师先完整演示一遍，再让学生动手；
- 提供最小项目模板和 `requirements.txt`；
- 把常见故障做成"排查清单"，学生先自查，教师再介入；
- 课内只要求"跑起来 + 第一次提交"，不要求写业务模块。

## 五、教学准备

- duty 项目可运行；准备好 `main.py`、`requirements.txt`、`.env.example`、`.gitignore` 的投影。
- 最小项目模板（目录 + 空文件 + 依赖清单），发给学生。
- 内网 Git 仓库地址（如有）；没有则用本地仓库。
- 计时器；排查清单（见环节7）。

## 六、教学过程

### 环节1：概念导入——为什么这样搭项目（10 分钟）

**教师提问**

> "为什么一个后端项目要分这么多目录？为什么不能把所有代码写在一个文件里？"

**学生讨论**

- 小组快速说 2 个理由。

**教师归纳**

| 做法 | 解决什么问题 |
|---|---|
| 标准目录结构 | 分层与模块化：知道代码放哪、别人能看懂、能复用 |
| 虚拟环境 | 可复现：依赖隔离，换机器也能跑 |
| `.env` 配置 | 环境无关：开发/测试/生产用不同配置，密钥不进代码 |
| Git | 协作与变更管理：记录历史、支持分支、可回滚 |

**强调**

> 这些不是"形式"，而是课次1 讲的"复杂性、变化、协作、质量"在项目层面的具体回应。

### 环节3：项目结构（20 分钟）

**教师展示 duty 的目录**

```
duty/
├── main.py                 # 应用入口
├── requirements.txt        # 依赖清单
├── .env.example            # 环境变量示例
├── app/
│   ├── api/
│   │   └── v1/
│   │       ├── module_system/   # 认证、用户
│   │       └── module_duty/     # 部门、人员、值班记录等
│   ├── core/               # 数据库、基础模型、异常、日志、安全
│   └── config/             # 配置
├── tests/                  # 测试
├── alembic/                # 数据库迁移
├── Dockerfile
└── logs/                   # 日志
```

**讲授**

- `main.py`：创建 app、注册路由、启动服务；
- `app/api/`：按业务模块组织；
- `app/core/`：跨模块的基础设施；
- `app/config/`：配置集中管理；
- `tests/`：测试与代码同仓；
- `alembic/`：数据库迁移；
- `logs/`：运行日志。

**学生任务**

- 按模板创建目录；
- 每个包放 `__init__.py`；
- 先不写业务，只搭骨架。

### 环节4：虚拟环境与依赖（30 分钟）

**教师演示（Windows）**

```bash
cd duty
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

**检查**

```bash
python -c "import fastapi, uvicorn, sqlalchemy, pydantic; print('ok')"
```

**常见问题与处理**

| 现象 | 原因 | 处理 |
|---|---|---|
| `python` 不是内部命令 | 未装 Python / 未加 PATH | 重装或使用完整路径 |
| `pip` 下载慢/超时 | 网络 | 配置国内镜像 |
| `SSL` 证书错误 | 代理/证书 | 使用内网镜像或离线包 |
| `ModuleNotFoundError` | 虚拟环境未激活 | 重新激活，确认 `which python` |
| 依赖冲突 | 版本不匹配 | 按 `requirements.txt` 固定版本重装 |
| 编译错误 | 缺少构建工具 | 使用预编译 wheel 或换 Python 版本 |

**学生任务**

- 创建并激活虚拟环境；
- 安装依赖；
- 运行导入检查；
- 把报错记录到"问题卡"（现象、原因、处理）。

**教师巡视**

- 优先处理"环境没激活"和"Python 版本不对"；
- 提醒不要在系统 Python 里装依赖。

### 环节5：配置与数据库（25 分钟）

**教师演示**

1. `.env.example` → 复制为 `.env`：

```env
DATABASE_URL="sqlite:///./duty.db"
SECRET_KEY="change-me"
ALGORITHM="HS256"
ACCESS_TOKEN_EXPIRE_MINUTES=30
DEBUG=True
```

2. `app/config/setting.py`：用 `pydantic-settings` 读取环境变量。
3. `app/core/database.py`：创建 engine、SessionLocal、Base。
4. `main.py`：

```python
from fastapi import FastAPI
from app.core.database import engine, Base
from app.config.setting import settings

Base.metadata.create_all(bind=engine)

app = FastAPI(title=settings.APP_NAME, version="0.1.0")

@app.get("/health")
def health():
    return {"status": "healthy"}
```

**学生任务**

- 创建 `.env`；
- 启动服务，确认 `duty.db` 生成；
- 访问 `/health`。

**强调**

- `.env` 不进 Git；`.env.example` 进 Git；
- SQLite 路径是相对于启动目录的，换目录启动会生成新的 db 文件；
- 生产环境不要用默认 `SECRET_KEY`。

### 环节6：第一个路由与 Swagger（20 分钟）

**教师演示**

```python
@app.get("/")
def root():
    return {"message": "Duty API", "docs": "/docs"}

@app.get("/hello/{name}")
def hello(name: str, greeting: str = "你好"):
    return {"message": f"{greeting}，{name}"}
```

**学生任务**

- 启动服务；
- 访问 `/docs`，调用 `/health`、`/hello/{name}`；
- 修改 `greeting` 默认值，观察变化；
- 故意传错类型，观察 422。

**强调**

- `/docs` 是自动生成的，但 `summary`、`description` 要人写；
- 每次改代码后，`--reload` 会自动重启；没有 `--reload` 就手动重启。

### 环节7：Git 初始化与提交（30 分钟）

**教师演示**

```bash
git init
git status
```

创建 `.gitignore`：

```gitignore
venv/
__pycache__/
*.pyc
.env
*.db
logs/
.pytest_cache/
```

提交：

```bash
git add .
git commit -m "chore: init fastapi project"
```

分支：

```bash
git switch -c feature/hello
# 修改 main.py，增加 /hello/{name}
git add main.py
git commit -m "feat: add hello endpoint"
git switch main
git merge feature/hello
git log --oneline --graph
```

**讲授**

- `add` 是暂存，`commit` 是记录，`push` 是共享；
- 提交信息用类型前缀：`feat:`、`fix:`、`docs:`、`test:`、`chore:`；
- 一个提交只做一件事；
- 不要提交 `venv/`、`.env`、`*.db`、`logs/`。

**学生任务**

- 初始化仓库；
- 完成至少 2 次提交；
- 创建并合并一个分支；
- 截图 `git log --oneline --graph` 作为过程证据。

**常见问题**

- `git` 未配置用户名/邮箱：`git config --global user.name/user.email`；
- 提交了 `venv/`：先加 `.gitignore`，再 `git rm -r --cached venv`；
- 冲突：打开文件，保留正确内容，`git add` 后继续。

### 环节8：故障排查（25 分钟）

**排查清单**

| 现象 | 先查什么 |
|---|---|
| 服务起不来 | 端口占用、依赖缺失、语法错误 |
| `/docs` 打不开 | 服务是否启动、路径是否正确 |
| 422 | 请求体字段、类型、必填 |
| 404 | 路径前缀、尾斜杠、方法 |
| 数据库为空 | `.env` 的 `DATABASE_URL`、启动目录 |
| 导入失败 | 虚拟环境、`__init__.py`、包路径 |
| Git 提交为空 | `git status`、`.gitignore` 是否误伤 |

**学生任务**

- 按清单自查；
- 把问题和处理写入"问题卡"；
- 教师集中讲 2–3 个高频问题。

---

### 环节9：小结与作业（15 分钟）

**教师总结**

> 项目初始化的目标不是"写完代码"，而是"建立一个可复现、可提交、可继续开发的起点"。
>
> 三件事：**结构清楚、环境可复现、提交有记录。**

**三问回顾**

- 为什么这样搭结构？——分层与模块化，让别人看得懂、能复用。
- 为什么要虚拟环境？——依赖隔离，换机器也能复现。
- 为什么要 Git？——记录历史、支持协作、可回滚。

**布置作业**

1. 完成项目模板的初始化与 Git 提交（至少 2 次）。
2. 增加一个 `POST /echo` 接口，接收 JSON 并原样返回，提交一次。
3. 整理"我遇到的环境问题 + 处理办法"清单（3 条以上）。
4. 预习课次7：用户认证与 JWT。
