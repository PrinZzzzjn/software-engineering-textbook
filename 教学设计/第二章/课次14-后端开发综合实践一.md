## 二、教学目标

**知识与技能**

- 能用代码质量清单检查自己的代码。
- 能说出并修复 4 类安全问题：密码明文、响应泄露密码、管理接口无权限、输入不校验。
- 能识别重复代码，并用公共函数消除。
- 能统一错误状态码：400/401/403/404/422/500。
- 能说清统一异常处理与事务边界：错误格式统一；写操作要么成功、要么回滚。
- 能说出 2 个性能问题：列表不分页、循环里查数据库。
- 能完成一次代码互评。

**过程与方法**

- 经历"清单自查 → 安全与异常/事务改造 → 跑测试 → 互评"的过程。
- 学会用"改前/改后 + 测试通过"证明修改有效。

**情感态度与价值观**

- 建立"安全第一、最小权限"的意识。
- 养成"改完必跑测试、改动要能解释"的习惯。

## 教学内容

> 对应教学计划：专题二基本内容第 11 条"后端开发综合实践（一）"。

1. **代码质量清单**：重复代码、错误处理不统一、响应泄露字段、权限缺失、输入不校验。
2. **安全（重点）**：密码只存哈希；响应不返回 `password_hash`；管理接口只给管理员；输入必填/长度/类型校验。
3. **统一异常处理与事务边界**：400 业务、401 未登录、403 无权限、404 不存在、422 参数、500 服务器；全局异常处理器；一个业务动作一次 `commit`；异常时 `rollback`，写操作要么成功、要么回滚。
4. **重构**：提取公共函数（如 `paginate`）；改前/改后对比。
5. **性能初步**：列表分页；避免循环里查数据库（N+1）；常用查询字段可加索引（只讲概念）。
6. **互评**：按清单互相找 2 个问题。

## 三、重点与难点

**重点**

- 四类安全问题及修复。
- 统一异常处理与事务边界。
- 错误状态码统一。
- 改完跑测试。

**难点**

- 判断"哪些字段不能返回"。
- 权限依赖加在哪。
- 事务边界：哪些操作要一起成功/失败。
- 重构后不破坏原有功能。

## 四、学情分析与教学策略

学生已经能写出"能跑"的接口，但代码里通常有：密码明文、响应带密码、管理接口没权限、错误码乱用、重复代码。本课次不追求"大重构"，只做**清单式小修**：

- 先安全检查，再谈重复代码；
- 每人只改 2 个问题，改完跑测试；
- 用"改前/改后"对比，让学生看到差异；
- 互评只找 2 个问题，避免泛泛而谈；
- **集中讲异常/事务**：课次11–12 只做规则和统计，这里统一讲错误格式与事务边界。

### 环节4：统一异常处理与事务边界（30 分钟）

> 承接课次11–12 的约定：规则和统计只回答“该不该做”，错误格式和事务边界在这里统一收口。

**一、错误格式统一（10 分钟）**

教师展示两种不一致的返回：

```python
# 有的接口这样
raise HTTPException(status_code=400, detail="部门编码已存在")

# 未捕获的异常直接 500，前端拿到 HTML 或堆栈
```

统一约定：

| 状态码 | 含义 | 谁抛 |
|---|---|---|
| 400 | 业务规则不满足 | service |
| 401 | 未登录、token 失效 | 依赖 |
| 403 | 已登录但无权限 | 依赖 |
| 404 | 资源不存在 | service / crud |
| 422 | 参数校验失败 | FastAPI 自动 |
| 500 | 未预期异常 | 全局兜底 |

参考实现（`app/core/exceptions.py`）：

```python
class BaseAppException(Exception):
    def __init__(self, status_code: int = 500, detail: str = "Internal server error"):
        self.status_code = status_code
        self.detail = detail


async def app_exception_handler(request, exc: BaseAppException):
    return JSONResponse(
        status_code=exc.status_code,
        content={"status_code": exc.status_code, "detail": exc.detail},
    )
```

注册：

```python
app.add_exception_handler(BaseAppException, app_exception_handler)
```

**强调**

- 业务代码只 `raise BadRequestException("部门编码已存在")`，不自己拼 `JSONResponse`；
- 422 由 FastAPI 自动处理，不要手工改成 400；
- 500 不把堆栈返回给前端，堆栈留在日志里；
- duty 参考实现对“重复资源”用 409；本课程统一用 400，关键是同一项目内一致。

**二、事务边界（10 分钟）**

教师展示一次写操作：

```python
def create_duty_record(db, data):
    person = db.query(Personnel).filter(
        Personnel.certificate_number == data.personnel_certificate_number
    ).first()
    if not person:
        raise BadRequestException("人员不存在")

    record = DutyRecord(**data.model_dump())
    db.add(record)
    db.commit()
    db.refresh(record)
    return record
```

**讲清四件事**

1. 一个业务动作 = 一个事务：要么全部成功，要么全部回滚；
2. `commit()` 只放在业务动作最后，不要写在循环里；
3. 出现异常要 `rollback()`，否则会话处于脏状态，后续请求会继续失败；
4. 统计等只读接口不需要事务。

**反例 → 正例**

```python
# 反例：中途 commit，失败会留下半批数据
for row in rows:
    db.add(DutyRecord(**row))
    db.commit()

# 正例：先校验，再一次 commit，异常回滚
try:
    for row in rows:
        db.add(DutyRecord(**row))
    db.commit()
except Exception:
    db.rollback()
    raise
```

**强调**：先校验、再写入、最后一次提交；`rollback()` 后继续向上抛，交给统一异常处理器。

**三、学生任务（10 分钟）**

- 在自己代码里找一处“多次 `commit`”或“异常后没 `rollback`”；
- 改成“一次 `commit` + 异常 `rollback`”；
- 用一条会失败的请求验证：数据库没有留下半条数据。

**常见错误**

| 现象 | 原因 |
|---|---|
| 接口 500 但看不到原因 | 全局处理器吞了异常，或没写日志 |
| 报错后下一次请求也失败 | 异常后没 `rollback`，会话脏了 |
| 400 和 422 混用 | 业务规则用了 422，或参数校验用了 400 |
| 返回堆栈 | 500 把异常字符串直接返回给前端 |

### 环节5：重构示范（20 分钟）

**重复代码示例**

```python
# dept 列表
total = query.count()
items = query.offset((page-1)*page_size).limit(page_size).all()

# personnel 列表：几乎一样
total = query.count()
items = query.offset((page-1)*page_size).limit(page_size).all()
```

**改后：抽成公共函数**

> 课次10 已经抽过 `CRUDBase` 的，先检查基类是否覆盖了这段；没抽完的，用下面的公共函数兜底。

```python
def paginate(query, page, page_size):
    total = query.count()
    items = query.offset((page - 1) * page_size).limit(page_size).all()
    pages = (total + page_size - 1) // page_size
    return {"items": items, "total": total, "page": page, "page_size": page_size, "pages": pages}
```

**教师强调**

- 只抽"完全重复"的部分；
- 抽完必须回归测试；
- 不要为了"看起来高级"过度抽象。

### 环节7：性能初步（10 分钟）

**问题 1：列表不分页**

- 数据多了会慢、会卡；改：`page`、`page_size`。

**问题 2：循环里查数据库（N+1）**

```python
# 改前：每条记录查一次人员

    person = db.query(Personnel).filter(...).first()

# 改后：先查一次，再用字典匹配
persons = {p.certificate_number: p for p in db.query(Personnel).all()}

    person = persons.get(r.personnel_certificate_number)
```
