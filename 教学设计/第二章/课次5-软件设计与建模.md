# 课次5：软件设计与建模——表怎么建，接口怎么定

## 二、教学目标

**知识与技能**

- 能说出"为什么先设计、再写代码"。
- 能画出三张表（部门、人员、值班记录），并说明主键、外键、一对多。
- 能为一个模块规划接口组（列表、详情、新增、修改、删除），并说明每个接口的方法、URL、参数来源和返回。
- 了解 controller、service、crud、model 四层分工（课前阅读），能指出一个接口该放哪层。
- 能写一份简单的设计文档：表结构 + 接口清单。
- 能依据课次3 的需求文档识别业务对象、完成模块划分，并能把 1–2 个模块细化为表字段和接口参数。

**过程与方法**

- 经历"想清楚表 → 想清楚接口 → 写下来"的设计过程。
- 经历"从课次3 的需求文档 → 业务对象与模块 → 表字段 → 接口参数 → 设计文档"的细化过程。
- 学会用"一个部门、多个人员"这种具体例子理解关系。

**情感态度与价值观**

- 建立"先想清楚再动手"的习惯。
- 认识到设计文档是给自己和同伴看的"施工图"。

## 教学内容

> 对应教学计划：专题二基本内容第 2 条"软件设计与建模"。

1. **为什么先设计再写代码**：不设计会导致表反复改、接口对不上。
2. **表、主键、外键、一对多**：用"部门—人员—值班记录"讲清。
3. **三张表的设计**：部门表、人员表、值班记录表；表之间的关系。
4. **一个模块需要哪些接口**：列表、详情、新增、修改、删除；业务动作如何映射成方法和 URL（接口四要素见课次4，本课次只做设计决策）。
5. **接口的参数来源与返回结构**：路径参数定位、查询参数筛选、请求体传数据；返回与表字段的对应。
6. **四层分工（课前阅读）**：controller 接请求、service 写规则、crud 读写库、model 表结构；课堂只做 5 分钟落层检查。
7. **设计文档**：表结构 + 接口清单。
8. **从需求文档到模块划分**：按业务对象与功能簇划分模块，每个模块一句话职责；再把 1–2 个模块细化为表字段和接口参数。
9. **接口契约与文档一致性**：接口清单要和表结构、前端页面对应；文档随代码更新。

## 三、重点与难点

**重点**

- 三张表的主键、外键和一对多关系。
- 一个模块的接口组规划（动作、方法、URL、参数来源）。
- 接口与四层分工的对应（课前阅读检查）。

**难点**

- 理解"外键"和"一对多"。
- 参数来源的选择（路径/查询/请求体）与接口命名的一致性。
- 第一次画表关系图。

## 四、学情分析与教学策略

学生几乎零基础，抽象概念多就容易掉队。

本课次只讲**一个核心问题**：

> 写代码之前，先想清楚两件事：**表怎么建，接口怎么定。**

教学策略：

- **一个例子讲到底**：用"部门—人员—值班记录"贯穿；
- **只用一种关系**：一对多，不讲多对多、范式、索引；
- **接口只讲设计决策**：一个模块有哪几个动作、URL 怎么命名、参数从哪来；四要素本身已在课次4 讲过。
- **四层分工放课前阅读**：课堂只做 5 分钟检查，每个接口放哪层；
- **画图 + 填表**：不要求写代码；
- **从课次3 出发**：不重复讲需求，直接拿课次3 的 v1/v2 需求文档，先按业务对象与功能簇完成模块划分，再选 1–2 个模块细化。

## 六、教学过程

### 环节1：导入——不设计会怎样（10 分钟）

**教师讲一个具体场景**

> "如果先写代码，后来发现部门表少了一个'部门负责人'字段，会发生什么？"

**衔接课次3**

> "课次3 你们已经写好了需求文档：角色、功能清单、用户故事。今天不重复讲需求，先按业务对象把功能归成模块，再选 1–2 个模块，把'功能'细化成'表字段、接口参数'。"

**快速示范：需求 → 模块**

| 需求（来自课次3） | 业务对象 | 模块 |
|---|---|---|
| 管理部门信息 | 部门 | `dept` |
| 管理人员信息 | 人员 | `personnel` |
| 记录谁在什么时间值班 | 值班记录 | `duty_record` |
| 统计值班次数与时段分布 | 统计结果 | `analytics` |

**强调**：模块按业务能力划分，不按页面划分；每个模块用一句话说清职责，本节只细化 1–2 个模块。

**引导学生说出**

- 表要改；
- 已经写好的新增/查询代码要改；
- 页面要改；
- 测试要重做。

**教师总结**

> 设计就是提前想清楚"表里有哪些字段、接口要哪些"，避免后面反复改。
>
> 设计文档就是"施工图"：表怎么建、接口怎么定。

---

### 环节2：数据库设计——三张表（30 分钟）

**教师先讲三个词（用生活例子）**

| 词 | 意思 | 生活例子 |
|---|---|---|
| 表 | 一类数据放一张表 | 一张"学生名单" |
| 主键 | 能唯一代表这一行的编号 | 学号 |
| 外键 | 指向另一张表的编号 | 学生表里的"班级编号" |

**教师带学生画三张表**

**部门表（dept）**

| 字段 | 说明 |
|---|---|
| dept_code | 部门编号（主键） |
| full_name | 部门名称 |
| address | 地址 |

**人员表（personnel）**

| 字段 | 说明 |
|---|---|
| certificate_number | 证件号（主键） |
| name | 姓名 |
| dept_code | 所属部门编号（外键） |
| position | 职位 |

**值班记录表（duty_record）**

| 字段 | 说明 |
|---|---|
| id | 记录编号（主键） |
| personnel_certificate_number | 值班人员证件号（外键） |
| start_time | 开始时间 |
| end_time | 结束时间 |

**画关系图**

```
部门 1 ───── N 人员 1 ───── N 值班记录
```

**教师解释"一对多"**

- 一个部门可以有多个人员；
- 一个人员可以有多条值班记录；
- 反过来，一条值班记录只属于一个人员。

**课堂小练习（5 分钟）**

> "如果再加一张'工位表'，它应该和哪张表有关系？为什么？"

**预期**：工位属于部门（一个部门多个工位）；工位和值班记录有关系（一条记录在一个工位）。

**强调**

- 表只存自己的信息；
- 关系用"外键"表达；
- 先画三张表，不要一上来就十几张。

---

### 环节3：接口设计——一个模块需要哪些接口（25 分钟）

**先划清与课次4 的边界**

> 课次4 已经讲过接口四要素（URL、方法、参数、返回）和状态码；今天不重复讲概念，直接用它们做设计决策。

**教师用"部门"举例**

| 方法 | URL | 意思 | 参数来源 | 返回 |
|---|---|---|---|---|
| GET | `/departments` | 查列表 | 查询参数：`page`、`page_size` | 部门列表 |
| GET | `/departments/{dept_code}` | 查一个 | 路径参数：`dept_code` | 一个部门 |
| POST | `/departments` | 新增 | 请求体：部门信息 | 新增后的部门 |
| PUT | `/departments/{dept_code}` | 修改 | 路径参数 + 请求体 | 修改后的部门 |
| DELETE | `/departments/{dept_code}` | 删除 | 路径参数：`dept_code` | 成功消息 |

**设计时要想清楚的四件事**

1. **动作**：这个模块有哪几个动作？（列表、详情、新增、修改、删除）
2. **方法**：每个动作用什么方法？（GET 查、POST 增、PUT 改、DELETE 删）
3. **URL**：资源怎么命名？哪些参数放在路径里？（如 `/departments/{dept_code}`）
4. **参数来源与返回**：筛选/分页放查询参数，新增/修改放请求体；返回列表、单个还是成功消息。

**状态码**

- 沿用课次4 的 200/201/404/422，不再展开；设计时只需要标注每个接口的预期状态码。

**课堂小练习（5 分钟）**

> "给'人员'设计 5 个接口，只写方法和 URL。"

**预期**

- GET `/personnel`
- GET `/personnel/{certificate_number}`
- POST `/personnel`
- PUT `/personnel/{certificate_number}`
- DELETE `/personnel/{certificate_number}`

**强调**

> 接口先定"方法和 URL"，再定"参数和返回"；不要一上来就写代码。

---

### 环节4：分层检查（5 分钟）

> 四层分工已放课前讲义；课堂只做一个检查：给你一个接口，说出它该放哪层。

**快速检查**

| 任务 | 放哪层 |
|---|---|
| 收到 `GET /departments` 请求 | controller |
| 判断部门编码是否重复 | service |
| 查询 `departments` 表 | crud |
| 定义 dept 表有哪些字段 | model |

**强调**

- 不需要背"分层架构"这个词；记住"四个文件夹，各干一件事"就够了；
- 课堂不再展开，课后按讲义对照 duty 的 dept 目录看一遍。

---

### 环节5：设计文档——表 + 接口（10 分钟）

**教师给一个简单模板**

```markdown
# 部门模块设计

## 1. 表结构
| 字段 | 类型 | 说明 |
|---|---|---|
| dept_code | 文本 | 主键 |
| full_name | 文本 | 部门名称 |
| address | 文本 | 地址 |

## 2. 接口清单
| 方法 | URL | 参数 | 返回 |
|---|---|---|---|
| GET | /departments | page, page_size | 部门列表 |
| GET | /departments/{dept_code} | dept_code | 一个部门 |
| POST | /departments | 部门信息 | 新增结果 |
| PUT | /departments/{dept_code} | dept_code + 部门信息 | 修改结果 |
| DELETE | /departments/{dept_code} | dept_code | 成功消息 |
```

**学生任务**

- 选一个模块（部门/人员/值班记录）；
- 填一张表结构 + 5 个接口；
- 不要求写代码，只要求写清楚。

**强调**

> 设计文档不用长；能让别人照着建表、照着写接口，就合格。

---

### 环节6：小结与出口题（10 分钟）

**教师总结**

> 设计 = 表怎么建 + 接口怎么定。
>
> 表：主键、外键、一对多。
>
> 接口：URL、方法、参数、返回。
>
> 四层：controller、service、crud、model，各干一件事。

**出口题（当场写，5 分钟）**

1. 主键和外键有什么区别？
2. "一个部门有多个人员"是什么关系？外键放在哪张表？
3. 查一个部门，应该用什么方法和什么 URL？

**布置作业**

1. 为你选的模块，填一张表结构 + 5 个接口。
2. 画一张三张表的关系图（部门—人员—值班记录）。
3. 预习课次6：项目初始化与版本控制。

## 七、板书设计

```
设计 = 表怎么建 + 接口怎么定

表：
  部门（dept_code 主键）
  人员（certificate_number 主键，dept_code 外键）
  值班记录（id 主键，personnel_certificate_number 外键）

关系：部门 1 ── N 人员 1 ── N 值班记录

接口设计：动作 → 方法 → URL → 参数来源 → 返回
  GET 查 / POST 增 / PUT 改 / DELETE 删
  状态码见课次4（200/201/404/422）

四层：controller 接请求 / service 写规则 / crud 读写库 / model 表结构（课前阅读）
```
