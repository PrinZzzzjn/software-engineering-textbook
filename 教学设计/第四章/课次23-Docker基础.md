# 课次23：Docker基础——从"本机能跑"到"哪儿都能跑"

## 一、课次基本信息

| 项目 | 内容 |
|---|---|
| 所属专题 | 专题四：软件部署与系统交付 |
| 学时 | 2 学时（理论，约 90 分钟） |
| 教材对应 | 第18章 容器化基础（18.1–18.3） |
| 主线案例 | `duty/Dockerfile`、`.dockerignore`、`docker-compose.yml`（只读，不要求本课独立编写） |
| 教学形态 | 讲授 + 现场演示 + 读 Dockerfile 练习 |
| 教学定位 | **理论为主**：容器与虚拟机、镜像/容器/仓库、镜像分层、Dockerfile 指令、部署流程；**不要求完整构建前后端镜像**（课次24） |

## 二、教学目标

**知识与技能**

- 能说清容器与虚拟机的三点区别：隔离层次、资源开销、启动速度。
- 能说清镜像、容器、仓库三者的关系。
- 能说清镜像分层与构建缓存：为什么先 `COPY requirements.txt` 再 `COPY . .`。
- 能读懂 `duty/Dockerfile` 的每一行：`FROM`、`WORKDIR`、`RUN`、`COPY`、`ENV`、`EXPOSE`、`CMD`。
- 能说清构建上下文与 `.dockerignore` 的作用。
- 能说出从代码到线上服务的容器化部署流程。

**过程与方法**

- 经历"同一个程序，本机能跑、换台机器跑不起来"的问题情境。
- 学会用"分层图 + 流程链"理解部署，而不是背命令。

**情感态度与价值观**

- 建立"环境一致性"和"可复现交付"的意识。
- 理解"代码写完不等于项目完成"。

## 教学内容

> 对应教学计划：专题四基本内容第 1 条"Docker基础"。
> 本课次只讲"为什么打包、打成什么、怎么描述"，动手构建在课次24。

1. **为什么要容器化**：开发机能跑 ≠ 服务器能跑；依赖、版本、路径、配置的差异。
2. **容器与虚拟机**：隔离层次、资源开销、启动速度的对比。
3. **核心概念**：镜像（image）、容器（container）、仓库（registry）。
4. **镜像分层与构建缓存**：每条指令一层；层只读；改了哪层，重建哪层及其上层。
5. **Dockerfile 指令体系**：`FROM`、`WORKDIR`、`RUN`、`COPY`、`ENV`、`EXPOSE`、`CMD`。
6. **构建上下文与 `.dockerignore`**：哪些文件不该进镜像。
7. **容器化部署的基本流程**：代码 → 镜像 → 仓库 → 拉取 → 运行 → 健康检查。
8. **读 `duty/Dockerfile`**：把七条指令落到一个真实后端项目上。

## 三、重点与难点

**重点**

- 容器与镜像的核心概念。
- Dockerfile 的指令与编写规范。
- 镜像分层与构建缓存。

**难点**

- 容器与虚拟机的本质区别（不是"小虚拟机"）。
- 镜像分层与缓存失效的规律。
- "构建时"与"运行时"的分界：`RUN` 与 `CMD` 的区别。

## 四、学情分析与教学策略

学生已经能跑 `duty` 和 `duty_frontend`，但所有操作都在本机完成，没有"换一台机器"的经历。Docker 命令多，容易变成"背命令"；容器与虚拟机也容易混淆。

策略：

- **先制造问题，再给工具**：用"服务器上跑不起来"开场，不先讲 Docker；
- **用类比**：虚拟机像每户一套房子，容器像标准集装箱；
- **先演示后解释**：先 `docker run` 一个现成镜像，再讲概念；
- **用真实文件讲语法**：逐行读 `duty/Dockerfile`，不讲脱离项目的命令清单；
- **只讲必要命令**：`images`、`ps`、`run`、`logs` 会看即可，构建实操放课次24。

## 五、教学准备

- Docker Desktop / Docker Engine 已安装，`docker version` 可用。
- 预拉取演示镜像（`hello-world` 或课程同款 Python 镜像），避免课堂等网络。
- `duty/Dockerfile`、`duty/.dockerignore`、`docker-compose.yml` 投影。
- 最小 Dockerfile 示例（教师提前在纸上或投影上准备好）。
- 镜像分层示意图（可打印）；计时器。

## 六、教学过程

### 环节1：导入——"老师电脑能跑，服务器跑不起来"（10 分钟）

**教师展示三样东西**

- `duty/requirements.txt`：一长串固定版本；
- `duty/.env.example`：`DATABASE_URL`、`SECRET_KEY` 等配置；
- 本机的 `duty.db` 和 `logs/`。

**提问**

> "把这三样东西拷到另一台电脑，能保证跑起来吗？"
>
> "如果那台电脑装的是 Python 3.10、没有这个依赖、路径也不一样呢？"

**引导学生说出**

- 代码只是系统的一部分；
- 运行环境（解释器、依赖、配置、数据、启动方式）也要一起交付；
- 每台机器手工装一遍，迟早不一致。

**教师点明本课边界**

> 今天不构建镜像，只搞清楚三件事：
>
> 1. 容器和虚拟机有什么不同；
> 2. 镜像、容器、仓库是什么关系；
> 3. Dockerfile 怎么把"怎么装、怎么跑"写下来。

---

### 环节2：容器与虚拟机（15 分钟）

**教师讲授**

| 对比项 | 虚拟机 | 容器 |
|---|---|---|
| 隔离层次 | 硬件虚拟化，每个 VM 带一套完整操作系统 | 进程级隔离，共享宿主机内核 |
| 启动速度 | 分钟级 | 秒级 |
| 资源开销 | 大（完整 OS、驱动） | 小（只含应用与依赖） |
| 隔离强度 | 强 | 较弱（同内核，靠配置约束） |
| 典型用途 | 需要不同操作系统的场景 | 应用打包与交付 |

**类比**

> 虚拟机像"每户一套房子"，水电地基都自己带；
>
> 容器像"标准集装箱"，港口、吊机、公路是共用的，箱子只装货。

**只要求知道**

- 容器靠 namespace 做隔离、靠 cgroups 限制资源；
- 本课不展开内核原理，知道"隔离靠操作系统能力"即可。

**强调**

> 容器不是"小虚拟机"。它没有自己的内核，启动快、开销小的原因就在这里；
> 也正因为共享内核，隔离强度不如虚拟机。

---

### 环节3：镜像、容器、仓库（15 分钟）

**教师讲授**

| 概念 | 是什么 | 类比 | 查看命令 |
|---|---|---|---|
| 镜像 image | 只读模板，包含文件系统和启动命令 | 类 / 安装包 | `docker images` |
| 容器 container | 镜像的运行实例 | 对象 / 进程 | `docker ps` |
| 仓库 registry | 存放和分发镜像的地方 | 应用商店 | `docker pull` |

**现场演示**

```bash
docker run --rm hello-world
docker ps -a
docker images
```

**讲清三句话**

1. 一个镜像可以跑出多个容器；容器删了，镜像还在。
2. 容器内的修改默认随容器删除而丢失，要保留就挂载卷（课次25）。
3. `docker run` 做了三件事：找镜像（没有就拉）、创建容器、启动进程。

**强调**

> 镜像是"死的模板"，容器是"活的进程"。交付时交付镜像，不是交付一台装好环境的电脑。

---

### 环节4：镜像分层与构建缓存（15 分钟）

**教师画分层图**

```text
duty-backend 镜像
├─ 基础层：python:3.12.9-slim
├─ 依赖层：pip install -r requirements.txt
├─ 代码层：COPY . .
└─ 启动层：CMD ["python", "main.py"]
```

**讲清三条规则**

1. Dockerfile 里每条 `RUN`、`COPY`、`ADD` 都会生成一层；
2. 层是只读的，上层叠在下层上，多个镜像可以共享下层；
3. 某一层变了，它和它上面的所有层都要重建，下面的层命中缓存。

**回到 duty**

> `duty/Dockerfile` 先写 `COPY requirements.txt .` 和 `RUN pip install ...`，
> 最后才 `COPY . .`。这样改业务代码时，依赖层不动，只重建代码层。

**演示缓存（教师操作）**

```bash
docker build -t demo-cache:1.0 .
docker build -t demo-cache:1.1 .   # 观察 CACHED
```

**强调**

> 镜像体积 = 各层之和。`venv/`、`.git/`、日志、本机数据库一旦被 `COPY . .` 带进去，镜像会又大又脏。

### 环节5：读 `duty` 的 Dockerfile（20 分钟）

**教师投影 `duty/Dockerfile`**

```dockerfile
# 使用本地 amd64 Python 镜像
FROM swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/python:3.12.9-slim

# 设置工作目录
WORKDIR /app

# 配置 pip 使用国内镜像
RUN pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 复制依赖文件并安装
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制项目文件
COPY . .

# 设置环境变量
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

# 暴露端口
EXPOSE 8000

# 启动命令
CMD ["python", "main.py"]
```

**逐条讲**

| 指令 | 作用 | 在 duty 中的写法 |
|---|---|---|
| `FROM` | 指定基础镜像，一切从它开始 | `python:3.12.9-slim` |
| `WORKDIR` | 设置容器内工作目录，后续命令都在这里 | `/app` |
| `RUN` | 构建时执行命令，结果写进镜像层 | 配 pip 源、装依赖 |
| `COPY` | 把构建上下文中的文件复制进镜像 | 先 `requirements.txt`，后 `.` |
| `ENV` | 设置运行时环境变量 | 不生成 `.pyc`；日志立即输出 |
| `EXPOSE` | 声明容器打算用哪个端口 | `8000` |
| `CMD` | 容器启动时执行的命令 | `python main.py` |

**讲 `.dockerignore`**

```text
__pycache__
*.pyc
.venv
venv
env
.env
*.log
*.sqlite3
.git
```

> 作用有两个：构建上下文更小、构建更快；避免把密钥、本机数据库、日志打进镜像。

**两个高频追问**

- "`EXPOSE 8000` 之后，为什么还要 `-p 8000:8000`？"——`EXPOSE` 只是声明，真正对外发布端口靠 `-p`（课次24）。
- "`RUN` 和 `CMD` 有什么区别？"——`RUN` 在构建时执行、结果留在镜像里；`CMD` 在容器启动时执行，每次启动都可以不同。

**强调**

> 写 Dockerfile 的顺序不是随便排的：变化少的放前面，变化多的放后面。
> 这是缓存规律，不是格式要求。

### 环节6：从代码到上线（10 分钟）

**教师画流程链**

```text
写代码 → 写 Dockerfile → docker build 构建镜像 → 推送镜像仓库
      → 服务器 docker pull → docker run（注入环境变量、挂载数据）
      → 健康检查 /health → 看日志、做监控
```

**讲清三个环境**

| 环境 | 由谁保证一致 | 说明 |
|---|---|---|
| 开发环境 | 开发者本机 | 依赖版本容易各不相同 |
| 构建环境 | Dockerfile + 基础镜像 | 镜像把依赖固定下来 |
| 运行环境 | 环境变量 + 挂载 | 数据库地址、密钥、数据目录按环境注入 |

**回到项目**

- 后端健康检查：`GET /health` → `{"status":"healthy"}`；
- 前端地址：`DUTY_API_BASE_URL` 环境变量；
- 日志：容器日志 + `logs/app.log`、`logs/error.log`（课次26）。

**强调**

> 部署上线不是终点。镜像跑起来只是开始，还要能看健康状态、看日志、能回滚。

### 环节7：小结与出口题（5 分钟）

**出口题（口头或纸条）**

1. 镜像和容器是什么关系？
2. 为什么先 `COPY requirements.txt`，再 `COPY . .`？
3. `EXPOSE` 和 `-p` 有什么区别？
4. 为什么改了业务代码，依赖层不用重装？

**教师总结**

> 容器把"代码 + 依赖 + 配置 + 启动方式"打成镜像，解决环境不一致。
>
> 镜像是模板，容器是实例；镜像是分层构建的，顺序决定缓存。
>
> Dockerfile 是"怎么装、怎么跑"的说明书，`.dockerignore` 决定什么不该装进去。

**布置作业**

1. 画出 `duty-backend` 的镜像分层图，标注每层对应 Dockerfile 的哪条指令。
2. 把 `duty/Dockerfile` 的七条指令各写一句话作用。
3. 列出 `.dockerignore` 排除的三类内容，并说明原因。
4. 预习课次24：要自己构建后端和前端镜像，先对比两个 Dockerfile 的差异。

## 七、板书设计

```text
一、为什么：本机能跑 ≠ 服务器能跑
   代码 + 依赖 + 配置 + 启动方式 = 一个包

二、容器 vs 虚拟机
   虚拟机：独立 OS，分钟级，开销大
   容器：共享内核，秒级，开销小（不是小虚拟机）

三、三件套
   镜像 = 模板（类 / 安装包）
   容器 = 实例（对象 / 进程）
   仓库 = 存放镜像（应用商店）

四、分层
   基础层 → 依赖层 → 代码层 → 启动层
   改哪层，重建哪层及其上层
   COPY requirements.txt 在前，COPY . . 在后

五、Dockerfile 七指令
   FROM / WORKDIR / RUN / COPY / ENV / EXPOSE / CMD
   RUN = 构建时；CMD = 启动时
   EXPOSE 只是声明，-p 才发布

六、流程
   代码 → build → 镜像 → push/pull → run → /health → logs
```
