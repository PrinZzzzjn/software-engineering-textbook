## 〇、本课次的理论课适配说明

本课次为**理论课**，不设【示范引领】【组织练习】【纠偏校正】三个实践教学环节。教学循环采用四环节：

| 教学环节 | 承担的节点 | 理论课形态 |
|---|---|---|
| 【要领讲解】 | ① 认知 + ② 解释 | 指认形式 → 说明机制，一次讲透 |
| 【案例解析】 | ③ 模仿 | 跟着教师读代码、在 duty 真实接口上"对号入座"，不要求跟敲跑通 |
| 【课堂研讨】 | ⑤ 辨析 | 用判断题、说理和抢答替代"找错改错"，能判断对错并说明原因 |
| 【小结讲评】 | 巩固与过渡 | 口诀化收束，形成可复述的结构 |

节点 ④ 独立 在本课次以"独立分析一个功能中每一层做什么 / 独立分析一个接口的完整流程 / 独立判断该用哪种参数"达成，不要求独立编码；节点 ⑥ 综合 本课次不落点，留作课后拓展。代码案例可以出现，但只服务于概念理解，不要求当堂独立编写。

## 二、①-⑥ 节点内容（最大路径）

> 审核要点：每个节点是否具体到"学生能做什么"？有没有空泛的"了解""掌握"？是否从 ① 到 ⑥ 逐级递进？

### 知识点 1：前端、后端、数据库的分工

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能说出前端、后端、数据库三个名称，指出各自负责"显示、处理、存储"。 | ☐ |
| ② 解释 | 能用"点查询按钮—后端取数—数据库返回—前端显示"的链路，说明为什么后端不负责画页面。 | ☐ |
| ③ 模仿 | 能在"前端—后端—数据库"示意图上，按教师给出的"查部门"五步流程，把每一步填到对应层。 | ☐ |
| ④ 独立 | 能独立分析"新增一条值班记录"的流程，指出每一步由哪一层完成。 | ☐ |
| ⑤ 辨析 | 能判断"页面上的表格是后端画的""数据库直接给浏览器返回数据"等说法错在哪里。 | ☐ |
| ⑥ 综合 | 能结合 duty 的一个完整功能（如部门列表），说明三层如何协作完成一次查询。 | ☐ |

### 知识点 2：请求—响应模型与 JSON

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能说出"请求"是前端发给后端的话、"响应"是后端回给前端的话；能认出 JSON 的大括号和键值对形式。 | ☐ |
| ② 解释 | 能说明一次请求—响应中"谁先发、谁后回、回的是什么格式"，解释为什么前后端约定用 JSON。 | ☐ |
| ③ 模仿 | 能在教师给出的请求/响应样例中，指出哪一行是请求、哪一行是响应、哪一部分是 JSON 数据。 | ☐ |
| ④ 独立 | 能独立把一条部门数据写成 JSON，如 `{"id": 1, "name": "作训科"}`。 | ☐ |
| ⑤ 辨析 | 能判断"响应一定是 HTML 页面""JSON 只能传字符串"等说法是否正确并说明理由。 | ☐ |
| ⑥ 综合 | 能描述 duty 前端点击"查询部门"后，请求与响应各自携带什么内容。 | ☐ |

### 知识点 3：接口四要素：一次后端请求的完整流程

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能说出接口四要素——URL、方法、参数、返回；能按"请求进来 → 匹配 URL → 确认方法 → 解析参数 → 执行 → 返回"的顺序复述一次处理流程。 | ☐ |
| ② 解释 | 能说明四要素分别对应后端的四个动作：URL 匹配路由（找谁）、方法决定操作语义（做什么）、参数是输入（带什么）、返回是输出（给什么）；能说明四者缺一不可，少一个接口就不完整。 | ☐ |
| ③ 模仿 | 能在 duty 部门列表接口上，把四要素与后端处理环节一一对应，填满"四要素—处理动作"对照表。 | ☐ |
| ④ 独立 | 能独立分析一个未见过的接口说明，说出它的四要素，并画出"请求—处理—响应"的流程。 | ☐ |
| ⑤ 辨析 | 能判断"URL 就是接口的全部""方法只是装饰""参数可有可无"等说法错在哪里。 | ☐ |
| ⑥ 综合 | 能用"查部门"一个例子，说明四要素如何共同构成一次完整的请求—响应，并指出哪一环出错会导致什么结果。 | ☐ |

### 知识点 4：URL 与路由：找谁

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能说出 URL 的常见组成（协议、主机、端口、路径、查询串）；能指出 `/api/v1/departments/` 中哪部分是路径。 | ☐ |
| ② 解释 | 能说明"路由"就是"URL 路径 → 处理函数"的对应表；能解释为什么 `/departments/` 与 `/departments/3` 会进入不同的处理逻辑。 | ☐ |
| ③ 模仿 | 能在 `/docs` 中找出两个不同 URL 对应的接口，并指出它们的路径。 | ☐ |
| ④ 独立 | 能针对"查部门列表""查单个部门"两个需求，说出大致的 URL 路径。 | ☐ |
| ⑤ 辨析 | 能判断"URL 越长越具体""URL 里不能带参数""路径写错也能匹配"等说法错在哪里。 | ☐ |
| ⑥ 综合 | 能解释 duty 中 `/api/v1/departments/` 与 `/api/v1/departments/{dept_id}` 的路由差异，并说明"找不到路由"时为什么返回 404。 | ☐ |

### 知识点 5：HTTP 方法与操作语义：做什么

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能说出 GET/POST/PUT/DELETE 四个方法及"查/增/改/删"。 | ☐ |
| ② 解释 | 能说明方法的语义约定——GET 只读、POST 新增、PUT 修改、DELETE 删除；能解释为什么"新增"不能用 GET（不符合语义、可能被缓存或重复执行）。 | ☐ |
| ③ 模仿 | 能在 `/docs` 中看出每个接口用的是哪个方法。 | ☐ |
| ④ 独立 | 能给一组操作（查列表、新增、改名称、删部门）匹配正确的 HTTP 方法。 | ☐ |
| ⑤ 辨析 | 能判断"GET 也能新增""POST 和 PUT 一样""方法写错不影响结果"等说法错在哪里。 | ☐ |
| ⑥ 综合 | 能说明 duty 部门模块的增删改查分别用什么方法，并解释方法写错会导致什么后果。 | ☐ |

### 知识点 6：路径参数与查询参数：带什么

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能认出 `/hello/{name}` 是路径参数、`/hello?name=张三` 是查询参数；能说出 `?` 后面是查询参数。 | ☐ |
| ② 解释 | 能说明路径参数是 URL 路径的一部分、用来定位某一个；查询参数在 `?` 后面、用来筛选或带条件；能解释"查 3 号部门"为什么用路径、"查第 3 页"为什么用查询。 | ☐ |
| ③ 模仿 | 能在两个代码样例中，把参数位置和取值逐项标出来。 | ☐ |
| ④ 独立 | 能针对"查 3 号部门"与"查第 3 页部门"两个需求，独立判断各用哪种参数并说明理由。 | ☐ |
| ⑤ 辨析 | 能判断"查询参数必须写在路径里""路径参数可以省略""两种参数可以随便换"等说法错在哪里。 | ☐ |
| ⑥ 综合 | 能读懂 duty 部门列表（查询参数）与部门详情（路径参数）两个接口，说明为什么这样设计。 | ☐ |

### 知识点 7：返回与状态码：给什么

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能说出 200 成功、201 新增成功、404 没找到、422 参数不对；能认出响应由"状态码 + 返回体（JSON）"组成。 | ☐ |
| ② 解释 | 能说明状态码是响应的"结果标识"；404 是地址或资源不存在，422 是参数不符合要求；能说明 200 是成功时的默认值。 | ☐ |
| ③ 模仿 | 能在 `/docs` 的响应区找到状态码和返回体，并按对照表说出含义。 | ☐ |
| ④ 独立 | 能给一组场景（查列表成功、新增成功、查不存在的部门、页码传字母）分别匹配状态码。 | ☐ |
| ⑤ 辨析 | 能判断"页面打不开都是 404""422 是服务器坏了""状态码必须手写"等说法错在哪里。 | ☐ |
| ⑥ 综合 | 能说明一次部门查询的完整响应由"状态码 + JSON 返回体"组成，并解释状态码与返回体各自告诉前端什么。 | ☐ |

### 知识点 8：FastAPI 框架：原理、作用与开发方式的变化

| 节点 | 内容 | 审核 |
|------|------|------|
| ① 认知 | 能说出 FastAPI 是一个 Python Web 框架；能认出 `app = FastAPI()`、`@app.get("/hello")`、`return {...}` 三个基本元素；知道 `/docs` 是框架自动生成的接口文档。 | ☐ |
| ② 解释 | 能说明没有框架时后端要自己处理网络连接、HTTP 解析、路由匹配、参数解析、JSON 序列化、状态码设置等"脏活"；框架把这些封装起来，开发者只需声明"URL + 方法 + 函数 + 参数类型 + 返回值"；能说明 FastAPI 如何把接口四要素映射到代码：URL 和方法写在装饰器上、参数写在函数签名上、返回值自动变成 JSON、类型声明触发自动校验并在不合格时返回 422。 | ☐ |
| ③ 模仿 | 能在最小接口代码上，把四要素逐项指认出来（URL、方法、参数、返回分别在哪里）。 | ☐ |
| ④ 独立 | 能独立复述"声明路由—启动服务—打开 `/docs`—Try it out"的流程，并说明框架在每一步做了什么。 | ☐ |
| ⑤ 辨析 | 能判断"FastAPI 就是 Python""用了框架就不用懂 HTTP""`/docs` 是手写的""参数校验要自己写"等说法错在哪里。 | ☐ |
| ⑥ 综合 | 能对比"不用框架"与"用 FastAPI"写同一个 `/hello` 接口的差异，说明框架带来的开发方式变化（从"处理协议细节"转为"声明接口契约"）。 | ☐ |
