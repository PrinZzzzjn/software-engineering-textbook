- [ ] **Step 6：新增 3.6「依赖注入：Depends」**

放在 3.5 之后、「示范例题」之前。内容按四段：

1. **重复的前置逻辑**：三个列表接口各自写「取 `page`、`page_size`，检查范围」，改一处就要改三处；认证、数据库会话同理。
2. **机制**：`Depends(callable)` 写在参数默认值上，FastAPI 在调用函数前先执行依赖，把返回值注入；依赖可以嵌套；测试时可用 `app.dependency_overrides` 替换（一句预告，不展开）。
3. **最小例子**，代码块 `**代码 3-6-1** · 依赖注入最小例子（Python）`：

```python
from fastapi import Depends, FastAPI

app = FastAPI()


def page_params(page: int = 1, page_size: int = 10):
    return {"page": page, "page_size": page_size}


@app.get("/items")
def list_items(params: dict = Depends(page_params)):
    return {"page": params["page"], "page_size": params["page_size"], "items": []}
```

  说明：`page`、`page_size` 仍来自 URL 查询串，由依赖的签名声明；访问 `/items?page=0` 会在依赖返回前被 `int` 转换与校验拦住（若加 `ge=1` 约束则返回 422）。函数体里不再写取值与检查。

4. **分工与落点**：依赖只做「准备与拦截」（取参数、拿会话、查当前用户），不放业务规则；项目里三处落点——`get_db`（第 5 章 5.1）、认证依赖与权限依赖（第 6 章 6.5）。加一条易错点：把业务判断塞进依赖，会让「422 归 Pydantic、4xx 归业务」的分工重新变糊。

`**代码 5-1-3** · app/core/database.py（Python）`：

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import declarative_base, sessionmaker

DATABASE_URL = "sqlite:///./duty.db"

engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

说明：`get_db` 是 3.6 讲的 `Depends` 在项目里的第一个落点——接口签名写 `db: Session = Depends(get_db)`，框架在调用前建会话、调用后关闭；`yield` 的写法保证异常时也能关。
