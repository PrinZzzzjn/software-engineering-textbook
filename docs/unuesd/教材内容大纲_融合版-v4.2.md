# 《AI时代的软件工程实践教程》教材内容大纲（融合版 v4.2）

> **编写理念**：以**课程教学计划的四章框架**为骨架——四章对应四个专题，**节对应课次**——以**独立版的知识体系与案例写法**为血肉，做成一本"**上课能对照、结课能查阅、换项目也能用**"的单册教材。
>
> **本版结构**：
> - **章 = 专题**，全书共四章；
> - **节 = 课次**，26 个课次对应 26 节；
> - **节内 = 一、二、三……**，需要再分层时用 **1.1、1.2……**；
> - **节末 = 实训块**（实践课次）或 **课堂活动块**（理论课次），正文与实训同在一册，用版式区分。
>
> **本版解决两版旧大纲各自的问题**：
> - **课程版**"节 = 课次"定位清楚，但内容像教学计划的逐条展开，缺少案例、步骤与练习，作为书读不起来。
> - **独立版**知识链完整、有案例与实验，但章节按知识逻辑切分，与课次不是一一对应，上课时无法直接定位。
>
> 融合的办法是**节内分工**：每一节前半讲清"为什么"，节末实训块讲清"怎么做"；课次对应关系落在**节标题 + 节首信息条 + 附录总表**上。

## 一、总体设计

### 1. 一册两区

**全书一册，正文与实训不拆书。** 每一节内部用版式分成两个区：前区是知识子节（一、二、三……），后区是节末实训块；理论课次的节不设实训块，改设课堂活动块。

| 组成 | 定位 | 主要使用场景 | 内容边界 |
|---|---|---|---|
| **知识区**（节内一、二、三……） | 讲原理、方法、判断依据 | 理论课通读；实践课前后的理解；结课后系统学习 | 概念、对比、最小可运行片段、常见错误、换场景映射 |
| **节末实训块**（实践课次） | 上课边做边查的操作区 | 实践课全程；课后完成任务 | 课前检查、分步操作、命令与预期输出、验收清单、排错表；**绑定 duty 项目** |
| **节末课堂活动块**（理论课次） | 课堂讨论与自测 | 理论课当堂 | 听讲要点、讨论题、课后自测 |
| **速查卡**（书末附录） | 工具书 | 结课后独立开发；课上任一时刻快速查 | 命令、API、模式、排查决策树；**不解释原理** |

### 2. 章节体系

- **章 = 专题**，全书四章，与课程四个专题一一对应。
- **节 = 课次**，26 个课次 = 26 节，顺序与课次完全一致。
- **节内 = 一、二、三……**；需要再分层时用 **1.1、1.2……**（如"三、数据校验"下的"3.1 类型校验""3.2 业务校验"）。
- **节末 = 实训块或课堂活动块**，按该课次是实践还是理论二选一。
- 每一节标题下**必须标注**「对应课次 X · X 学时 · 讲授/实践」，学员凭这一行就能定位。

> 这样做的理由：您最看重的是"教材流程 = 授课流程"。四章对应四个专题、节对应课次后，"今天上第 7 课次"与"翻开第二章第四节"是同一件事，不需要再在书里找对应关系。

### 3. 节内两个区的分工（避免重复）

| | 知识区 | 节末实训块 |
|---|---|---|
| 代码 | 说明问题的 10–30 行关键片段 | 完整可执行代码与文件位置 |
| 步骤 | 只讲"顺序与理由" | 编号步骤 + 命令 + 预期输出 |
| 错误 | "常见错误"归类与原因 | "现象 → 原因 → 处理"排错表 |
| 结尾 | 小结 + 练习 | 验收清单 + 课后扩展 |

> 实训块引用知识区已经给过的代码时，用编号（如"代码 2-4-2"）引用，不再整段重排；知识区也不复述实训步骤。

### 4. 内容范围规则

教材可以略多于课堂，但必须可预期：

1. **课次教案是课堂的最低范围，不是教材的上限。** 教材知识区可以多讲 10%–20%，但超出部分一律放进"延伸"灰色侧栏，并在节首信息条注明"延伸内容不进入实训验收"。
2. **教案刻意延后的内容，教材只做"先导"不做"展开"**：用 1–2 句交代概念并明确写出"完整展开见第 X 章第 Y 节"。例如：
   - JWT 三段结构：第二章第四节先导，不展开，附录 L 选读；
   - 事务边界、统一异常：第二章第八、九节先导，第十一节完整讲；
   - 401/403/404/422/500：第三章第五节先导，第七节完整讲。
3. **基础知识的补课责任写清楚**：见第 6 条"先修假设"。

### 5. 场景策略：全书以 duty 为主线案例

- **知识区主线示例**：duty（值班数据统计系统）—— 用户、部门、人员、工位、值班记录、查班记录、统计。全书知识点都从 duty 的真实代码中取例，保证每段示例可运行、每个"预期结果"可复现。
- **通用性靠写法，不靠第二套代码**：
  - 概念与方法的表述保持项目无关（讲"资源""关联关系""状态流转"，不把 duty 的字段名写进定义）；
  - 每章末一张"换场景总表"，把本章方法映射到图书借阅、选课、报修等业务；
  - 每节末一组"换成你的项目"检查项，引导学生把方法迁移到自己的选题。
- **只维护 duty 一套实现**：正文、实训、附录共用同一套代码，附录 G/H 提供模块索引。

| duty 模块 | 业务角色 | 对应节 |
|---|---|---|
| `auth` / `user` | 登录、账号、权限 | 第二章第四、五节 |
| `dept` | 部门 | 第二章第六、七节 |
| `personnel` | 人员 | 第二章第六、七节 |
| `workstation` | 工位 | 第二章第六、七节 |
| `duty_record` | 值班记录 | 第二章第八、九节 |
| `inspection_record` | 查班记录 | 第二章第八、九节（扩展） |
| 前端 `pages/` | 部门管理、数据统计 | 第三章第二至七节 |
| `Dockerfile` / `docker-compose.yml` | 部署 | 第四章第一至四节 |

> 通用性说明：duty 是军事值班场景，但本书讲的是"任何一个 CRUD + 权限 + 统计系统"的做法。示例用 duty 是为了可运行；方法本身通过映射表和迁移练习保持通用。

### 6. 先修假设

本书面向"有 Python 基础、没有项目经验"的学生，**不假设 SQL、HTTP、Git 基础**：

| 知识 | 在哪里补 | 说明 |
|---|---|---|
| Python 基础语法 | 导论 + 附录 A | 不达标者先补 |
| HTTP / JSON | 第二章第一节 | 从零讲 |
| SQL / SQLite | 第二章第二节二 + 附录 D | 最小集在正文，完整语法在附录 |
| Git | 第二章第三节二 | 从零讲 |
| HTML/CSS | 不要求 | Streamlit 不需要 |

### 7. AI 的定位

- **不进主线**：知识区不以"AI 辅助"作为一节，避免教材依赖具体工具与可用环境。
- **每节末侧栏"AI 协作提示"**：该节内容 AI 能生成什么、常见错误、审查要点。
- **附录 L"AI 辅助开发与输出审查"（选读）**：集中讲提示词、审查清单、风险边界；无 AI 环境可整篇跳过。
- **速查卡 10**：AI 输出审查清单，可单独抽出使用。

## 二、每一节的统一骨架

### 2.1 节首（所有节）

1. **节首信息条**：对应课次 / 学时 / 课堂用法（讲授·演示·动手）/ 前置知识 / 本节实训。
2. **学习目标**：3–5 条，用"能说清 / 能完成 / 能判断"开头，可检验。

### 2.2 知识区（一、二、三……）

每一节按 3–6 个一级要点组织，编号用"一、二、三……"；每个一级要点下如需再分，用"1.1、1.2……"。每个要点按以下五段写：

1. **场景引入**：duty 系统里的一个真实问题，说明"不学这一点会怎样"。
2. **知识讲解**：概念、原理、对比表；每个概念回答"是什么、为什么、什么时候用"。
3. **关键代码 / 关键操作**：10–30 行最小片段，编号（代码 2-4-2），附"预期结果"与"改哪里会出错"。
4. **常见错误与排查**：3–6 条，按"现象 → 原因 → 处理"写。
5. **小结与练习**：本节要点清单；基础题 / 进阶题 / 换场景题。

### 2.3 节末实训块（实践课次）

用底色或左侧色条与知识区区分，标题格式「◆ 实训 X-Y：任务名」（X = 章号，Y = 节号）。固定七段：

1. **任务目标与验收标准**：3–5 条可勾选，与课次教案的验收标准一致。
2. **课前准备**：环境检查、需要的参考代码、前置知识复习页。
3. **操作步骤**：Step 1…n，每步给"做什么 / 命令或代码 / 预期输出 / 做错了会看到什么"。
4. **排错清单**：现象 → 原因 → 处理，表格化。
5. **提交与验收**：提交物、验收方式、常见扣分点。
6. **课后扩展**：基础巩固 / 进阶挑战 / AI 加速层（可选）。
7. **回链**：`◀ 对应知识区 §X.Y`。

### 2.4 节末课堂活动块（理论课次）

标题格式「◇ 课堂活动」，固定四段：

1. **听讲要点**：3–5 条，告诉学生"这节课最该记住什么"。
2. **课堂讨论 / 演示**：1–2 个问题或演示任务。
3. **课后自测**：5 题。
4. **回链**：本课次的知识在后续哪一节会被用到。

### 2.5 章首与章末（每章一次）

1. **章首知识地图**：说明本章各节的关系，以及与前后章的关系。
2. **章末检查清单**：可勾选，覆盖本章重点与难点。
3. **章末换场景总表**：本章方法在四种业务场景中的对应写法。
4. **章末 AI 提示汇总**：本章各节 AI 提示的索引。

### 2.6 体例约定

- 代码块统一标注文件名与语言，并编号（如"代码 2-4-2"），供实训块与附录引用；命令统一用 `$` 前缀；预期输出用 `→` 引出。
- 实训块与知识区用**不同底色或色条**区分；实训块内不重复知识区已给的完整代码段，改用编号引用。
- 术语首次出现给中英文对照，附录 I 收口。
- 图：架构图、ER 图、流程图用 Mermaid；界面截图统一尺寸与标注。
- 节内层级最多三级：**节（第X节）→ 一、二、三 → 1.1、1.2**；不再往下分。

## 第二章 后端服务开发

> **定位**：对应专题二（36 学时，理论 4 / 实践 32），是全书主体。按开发者真实工作顺序编排：先建立 Web 与框架认知，再设计与建模，然后初始化项目，依次开发用户、数据、业务模块，最后测试、重构与整合。本章十二节对应课次 4–15。

### 第一节 后端开发框架基础【课次4 · 2 学时 · 讲授】

- **一、Web 应用与 HTTP 基础**
  - 1.1 Web 应用的工作方式：浏览器、服务器、数据库；请求—响应；前后端分离
  - 1.2 HTTP 请求与响应：GET/POST/PUT/DELETE；状态码；请求头、响应头、请求体、响应体
  - 1.3 幂等性与安全性
- **二、JSON 与接口调试**
  - 2.1 JSON 语法与类型；日期、枚举、空值的处理
  - 2.2 Swagger UI / ReDoc / Postman / cURL
- **三、FastAPI 入门**
  - 3.1 设计理念：轻量、现代、类型驱动；与 Flask/Django 的对比
  - 3.2 第一个 FastAPI 应用与项目入口
- **四、路由、校验与接口文档**
  - 4.1 路径参数、查询参数、请求体
  - 4.2 Pydantic 模型与字段约束；校验失败的错误响应
