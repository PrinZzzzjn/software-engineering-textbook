# 《AI时代软件工程实践教程》教材内容大纲（v3.0）

> **编写理念**：本版教材大纲从"课程课次同步稿"升级为**独立成体系的教材大纲**。
> 教材按"工程认知 → 后端构建 → 前端呈现 → 部署交付 → 综合实践"的知识链条组织，
> 以主线项目"值班数据统计系统"（duty）贯穿全书；课程教学计划从教材中选取核心章节，
> 扩展章节供学生自学与差异化发展。
>
> **与课程计划的关系**：教材章节不再与 26 个课次一一对应；教材内容可以多于 80 学时，
> 各章标注"课程对应"与"建议用法"（核心/选讲/自学），完整映射见附录 H。
>
> **AI 的定位**：AI 辅助开发作为**可选扩展章**（第 22 章）与各章"AI 辅助"小节出现，
> 不作为教材主线，也不绑定具体工具；无 AI 环境下可完整使用本教材。
>
> **每章结构**：学习目标 → 知识要点 → 案例（duty）→ 实验 → 小结与练习。

## 第1章 软件工程与开发过程

> **学习目标**：理解软件开发生命周期与敏捷方法，能用 duty 的开发过程解释各阶段。
> **课程对应**：课次1（核心）。

### 1.1 软件工程的定义与目标
- 软件工程的定义、目标与基本原则
- 质量属性：可维护性、可扩展性、可复用性、可靠性、效率
- 工程化与随意编码的差异

### 1.2 软件开发生命周期
- 需求、设计、编码、测试、部署、运维各阶段的任务与交付物
- 瀑布模型、迭代模型、敏捷模型的对比
- 阶段划分不是目的，控制复杂度才是

### 1.3 敏捷开发
- 敏捷宣言的价值观与原则
- Scrum：角色、工件、事件
- Kanban：看板、在制品限制、流动效率
- 迭代与增量：小步交付、持续反馈

### 1.4 团队角色与协作
- 产品、开发、测试、运维的职责
- 需求评审、设计评审、代码评审
- 文档与沟通在团队中的作用

### 1.5 案例：duty 是怎么造出来的
- 从 `开发步骤.md` 看真实项目的阶段推进
- 把 `app/`、`tests/`、`Dockerfile`、`api说明.md` 归入生命周期各阶段
- "文档属于哪个阶段"——一个没有标准答案的讨论

**案例与实验**：绘制 duty 的开发流程图；把项目文件归类到生命周期阶段。
**重点/难点**：生命周期各阶段与真实项目活动的对应；从"个体编码"到"工程化管理"的转变。

## 第2章 需求工程

> **学习目标**：掌握需求获取、需求表达、优先级划分与需求文档编写；能对 duty 的一个子系统完成需求分析。
> **课程对应**：课次2–3（核心）。

### 2.1 需求获取方法
- 用户访谈、问卷调查、现场观察、原型法、文档分析
- 每种方法能补什么、容易漏什么
- 开放式问题与追问技巧
- 用户画像与利益相关者分析

### 2.2 需求表达
- 需求规格说明书（SRS）的结构
- SMART 原则：具体、可测量、可实现、相关、有时限
- 用户故事格式："作为[角色]，我想要[功能]，以便[价值]"
- INVEST 原则与验收标准
- 好故事与坏故事的对比
- AI 辅助需求整理与文档初稿（详见第 22 章）

### 2.3 功能优先级与 MVP
- MoSCoW：Must / Should / Could / Won't
- 从用户故事到功能清单
- MVP 与迭代交付

### 2.4 非功能需求
- 性能、安全性、可用性、可维护性
- 非功能需求的量化描述
- 约束条件与假设

### 2.5 需求评审与变更管理
- 需求评审的检查清单
- 需求变更的影响分析
- 需求追踪矩阵初步

### 2.6 案例：duty 的需求文档
- 从用户视角推测后台功能
- 对照 `api说明.md` 的接口清单查漏补缺
- "先猜后对照"：猜在前、答案在后

**案例与实验**：为 duty 的一个子系统写 3–5 条用户故事、功能清单与 MoSCoW 优先级；与真实接口清单对照评审。
**重点/难点**：需求获取方法的综合运用；区分"用户想要的"与"用户需要的"；需求文档的完整性与一致性。

## 第3章 软件设计与建模

> **学习目标**：掌握分层设计、数据库建模与 API 设计；能为 duty 的一个模块完成模型与接口设计。
> **课程对应**：课次5（核心）；课次9–10（设计部分）。

### 3.1 设计原则
- 单一职责、开闭、依赖倒置
- 高内聚、低耦合
- 分层：Controller / Service / Repository

### 3.2 架构风格
- 分层架构、MVC、C/S、B/S
- 单体与微服务的取舍
- 本课程为什么选择"单体 + 分层"

### 3.3 数据库设计
- ER 图与实体识别
- 一对一、一对多、多对多
- 范式与反范式的取舍
- 主键、外键、唯一约束、索引初步

### 3.4 接口设计
- RESTful 资源命名与 URL 设计
- HTTP 方法与状态码
- 统一响应格式与错误码
- API 版本管理
- 接口文档与代码的一致性

### 3.5 设计文档与评审
- 概要设计与详细设计
- 数据库设计文档、接口文档
- 设计评审的检查清单

### 3.6 案例：duty 的 `app/core` 与模块划分
- 通用基础设施：配置、数据库、安全、异常、日志、基础 CRUD
- 业务模块：dept/personnel/duty_record 等的分层
- 接口契约与代码不一致的真实案例（`/departments/`、`sort_order`、`dept_code`）

**案例与实验**：为 duty 设计一个新模块的 ER 图、表结构与接口清单。
**重点/难点**：表关系设计；RESTful API 设计规范；接口契约与文档一致性。
