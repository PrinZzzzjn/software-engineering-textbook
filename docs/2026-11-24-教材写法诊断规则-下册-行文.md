# 教材写法诊断规则·下册：行文方式

> 日期：2026-11-24
> 用途：定位“行文不像教材”的根源，给出全书可执行的行文规则。适用于正文段落、章首模板段、例题与习题答案。
> 配套：上册《教材写法诊断规则-上册-章节骨架》负责章节结构、主线与详略。
> 来源：第 3、4 章修改复盘（`docs/2026-11-23-第3章修改复盘与跨章修改参考.md`）与 01、05、06、10、14、17、21 章抽样。

## 零、与上册的分工

上册判断“这一章/这一节该不该存在、该讲多少、和邻章怎么分工”；下册判断“每个段落、句子是否像教材在跟读者说话”。先过上册，再过下册；骨架没理顺时，单纯改句子不会解决问题。

## 一、问题的定性

结构层面的问题（主线、合并、术语、详略）已在第 3、4 章复盘中解决。剩下的问题发生在**句子层面**：

> 教材正文只说读者此刻需要知道的知识；任何“作者为了让稿子自洽而写的话”都应删除或改写。

这类句子单独看都不算错，但密集出现时，教材读起来像编写说明书。最典型的是成串的“本章只写……”“完整用法见第 N 章……”“本节说明……下一节展开……”。

**终极判定问题**：删掉这句话，读者会不会少知道一件他此刻能用上的事？答案是不会，就删。

## 二、四类编写说明与处置规则

按用户确认的优先级排列：

| 类型 | 典型例子（均出自现有章节） | 处置 |
| --- | --- | --- |
| B1 模块边界声明 | 3.2.1“认证请求头的完整用法见第 8 章”；3.3.1“`Depends` 在第 4 章 4.5 随查询参数一并讲”；3.2.1“本章只写路径” | **最优先删除**。成串的章节分工汇报，不是读者知识 |
| B2 提前目录式声明 | 3.2.2“本节说明怎样读一条响应……3.4.3 按请求经过的关卡逐一说明”；21 章“本章解决三个问题：为什么打包、打成什么、怎么描述” | **删除或改为正文的推进句**，让读者跟着问题走，而不是听作者报幕 |
| B3 代码/表格后的复述转场 | 3.3.4 五个端点表后的“HTTP 方法与状态码……状态码的分类与责任划分见 3.2.2” | **删除复述**，需要时只补一句表格回答不了的东西（为什么这样设计） |
| B4 元话语式提醒 | 3.3.4“这里由函数手写字段检查……**400 不是输入校验的正式口径**”；习题答案“使用模型后……为最终形态” | **保留，但改写为稳定的知识表述**。它帮助读者理解“为何当前代码故意不完美”，删掉会丢失知识 |

边界已确认：**不禁止跨章引用本身**。顺带一句“完整用法见第 8 章”可以接受；被禁止的是成串的“本章不讲/后面讲/见第 N 章/见实训手册”。A 类（连续定义堆砌）为第二优先，C 类（例题泄题）最轻；C 类中夹带“临时安排/最终形态”的句子按 B4 处理。

## 三、分层规则

### 3.1 普通正文段落

1. **边界写成判断力，不写成分工汇报。** 用户选定的最佳改法：
   - 原句：“完整形式还包含协议、主机与端口……但主机与端口由部署环境决定，本章只写路径。”
   - 改法：“主机与端口由部署环境决定，路径只指出要操作哪个资源。因此联调时先确认路径，再确认它要发往哪台服务器。”
   - 规则：说明“这件事回答什么问题、由谁决定”，读者自然知道边界在哪；不用“本章不展开”画边界。
2. **路标每处最多一句，挂在真实问题上。** 如确需跨章指引，放在读者可能产生疑问的地方，不在段首预先声明，不连续出现两条以上。
3. **定义之后必须跟着用途或后果。** A 类连续定义堆砌的改法：每个“X 是……”后面立刻接“它回答什么问题/它错了会怎样/下一步拿它做什么”，不复述“读者应掌握”。
4. **表格和代码后不写“流水账转场”。** 不重复表中已列出的条目；只写“为什么这样设计”“哪里容易出错”“这和前一处知识是什么关系”。
5. **元话语改成知识句。** 不说“这里是临时写法”，说“在引入模型前……模型接管后……”，把时间性表述变成读者可用的因果知识。
6. **“初学阶段需认识”“本章只涉及”等编辑器口吻，改为直接给清单或判断标准。** 清单本身已经完成了收窄范围的工作，不必再声明范围。

### 3.2 章首模板段（“本章要解决的问题 / 本章学习目标”）

1. **“本章要解决的问题”允许交代边界，但只写正面接手什么。** 已在第 4 章复盘中确立：精确写清上一章完成到哪一步、本章从哪个层级接手；不写“本章不展开 X”。
2. **问题句须落到本章产物。** 如第 4 章“转化为表、模块、接口组和文件结构，并据此搭出可运行的最小实现”，不写成与前一阶段相似的文档产物。
3. **“本章关心的是……”只用一次，后面直接给具体情境。** 抽样中 01、06、14、17 章都有“本章关心的是”；它是可接受的启动句，但如果其后又接“本章解决三个问题”则算重复报幕，删其一。
4. **学习目标写可验证的动作**，不写“了解/理解/掌握”式内部状态；目标不涉及章节分工说明。

### 3.3 例题与习题答案

1. **答案只回答题目。** 不在解题末尾补“这是临时形态/最终写法见 X 节”之类稿件说明；若该信息影响答题判断，写进题干，例如“此时尚未引入输入模型，字段检查写在函数体内”。
2. **答案条目按解题推理排列**，不按“知识点目录”排列。例 3-1 的六条答案按“方法→URL→参数→状态码→响应体→综合结论”就是正确顺序；不需要额外前置“本题考查请求与响应的组成”。
3. **不泄题的判据**：示范例题的“题目”段不得出现答案中的结论性词句（状态码、模型名、具体数值）；题干只给情境与任务。
4. **元话语在答案中的处理**：如“使用模型后字段缺失改由 422 返回”，若属于题目要求的区分，就写为“因为模型校验发生在函数外，422 由框架产生……”；若只是解释稿件安排，删掉。

## 四、改写操作四步

1. 圈出段落中所有“作者声”：本节、本章、下文、第 N 章、完整实现、初学阶段、临时、最终形态、先不展开。
2. 逐句问终极判定问题；回答“读者学不到东西”的直接删。
3. 保留的句子按三类改写：边界→判断力；路标→一句且挂问题；临时说明→稳定知识句。
4. 检查段落是否形成推进：例子/问题 → 判断/结论 → 用途/后果。若仍在“定义→定义→定义”，补用途句。

## 五、全书检查表（动笔前后各过一遍）

- [ ] 是否出现“本章只写/后面讲/完整用法见/见实训手册”的成串分工汇报？
- [ ] 是否有提前报幕：“本节说明……下一节展开……”？
- [ ] 表格/代码后是否只是复述已列内容，而没有新增判断力？
- [ ] 连续定义段是否每条都跟了用途或后果？
- [ ] “初学阶段”“本章只涉及”等范围声明能否删掉而由内容本身完成收窄？
- [ ] 元话语是否改写为读者可用的稳定知识？
- [ ] 跨章路标是否每处不超过一句、且挂在真实问题上？
- [ ] 章首问题句是否写清上一章止步处与本章落点，且落点是本章产物？
- [ ] 例题题干是否不含答案结论；答案末尾是否夹带稿件说明？
- [ ] 终极检查：逐句删读，删掉后读者会不会少知道一件此刻能用上的事？

## 六、边界与例外

- 第 3、4 章复盘中的结构规则（主结构编号、机制与应用合并、术语一词一义、实训从零起步等）继续有效；本清单只管**行文**这一层。
- “示例/反例/易错点”是教材的正式教学组件，不属于编写说明，不得按本清单删除。
- 大量删除后若出现过渡生硬，用“上一结论 + 新问题”一句衔接即可，不恢复“本节说明……”式报幕。
