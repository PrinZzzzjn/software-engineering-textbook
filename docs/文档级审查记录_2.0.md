## 三、跨文档共性问题（本批 3/3 命中，需按批统一处置）

### G-01【A】mermaid 图块被误插「代码编号」，图无法渲染 —— 全书级回归

- **现象**：三章的流程图围栏内，在闭合 ` ``` ` 之前被插入一行 `**代码 X-1-1** · 示例（文本）` 及空行（01 L82–90、02 L115–123、03 L50–60）。mermaid 解析器会把这行当作图节点文本，图渲染失败；纯纸质付印时更会直接印出这行源码。
- **性质**：**2.0 引入的回归**。1.x 备份 `docs/_覆盖前手动备份/01-软件工程基本概念.md` L66–72 的同一图块是干净的。
- **根因（已定位）**：`tools/rollout_style.py` `caption_code_blocks()`（L565–591）。该函数用正则 `^```([A-Za-z0-9]*)\s*$` 匹配围栏，开围栏 ` ```mermaid ` 被排除，但**闭合围栏 ` ``` `（语言为空）被误判为「无语言代码块的开围栏」**，于是把编号插进图块内部。全书扫描：**21 份文件、22 处 mermaid 图受污染**（01/02/03/06/07/09/10/11/12/13/14/16/17/18/19/20/21/22/23 两处/25/26）。
- **连带问题**：这三章本身没有真正的代码块，脚本 `check_structure.py` 的「代码编号」判据只是全文正则 `代码 \d+-\d+-\d+` 命中一次（见 `tools/common.py` L112），**GREEN 恰恰是靠这处伪编号达成的**。设计 §7.2 要求的是「代码块标文件名＋语言＋编号」，图表应标图号，无代码章节不应强行配编号。
- **建议动作**：① 修 `caption_code_blocks()`：维护 `in_fence` 状态，仅在开围栏处插编号并跳过 mermaid 整块；② 批量清除 22 处污染；③ 把 `check_structure` 的「代码编号」改为「存在非 mermaid 代码块时必须有编号，且 mermaid 块内不得出现 `**代码 `」，并新增断言跑一次 RED→GREEN；④ 01/02/03 改用「本章无代码」豁免，不补假编号。
