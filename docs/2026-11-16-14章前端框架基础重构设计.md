# 第 14 章《前端开发框架基础》内容架构重构设计

> 本文记录经对话确认的重构口径。方案：概念 → 工具 → 机制 → 状态 → 边界（六节）。原章四节中，讲解内容保留并重新归位，章首问题、学习目标、小结与跨章引用同步调整。

## 一、问题

原章以"页面为什么会在点击后重算、状态为什么有时丢"开篇，14.1 在前端概念上只用了不到十行，随即进入计数器、重跑与 `session_state`。本章是专题三"前端界面构建"的第一章，读者尚未建立"前端是什么、为什么需要前端"的认识，也未见过 Streamlit 的定位与运行方式，先讲重跑与状态属于机制先行。

另一个缺口：全书未出现 Streamlit 的安装与运行方式，而教材设计对本章的定位是"理解页面重跑与会话状态，跑通首个页面"。

## 二、目标与非目标

**目标**

1. 章首与 14.1–14.2 建立前端概念：前端在系统中的位置、职责、与后端的分界；页面的三层构成。
2. 14.3 给 Streamlit 一个完整落点：定位、组件概念、第一个页面、安装与运行、脚本即页面的开发方式、控制力与速度的取舍。
3. 重跑、差量更新、`st.session_state` 保留在本章，但移到读者已经知道"自己在用什么工具、怎样运行"之后。
4. 保持与第 15–20 章的衔接：第 15 章仍可写"上一章知道了页面怎么跑起来"。

**非目标**

- 不增加示范例题与独立习题数量；不改动 Bloom 层级。
- 不引入布局、多页面、接口调用、图表；这些分别属于第 15–19 章。
- 不重写第 15–20 章正文，只同步两处节号引用。
- 不更新 R1 审计记录（`概念与依据登记表_3.0.md`、`章节标题总表_2026-11-12.md`）；如后续继续概念审计，再按新节号补登记。

## 四、新增与改写内容

### 章首

- 开篇说明本章进入专题三，先概念、再工具与运行方式、最后边界。
- "本章要解决的问题"改为：后端已能按契约返回数据，用户为什么还需要界面；本课程用什么工具、它按什么方式运行。

### 14.1 前端在系统中的位置

- 三层架构：前端（浏览器中的页面）、后端（服务端应用）、数据库；与 3.1 的表述一致，不重复展开。
- 前后端分离：可独立开发与部署，共同依据是接口契约（见第 3 章）；同一接口可服务网页、移动端与第三方系统。
- 前端职责四项：展示数据、接收输入并做基本校验、组织导航、给出操作反馈；发起请求与处理响应留到第 17 章。
- 保留第 8 章部门列表 JSON 的对照，说明"给程序读的数据"与"给人用的界面"之间的转换。
- 明确本课程前端范围：管理工具与数据应用，不以像素级视觉设计为目标。

### 14.2 页面的三层构成

- 保留计数器页面的三层表格与"改颜色不碰点击逻辑"的论证。
- 补一句过渡：三层由浏览器解释；前端框架的价值在于替开发者生成这三层。

### 14.3 Streamlit：用 Python 写页面

- 定位：用 Python 编写数据应用的 Web 框架；把脚本变成可交互页面，无需分别编写 HTML、CSS 与 JavaScript。
- 组件概念与引用方式沿用原文（Streamlit 官方文档）。
- 顺序为安装 → 第一个页面 → 运行：先 `pip install streamlit`（代码编号 `14-1-1`），再给四行页面（代码编号 `14-1-2`），最后 `streamlit run app.py`（代码编号 `14-1-3`）；说明浏览器打开、保存文件后页面重新执行、`Ctrl+C` 停止；说明课程项目在 `requirements.txt` 中约定 `streamlit>=1.50,<2`。
- 开发方式：脚本从上到下执行，调用顺序决定页面从上到下的顺序；这是 14.4 重跑模型的前提。
- 取舍：控制力换开发速度；组件清单与布局留到第 15–16 章。
