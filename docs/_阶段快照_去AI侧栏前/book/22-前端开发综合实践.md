## 22.1 概念讲解

### 22.1.1 联调：按用户路径验证

联调不是“把页面点一遍”，而是按用户真实路径验证：未登录访问 → 登录 → 列表 → 搜索 → 新增 → 编辑 → 删除 → 统计 → 切换条件 → 退出。每一步都要有明确期望，否则失败了也看不出来。

| 步骤 | 操作 | 期望 |
| --- | --- | --- |
| 1 | 未登录直接访问部门页 | 被守卫拦住，提示登录 |
| 2 | 用管理员账号登录 | 进入首页，侧边栏显示当前用户 |
| 3 | 打开部门管理 | 列表显示，分页正常 |
| 4 | 搜索“保障” | 只显示匹配的部门 |
| 5 | 新增一个部门 | 列表出现新记录 |
| 6 | 编辑该部门名称 | 列表显示新名称 |
| 7 | 删除该部门 | 二次确认后列表少一条 |
| 8 | 打开数据统计 | 指标卡与图表有数据 |
| 9 | 切换人员或年份 | 指标与图表跟着变 |
| 10 | 退出登录 | 回到登录页，子页面再次被拦截 |

先保证主流程，再管边角。失败先记录，不要立刻改代码；全部走完后按影响排序，先修影响主流程的。

### 22.1.2 排查顺序：现象 → 状态码 → detail → 日志 → 定位

```mermaid
flowchart LR
    A[现象] --> B[状态码]
    B --> C[detail / 返回体]
    C --> D[后端日志]
    D --> E[定位页面/接口/字段]
    E --> F[修复并重跑清单]
```

*图 22-1：前端联调的排查顺序*

状态码是第一线索：

| 状态码 | 含义 | 先查什么 | 页面提示 |
| --- | --- | --- | --- |
| 401 | 没登录/登录过期 | 令牌是否存在、请求头 | 清登录态，回登录 |
| 403 | 登录了但没权限 | 当前角色、接口权限 | “当前账号没有权限” |
| 404 | 资源不存在 | 路径、编码是否已删除 | “数据不存在，可能已被删除” |
| 422 | 参数校验失败 | 字段名、类型、必填 | 显示具体字段问题 |
| 500 | 后端异常 | 后端日志/堆栈 | “服务器开小差了，请稍后重试” |

401 与 403 要分清：一个是“没证件”，一个是“证件不够级别”。500 先看后端日志，不要在前端反复改。

### 22.1.3 非状态码问题

| 现象 | 先查什么 |
| --- | --- |
| 页面不渲染 | 是否有未捕获异常；`st.stop()` 位置 |
| 数据不更新 | 是否 `st.rerun()`；取数是否在操作之前 |
| 样式异常 | `config.toml` 是否重启；是否重复注入 CSS |
| 图表空白 | 数据结构/字段名是否与接口一致 |
| 页面卡顿 | 是否在循环里发请求；是否一次取太多 |

### 22.1.4 统一错误处理

每个页面各写一套 `try/except` 会重复，提示也不一致。把“错误 → 提示”的映射收拢到一个函数：

**代码 22-1-2** · 示例代码（Python）

```python
def show_api_error(exc) -> None:
    if exc.status_code == 401:
        st.session_state.clear()
        st.warning("登录已过期，请重新登录")
        st.rerun()
    elif exc.status_code == 403:
        st.error("当前账号没有权限执行该操作")
    elif exc.status_code == 404:
        st.error("数据不存在，可能已被删除")
    elif exc.status_code == 422:
        st.error(f"提交内容有误：{exc.detail}")
    elif exc.status_code == 500:
        st.error("服务器开小差了，请稍后重试或联系管理员")
    elif exc.status_code == 0:
        st.error(f"无法连接后端服务：{exc.detail}")
    else:
        st.error(exc.detail)
```

页面里统一调用：

**代码 22-1-4** · 示例代码（Python）

```python
try:
    data = api.get("/departments/", params=params)
except api.ApiError as exc:
    show_api_error(exc)
    st.stop()
```

四种策略：401 清登录态并回登录；403 提示没权限、不重试；404 提示数据不存在、刷新列表；422 显示具体字段问题；500 提示稍后重试并记录时间与操作；空数据不是错误，用 `st.info` 提示。

错误提示要“说人话”，不要把堆栈直接给用户；401 必须在统一入口处理；提示里不要泄露令牌、密码与服务器路径。

### 22.1.5 复用与扩展：照抄结构，不照抄字段

人员管理页可以照部门页改，主要改三处：接口路径 `/departments/` → `/personnel`；展示字段改成人员字段；排序参数以 `/docs` 为准。真实项目里，部门列表用 `sort_order`，人员列表可能用 `order`，照抄参数名就会静默失效。

扩展步骤：复制页面文件；改标题与图标；改接口路径与字段；改表单字段；运行并按联调清单走一遍。每改一处运行一次，不要一次改十处。

### 22.1.6 交付清单

| 类别 | 内容 |
| --- | --- |
| 代码 | 前端项目，可运行 |
| 截图 | 登录、列表、新增/编辑/删除、统计 |
| 联调记录 | 10 步清单的通过情况 |
| 错误处理 | 401/403/404/422/500 各一条记录 |
| 已知问题 | 还没解决的问题 + 原因 |
| 说明 | 如何启动、依赖、测试账号 |

已知问题也要写。交付不是“没有问题”，而是“问题说清楚”：什么情况下会出问题、目前怎么规避。藏起来的问题会在验收时集中爆发。

### 22.1.7 三分钟展示

四段结构：一句话说明做了什么；演示主流程；说一个排查过的故障（现象 → 原因 → 改法）；说一个已知问题或下一步。展示的重点不是“功能多”，而是“能说清边界”。

## 22.2 示范例题

#### 例 22-1：照部门页扩展人员页【Bloom：应用】

**题目**：把部门管理页复制成人员管理页，要求改标题、接口路径与展示字段；说明哪些地方不能照抄。

**解**：

**代码 22-2-1** · 示例代码（Python）

```python
import streamlit as st

st.set_page_config(page_title="人员管理", page_icon="👥", layout="wide")
st.title("👥 人员管理")

with st.container(border=True):
    keyword = st.text_input("姓名", placeholder="输入关键字")

# 取数：路径改为 /personnel；参数以 /docs 为准
data = api.get("/personnel", params={"name": keyword, "page": 1, "page_size": 10})
items = data.get("items", [])

st.dataframe(
    [{"certificate_number": p["certificate_number"], "name": p["name"], "position": p.get("position")} for p in items],
    width="stretch",
    hide_index=True,
)
```

不能照抄的地方：接口路径（`/departments/` vs `/personnel`）；字段名（`dept_code`/`full_name` vs `certificate_number`/`name`）；排序参数（部门可能用 `sort_order`，人员可能用 `order`）。以 `/docs` 为准。

#### 例 22-2：读接口文档找差异【Bloom：分析】

**题目**：部门列表与人员列表的接口文档分别写着 `sort_order` 与 `order`，字段名也不同。请说明照抄部门页会出什么问题，以及如何避免。

**解**：

1. 照抄 `sort_order` 传给人员接口，后端不认识该参数，会使用默认排序；页面不报错，但排序不生效，属于静默失败。
2. 照抄 `dept_code`/`full_name` 展示人员数据，字段不存在，表格出现空列或 KeyError。
3. 避免方法：扩页面前先打开 `/docs`，逐项核对路径、查询参数、返回字段；把差异列成对照表；改完用一条真实请求验证排序与字段。

## 本章小结

**核心结论**：

1. 联调按用户路径验证，不按页面逐个点；每步有明确期望，失败先记录后排序修复。
2. 排查按“现象 → 状态码 → detail → 日志 → 定位”的顺序；401/403/404/422/500 分别对应身份、权限、资源、参数、服务器。
3. 统一错误处理收拢到一个函数：401 清登录态，403 提示权限，404 提示不存在，422 显示字段问题，500 提示稍后重试；空数据不是错误。
4. 复用页面照抄结构、不照抄字段；接口路径、字段名、排序参数以 `/docs` 为准。
5. 交付包括代码、截图、联调记录、错误记录、已知问题与 README；已知问题要说清，不藏。

**例 22-3（引导练习）：把人员页接入真实接口【Bloom：应用】**

**提示 1（方向）**

用 `api.get("/personnel", params={"name": keyword, ...})`；响应结构与部门列表相同，都是 `items`/`total`。

**提示 2（关键步骤）**

用 `st.spinner` 包请求；`ApiError` 交给 `show_api_error`；`items` 为空时提示“暂无人员数据”。

**完整解答**

**代码 22-4-1** · 示例代码（Python）

```python
try:
    with st.spinner("正在加载人员列表..."):
        data = api.get("/personnel", params={"name": keyword, "page": 1, "page_size": 10})
except api.ApiError as exc:
    show_api_error(exc)
    st.stop()

items = data.get("items", [])
if not items:
    st.info("暂无人员数据")
else:
    st.dataframe(items, width="stretch", hide_index=True)
    st.caption(f"共 {data.get('total', 0)} 条")
```
