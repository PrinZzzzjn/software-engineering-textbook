## 一、结论先行

1. 四条意见全部成立。第 1 条（准确、官方、可追溯）和第 3、4 条（写作元话语、课后自测 / 98）不只是第一章的问题，而是全书问题。
2. 第一章需要的不只是改措辞，而是一次**概念与依据审计**。现有 `docs/事实核校记录_2.0.md` 只核了三个案例数字和标准版本年份，**没有核过概念来源**；本次要补的正是这一块。
3. 已核出的来源链问题：
   - **「四个根本挑战」（复杂性、变化、协作、质量）**：直接来自 `教学设计/第一章/课次1-软件工程基本概念.md`，教案自身标注为“初稿，未校对”。它不是学术通行的分类，需要改口径或换依据。
   - **「工程化交付」**：是本书自建的工作说法，不是标准术语。可以保留，但必须标明是“本书的工作定义”，并把三层含义锚到标准概念上。
   - **案例的「四层问题拆分」**：ESA 调查报告确实覆盖复用、规格、测试、冗余四项发现，但“四层”与“本可以怎样拦住”的表述是本书的再归纳，应标明“据报告归纳”，不能写成报告原文结论。
4. 建议第一章先做样板，确认引用体例与处理口径后，再批量处理全书。否则 24 章改两遍。

### 3.3 概念与依据审计（全书）

**目标**：让每个定义、分类、数字、标准条款都能回答“依据是什么”；本书自建的教学归纳，明确标注“本书归纳”，不冒充标准或学术定论。

**新建登记表**：`docs/概念与依据登记表_3.0.md`

字段：`编号 | 章/节 | 概念或论断 | 类型 | 来源 | 正文处理 | 状态`

类型四类：

1. **标准定义**：ISO/IEC/IEEE 24765、ISO/IEC/IEEE 12207、ISO/IEC 25010、GB/T 11457 等。
2. **权威文献**：Brooks 1987、Royce 1970、Agile Manifesto 2001、SWEBOK、Larman & Basili 2003 等。
3. **官方报告**：ESA / NASA 事故调查报告等。
4. **本书归纳**：教学框架、判断启发式、作者自建分类；必须标注“本书归纳”，并尽量给出每一条的来源锚点。

> **R1 复核调整（2026-11-15）**：执行中发现“本书归纳”过多，且多数并非知识断言。现取消第 4 类：能对应标准的优先用标准原义，能对应文献的补作者年份；教学装置改记为课程定义 / 课程约定 / 教学安排 / 教学检查项 / 教学建议 / 教学示例，工具与工程内容记为工具文档 / 工程实践。正文不再使用“本书归纳”。详见 `概念审计实施方案_R1.md`。

**优先级**：

1. 01 章试点（本次）。
2. 理论章 02、03、04、14、21。
3. 其余 18 章中“首次引入的概念、定义、分类、数字”。
4. 交叉引用与版本年份。

**引用体例（建议）**：

- 行内括注：`（ISO/IEC/IEEE 24765:2017）`、`（Brooks, 1987）`、`（ESA 事故调查委员会, 1996）`。
- 章末新增 `## 本章依据`：列本章用到的标准、文献、报告，3–8 条；纯纸质不需要二维码。
- “本书归纳”的框架在首次出现处加一句：“这是本书为便于教学做的归纳，不是某标准中的分类。”
- 不能联网核对原文时，标“待核对原文”，不写“已验证”。现有 `事实核校记录_2.0.md` 已采用这一口径，沿用。
