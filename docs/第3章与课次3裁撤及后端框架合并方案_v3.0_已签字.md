## 七、02 章 B 方案并轨（更新版）

专题一现在只剩 2 章理论，02 是唯一需求章，必须自成体系。原 B 方案四项照做：

1. 补「软件需求」一句话定义与边界（业务需求／用户需求／功能需求的层次只点到为止，不展开建模）、需求工程过程主线（复用 1.x 图 2-1「获取 → 表达 → 取舍 → 验证 → 变更」闭环，并在此处向读者交代 02/03 分工已改为「02 讲方法 ＋ 交产品，第 3 章起做接口」）。
2. 2.3 获取方法补成「能补什么／容易漏什么／获取后复述确认」对照。
3. 把「分析」显性化为四步加工（分类 → 去重与冲突消解 → 抽出业务对象与业务规则 → 一致性检查），命名章名里那个「分析」。
4. 新增 1 道纸上辨析习题（给一段访谈记录，要求分类、找冲突、抽业务对象与规则），**不要求写成功能清单或文档**；98 同步补答案。

三处边界：**「给定—当—则」上移 2.5**；新增习题不碰文档；访谈提纲／角色卡／空白模板不进教材。**再加第五节的产品交付卡**。结构化需求分析（DFD／数据字典／判定表）与面向对象需求分析（用例图／类图）仍**不整套讲**，只在过程主线里用一句背景说明带过并回链新第 4 章 6.1 —— 课时无余量、五份上位文件都没规划、技术路线是「用户故事 → 业务对象 → 表与接口」，引入两套建模语言会学完不用。

**02 改写必须与结构迁移同一轮**，避免对同一文件动两次、跑两次门禁。
