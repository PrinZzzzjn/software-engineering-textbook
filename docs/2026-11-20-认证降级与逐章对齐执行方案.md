## 一、背景与目标

简化参考工程 `duty-simplified/` 采用 **hashlib 盐哈希 + 简单令牌（不做 JWT）**。教材第 6 章《登录认证》目前以 **JWT（jose）+ passlib（pbkdf2）** 为教学主线。二者矛盾。

用户裁决：**以简化工程为准**——建立简化工程的目的之一就是"简化教材使其更好地匹配教学"。因此：

1. 密码哈希：`passlib` 的 `pbkdf2_sha256` → 标准库 `hashlib` + 随机盐。
2. 令牌：JWT（`jose`）→ **随机 token（`secrets.token_hex`）+ 服务端内存字典**（`token → user_id`）。
3. **JWT 从"第 6 章核心教学目标"降级为"扩展知识"**，移到课后扩展区块。

## 二、认证降级后的技术方案（第 6 章新教学主线）

### 2.1 密码哈希（`app/core/security.py`）

```python
import hashlib
import secrets


def get_password_hash(password: str) -> str:
    salt = secrets.token_hex(16)
    digest = hashlib.sha256((salt + password).encode()).hexdigest()
    return f"{salt}${digest}"


def verify_password(plain_password: str, hashed_password: str) -> bool:
    salt, digest = hashed_password.split("$", 1)
    return hashlib.sha256((salt + plain_password).encode()).hexdigest() == digest
```

教学要点：为什么不能存明文、什么是盐（随机种子）、为什么哈希不可逆但可验证、`hashlib` 是标准库零依赖、`$` 分隔"盐 + 摘要"。

### 2.2 简单令牌（`app/core/security.py` 续写）

```python
import secrets

# 令牌表：token -> user_id，内存字典，重启即失（与第 6 章用户表一致）
TOKEN_STORE: dict[str, int] = {}


def create_access_token(user_id: int) -> str:
    token = secrets.token_hex(16)
    TOKEN_STORE[token] = user_id
    return token


def resolve_token(token: str) -> int | None:
    return TOKEN_STORE.get(token)
```

教学要点：登录后给一个随机字符串当凭证；服务端用一个字典记住"这个 token 属于谁"；校验就是查字典。比 JWT 少了"签名、过期、载荷"，但把"登录后给个凭证、之后凭它认人"这个核心思想讲清楚了。JWT 作为扩展知识，说明"当令牌要跨服务、要无状态、要防伪造时，就需要 JWT 这种带签名的令牌"。

### 2.3 认证依赖（`app/core/security.py` 续写）

```python
from fastapi import Depends, HTTPException
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer

bearer_scheme = HTTPBearer(auto_error=False)


def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme),
) -> dict:
    if credentials is None:
        raise HTTPException(status_code=401, detail="未提供令牌")
    user_id = resolve_token(credentials.credentials)
    if user_id is None:
        raise HTTPException(status_code=401, detail="令牌无效")
    # 查用户表拿 role（内存版直接查 TABLE）
    from app.modules.user import crud
    user = crud.get_by_id(user_id)
    if user is None:
        raise HTTPException(status_code=401, detail="令牌无效")
    return {"id": user.id, "role": user.role}
```

注意：简单令牌字典只存 `user_id`，不含 `role`，所以 `get_current_user` 要**查用户表**取 role（与 JWT 版"只读令牌不查表"不同，这是简单令牌的代价，正好是 JWT 扩展知识里"为什么 JWT 把 role 放进载荷"的反衬）。

### 2.4 login 的变化

```python
def login(data) -> dict:
    user = crud.get_by_username(data.username)
    if not user or not verify_password(data.password, user.password_hash):
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    if not user.is_active:
        raise HTTPException(status_code=401, detail="账号已禁用")
    token = create_access_token(user.id)
    return {"access_token": token, "token_type": "bearer"}
```

`sub`（字符串化 user.id）不再需要，因为简单令牌的字典直接存整数 user_id。

## 三、JWT 作为扩展知识的摆放

第 6 章 6.2 的 JWT 讲解整体移入 **6.x 课后扩展** 或章末新增一个「扩展知识」小节，内容精简为：

- JWT 是什么：带签名、含载荷（sub/role/exp）、无状态、可跨服务校验；
- 与简单令牌的对比：简单令牌要服务端存字典（有状态）、JWT 无状态但需要密钥管理；
- 本课程为何用简单令牌：够讲清"认证"思想、零依赖、学生能看懂每一步。

JWT 相关依赖（`python-jose`、`passlib`）从 `requirements.txt` 移除；`hashlib`/`secrets` 是标准库，无需新增依赖。
