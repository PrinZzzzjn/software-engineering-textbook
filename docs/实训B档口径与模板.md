# 实训 B 档口径与模板

> 日期：2026-11-23
> 依据：`docs/superpowers/specs/2026-11-23-后续实训B档全局重设计-design.md`
> 适用：实训 3-1/4-1 复查回改与实训 5-1～20-1 全局重设计

## 一、B 档定义

B 档是“典型任务闭环”：一个实训只要求完成该类任务的 2–3 个关键动作，并保留至少一个成功状态和一个失败状态验证。它既是课堂达标线，也是新的及格线。

每个 B 档实训必须写清四个字段：

| 字段 | 内容 |
| --- | --- |
| 主任务 | 2–3 个关键动作，围绕一个典型任务闭环 |
| 验证任务 | ≥1 个成功状态 + ≥1 个失败状态（400/401/403/404/422 中至少一种） |
| 课堂主动概念 | ≤2 个，要求理解并能解释 |
| 模板接触/演示概念 | 其余概念，只要求会照写、会验证，不推导机制 |

## 二、B 档效力

B 档成为新及格线后：

1. 课程计划阶段成果考核条目按 B 档交付物评分。
2. 教材章末实训验收表分两栏：**课堂达标（B 档）**和**完整达成（教师版）**。
3. 验证记录分两栏：B 档冒烟验证、教师完整版回归证据。
4. 教师 `项目/` 保留为教师参考，不再是学生必做标准。
5. 接口契约事实源不变；B 档只缩小课堂必做子集，不改路径、字段、状态码语义。

## 三、六段式学员指南模板

每个新建学员手册的 `分步实现指南.md` 按以下六段写：

1. **本步目标**：一句话，做完能看到什么。
2. **先看效果**：先运行/看响应，再读代码。
3. **语法卡片**：只讲本步出现的语法，不展开语言全貌。
4. **代码与逐行解释**：完整代码片段 + “在做什么 / 为什么需要”表。
5. **操作与检查点**：bash 命令为主、PowerShell 对照；2–4 项可观察结果。
6. **常见错误与求助**：现象 → 先查什么 → 怎么改；卡住时先做哪三件事。

代码块内只用英文半角标点；中文弯引号、全角括号只出现在正文。

## 四、节奏建议

- 4 学时：语法/操作 45 分钟 → 跟做主任务 70 分钟 → 验证与错误分支 35 分钟 → 排错与提交 30 分钟。
- 2 学时：语法/操作 20 分钟 → 跟做主任务 35 分钟 → 验证 20 分钟 → 排错提交 15 分钟。
- 13-1、20-1 等交付/联调实训保留自定义时间表；教材章末和教师 README 可保留原表，但须标明 B 档课堂口径。

## 五、snapshot-b 目录规则

为 5-1～20-1 每节新建：

```text
实训工程参考/实训N-1/snapshot-b/
├── B档说明.md                 # 本节 B 档产物清单、上一节承接点、启动/验证命令
└── （B 档达标产物源码，不含 venv/数据库/缓存/.env）
```

规则：

- 内容等于**上一实训的 B 档达标产物加本节 B 档增量**，不是现有完整版 `项目/`。
- 12-1 快照：2 条测试 + 1 处改坏记录；19-1 快照：三个指标 + 两张图 + 基本组合。
- 每节接缝表加“学生 B 档产物如何接入”“教师 B 档快照如何接入”两列。
- 若学生产物不完整，教师直接给 `snapshot-b/`，保证本节可开始。

## 六、验证记录两栏模板

每节 `验证记录.md` 顶部写：

```markdown
## B 档验证（课堂达标）

| 项 | 命令/操作 | 预期 | 实际 | 结论 |
| --- | --- | --- | --- | --- |

## 教师完整版回归证据

| 项 | 命令 | 原有结果 | 说明 |
| --- | --- | --- | --- |
```

学生 B 档不写教师完整版的 13/23/33/119/144 等测试数字；这些数字只放在第二栏。

## 七、被删内容落点登记

B 档把部分完整能力移出课堂必做，但 `docs/各个专题基本内容.md` 的重点/难点不能消失。每项至少落在“B 档必做”或“教师演示”之一：

| 基本内容条目 | B 档落点 | 教学处理 |
| --- | --- | --- |
| 分页、过滤与排序；通用查询复用 | 7-1 department 过滤 + 固定排序 | 课堂必做；personnel 作第二模块教师演示 |
| 用户角色与授权、权限校验、权限管理 | 9-1 管理员依赖 + 一个写接口 403 | 课堂最小权限；列表/改角色/禁用为教师演示 |
| 批量数据处理、事务边界与异常处理 | 10-1 一条重叠规则；13-1 一处事务收拢 | 课堂各做一处；批量入口为教师演示 |
| 测试路径与用例设计 | 12-1 成功 + 异常 + 一次改坏 | 课堂 2 条；边界与三处改坏为教师演示/课后 |
| 统一错误处理、联调排错与交付验收 | 20-1 6 步路径 + 一个错误映射 + 交付清单 | 课堂代表闭环；十步路径为教师完整版 |
| 数据提交与回填、数据删除与反馈 | 18-1 单位页新增 + 编辑 + 删除反馈 | 课堂一个页面；其他模块用教师快照提供 |

每批实施结束逐项核对；若某重点/难点既不在必做也不在教师演示，必须补进该批设计。
