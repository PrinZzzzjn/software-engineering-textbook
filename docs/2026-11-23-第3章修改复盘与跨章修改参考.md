## 一、这一轮改了什么

### 1.1 3.1 接口与契约：只讲接口，不讲框架

**改前**：3.1 在定义接口与契约之后，提前列出 FastAPI 的路由、输入模型、异常处理、依赖注入，并讨论“契约是应然、代码是实然”和契约存放位置。

**改后**：

- 3.1 只说明三层部署、接口是什么、契约是什么、契约至少写清哪五件事。
- 五件事收敛为：调用方式、请求数据、成功响应、失败响应、兼容方式。
- 删除全书不再出现的词：cookie、业务错误码、可重试、版本策略、迁移周期、schema。
- 删除法律免责长句，改为“联调出现分歧时，对照契约判断谁偏离了约定”。
- 把“契约与代码不一致”和“契约存放位置”移到 3.3.2 的 `/docs` 之后，因为那里才有代码与文档的具体对照。
- 3.1 末尾只保留一句过渡：先看清一次 HTTP 请求与响应里有哪些部分。

**可复用点**：概念章不要提前替后文讲机制；定义段只保留本章会用到、后文会兑现的词。

### 1.2 3.2 请求与响应：从“八个小标题”改为“两个主部分”

**改前**：3.2 一度有 3.2.1 请求行、3.2.2 请求头、3.2.3 请求体、3.2.4 状态行、3.2.5 响应头、3.2.6 响应体、3.2.7 数据位置、3.2.8 消息骨架，每个小节只有一两段，标题比内容多。

**改后**：

- 3.2.1 请求：请求行（含 HTTP 方法表、安全与幂等）、请求目标、请求头、请求体、数据位置。
- 3.2.2 响应：状态行与状态码、响应头、响应体。
- 末尾不设“消息骨架”小节，改成一段收束与一张“请求 / 响应各由三部分组成”的表。
- 编号只给“请求”和“响应”两个主结构；元素降为粗体标签，既有路标又不制造薄小节。

**可复用点**：一级编号对应读者要记住的主线；元素级内容用粗体 run-in 标签，不要每个元素都开一个编号小节。

### 1.3 3.3 与 3.4 合并：机制与应用放在同一节

**改前**：3.3 讲 FastAPI 与路由，3.4 讲一个资源的四个 HTTP 方法；路由机制和五个端点分成两节，读者先学机制、再迁移，中间有一次跳转。

**改后**：

- 合并为 3.3 FastAPI 与接口实现。
- 3.3.1 框架替开发者做了什么。
- 3.3.2 启动应用与 `/docs`（含契约与 `/docs` 的差异）。
- 3.3.3 装饰器与 APIRouter。
- 3.3.4 五个端点的实现：代码拆成“查询与新增”“修改与删除”两块；五个端点表、请求/结果对照表、400 与 422 的过渡、参数位置、幂等性都在这一节。
- 方法表、状态码表、请求头表、数据位置表移到 3.2；3.3.4 只保留“在端点上怎么用”的一句话引用。
- 删除 3.3.5 同步端点与异步端点：本章示例全用 `def`，异步不在本章主线上。

**可复用点**：机制节与应用节共享同一组概念时，合并为一节；机制讲完立刻落到例子，不要让读者跨节搬运。

### 1.4 3.5 与 3.6 合并：模型与错误放在同一节

**改前**：3.5 输入与输出模型，3.6 规则性失败。

**改后**：

- 合并为 3.4 输入、输出与规则性失败。
- 3.4.1 用 Pydantic 声明输入。
- 3.4.2 输入与输出要分开。
- 3.4.3 规则性失败：`HTTPException`、422/400/404 分工、失败责任表。
- 原 3.6 不再单独设节。

**可复用点**：错误处理的讲法依赖模型（422 由模型产生），模型与错误应同节；单独一节“规则性失败”会把 422 与 400 的对照拆散。

### 1.5 术语统一：一词一义

本章统一了四组词：

| 统一后 | 清除的写法 |
| --- | --- |
| 请求体、响应体 | 正文、返回体 |
| 请求头、响应头 | 头部 |
| HTTP 方法 | 单独写“方法” |
| 请求数据的位置 | 路径参数、查询参数、请求头、请求体四类固定说法 |

同步范围：章内正文、表格、课堂活动、实训、本章小结、`98-参考答案.md`、`术语表.md`。术语表新增“HTTP 方法”词条，并把“接口”“接口契约”“RESTful”“路由”定义中的“方法”改为“HTTP 方法”；“请求头”首次出现章节由第 8 章改为第 3 章。

**可复用点**：改一章的术语时，至少同步“章内正文、例题答案、术语表、跨章引用”四处；只在正文改，答案与术语表会留下旧词。

### 1.6 交叉引用：改号后全库对账

本轮因合并与重排，章内与跨章的节号、代码号都变了。实际更新的文件：

- 章内：例 3-4、课堂活动、实训 3-1、本章小结、自检中的旧指向。
- 跨章：04、05、06、08、09、10、12、13、16、00-教材设计、术语表。
- 代码号：原 3-4-1 改为 3-3-5；原 3-5-x 改为 3-4-x；原 3-6-1 改为 3-4-6；例 3-4 的代码改为 3-4-7，避免与 3.4 节代码重号。
- 例题 3-1 的状态行从 `200 OK` 改为 `HTTP/1.1 200 OK`，答案改为“状态码为 200（状态短语 OK）”。

**可复用点**：任何节号变化后，至少 grep 四类字符串：`第 N 章 X.Y`、`见 X.Y`、`代码 N-X-Y`、`X.Y 的示例/写法`。

### 1.7 实训 3-1：从零开始，一步一个端点

**改前**：starter 已给列表与字典，学生一次补四个端点；POST 与 PUT 挤在同一步。

**改后**：

- 从空目录开始，第 1 步自己写 `app` 与 `GET /health`。
- 第 2 步先返回写死列表，再改为 `DEPARTMENTS` 字典。
- 第 3–6 步依次补详情、新增、修改、删除。
- 第 7 步走完整链路、填状态码记录表、写幂等说明。
- 第 8 步重启复核与提交。
- 必做仍是五个端点；`/health` 只作第 1 步的练习端点，不计入资源端点验收。
- 参考工程同步：starter 改为空白起点；项目加 `/health`；测试 11 项；分步指南改为阶段 0–7；README、难度评分、学员版差异说明、接缝表、验证记录全部同步。

**可复用点**：实训改造优先降“起点”和“步子”，不一定降“最终目标”；每一步都要能在 `/docs` 验证，最后一步才收口提交。

## 二、可复用于其他章节的修改原则

### 原则 1：标题用正式名词短语

- 避免“一个资源的五个端点”这类口语化标题；改为“接口实现”“五个端点的实现”“数据位置”等。
- 标题要能直接进目录，读者不看正文也知道这一节讲什么。

### 原则 2：编号只给主结构，元素用粗体标签

- 一节里如果元素多，先问“读者要记住的主线是什么”，编号只给主线。
- 元素级内容用 `**请求行**`、`**请求头**` 这类粗体标签，不单独开编号小节。
- 判断标准：一个小节如果只有一两段，就不该单独占一个编号。

### 原则 3：先给例子，再点结构，最后展开

- 3.2 的顺序是：完整请求/响应示例 → 三部分结构 → 逐元素说明。
- 不要先列七个组成部分再逐个定义；读者手里没有具体消息，定义会悬空。

### 原则 4：定义只保留本章会兑现的词

- 3.1 删掉 cookie、业务错误码、可重试等后文不出现的词。
- 新词要么在本章后面有落点，要么明确标“本书不展开”。
- 术语表、例题答案、跨章引用要与正文同步。

### 原则 5：机制与应用合并，模型与错误合并

- 读者需要“学完机制立刻用”的章节，合并机制节与应用节。
- 错误处理依赖模型时，把模型与错误放在同一节，保住 422/400 的对照。

### 原则 6：不服务本章主线的节，删掉或后移

- 3.3.5 同步/异步删除：本章全用 `def`，异步没有落点。
- 3.6 规则性失败并入 3.4.3：单列会把 422 与 400 拆散。
- 3.1 的“契约与代码不一致”后移到 3.3.2：那里才有 `/docs` 可对照。

### 原则 7：代码块分段要有“连续性”标注

- 3.3.4 的代码拆成两块：3-3-5 查询与新增，3-3-6 修改与删除，第二块标明“接在上一段之后”。
- 如果章节规范要求每个代码块可独立运行，就合回一块；分段是阅读优化，不是硬规则。

### 原则 8：实训从零、一步一端点、每步可验证

- starter 只给空白起点与依赖，不预写应用。
- 第一步先写最小应用与 `/health`，让学生练习“应用怎么起来”。
- 数据从静态列表过渡到字典，先看到响应，再理解数据结构。
- 五个端点分步补，每步在 `/docs` 验证；最后一步才填记录表与提交。
- 参考工程、测试、指南、README、难度评分、差异说明、接缝表、验证记录要一起改。

### 原则 9：改完必须做三类验证

1. **结构验证**：标题层级、代码块围栏数、章内引用、跨章引用。
2. **行为验证**：自动测试 + 真实服务请求；记录实际状态码与响应体。
3. **文本验证**：指南最终代码与完成态逐字一致；术语表与答案同步。

## 七、遗留问题与下次注意

1. **原文件未同步**：`03-后端开发框架.md` 仍是旧结构，当前以 `03-后端开发框架 修改版.md` 为工作稿；定稿时需要替换原名。
