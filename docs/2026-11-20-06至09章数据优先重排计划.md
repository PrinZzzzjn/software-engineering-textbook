## 二、理由与收益

1. **依赖方向归正**：建库、表约束、CRUD、分页、查询复用是用户模块的存储前提。先建地基，用户模块从落库版起步。
2. **消除二次返工**：现方案让用户先写内存版 user（06/07）、再在 08 换成落库版；重排后 user 一步到位落库，与 `项目参考/duty-simplified/app/modules/user/model.py` 已落库的 `class User(Base)` 一致。
3. **地基范式只讲一次**（v1 表述已修正）：`database.py` 的 engine / `Session` / `Base` / `get_db` 与「六文件读写」「分页」「查询复用」在新 06/07 建立一次；`users` 表**不是地基**，它是新 08 在同一范式下建的第一张属于用户模块的表。这样既守住「先地基后上层」，又避免数据章同时讲两个业务对象、把 users 字段含义悬空两章（见第十节确认项 1）。
4. **依赖链：章号正向，机制有回头应用**（v1「没有回指的环」结论已修正）：新 06→07（复用）、07→08（在同一范式上建 users 表并接认证）、08→09（授权）、09→10（业务规则）章号上均为前向；但新 08/09 建立的权限依赖**必须回头套用到新 06/07 已经建好的数据接口上**，这是内容级回指，需按 3.1 / 3.4 / 3.5 显式交代，不能当作不存在。
