# 执勤电子年鉴案例数据管理使用说明

## 1. 事实源与生成物

- 可编辑事实源：`data/case_data.yaml`
- 运行副本：`data/case_data.json`（由命令生成，不要手改）
- 静态清单：`docs/案例数据清单_执勤电子年鉴.md`

事实源按四类数据组织：

1. `baseline`：正式种子数据，当前统一值为 D001/P001/W001 及 admin/admin123。
2. `teaching_simplified`：旧值映射，记录 D01/P01/W01 等旧写法到基线值的替换关系；旧写法不再视为可保留差异。
3. `verification`：测试与临时数据，如 alice、D404/D99、D013、手算样本；不写入 seed。
4. `frontend_demo`：15-1 前端假数据；D003–D012 仅用于该实训。

## 2. 三种修改方式

### 2.1 直接改 YAML

用编辑器打开 `data/case_data.yaml`，修改对应实体的 `fields` 或 `aliases`。保存后执行标准流程（见第 3 节）。

### 2.2 命令行

查看当前数据：

```bash
python tools/case_data.py show
```

修改单个字段：

```bash
python tools/case_data.py set baseline departments D001 address 一号营区
```

`set` 的第一个参数是数据集，第二个是实体类型，第三个是记录 ID，第四个是字段名，第五个是新值。

### 2.3 Streamlit 页面

在仓库根目录启动：

```bash
streamlit run tools/case_data_editor/app.py
```

页面左侧选择数据集，主区选择实体和记录，在表单中改字段后点“保存修改”。页面会自动生成运行副本。同步与检查区提供“生成运行副本”“检查引用”“应用到全仓”；“应用到全仓”需要先勾选确认。

## 3. 标准流程

每次修改后依次执行：

```bash
python tools/case_data.py build
python tools/case_data.py check
python tools/case_data.py diff
python tools/case_data.py apply --yes
```

含义：

1. `build`：从 YAML 生成 `data/case_data.json`。
2. `check`：扫描活动文件里的旧值；`active_unmatched` 应为 0，`history(docs)` 是历史文档计数，不计失败。
3. `diff`：预览将改哪些文件；默认只输出清单，不写盘。
4. `apply --yes`：按别名规则批量替换旧值到新值。

## 4. 例外样本

以下内容不参与自动替换：

- `hand_calc_sample_1`：第 11 章例 11-1 的 5 条手算记录（5 天、16 小时）。
- `rule_sample_overlap`：第 10 章 08:00–12:00 基准记录与冲突判断。
- `test_random_day`：第 12 章随机日期测试。
- `not_found_examples`：D404/D99 不存在反例。
- `frontend_demo` 的 D003–D012：只用于 15-1 前端假数据。

## 5. 历史文档口径

`docs/` 下的历史设计、复盘与本次替换清单保留原貌，不回改；`check` 会把它们列在 `history(docs)` 中，只作提示，不判失败。新写的说明文档一律使用统一后的 D001/P001/W001。

## 6. 工程侧说明

各含 seed 的工程 `main.py` 增加了 `_load_case_data()`，启动时从仓库 `data/case_data.json` 读取；找不到时回落到本文件已同步的内置常量。因此工程既可跟上统一数据，也能独立启动。15-1 前端的 `SEED_DEPARTMENTS` 同样读取 `frontend_demo.departments`。
