# 概念与依据登记表（3.0）

> **用途**：逐条登记教材中的定义、分类、数字、标准条款与教学安排，回答每个论断“依据是什么”。
> **口径**：能对应标准、文献或官方报告的，优先用其原义并标注；项目模板、检查清单、讲解顺序等教学装置，记为「教学安排 / 课程约定 / 教学示例」，不冒充知识分类；不能对照原文核实的，记「待核对原文」，不写「已验证」。
> **轮次**：R1（2026-11-15）从第 1 章试点；随后理论章 02、03、04、14、21，再覆盖其余章节的首现概念。
> **相关文件**：[事实核校记录_2.0.md](事实核校记录_2.0.md)（案例数字与标准版本年份的专项核对）、[审核反馈_2.0/00-修改计划_R1.md](审核反馈_2.0/00-修改计划_R1.md)（本轮方案）。

## 一、类型与状态

| 类型 | 含义 | 正文处理 |
| --- | --- | --- |
| 标准定义 | 国际标准、国家标准中的定义或条款 | 行内括注标准号；措辞与标准不一致时注明“教学归并/改写” |
| 权威文献 | 学术论文、经典著作、行业知识体系 | 行内括注“作者, 年份”；专题依据表列全 |
| 官方报告 | 事故调查委员会等官方调查报告 | 行内括注报告名与年份；数字无法核原文时标“待核对原文” |
| 工具文档 | 框架、语言、工具的官方文档 | 行内括注官方文档名；版本以书中所用为准 |
| 工程实践 | 安全规范、工程惯例与经验规则 | 括注 OWASP、12-Factor 等来源；无来源的写明“经验规则” |
| 常用术语 | 学科或行业通用术语，无单一出处 | 正文写“通常称为……”，不冒充标准定义 |
| 课程定义 | 本课程为教学引入的工作定义 | 正文写“本课程用……指”，首次出现解释一次 |
| 课程约定 | 项目模板、字段命名、返回结构、检查清单 | 正文写“本课程约定”“本课程的项目模板” |
| 教学安排 | 讲解顺序、步骤拆解、练习设计 | 正文写“本章按……”“按……步骤”，不称为分类或框架 |
| 教学检查项 | 面向读者的检查清单 | 正文写“逐条检查以下……”，不冒充标准条款 |
| 教学建议 | 选择启发式、经验建议 | 正文写“一个够用的起点是”“通常……” |
| 教学示例 | 示例工程、示例数据、示例目录 | 正文写“本章示例”，不作为通用结论 |

| 状态 | 含义 |
| --- | --- |
| 已标注 | 正文已按上述体例处理，来源可追溯 |
| 待核对原文 | 来源名称可确认，具体表述/数字/译法须付印前按原文复核 |
| 待补 | 尚未处理，留待对应阶段 |
