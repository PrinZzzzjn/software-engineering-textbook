# 06–07 章认证与授权简化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把第 6、7 章压缩为“登录闭环”与“授权闭环”两段最小实践，并同步全书引用。

**Architecture:** 第 6 章只做认证（注册、登录、令牌、`/me`），第 7 章只做授权与最小账号管理（管理员依赖、列表、改角色/启停）；登录并入 user 模块，取消 `auth/` 与 `crud.py`，依赖函数集中到 `app/core/security.py`。先建可运行验证工程锁定代码事实，再据其重写正文，最后统一改交叉引用并跑校验。

**Tech Stack:** FastAPI、SQLAlchemy、Pydantic、python-jose、passlib、FastAPI TestClient。

**Spec:** `docs/2026-11-16-06-07章认证授权简化设计.md`

## Global Constraints

- 章内带序号的二级标题只能是 `## 6.1`–`## 6.4`、`## 7.1`–`## 7.4`，连续无跳号；「示范例题」「独立习题」「本章小结」不带编号。
- 每章 4 条学习目标、≥2 道独立习题；例题标题为 `#### 例 6-1`，习题为 `#### 习题 6-1`。
- 代码块标题格式：`**代码 6-1-1** · \`路径\`（说明，Python）`；每个代码块只对应一个文件。
- 登录路径统一为 `POST /api/v1/users/login`；不再出现 `auth/login` 或 `modules/auth`。
- 不新增模块与分层：代码只落在 `app/core/security.py`、`app/modules/user/` 四文件、`app/scripts/create_admin.py`。
- 语体按 03–05 章口径：规范书面语，不用“你/我们/大家”，长句拆到 40 字内，不用比喻与口语。
- 正文不出现校验脚本敏感词：`已验证`、`核验记录`、`实际输出`、`运行命令`、`✅`。
- 提交由作者决定；本计划不自动执行 `git commit`。

  - `scripts/create_admin.py`：`create_admin(username="admin", password="admin123") -> None`。

- [ ] **Step 1: 建目录与 `database.py`**

复制第 5 章 `database.py`，仅把 `DATABASE_URL` 改为 `"sqlite:///./verify_user.db"`；其余（`engine`、`SessionLocal`、`Base`、`get_db`）不改。

- [ ] **Step 2: 写 `security.py`**

按 Interfaces 写六个函数。要点：三项配置用 `os.getenv` 带回退值；`oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/v1/users/login")`；`get_current_user` 中 `sub` 缺失或解析失败返回 401，返回的 `id` 用 `int(payload["sub"])`；管理员依赖在 `role != "admin"` 时返回 403。

- [ ] **Step 3: 写 `model.py`、`schema.py`**

`User` 与第 6 章现有模型一致，`role` 默认 `"normal"`、`is_active` 默认 `1`。`UserCreate` 只收 `username`（3–100）与 `password`（6–50），不含 `role`。

- [ ] **Step 4: 写 `service.py`**

- `create_user`：按用户名查重，重复抛 `HTTPException(400, "用户名已存在")`；`get_password_hash` 后入库，`db.commit()`、`db.refresh()`。
- `login`：查用户 → `verify_password` 失败抛 401“用户名或密码错误” → `is_active` 为 0 抛 401“账号已禁用” → `create_access_token({"sub": str(user.id), "role": user.role})`，返回 `{"access_token": token, "token_type": "bearer"}`。
- `list_users`：`order_by(User.id).limit(50)`，返回 `{"items": [...], "count": n}`，字段为 `id`、`username`、`role`、`is_active`。
- `update_user`：先查用户（不存在 404），再判断 `current_user["id"] == user_id and data.is_active == 0`（400“不能禁用自己”），最后按传入字段更新并提交。

- [ ] **Step 5: 写 `controller.py` 与 `main.py`**

`controller.py`：`APIRouter(prefix="/users", tags=["用户"])`；注册 `@router.post("/", response_model=UserOut, status_code=201)`；登录 `@router.post("/login", response_model=TokenOut)`；`@router.get("/me")`；列表 `@router.get("/", dependencies=[Depends(get_current_admin_user)])`；修改 `@router.put("/{user_id}")` 参数带 `current_user: dict = Depends(get_current_admin_user)`。

`main.py`：创建 `FastAPI` 应用、`/health`、`include_router(user_controller.router, prefix="/api/v1")`、`from app.modules.user import model  # noqa: F401`、`Base.metadata.create_all(bind=engine)`。

- [ ] **Step 6: 写 `scripts/create_admin.py`**

`create_admin()` 打开 `SessionLocal`，按用户名查重，不存在则写入 `role="admin"` 与 `get_password_hash(password)`；`finally` 关闭会话。文件末尾 `if __name__ == "__main__": create_admin()`。

- [ ] **Step 7: 写回归脚本 `docs/_验证/run_user_module_test.py`**

脚本先删除同目录验证工程的 `verify_user.db`，再 `sys.path` 插入该目录、导入 `main` 与 `create_admin`，按下列断言逐条 `PASS/FAIL` 打印，末行输出 `n/n PASS`，有失败则 `sys.exit(1)`：
