## 一、现状诊断

核查范围：04 / 05 / 06 / 07 章全文、M02 v1.23、`00-教材设计.md`、`98-参考答案.md`、`tools/common.py`、`tools/rollout_style.py`、duty 的 `dept/controller.py` 与 `dept/crud.py`。共六处结构性问题。

1. **三章不是一条链**。第 4 章讲接口契约（抽象约定），第 5 章列「四件机制 + 8 张卡」（零件清单），第 6 章讲需求→对象→表→模块→接口→分层的翻译链（通用软件设计）。学完三章，学生仍答不出「一次请求进到 duty 工程，依次经过哪几个文件、每个文件负责什么」。
2. **第 5 章在制度上自废武功**。章首写「不要求一次学完」「跳过不影响后续章节」，5.1.5 整节 ◇ 选读，8 张卡全 ◇ 选读，末尾完整最小工程 ◇ 选读；但 07 / 08 / 09 / 15 章的节首信息条与前置知识卡都把 K-03 / K-04 / K-05 / K-06 / K-08 当作已掌握的前置来引用。**被声明为可跳过的内容，后面却按已掌握复用**——铺垫在体例上就不成立。这正是用户「直接和正课一样对待」要修的根。
3. **目录三套，第 7 章另起炉灶**。第 5 章最小工程是平铺的 `schemas.py` / `deps.py` / `main.py`；第 6 章讲 controller / service / crud / model 四层；第 7 章 7.1.1 却明确「**本书从本章起统一使用下面这套教学工程结构**」：`app/core/` / `app/routers/` / `app/schemas/` / `app/models/`。学生照第 5 章敲出的框架，到第 7 章被推翻重来。
