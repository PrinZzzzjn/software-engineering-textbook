# 教材写法诊断规则·上册：章节骨架

> 日期：2026-11-24
> 用途：按第 3、4 章的调整记录，提炼章节骨架层面的诊断问题与全书规则。
> 配套：下册《教材写法诊断规则-下册-行文》负责段落、句式和模板段的写法。
> 依据：`docs/2026-11-23-第3章修改复盘与跨章修改参考.md`（第 3、4 章改前/改后与说明），以及对 01–24 章二级标题、代码密度和三级标题的抽样核查。

## 一、上册管什么

骨架指读者翻目录时能看到、合上书后能回忆的结构：章首问题与学习目标、二级/三级标题的切分、正文机制与应用的先后、概念之间的分合、正文与实训的代码分配、跨章分工、例题和习题的布局。

**骨架层面的终极判定问题**：读者沿着这条路线走一遍，能不能从上一章停下的地方走到本章要解决的问题，并在章末得到可核对的产物？

不能，就先改骨架，不要先润色句子。

**注意**：节数多或少、代码块多或少本身不是错误。只有当它们让主线断裂、重复或失衡时才是问题。

### 2.2 三级标题：全书统一采用节内小标题制度

口径以 `docs/unuesd/三级标题规范_2.0_草案.md`（v2）与 `docs/unuesd/三级标题清单_2.0.md` 为准：全书 1–24 章统一使用 `## x.y` 下的三级/节内小标题，**没有的地方按判据补充一点**；不是每节都设，也不追求章与章条数一致。

**立标题的判据**（前两个都通过才立）：

- **T1 对象或范围换了**：换了对象、范围、阶段或要回答的问题；
- **T2 读者会跳读**：读者可能只想看其中一块，标题能让他直接定位；
- **T3 各有结论**：相邻两块各自给出结论或可执行结果，而不是同一条论证的上下句。

**不立标题**：同一论证链（现象→原因→修正，命令→参数→输出，定义→例子→边界）；只为篇幅切分；反例、提示、代码说明；节开头第一段。

**数量**：常规 `##` 小节 0–3 个；并列结构（逐文件、逐步骤、逐类型）≤5 个。一章总量约为二级节数的 1.5 倍，超出说明按篇幅切了。

**命名**：名词短语或紧凑内容短语，4–16 字，同节内结构平行；具体可指认；不用概括后缀词（职责、构成、契约、约束、边界、机制、模型、体系、适用、定位、取舍、维度、原则）；不用疑问句、人称、箭头、完整句、反引号。

**编号与呈现**：编号 `x.y.N`，随所在二级节递增，换节从 1 重数；不进目录、不被跨章回指；跨章引用仍指向 `## x.y` 层。正文 Markdown 可用 `### x.y.N 标题` 呈现，转换脚本生成最终编号。

**补充方式**：先做“现有 / 应删 / 应增 / 应改名”对照表，按样张（`docs/unuesd/三级标题样张_第09章.md`、`docs/unuesd/三级标题样张_第16章.md`）确认后再动正文。14–24 章中现有的 `### 一、…` 式标题按 v2 口径重划为 `x.y.N`。

## 三、全书骨架诊断流程（按顺序执行）

### 步骤 1：画本章路线

写出四个句子：上一章止步于哪一步；本章接手什么问题；本章产出的可核对物是什么；下一章为什么接手下一步。写不出，就先解决章首或章末，不进入细分。

### 步骤 2：列出二级标题，逐节问三个问题

1. 这一节回答本章问题中的哪一部分？
2. 删掉它，本章路线会断在哪里？如果不断，它是否属于其他章或实训？
3. 它和相邻章是否讲同一层内容？若是，本章应抽象成规则/模板，还是上一章应下沉为实例？

### 步骤 3：检查节的粒度与顺序

- 元素堆叠成多个薄节 → 合并为一条主线，元素降为粗体标签（S2）。
- 机制与应用分在两节、读者需要跨节搬运 → 合并（S3）。
- 多个概念互相纠缠 → 分节讲清边界后加对照表（S5）。
- 先给结构后给问题 → 改为“变化场景 → 结构 → 术语”（S7）。
- 先给反例或先列元素定义 → 改为“完整例子/规范 → 结构 → 展开”（S10）。

### 步骤 4：检查详略与落点

- 正文与实训是否重复同一份完整代码？正文只留核心片段（S8）。
- 每节定义的词，本章后面是否兑现？没有落点的定义删掉或后移（S9）。
- 章末落点是代码/项目/可核对记录，还是又写一篇与需求文档相似的文档？（S1）

### 步骤 5：跨章对账

按章节号变化同步四类字符串：`第 N 章 X.Y`、`见 X.Y`、`代码 N-X-Y`、`X.Y 的示例/写法`；同步范围至少包括正文、习题答案、术语表、`00-教材设计.md` 和实训手册（S11）。

## 五、章节骨架检查表

### A. 章首与落点

- [ ] 章首是否准确说明上一章完成到哪一步、止步于哪里？
- [ ] 问题句是否指向本章产物，而非另一份文档？
- [ ] 学完本章，学生手上多出什么可运行/可核对的东西？

### B. 标题与主结构

- [ ] 每个二级标题是否回答本章问题的一部分？
- [ ] 是否有只有一两段、删掉不断主线的薄节？
- [ ] 编号是否只给主结构，节内是否按 T1/T2/T3 补了必要的三级标题？
- [ ] 三级标题命名是否为名词短语、无禁用词，且不在目录或跨章引用中出现？
- [ ] 标题是否为正式名词短语，能直接进目录？
- [ ] 是否按“规范 → 正例 → 反例 → 边界”或“问题 → 结构 → 展开”的次序？

### C. 分合与跨章关系

- [ ] 机制与应用是否被拆成两节，需要跨节搬运？
- [ ] 互相依赖的概念（模型/错误、对象/表/模块）是否被拆散？
- [ ] 相邻章相似内容是否已抽象为规则/模板？
- [ ] 不服务本章主线的节是否已删除或后移？

### D. 详略

- [ ] 正文代码块是否只保留说明机制的最小片段？
- [ ] 完整工程、逐步操作是否在实训手册/参考工程，而不在正文？
- [ ] 定义中的词是否本章会兑现？
- [ ] 综合应用是否独占一条主线，而不是塞在最后一节的尾部？

### E. 对账

- [ ] 节号、代码号、例题号变更后是否全库 grep？
- [ ] 术语表、`00-教材设计.md`、习题答案与跨章引用是否同步？
- [ ] 章末小结是否回扣章首问题，并说明下一章接手什么？

## 六、边界与例外

- 本册只管骨架；“编写说明腔”“连续定义”“题干泄题”等交给下册。
- 第 3、4 章的具体做法不是模板；“把机制与应用合并”“元素降粗体”等都要按本章主线判断。
- 抽样表中的观察是复查线索，不应作为“照单全改”的指令。任何改动都先回答上册的终极判定问题。
