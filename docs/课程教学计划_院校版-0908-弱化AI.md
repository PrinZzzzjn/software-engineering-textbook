## 课程概述

本课程是理解软件工程基本理论与敏捷开发方法论，掌握FastAPI后端开发、Streamlit前端构建及Docker容器化部署等主流技术技能，培塑学员经历从需求分析到系统交付完整工程链条所形成的工程化思维与规范意识，以及坚持测试先行、代码评审、持续重构的精品追求的一门实践性、应用性强的专业核心课程，具有鲜明的军事特色与工程导向，对提升学员军事信息系统分析设计、开发交付与工程化实践能力，为部队信息化建设培养软件开发后备力量具有重要支撑作用。

## 一、教学目标

### （一）总目标

通过学习，了解软件工程的基本概念和开发流程，理解敏捷开发的核心理念，掌握FastAPI后端开发、Streamlit前端开发及Docker容器化部署技术，能够独立完成军事信息管理系统的设计、开发、测试与部署，了解AI工具在软件开发中的基本作用与使用方法，养成规范编码和文档撰写的良好习惯，树立工程质量意识和团队协作精神，具备分析问题、解决问题的实践能力，达到软件工程初级开发人员的要求，为部队信息化建设和后续从事软件开发相关工作奠定坚实基础。

### （二）分目标

#### 1. 知识与技能

通过学习，了解软件工程的基本概念、软件开发生命周期及敏捷开发方法论，理解需求分析的方法与流程、数据库设计原则、RESTful API设计规范，掌握FastAPI框架的路由定义、数据验证、用户认证机制，掌握Streamlit前端组件使用和页面布局设计，掌握Docker容器化技术的基本原理与部署流程，能够独立完成从需求分析到系统部署的完整开发流程，会使用Git进行版本控制和团队协作，了解Claude等AI工具在代码生成、调试和优化中的一般用法，能阅读和理解他人编写的代码，能编写规范的技术文档和API接口文档，能结合部队实际需求进行系统分析与设计。

#### 2. 过程与方法

经历从需求调研、需求文档编写、后端API开发、前后端联调到Docker容器化部署的完整软件开发过程，体验需求分析→系统设计→编码实现→测试调试→部署上线的工程化开发流程，参与小组讨论、代码评审、需求评审等协作活动，了解AI辅助编程工具的一般使用方式，形成"先设计后编码、先测试后上线"的科学开发习惯，养成严格按规程操作、层层把关的工程作风。

#### 3. 情感态度与价值观

养成严谨细致的编码风格和文档撰写习惯，形成规范意识和工程质量意识，领悟团队协作在软件开发中的重要性，树立自主学习和持续学习的理念，具备面对技术难题不轻言放弃的坚韧品质，增强对软件开发职业的认同感和责任感，培养保密意识和安全意识（严守军事信息保密纪律、不泄露敏感数据），激发创新思维和解决实际问题的使命感，强化"科技强军、信息制胜"的责任担当。

## 二、教学设计

本课程采用"项目驱动"的教学模式，以军事信息管理系统为载体，将软件工程理论知识融入实际项目开发全过程。其中，"项目驱动"是指以一个完整军事信息系统从需求分析到部署交付的全生命周期为主线，让学员在真实的工程实践中体悟理论、掌握方法，做到"做中学、学中悟"，避免纸上谈兵。AI工具（如Claude等）在本课程中定位为**环境允许时的可选辅助手段**，由教师根据实际上课环境决定是否使用：若环境允许，可由AI承担代码生成、语法检查、调试建议等重复性工作，降低技术门槛，让学员从繁琐的编码细节中解放出来，把主要精力投入到需求分析、系统设计、工程决策和质量控制等更高层次的能力锤炼上；若环境不允许，则完全以学员自主编码与教师现场指导为主，不影响教学目标的达成。针对军队院校学员具有较强纪律执行力但软件工程实践经验不足的特点，课程以部队信息化岗位任职需求为牵引，将课堂所学知识与岗位实践能力紧密对接，形成"所学支撑任职、任职反哺所学"的良性循环。通过专题一的教师示范让学生建立工程化思维，专题二至四逐步放手让学生自主探索完成项目，教师全程提供技术支持和答疑。把课堂所学转化为任职本领，同时以岗位实景中的真实问题倒逼理论学习，实现知识掌握与能力生成的互为支撑、双向促进。

### （一）内容设计

本课程以Python全栈开发技术为主线，前导课程为Python程序设计基础，后续课程为软件开发综合实训或部队岗位实践。课程内容体系遵循软件工程全生命周期逻辑，构建四个递进式专题，形成"认知奠基→核心构建→界面呈现→交付闭环"的能力培养链条：

**专题一：软件工程基础（4学时）**，安排在课程起始阶段，解决"什么是软件工程"和"开发之前做什么"两个问题。本专题两个课次均为理论：课次一讲授软件工程的基本概念与开发过程，课次二讲授需求分析的方法与表达，使用通用案例（校园图书借阅系统）帮助学生建立完整框架。需求获取与需求文档编写并入课次二的「专题一综合实践」，在课次二内完成背景与角色分析、功能清单与优先级划分、用户故事与验收标准、非功能需求与约束，产出《duty 需求文档 v1》，作为专题二设计与开发的输入。本专题学时较少但定位关键，是从"学军思维"向"工程师思维"转变的起点。**本专题的重点在于软件工程的定义与目标、需求获取方法的理解与运用、用户故事的规范编写、功能优先级的划分方法以及需求文档的结构与编写规范，难点则在于从用户模糊表述中区分"想要的"与"需要的"，以及保证需求文档的完整性与一致性。**

**专题二：后端服务开发（38学时）**，是课程的核心主体，学时占比近半，解决"系统的核心业务逻辑与数据管理如何构建"的问题。本专题以主线项目"值班数据统计系统"（duty）的后端为对象，按"先搭骨架后完善"的节奏组织：课次3先用后端开发框架讲清 HTTP 四方法、请求响应与 FastAPI 路由，课次4–5完成软件设计与六文件最小实现，课次6起完成项目初始化、核心基础设施与数据模型，再依次实现系统用户（user，含登录认证）、部门（dept）、人员（personnel）、值班记录（duty_record）等模块，并完成两个执勤统计（查班记录作为扩展），最后通过测试、调试、重构保障代码质量。教学采用"前期自己敲、后期改脚手架"的渐进方式：user（含登录）、dept 等模式样板模块由学生对照参考实现自己编写，建立手感；personnel 之后的复杂模块转为在 duty 脚手架上"读→改→扩"，避免课时被重复劳动吃掉。模块开发中同时强调接口契约与文档一致性——例如部门接口实际是 `/api/v1/departments/`、排序参数是 `sort_order`、创建部门要求 `dept_code` 必填，这些与旧文档的差异正好作为"以代码为准"的工程训练。**本专题的重点在于路由与 HTTP 方法的定义、RESTful API 设计规范、FastAPI 项目的标准结构与搭建方式、用户信息的增删改查、统一异常处理、业务逻辑层设计、统计查询与聚合、单元测试与代码重构，难点则在于基于 JWT 的登录与令牌使用、数据校验与约束策略、分页、过滤与排序、通用 CRUD 基类的抽取与复用以及接口契约与文档一致性。**

**专题三：前端界面构建（26学时）**，在后端API就绪的基础上展开，解决"如何让用户看到和使用系统"的问题。本专题以主线项目"值班数据统计系统"（duty）为对象，由教师先提供一份 Streamlit 参考实现（登录、部门管理、数据统计三页），学生在此基础上完成前端开发与扩展。内容组织遵循"先会用再做好"的原则：先掌握基本组件和页面布局，再实现前后端数据联调，最后进行界面美化与体验优化；界面美化环节以参考实现的"基础版—美化版"对比为素材，让学生直观理解布局、配色与信息层级的作用。本专题强调前后端的衔接配合，学生需要理解后端API的接口规范，将后端数据以直观友好的方式呈现给终端用户。界面设计注重简洁高效、操作便捷，符合部队实际使用场景和操作习惯。**本专题的重点在于常用基本组件的使用、多页面应用与侧边栏导航、前后端API联调、主题配置与数据仪表盘的构建，难点则在于Streamlit的页面重跑机制、会话状态管理、页面访问守卫与登录态入口以及界面美观性与易用性的平衡。**

**专题四：软件部署与系统交付（12学时）**，是课程的收尾环节，解决"如何让系统真正运行起来"的问题。本专题以主线项目"值班数据统计系统"的后端（duty）与前端（duty_frontend）为对象，遵循"先打包后上线"的流程：先学习容器化打包技术，基于 duty 的 `Dockerfile` 与 `.dockerignore` 构建后端镜像，再为前端编写 Dockerfile 并完成前后端服务的部署配置（端口 8000/8501、`DATABASE_URL`、`SECRET_KEY`、`DUTY_API_BASE_URL` 等环境变量），最后以软件部署综合实践收尾，结合 `logs/`、`X-Process-Time` 响应头与 `/health` 健康检查排查部署问题；项目答辩与终结性考核为课程考核环节，不占80学时，于课次26之后另行安排。本专题学时虽少，但让学生体验从开发环境到生产环境的跨越，理解"代码写完不等于项目完成"的工程理念。部署环节特别强调安全配置和数据备份，强化保密意识。**本专题的重点在于 Dockerfile 的编写规范、镜像构建、前后端服务的容器化部署、部署问题排查与日志监控，难点则在于容器技术的基本原理、镜像分层与体积优化、环境变量与配置管理、网络配置与端口映射以及容器编排的基本概念。**

四个专题之间呈现严密的因果递进关系：专题一产出的需求文档，是专题二设计与开发的依据；专题二开发的后端接口，是专题三界面联调的数据来源；专题三完成的前端界面与专题二的后端服务，最终在专题四中整合交付为可运行的完整系统。从学时分配看，专题二占比最大（38学时，47.5%），因为后端开发涉及业务逻辑实现、数据管理、安全认证等核心环节，是整个系统的中枢；专题三次之（26学时，32.5%），强调将技术能力转化为用户可见的价值；专题一和专题四学时较少，分别承担奠基和收尾的角色。

### （二）教学策略

**段引：课程与学情特点。** 本课程是一门实践性、应用性强的专业核心课程，以"项目驱动"为基本模式，以军事信息管理系统为载体，贯穿从需求分析到系统交付的完整工程链条，具有鲜明的工程导向与军事特色。课程内容技术栈新（FastAPI + Streamlit + Docker）、实践课时比重大（68/80）、前后端贯通性强，要求学员不仅会写代码，更要具备工程化思维、规范意识和团队协作能力。AI工具作为环境允许时的可选辅助手段，不作为课程的必备要素。教学对象为军队院校学员，他们政治觉悟高、纪律执行力强、组织服从性好，能严格按照规程完成任务，这是教学中可以依托的宝贵品质；但普遍缺乏完整的软件工程实践经验，对"需求—设计—编码—测试—部署"全链条的真实体感不足，编码习惯参差不齐，对工程化工具（Git、测试、代码评审）的使用不够熟练，面对开放性、非确定性的工程问题容易产生畏难情绪。基于以上特点，教学策略的总体取向是：**以真实项目为战场，以工程规范为纪律，把"学军思维"转化为"工程师思维"，让学员在"做"中建立工程信心、在"战"中生成任职能力。** 所有教学方法、资源准备与考核设计均围绕这一取向展开，并始终聚焦教学目标的达成。

**一、教学方法手段——聚焦"知识与技能""过程与方法"目标的达成。**

本课程的教学方法以促进教学目标达成、提升学员工程实践能力为导向，针对不同专题内容与学员能力层级，采用分层递进、多法并举的教学策略。通过"示范—模仿—放手"的渐进式实践教学法贯穿专题二至四，在"有支架"的情况下逐步撤除支架，帮助学员跨越技术门槛、建立工程信心，实现从模仿操作到自主开发的平稳过渡；通过"需求先行、测试兜底"的工程习惯养成法强化学员规范化开发意识，纠正"重编码、轻设计"的倾向，促使其养成先设计后编码、先测试后上线的科学开发习惯；通过代码评审与结对编程的协作学习法培育团队协作能力，让学员在真实协作中体悟"代码是写给人看的"这一工程理念；通过角色扮演的需求获取法破解需求分析难点，帮助学员学会从用户模糊表述中区分"想要的"与"需要的"；通过部队技术汇报式的成果验收法强化工程交付与军事文化融合，锻炼学员的表达与沟通能力。各类教学方法均与具体教学目标相对应，协同服务于学员从"具备编码能力"向"能够独立交付完整系统"的综合能力跃升，有效提升了教学的针对性与实效性。

教学方法的选择不是为了"教得热闹"，而是为了让学员真正"学会工程化地干活"。针对不同专题、不同能力层级，采取分层递进、刚柔并济的方法组合：

**（1）"示范—模仿—放手"的渐进式实践教学法。** 这是贯穿专题二、三、四的核心方法，直接服务于"掌握技术技能、经历完整开发过程"的目标。专题二以 duty 后端为对象，user（含登录）、dept 等模式样板模块由教师先完整示范：一边讲解需求，一边现场编码，一边演示如何组织代码结构、如何用pytest编写测试；personnel之后逐步过渡到"教师给出需求与设计框架，学生在参考实现上读、改、扩"；最后完全放手，学生自主开发，教师只提供技术支持和答疑。这一节奏设计的依据是：工程能力不是听会的，是练会的，但需要在"有支架"的情况下逐步撤架，否则学员会因技术门槛而丧失信心。专题三的前端开发同样遵循"先会用再做好"的节奏：以专题三参考实现为样板，先由教师演示Streamlit组件与布局的基本用法，学生模仿完成"能跑起来"的界面；课次21再以参考实现的"基础版—美化版"对比为素材，逐步过渡到自主设计与优化。

**（2）"需求先行、测试兜底"的工程习惯养成法。** 针对学员"重编码、轻设计"的倾向，每个模块开发前强制安排"设计环节"：先写接口设计、再写数据库表结构、最后才动笔编码；开发后强制安排"测试环节"：每个模块至少编写一组单元测试，用Postman逐接口调试，教师随机抽查测试用例是否覆盖了边界情况。这一方法对应"过程与方法"目标中"形成先设计后编码、先测试后上线的科学开发习惯"的要求，也呼应专题二"代码优化与重构"环节对"测试先行"的强调。

**（3）代码评审与结对编程的协作学习法。** 对应"团队协作""代码评审"等工程实践要求，也服务于"情感态度与价值观"目标中"领悟团队协作重要性"的要求。具体做法：每完成一个模块，小组内交换代码进行评审，评审前教师给出检查清单（命名规范、注释完整性、异常处理、安全漏洞、接口一致性），学生按清单逐项检查并填写评审记录；在用户认证、数据管理等关键模块安排一次结对编程，两人一组共同完成，一人主写一人审查，角色轮换。通过这一方法，让学员在真实协作中体悟"代码是写给人看的"这一工程理念。

**（4）真实项目需求文档编写法。** 专题一前两课次以通用案例建立知识框架；课次二的「专题一综合实践」以主线项目"值班数据统计系统"（duty）为对象，小组分演"值班业务骨干"与"开发人员"完成需求获取，按需求文档模板整理背景与角色、功能清单与优先级、用户故事与验收标准、非功能需求与约束，经组间评审后落稿，形成《duty 需求文档 v1》，再对照 duty 的真实模块与接口清单校准——抓准了什么、漏了什么、多想了什么。这一方法的针对性在于：学员对业务场景熟悉但缺乏"从需求到文档"的完整训练，真实项目能让他们走完"访谈—分析—编写—评审—落稿"的链条，而对照真实实现能校准需求的颗粒度与完整性——这正是专题一标注的难点所在。

**（5）部队技术汇报式的成果验收法。** 专题四的项目答辩参照部队技术汇报的形式和要求进行：学生着装规范、PPT简洁、汇报聚焦"解决了什么问题、如何解决、质量如何保证"，评委由教师和小组代表组成，提问环节模拟部队技术论证场景。这一方法将工程交付与军事文化融合，对应"科技强军、信息制胜"的价值引领，也锻炼了学员的表达与沟通能力。

**二、教学资源——聚焦"支撑教学实施、保障目标达成"的实战化准备。**

本课程教学资源的建设遵循"够用、实用、管用"的原则，注重在各教学环节中切实发挥作用，为教学方法的实施与教学目标的达成提供必要的物质与内容支撑。教学资源的准备，系针对学员工程化能力的现实短板与教学实施的规范化需要而设：学员工程规范意识与基础能力不足，实战化工程经验也较为欠缺，同时需要为学员课后复习与进阶学习提供系统化支撑。基于此，教学资源的准备分为目的不同的两个方面。一是提供教学模板与案例素材，涵盖技术文档模板、项目模板与脚手架，以及经脱敏处理的部队业务案例素材、Postman接口测试集合与pytest测试用例等测试数据、Git内网代码仓库，由教师带领学员在教学过程中逐项填写与应用，用于案例教学、测试驱动与团队协作，旨在促使学员养成规范的文档编制习惯、降低技术门槛，弥补学员在真实业务场景与协作实践方面的经验不足，强化学员的工程规范意识与基础能力。二是提供教学文件、教材文献与在线学习资源，包括课程标准、教学大纲、课件PPT、教案与实践指导书、主教材与参考书目、军用软件工程标准与规范、技术栈官方文档与学习路径、开发环境配置指南等，旨在保障教学实施的规范化，并为学员课后复习与进阶学习提供系统化的支撑。各类资源均纳入考核评价，贯穿课程全程，切实发挥了支撑教学、服务育人、提升教学效果的作用。

**（1）教学模板与案例素材资源。** 学员文档编制的规范性不足，存在文档滞后于开发过程、质量参差不齐的突出问题，因此准备四类标准化技术文档模板：需求文档模板（含用户故事格式、MoSCoW优先级标注位）、API接口文档模板（含请求参数、响应格式、错误码说明）、数据库设计模板（含ER图绘制规范、表关系标注）、部署文档模板（含环境变量配置清单、端口映射说明、备份策略），由教师带领学员在各环节逐项填写，使学员在实践中理解"文档编制应与开发过程同步"的理念，养成规范撰写的习惯；学员对FastAPI、Streamlit、Docker等项目的标准结构缺乏了解，自行搭建环境将分散其对业务逻辑的专注，因此准备三类项目模板与脚手架（含标准目录结构、虚拟环境配置脚本、Git初始化配置、多页面应用结构、公共样式文件、Dockerfile示例与docker-compose.yml示例），降低技术门槛，引导学员将精力集中于业务逻辑与功能实现；学员虽熟悉部队业务场景，但缺乏从用户模糊表述中提炼精确需求的训练，且课程需要贴近部队实际业务场景的案例支撑以增强岗位适应性，因此围绕主线项目"值班数据统计系统"的各业务模块，收集经脱敏处理的部队实际业务场景案例素材，用于需求分析课的案例教学、界面设计课的实战化参考、课程思政中"为战育人"元素的具象化呈现；学员在测试驱动开发与团队协作方面能力不足，缺乏标准化的测试素材与协作载体，因此配备Postman接口测试集合（按模块组织，含标准请求示例与预期响应）、pytest测试用例模板和Git内网代码仓库，作为测试数据与团队协作素材，并将测试用例提交与Git提交记录纳入考核，保障"测试先行"与团队协作真正落地、可查可验。

**（2）教学文件、教材文献与在线学习资源。** 针对教学实施规范化与学员课后复习、进阶学习的需要，准备课程标准、教学大纲、各课次课件PPT、教案与实践指导书（每模块一份，含操作步骤、常见问题与调试提示），主教材与参考书目（如《敏捷软件开发：原则、模式与实践》《用户故事与敏捷方法》）、军用软件工程标准与规范（如GJB 5000A）、RESTful API设计规范，以及FastAPI、Streamlit、Docker三类技术栈的官方文档链接与学习路径、开发环境配置指南（Python、VS Code、Docker Desktop、Git）、内网代码仓库访问与使用说明，为教学实施提供标准化的教学载体，并为学员自主复习、拓展学习与环境搭建提供系统化的支撑。

**三、考核评价——聚焦"过程性、多维度、可验证"的目标达成度测量。**

本课程考核评价以教学目标达成度为核心，采用"过程性评价+终结性评价"相结合、"知识考核+能力考核+素养考核"相统一的综合评价体系，确保三维教学目标均有对应的测量方式，充分发挥评价"以评促学、以评促教"的导向作用。过程性评价与终结性评价各占总评50%：前者聚焦"过程与方法"及"情感态度与价值观"目标，引导学员重视开发过程、规范编码行为、积极参与协作，改变"只看结果、不重过程"的学习倾向；后者以**上机考试**为载体，聚焦"知识与技能"目标的综合达成，全面检验学员对软件工程理论的掌握程度与动手开发、部署交付的实际能力。此外，将保密意识、安全编码、诚信守纪等思政素养表现纳入评价，落实"质量就是生命""诚实守信"的职业底线要求。

考核评价是教学目标的"指挥棒"。本课程的考核打破"一考定终身"的传统做法，采用"过程性评价+终结性评价"相结合、"知识考核+能力考核+素养考核"相统一的综合评价体系，确保三维教学目标均有对应的测量方式。本节按**评价方式**组织——即回答"以什么形式评、由谁评、用什么载体评"，而非罗列评分细则与扣分标准，目的是让读者先理解"怎么评"，再理解"评什么"：

**（1）过程性评价方式（占总评50%），聚焦"过程与方法""情感态度与价值观"目标。**

过程性评价不以单次考试定高低，而是通过贯穿课程全程的多种日常记录与活动表现综合评定，让学员的每一份提交、每一次协作都被看见、被记录、可追溯。具体方式包括：
- **平时作业——文档评分**：以需求文档、设计文档、API接口文档、部署文档为载体，由教师按标准化模板逐项评分，重点关注需求完整性与一致性（对应专题一重难点）；
- **平时作业——Git提交记录评审**：以Git提交记录为依据，结合代码规范性、注释完整性、异常处理与测试用例覆盖率，由教师与小组互评结合，评定各模块编码与测试质量；
- **各专题阶段性成果——专题一：duty 需求文档（4%）**：以课次2提交的《duty 需求文档 v1》为载体，考查需求获取、用户故事规范编写、MoSCoW优先级划分与需求文档规范性，按文档完整性、一致性与规范性计分；
- **各专题阶段性成果——专题二：后端API开发与测试成果（10%）**：以各模块API代码、接口文档、单元测试、代码评审记录为载体，考查API设计规范、CRUD实现、测试覆盖、代码评审参与度，按功能完成度与测试覆盖度综合计分。
- **各专题阶段性成果——专题三：前后端联调与界面实现（6%）**：以课次22提交的Streamlit应用代码、联调报告与界面优化说明为载体，考查组件使用、页面布局、前后端联调与用户体验优化，按界面完整性与联调效果计分；
- **各专题阶段性成果——专题四：容器化部署与项目答辩（5%）**：以课次26提交的Dockerfile、部署文档与现场答辩为载体，考查镜像构建、服务部署、环境变量管理与表达展示，按部署可用性与答辩表现计分。

**（2）终结性评价方式（占总评50%），聚焦"知识与技能"目标的综合达成。**

终结性评价采用**上机考试**的形式，在课程末段集中进行，综合考核学员对软件工程理论的掌握程度与动手开发、部署交付的实际能力。考试分为两部分：
- **理论部分**：以闭卷或限时在线作答方式进行，考察软件工程基本概念、敏捷开发方法论、需求分析与设计方法、FastAPI/Streamlit/Docker 的基本原理与使用、RESTful API 设计规范、安全编码与保密要求等知识目标；
- **实操部分**：在限定时间内完成一个完整的开发任务（如给定需求，完成接口开发、前后端联调或容器化部署），考察编码规范、测试编写、调试排错、文档撰写与部署配置等实际工程能力。

两部分均提前公布评分量规（rubrics），使评价标准公开透明、客观可验证。

**（3）思政素养评价方式。**

将保密意识、安全编码、诚信守纪等表现纳入评价，采用**过程观察+一票否决**的方式：在需求文档、代码提交、提交记录、平时测试与上机考试等日常环节中观察学员表现，对涉密信息未脱敏、安全漏洞不处理、提交记录弄虚作假等情形，实行一票否决或大幅扣分，落实"质量就是生命""诚实守信"的职业底线要求。

**四、教学反思——聚焦"持续改进、螺旋上升"的质量闭环。**

本课程教学反思贯穿课程全程，旨在形成"设计—实施—评价—改进"的质量闭环，持续提升教学方案对目标达成的支撑度，推动教学质量螺旋上升。课程建立"三阶段反思"制度：课前反思（备课阶段）依据上一轮教学中发现的问题调整教学设计，如针对JWT认证原理理解困难增加图解演示环节、针对数据库表关系设计薄弱增设专项练习，实现教学设计的精准优化与有的放矢；课中反思（教学实施阶段）由轮值观察员学员记录典型问题与优秀做法，供教师判断教学节奏是否需要调整及是否增设辅导环节，实现教学过程的动态调控与即时纠偏；课后反思（课程结束后）通过专题教研活动系统梳理教学方法有效性、学员达标情况与资源准备不足之处，并鼓励学员通过课程反馈表提出改进建议，以发现教学中的盲点，实现教学方案的持续迭代与长效改进。三阶段反思环环相扣，使教学改进有据可依、有的放矢，有效保障了教学目标的达成与教学质量的持续提升。

教学反思不是课程结束后的"事后感想"，而是贯穿课程全程的改进机制。课程建立"三阶段反思"制度：

**课前反思（备课阶段）：** 每次课前，教师根据上一轮教学中发现的问题调整教学设计。例如：若发现学员在JWT认证模块理解困难，则在该课次增加原理图解与动画演示环节；若发现学员对数据库表关系设计普遍薄弱，则在专题二"软件设计与建模"课次增加一次专门的关系设计练习。

**课中反思（教学实施阶段）：** 每次实践课安排一名"观察员"学员（轮流担任），记录本课次中遇到的典型问题、共性错误和优秀做法，课后汇总给教师。教师据此判断"示范—模仿—放手"的节奏是否需要调整，以及是否需要增加针对性的辅导环节。

**课后反思（课程结束后）：** 课程结束时组织专题教研活动，系统梳理三个问题——哪些教学方法对目标达成最有效（如代码评审、渐进式实践）、哪些环节学员普遍达不到预期（如需求文档的一致性、部署环节的环境变量管理）、哪些资源准备不足（如特定业务场景的案例素材）。基于反思结果修订教学方案，形成"设计—实施—评价—改进"的闭环，为下一轮教学提供优化依据。同时，鼓励学员通过课程反馈表提出改进建议，学员的视角往往能发现教师忽视的盲点。

总体而言，本课程的教学策略以"让学员在真实工程实践中生成能力"为核心，以教学目标达成为唯一衡量标准——教学方法服务于"学会"，教学资源服务于"能做"，考核评价服务于"验真"，教学反思服务于"更好"。四个环节环环相扣，共同支撑学员从"会写代码的学员"成长为"能交付系统的初级软件工程师"。





### （三）课程思政

本课程秉持"立德树人"根本任务，遵循"知识传授与价值引领相统一"的教育理念，将课程思政有机融入软件工程实践全过程。课程以"科技强军、信息制胜"为核心价值引领，通过"四维融合"路径实现思政教育的入脑入心：在需求分析阶段融入"为战育人"的根本导向，引导学生理解软件系统服务于部队战斗力提升的使命感，树立正确的技术伦理观和军事信息安全意识，自觉遵守军事保密纪律；在代码开发阶段融入"精益求精"的工匠精神和"代码即战斗力"的责任意识，培养学生严谨细致的工作作风和对产品质量的敬畏之心，理解每一行代码都可能关系到部队行动的成败；在团队协作阶段融入"团结就是力量"的集体主义价值观和"令行禁止"的军人作风，通过代码评审、结对编程等活动让学生体悟分工协作、密切配合、共同完成任务的团队力量，强化号令意识和协同意识；在项目交付阶段融入"诚实守信"的军人品格和"质量就是生命"的工程伦理，强调按时交付、代码真实、数据可靠的职业底线，杜绝弄虚作假、敷衍了事。课程思政不搞"两张皮"，而是将忠诚担当、战斗精神、保密意识、科学精神等思政元素如盐入味般融入每一次需求调研、每一行代码编写、每一次团队协作之中，实现"润物细无声"的育人效果，培养既有扎实技术功底、又有过硬政治素质的新时代军事软件工程人才。

## 三、内容标准

### 专题一：软件工程基础（4学时）

#### （一）基本内容

1. 软件工程基本概念：软件工程的定义与目标；软件开发生命周期的主要阶段及其特点；敏捷开发的核心理念与常见实践框架；生命周期各阶段与真实项目活动的对应关系。
2. 需求分析方法：需求获取的常用方法及其适用场景；需求文档的结构与编写规范；用户故事的表达格式与质量原则；用户需求的识别与提炼。
3. 需求文档编写：需求调研的实施流程与组织方式；功能清单的编写要点；功能优先级的划分思路；用户故事与验收标准在项目中的编写；需求文档的组织与落稿；非功能需求与约束的描述；需求评审与文档修订。

### 专题二：后端服务开发（38学时）

### （三）考核内容与要求

#### 1. 形成性考核

形成性考核贯穿课程全程，以日常作业与各专题阶段性成果为依据，重点考查"过程与方法""情感态度与价值观"目标的达成。具体包括平时作业与各专题阶段性成果两个方面。

##### （1）平时作业（15%）

平时作业以学员日常提交的文档与代码成果为载体，由任课教师按标准化要求逐项评定，旨在强化学员规范撰写与规范编码的习惯。

**① 文档评分（15%）**
- **考核内容**：需求文档、设计文档、API接口文档、部署文档的完整性、规范性与一致性。
- **实施安排**：随堂批改，由任课教师按标准化模板逐项评分，批改后即时反馈修改意见。
- **评定标准**：优秀（90-100分）——内容完整、逻辑清晰、文档与开发同步、无遗漏；良好（80-89分）——内容基本完整、偶有细节遗漏、文档基本同步；合格（60-79分）——内容有明显缺漏或一致性问题；不合格（60分以下）——文档严重缺失或与实际开发严重脱节。

**② Git提交记录评审（10%）**
- **考核内容**：以Git提交记录为依据，考查代码规范性、注释完整性、异常处理、测试用例覆盖率与提交及时性。
- **实施安排**：课程结束前汇总，教师评阅与小组互评结合，结果计入总评。
- **评定标准**：优秀（90-100分）——代码规范、注释完整、测试覆盖全面、提交及时；良好（80-89分）——代码较规范、测试覆盖较好、偶有延迟提交；合格（60-79分）——代码有不规范处、测试覆盖不足；不合格（60分以下）——代码混乱、无测试或提交弄虚作假。

##### （2）各专题阶段性成果（15%）

各专题阶段性成果以专题教学节点为单位进行考查，旨在引导学员"章章清、节节检"，避免期末集中突击。本项按专题组织，每个专题设一项标志性成果，明确交付物、考核要点与成绩评定，总权重25%。

**① 专题一：duty 需求文档（权重4%）**
- **交付物**：《duty 需求文档 v1》（含项目背景与目标、用户角色与职责、功能清单与 MoSCoW 优先级、用户故事与验收标准、非功能需求与约束）。
- **考核要点**：需求获取的完整性、用户故事规范编写、功能优先级划分、需求文档的规范性与一致性。
- **成绩评定说明**：根据需求文档模板逐项评分，考察学员需求获取、用户故事编写、功能优先级划分与需求文档撰写的能力，按文档完整性、一致性与规范性计分。

**② 专题二：后端API开发与测试成果（权重10%）**
- **交付物**：基于 duty 主线项目的后端模块（auth、user、dept、personnel 等）与接口文档（含单元测试、代码评审记录）。
- **考核要点**：API 设计规范、CRUD 功能实现、统一异常处理、单元测试覆盖、代码评审参与度、对所做改动的解释能力。
- **成绩评定说明**：根据API设计规范与测试覆盖度综合评定，考察学员后端开发与测试能力；代码评审记录按检查清单覆盖情况计分，并抽查学员对关键改动的解释。AI工具的使用在本课程中为可选手段，不使用不扣分、不加分，也不作为考核载体；若环境允许使用，学员可自主选择是否使用，仅要求使用时遵循"逐行审查"的基本规范，不设违规扣分条款。

**③ 专题三：前后端联调与界面实现（权重6%）**
- **交付物**：基于 duty 后端的前端界面实现（含登录、部门管理、数据统计页面与前后端联调报告）。
- **考核要点**：Streamlit 组件使用、多页面组织、前后端联调、会话状态与错误处理、界面优化与体验。
- **成绩评定说明**：根据界面功能完整性、联调效果与视觉优化程度评定，考察学员前端开发与前后端协作能力，按组件使用、页面布局、联调完成度与优化效果计分。

**④ 专题四：容器化部署与项目答辩（权重5%）**
- **交付物**：duty 后端与 duty_frontend 前端的容器化部署（含 Dockerfile、部署文档与项目答辩）。
- **考核要点**：Dockerfile 规范编写、镜像构建、前后端服务部署、环境变量与日志排查、答辩表达。
- **成绩评定说明**：根据部署可用性、日志排查效果与文档规范性评定，考察学员容器化部署与工程交付能力，按部署成功度、文档完整性与答辩表现计分。

#### 2. 终结性考核

终结性考核在课程末段集中进行，综合考核学员对软件工程理论的掌握程度与动手开发、部署交付的实际能力，分为理论考试与实践操作考核两部分。

##### （1）理论考试（20%）

- **考核内容**：软件工程基本概念、敏捷开发方法论、需求分析与设计方法、FastAPI/Streamlit/Docker的基本原理与使用、RESTful API设计规范、安全编码与保密要求。
- **考核形式**：闭卷或限时在线作答，题型包括选择题、简答题、案例分析题。
- **实施安排**：统一命题、统一时间集中进行，提前公布考试范围与评分量规。
- **评定标准**：按正确率评定。优秀（90-100分）——答对率90%以上；良好（80-89分）——答对率80%以上；合格（60-79分）——答对率60%以上；不合格（60分以下）——答对率60%以下。

##### （2）实践操作考核（50%）

- **考核内容**：在限定时间内完成一个完整的开发任务（如给定需求，完成接口开发、前后端联调或容器化部署），考查编码规范、测试编写、调试排错、文档撰写与部署配置等实际工程能力。
- **考核形式**：线下机房实操，限定时间内提交代码、测试用例与部署文档。
- **实施安排**：统一命题、统一时间、统一平台，提前公布任务书与评分量规。
- **评定标准**：按功能完成度、代码质量、测试覆盖度与文档规范性综合评分。优秀（90-100分）——功能完整、代码规范、测试覆盖全面、文档齐全；良好（80-89分）——功能基本完整、代码较规范、测试覆盖较好；合格（60-79分）——功能部分完成、代码有不规范处；不合格（60分以下）——功能未完成或代码质量差。

两部分均提前公布评分量规（rubrics），使评价标准公开透明、客观可验证。

## 附录：信息化教学资源

本课程信息化教学资源的建设，遵循"服务教学、辅助实战、军网可用、安全可控"的原则，以信息技术赋能教学全过程，为学员自主学习、协作开发与工程实践提供数字化支撑。资源体系涵盖教学平台、实训环境、数字教材、评测工具与协作平台五个方面，各资源均适配军队院校内网环境，落实保密与安全要求。

### （一）在线教学平台

依托课程教学平台（内网部署），构建线上教学空间，支撑"课前预习—课中实施—课后复习"全链条教学活动。平台功能包括：
- **教学内容数字化**：各专题课件PPT、教案、实践指导书上线，支持学员课前预习与课后回看；
- **任务与作业管理**：各模块开发任务书、需求文档模板、设计文档模板在线发布与提交，支持教师在线批改与即时反馈；
- **学习过程留痕**：学员的文档提交、代码提交、测试用例提交等过程性材料全程记录，直接对接过程性考核评价，实现"可追溯、可验证"；
- **答疑互动区**：设置技术问答专区，学员可在线提问，教师与助教集中答疑，常见问题沉淀为"FAQ知识库"供后续学员查阅。

### （二）虚拟仿真实训环境

针对软件工程课程"开发环境配置复杂、实践环节受机房环境限制"的痛点，建设虚拟化实训环境：
- **一体化开发沙箱**：基于Docker容器技术构建预配置的开发环境镜像（含Python、FastAPI、Streamlit、Docker、VS Code Server等），学员通过浏览器即可一键进入开箱即用的开发环境，免除本地环境配置之苦，把精力集中于业务逻辑实现；
- **内网代码仓库**：基于Git搭建内网代码仓库，按小组划分仓库权限，集成代码规范检查、提交记录统计、分支管理等功能，支撑团队协作与过程性评价；
- **接口测试沙箱**：预置Postman接口测试集合与测试数据，支持学员在线完成接口调试与测试用例编写，测试结果自动归档。

制作与课程内容相配套的系列微课视频，作为课堂教学的延伸与补充：

- **军事信息系统案例库**：收集经脱敏处理的部队实际信息系统案例（装备管理、人员管理、训练计划管理、物资管理等），以图文、演示视频等形式呈现，用于需求分析课的案例教学与课程思政的具象化呈现。

### （四）在线题库与评测系统

建设支撑过程性评价与终结性考核的数字化评测工具：

- **错题集与个性化反馈**：系统自动记录学员的错题与薄弱环节，生成个性化学习建议，引导学员"章章清、节节检"，避免期末集中突击。

- **微学习卡片**：将核心知识点、编码规范、常见调试技巧等整理为图文并茂的"学习卡片"，支持手机端随时查阅与分享；
- **离线资源包**：将课件PPT、微课视频、技术文档等打包为离线资源，供学员在无网络环境下学习，保障学习不掉线。

### （七）官方技术文档与权威在线资源

将各技术栈的官方文档与权威在线学习资源纳入信息化教学资源体系，作为学员自主学习与教师课堂教学的重要支撑。官方文档具有内容权威、更新及时、示例规范的特点，是培养学员"阅读第一手资料"习惯的最佳载体。具体包括：

- **FastAPI官方文档**（https://fastapi.tiangolo.com/）：涵盖路由定义、数据验证、依赖注入、JWT认证、自动生成交互式API文档（Swagger UI）等全部核心特性，是后端开发学习的首选权威资料，教学中引导学员直接阅读官方文档而非二手教程；
- **Streamlit官方文档**（https://docs.streamlit.io/）：包含全部内置组件的用法说明、多页面应用组织、会话状态管理、部署指南等，是前端界面开发的权威参考，配套官方示例代码供学员模仿与拓展；
- **Docker官方文档**（https://docs.docker.com/）：涵盖容器与镜像核心概念、Dockerfile编写规范、镜像构建与优化、Docker Compose多容器编排、部署与运维等，是容器化部署环节的核心学习资料；
- **Python官方文档**（https://docs.python.org/zh-cn/3/）：Python标准库与语言基础的权威参考，配合官方教程帮助学员夯实语言基础；
- **Git官方文档与Pro Git在线书籍**：Git版本控制与分支策略的权威学习资料，支撑团队协作开发环节；
- **RESTful API设计规范与行业权威指南**：作为API设计环节的规范化参考，帮助学员掌握通用接口设计约定；
- **军用软件工程标准与规范**（如GJB 5000A《军用软件开发通用要求》）：军事软件工程领域的权威标准文件，用于课程思政与工程规范教学，强化学员的军标意识与保密要求。

上述官方与权威在线资源与内网教学平台资源互为补充，既保障教学实施的规范化，又为学员课后复习、拓展学习与自主探究提供系统化的第一手资料支撑，培养学员查阅权威文档、终身学习的工程素养。

以上信息化教学资源与课程教学内容、教学方法、考核评价有机融合，贯穿课程全程，切实发挥"支撑教学、服务育人、提升效果"的作用，为学员从"会写代码的学员"成长为"能交付系统的初级软件工程师"提供坚实的数字化支撑。
