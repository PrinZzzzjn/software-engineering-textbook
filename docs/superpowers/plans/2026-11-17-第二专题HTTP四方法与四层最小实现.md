# 第二专题前期改造实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.
> **本项目的执行方式**：作者已指定按计划直接实施，由本会话逐任务执行。提交由作者决定，本计划不自动执行 `git commit`。

**Goal:** 把 HTTP 四方法最小实践与 FastAPI 六文件最小实现前置到第 3、4 章，并让第 5–8 章沿用同一副六文件骨架。

**Architecture:** 第 3 章用单文件内存应用讲四方法与状态码；第 4 章把同一组接口拆成六文件并讲 `Depends`；第 5 章在六文件上做工程化；第 6 章只替换 `model.py` 与 `crud.py`；第 8 章补齐数据库版删除接口；第 13 章两个实训合并为一个。

**Tech Stack:** FastAPI、Pydantic、uvicorn、pytest、FastAPI TestClient；不引入 ORM 以外的库。

**Spec:** `docs/2026-11-17-第二专题HTTP四方法与四层最小实现改造计划.md`

## Global Constraints

- 24 章、80 学时（理论 12 / 实践 68）、26 课次、专题二 38 学时均不变。
- 第 3 章 = 课次 3 · 4 学时（2 理论 + 2 实践）；第 13 章 = 课次 14–15 · 4 学时，一个实训块。
- 案例统一为部门 `dept`，字段 `dept_code` / `full_name` / `address`，主键 `dept_code`；第 3 章的 `dept_name` 全部改为 `full_name`。
- 章内带序号的二级标题只能是 `## N.1`–`## N.k`，连续无跳号；「示范例题」「独立习题」「本章小结」不带编号。
- 每章学习目标不少于 4 条，条间不得重复；示范例题标题为 `#### 例 N-M`，独立习题为 `#### 习题 N-M`。
- 代码块标题格式：`**代码 N-M-K** · \`路径\`（说明，语言）`；每个代码块只对应一个文件。
- 正文用规范书面语，不用"你/我们/大家"，长句拆到 40 字内，不用比喻与口语。
- 正文不出现校验脚本敏感词：`已验证`、`核验记录`、`实际输出`、`运行命令`、`✅`（代码图标白名单除外）。
- 独立习题答案写入 `98-参考答案.md`；章内只留题干。
- 每个任务结束运行对应校验命令；最后统一运行 `python tools/run_all.py`。
- 不自动执行 `git commit`。

## Review Focus

- 3.4 用手写字段检查（非法输入返回 400）过渡到 3.5 的 Pydantic（非法输入返回 422），两节状态码口径必须写清，不得让 400 成为输入校验的正式口径。
- DELETE 成功返回 204、重复删除返回 404，第 3、4、8 章三处必须一致，且 204 不得带响应体。
- 内存版与数据库版的 URL、方法、状态码、字段名必须逐项一致；换实现只改内部签名。
- 第 5 章"用到才建"表与第 6 章实际新建的文件必须对齐，不得再把 `model.py`、`service.py` 推到第 8 章。
- 第 13 章合并后只有一个实训块，4 学时的时间分配与 5 项验收必须能逐项判定。
