# 教材样书排版与 PDF 合订 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `软件工程实践-2.0/` 的 24 章正文排成一本 A4 送审样书 PDF，并同时产出 26 份分章 PDF。

**Architecture:** `markdown-it-py` 把每章 Markdown 转成 Typst 标记（自写转换器，逐条控制非标准写法），`style.typ` 承载全部版式参数，`build.py` 装配封面/前言/目录/正文/附录后调用 Typst 二进制一次编译出合订本；mermaid 图由 mermaid-cli 驱动本机 Edge 预渲染成 SVG，按内容哈希缓存。

**Tech Stack:** Python 3.12、markdown-it-py、pytest、pypdf；Typst 0.15.1（`build/pdf-toolchain/bin/typst-x86_64-pc-windows-msvc/typst.exe`）；`@mermaid-js/mermaid-cli`（`build/pdf-toolchain/node_modules/.bin/mmdc`）+ Edge。

**Spec:** `docs/superpowers/specs/2026-11-18-教材样书排版-design.md`

## Global Constraints

- 开本 A4 210×297；页边距 上 25 / 下 25 / 订口 30 / 切口 22 mm；双面镜像版心（`binding: left`）。
- 正文 宋体 `SimSun` 10.5 pt，行距约 1.6，首行缩进 2 字符，两端对齐；西文与数字 `Times New Roman`。
- 标题 `SimHei`：章 22 pt 居中；二级 15 pt；三级 12 pt；四级 10.5 pt 加粗。
- 代码 `Consolas` 8.5 pt，底色 `#F6F6F6`，左竖线 1.5 pt；单行超过 95 列软换行（续行缩进 2 字符 + `↩`）。
- 图题注在图下 9 pt 居中，格式沿用原文 `图 4-1：…`；表为三线表，表内 9 pt。
- 页码：卷首罗马 i, ii, …；正文阿拉伯从 1 起；封面无页眉页码。
- 页眉：偶数页书名，奇数页当前章名，下加 0.5 pt 细线。
- 图与题注、代码块不跨页；表跨页时表头重复。
- 输出目录固定为仓库根下 `样书/`，构建中间件在 `build/print/`。
- 不改正文文字；仅省略 `00-前言.md` 的「## 目录」一节与两处编者提示（见 Spec「卷首的两处编辑处理」）。

## Review Focus

- **长代码行**：全文最长 121 列，若某块溢出到版心外或把页边距撑破，读者看到的是被裁掉的代码——软换行必须对每个代码块生效，而不只是超长的那几块。
- **mermaid SVG 的 `foreignObject`**：若关闭 `htmlLabels` 失败，Typst 会整块丢图，读者看到的是空白和悬空的题注——渲染后必须校验 SVG 里无 `foreignObject`。
- **`#### 例 13-1` 这类跳级标题**：挂在 `## 示范例题` 下（h2 → h4），若按层级相加映射就会排成章级标题，把整本书的目录撑坏——按 Markdown 层级原样映射，不做补偿。
- **`**顺序的依据**` 独立加粗段**：全文约 60 处，若当普通加粗段落排，读者会把它读成正文的一部分，找不到小节边界。
- **Typst 特殊字符**：正文与代码里的 `#`、`*`、`_`、`$`、`<`、`>`、`@`、`~`、`` ` ``、行首 `-`/`+`/`=`/`/` 若未转义，轻则丢字重则编译失败——转义规则要对每段文本生效。
- **表格竖线对齐**：GFM 的对齐标记（`---:`）若不解析，数字列会左对齐，评委看到的是歪的数值列。
