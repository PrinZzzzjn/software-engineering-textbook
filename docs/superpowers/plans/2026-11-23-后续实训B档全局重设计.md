# 后续实训 B 档全局重设计实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 3-1/4-1 复查回改与 5-1～20-1 实训按 B 档“典型任务闭环”重做，使 B 档成为新及格线，并同步课程考核、教材章末验收、学员手册、教师参考、B 档快照和验证口径。

**Architecture:** 先做统一模板与 B 档口径，再按“4-1/5-1 样板 → 后端地基 6-1～9-1 → 后端业务 10-1～13-1 → 前端 15-1～20-1 → 考核验收同步”五批推进。每批同时产出学员手册、教师材料同步和 `snapshot-b/`，并用固定检查脚本/命令核对代码块、链接、旧口径残留和教师完整版回归。

**Tech Stack:** Markdown 文档、Python/FastAPI 后端工程、Streamlit 前端工程、pytest、AppTest 自测脚本、bash/Git、现有 `tools/check_links.py`。

**Spec:** `docs/superpowers/specs/2026-11-23-后续实训B档全局重设计-design.md`

## Global Constraints

- **档位**：B 典型任务闭环：每个实训覆盖典型动作的 2–3 个，并保留至少 1 个成功状态和 1 个失败状态验证。
- **B 档效力**：B 档是新及格线与课堂达标线；课程计划阶段成果、教材章末实训验收、验证记录口径同步改 B 档。
- **4-1 → 5-1**：4-1 缩为六文件 + 列表/新增两个接口；5-1 starter 与验收同步改为两接口，不要求 DELETE 204 或“五接口仍是 4-1 契约”。
- **3-1**：保持已完成的四学时五端点版本，作为全书唯一完整 CRUD 样板，不再缩减。
- **新概念记账**：课堂主动掌握 ≤2 个；其余概念写为“模板接触/演示”，只要求会照写、会验证，不推导机制。
- **教师完整版**：`项目/` 保留为教师参考与回归证据，不再是学生必做标准；验证记录分“B 档冒烟验证”和“教师完整版回归证据”两栏。
- **双轨起点**：为 5-1～20-1 新建 `实训工程参考/实训N-1/snapshot-b/`，内容等于上一实训的 B 档达标产物；不是完整版 `项目/`。
- **12-1、19-1 例外**：已减时版本保留；本轮只同步教师 README/难度评分/验证记录两栏，不补六段式学员手册；19-1 统一为三个指标 + 两张图。
- **被删内容落点**：`docs/各个专题基本内容.md` 的重点/难点必须在“课堂 B 档必做或教师演示”中出现，不得默认删除。
- **课时账不变**：课次 3、4 各 6；12、19 各 2；13、20 各 4；总计 80。
- **环境验收**：本轮无 ARM64 学员环境；交付说明标注“教师走查完成，待授课机验证”。
- **提交纪律**：不提交 `venv/`、数据库、缓存、`.env`；每批完成独立提交。

## Review Focus

- 4-1 缩为两接口后，5-1 仍按五接口验收：Task 1 用 grep 检查 5-1 README 不再含“五接口仍是”“删除单位 204”，并验证 `snapshot-b/` 只有 GET 列表与 POST 新增。
- B 档成为及格线但课程计划/章末验收仍写完整口径：Task 5 逐章核对课程计划形成性考核条目与章末验收表，grep 旧“五接口/四页新增/十步联调”等学生必做表述。
- `snapshot-b/` 错用教师完整版：每个快照批次检查 `B档说明.md` 与 B 档产物清单；Task 1～4 均验证快照不出现未纳入 B 档的路由/页面动作。
- 被删内容没有落点：Task 5 用“专题基本内容落点表”逐项核对每个重点/难点至少出现在 B 档必做或教师演示栏。
- 12-1、19-1 口径冲突：Task 4/5 grep “两个指标/一张图”应为 0；确认不创建 `实训手册/实训12-1/`、`实训手册/实训19-1/`。
- 教师完整版回归被改坏：Task 1～4 每批运行对应完整版 pytest/AppTest；数字与现有验证记录一致。
