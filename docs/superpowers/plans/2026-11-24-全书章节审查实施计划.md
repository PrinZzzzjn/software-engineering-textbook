# 全书章节审查实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用已有的两册写法规则与 `textbook-chapter-audit` skill，对第 1–24 章逐章审查，每章落盘一份报告，并最终形成全书汇总与修改优先级。

**Architecture:** 单章是最小执行单元，逐章调用审查 skill 生成固定格式报告；每批章节完成后做机械验收和原文未改动校验；全部章节审完后再做跨章汇总，不在逐章阶段擅自改正文。

**Tech Stack:** Markdown 文档、Claude Code skill、Bash/Python 文件检查脚本。

**Spec:**
- `docs/2026-11-24-教材写法诊断规则-上册-章节骨架.md`
- `docs/2026-11-24-教材写法诊断规则-下册-行文.md`

- `docs/unuesd/三级标题清单_2.0.md`

## Global Constraints

- 审查对象固定为 `软件工程实践-2.0/NN-*.md`，N = 1–24，NN 两位补零。
- 每章报告固定写入 `docs/章节审查/NN-章审查.md`。目录不存在时创建。
- 每章只能调用 `textbook-chapter-audit` 完成；不得凭经验替代规则或自行压缩报告字段。
- 默认不改章节正文。用户明确要求修改时，先完成审查报告，再另起修改任务。
- 默认审查范围为骨架 / 三级标题 / 行文三项全做；若局部审查，仍使用完整模板，未审部分写“不适用：本次仅审查 X”。
- 三级标题规范实际位于 `docs/unuesd/`，不是 `docs/` 根目录；报告中必须记录实际规范路径。
- 教学组件（示范例题、独立习题、实训模板、章末组件）不纳入 `x.y.N` 三级标题；其 T1/T2/T3 列写“不适用（教学组件）”。
- 跨章冲突只记录证据和“需主编裁决”，不在单章审查中替主编决定全书口径。
- 报告对话回报固定四行：文件路径；骨架发现条数与首要问题；标题对照覆盖数与首要建议；行文发现条数与首要问题。
- 未经用户要求，不做 git commit / push。

## Review Focus

- **规则或 skill 缺失**：Task 1 预检必须找出缺失文件并停止，不能用记忆替代规则。
- **Deadline 下压缩成几条要点**：Task 2–8 批次完成后运行机械验收脚本，强制检查六个二级标题、路线四句、三级标题表和两类问题清单。
- **本章路线缺失或凭空写**：Task 1 的模板要求路线四句附位置或原文证据；机械验收检查四句字段存在。
- **三级标题被跳过或粗体标签被误当标题**：Task 2 的试审报告与 Task 3–8 的机械验收检查三级标题对照表存在；Task 2 人工确认教学组件写“不适用（教学组件）”。
- **局部审查破坏全模板**：Task 1 的 ledger 默认记录“三项全审”；任何例外必须在报告头备注，机械验收仍按全模板检查。
- **审查过程中误改正文**：Task 1 保存审查前 SHA256；Task 2–8 每批后用脚本比对哈希，章节文件哈希必须不变。
- **跨章问题被单章审查误裁决**：Task 9 汇总时才统一整理“需主编裁决”项；单章报告只允许记录证据，不修改邻章或设计文档。

from pathlib import Path
import hashlib

out = Path("docs/章节审查/00-审查前SHA256.txt")
lines = []
for n in range(1, 25):
    files = list(Path("软件工程实践-2.0").glob(f"{n:02d}-*.md"))
    assert len(files) == 1, f"第 {n} 章文件不唯一: {files}"
    p = files[0]

out.write_text("\n".join(lines) + "\n", encoding="utf-8")
