# 全书后续实训 B 档重设计（全局设计）

> 日期：2026-11-23
> 状态：待审核
> 档位：**B 典型任务闭环**（每个实训覆盖典型动作的 2–3 个，并保留至少一个错误码验证）
> 范围：实训 3-1、4-1（复查并微调）与 5-1～20-1（重新设计必做边界、学员材料与承接）
> 事实边界：`docs/各个专题基本内容.md` 是本轮学习目标的最大边界；`实训工程参考/` 的教师完成态和接口契约是技术事实源，不要求课堂全部实现。

## 一、意图与判断

3-1、4-1 的四学时重设计已经完成，但学员基础差的根因没有消失：从 5-1 起，实训仍按“教师工程完整能力”设计，出现三个问题：

1. **新概念密度过高**：6-1 同时引入 ORM、Session、建表、seed、分页；8-1 同时引入 users 表、哈希、令牌、三个接口；10-1 单次 6 个新概念；前端 16-1～19-1 每个实训 3–5 个新概念。
2. **重复劳动吃掉理解时间**：7-1 要求新建 personnel 六文件约 179 行；18-1 一次改四页写操作、1470 行工程；教师测试扩展常作为“验证背景”，学生看不见但被它牵引。
3. **学员手册与教师工程混在一起**：大量实训只有“学员版差异说明”，没有像 3-1/4-1 那样的语法级分步指南；基础弱的学员知道要做什么，但不知道每行代码在干什么。

本轮目标不是重写教材概念节，也不是推翻教师完成态，而是以 B 档为统一口径重做课堂必做边界：

- **一个实训一个典型任务闭环**：覆盖该类任务的 2–3 个关键动作，不追求模块全 CRUD。
- **一个实训最多两个新概念**：超出部分改为“按模板用、验证行为”，不讲内部机制或移到后续/课后。
- **一条链只保留一条主线增量**：每个实训只在承接产物上增加一小块可观察功能。
- **所有学生必做内容都配语法级分步材料**：复用 3-1/4-1 的六段式。

## 二、B 档的统一定义

### 2.1 每个实训的必做结构

| 组成 | 要求 |
| --- | --- |
| 主任务 | 2–3 个关键动作，围绕一个典型任务闭环 |
| 验证任务 | 至少 1 个成功状态 + 1 个失败状态（400/401/403/404/422 中至少一种） |
| 语法讲解 | 只讲本步用到的语法与操作，每段完整代码配逐行解释 |
| 检查点 | 每阶段 2–4 项可观察结果 |
| 提交物 | 可运行的小工程/页面 + 一页验证记录 + 一页说明（可选） |

### 2.2 明确的非目标

- 不要求课堂实现教师完成态的全部文件、全部测试、全部接口。
- 不要求课堂推导 `Depends`、SQLAlchemy Session、令牌、session_state 重跑等机制的源码原理。
- 不要求自选业务对象的完整改编；课堂统一示例，改编转课后。
- 不要求新增教师测试；教师测试仍用于证明完成态可运行。
- 不改变接口契约事实源：路径、字段、状态码与教师工程保持一致；必做只是子集。但**B 档成为新及格线**，课程计划考核条目、教材章末验收表、验证记录口径都要同步改。

### 2.3 B 档与 A/C 的区别

- A（未选）只做一个动作跑通，太薄，难以支撑专题基本内容里的“典型功能实现思路”。
- C（未选）保留全部契约但只讲用法，代码量仍大，不适合基础差的学员。
- B（选用）保留“能读、能写、能失败”的闭环，删掉重复动作和机制推导，是最平衡的一档。

## 三、全局目标与不变量

### 3.1 目标

1. 5-1～20-1 每个实训都给出 B 档“必做最小闭环”，写入对应 README 和教材章末实训块。
2. 每个实训的新概念数压到 ≤2；现有评分文档标注“课堂新概念”和“课后/演示概念”。
3. 学员材料统一补 `分步实现指南.md`、记录表、starter 注释；与教师 `项目/` 不混发。
4. 保持 5-1→6-1→…→20-1 的产物承接：每节的学生产出仍可作为下一节起点；若课堂做不完，教师快照可接上。
5. 课时账不变：课次 3、4 各 6；12、19 各 2；13、20 各 4；总计 80。

### 3.2 不变量

- 后端接口路径、字段、成功码与失败码按 `_shared/接口契约清单.md`。
- 认证仍为 hashlib 盐哈希 + `TOKEN_STORE`，不引入 JWT/passlib。
- 第 6 章首次出现 `app/core/database.py`，第 8 章首次出现 `users` 表与安全模块，第 12 章进入正式 `tests/`。
- 前端 auth、api_client、components 等公共文件在后续实训原样复用，不因减负改名。
- 教师 `项目/`、`验证记录.md`、`难度评分.md`、`接缝表.md` 仍保留完整版，供教师与课后使用；但考核、验收与 B 档快照口径按新及格线改写。
- 课时与课程计划表不改。

## 五、3-1、4-1 的再次调整

3-1 保持已完成版本：五端点作为全书唯一“完整 CRUD 样板”，不再缩减；增加的语法讲解已满足 B 档可操作性。

4-1 需要微调：当前 4 学时版本仍要求六文件五个接口全做，与 B 档“2–3 个关键动作”不完全一致。

- **课堂必做**：六文件中 `model.py`、`schema.py`、`param.py` 由 starter 提供；学生补 `crud.py` 的 `list_all/create`、`service.py` 的 `list_departments/create_department`、`controller.py` 的 GET 列表与 POST 新增，验证 200、201、400（重复）与 422（缺字段）。
- **课堂知道但不必写**：详情、修改、删除三个路由与 `response_model` 的单条输出；用教师完成态在 `/docs` 演示即可。
**B 档的效力（已定）**：B 档是新的及格线与课堂达标线。专题二/三阶段性成果、教材章末实训验收、验证记录的“完成态”口径都按 B 档重写；教师 `项目/` 仍是教师完整参考，但不再作为学生必做标准。课程计划形成性考核中的“后端 API 开发与测试成果”“前后端联调与界面实现”条目改为按 B 档交付物评分。

**4-1 → 5-1（已定）**：4-1 缩为两接口后，5-1 同步改为两接口验收。5-1 的 starter 换成“4-1 B 档两接口版六文件”，README 前置条件改成“能说明六文件职责与 GET 列表 / POST 新增两个接口”，验收中删除“五接口仍是 4-1 契约”与“删除 204”等要求。5-1 仍只做工程化与 Git，不补课堂未写的三个接口。

这项调整需要在 4-1 学员手册、教师 README、难度评分和教材章末实训块做小幅回改；不必重做整个 4 学时时间表，可把详情/修改/删除的原阶段压缩为演示。

## 六、承接策略

### 6.1 双轨起点

| 起点 | 用途 |
| --- | --- |
| 上一实训 B 档学生产物 | 正常承接；即该实训章末验收的达标产物 |
| 教师 B 档快照（新建） | 若上一实训未完成或错误较多，教师直接给快照，保证本节可开始 |

**快照实体（已定）**：为 5-1～20-1 每个实训新建 `实训工程参考/实训N-1/snapshot-b/`，内容等于上一实训的 B 档达标产物（不是现有完整版 `项目/`）。快照由教师维护，需通过一组冒烟验证；不提交 venv、数据库、缓存。12-1 的 B 档快照是 2 条测试+1 次改坏记录，19-1 的 B 档快照是主题四键+三个指标+两张图的统计页（见第六节对 12/19 的收口）。

接缝表新增两列：“学生 B 档产物如何接入”“教师 B 档快照如何接入”；不改接口契约。若教师快照与上一节课堂产物结构不同，以上一节的 B 档验收标准为准。

### 6.2 每节节奏（建议，不强制套用）

6-1～11-1 的 4 学时实训建议：语法/操作 45 分钟 → 跟做主任务 70 分钟 → 验证与错误分支 35 分钟 → 排错与提交 30 分钟。13-1、20-1 这类交付/联调实训保留自定义时间表；15-1～18-1 按各节前端操作量微调。教材章末、教师 README 可保留原时间表，但需标注“课堂 B 档口径”的段落。排错嵌入各段，不另设长排错环节；这与 3-1/4-1 的六段式一致。

### 6.3 新概念记账

难度评分文档分两栏写：

- 课堂主动掌握：≤2 个；
- 模板接触/演示：其余概念，注明“会验证、不推导”。

这样既尊重总计划“≤2”规则，也避免把教师工程的全部概念硬塞进课堂。

### 6.4 被删内容在各专题基本内容中的落点

B 档会把部分完整能力移出课堂必做，但这些内容不能从课程中消失。按 `docs/各个专题基本内容.md` 的重点/难点逐项登记：

| 基本内容条目 | B 档落点 | 教学处理 |
| --- | --- | --- |
| 分页、过滤与排序；通用查询复用 | 7-1 department 过滤 + 固定排序 | 课堂必做；personnel 作为教师演示中的第二个模块对照，不新建完整六文件 |
| 用户角色与授权、权限校验、权限管理 | 9-1 管理员依赖 + 一个写接口 403 | 课堂必做最小权限；用户列表/角色修改/账号状态管理由教师快照演示，不进入课堂必做 |
| 批量数据处理、事务边界与异常处理 | 10-1 单条新增 + 时间重叠 400；13-1 一处事务收拢 | 课堂做一条规则与一处事务；批量入口只演示，不作为达标条件 |
| 测试路径与用例设计 | 12-1 登录成功 + 一个异常 + 一次改坏 | 课堂做 2 条测试；边界路径与三处改坏保留为教师演示/课后 |
| 统一错误处理、联调排错与契约对账、交付验收 | 20-1 6 步用户路径 + 一个页面错误映射 + 交付清单 | 课堂做代表性闭环；其余页面/十条路径为教师完整版参考 |
| 数据提交与回填、数据删除与反馈 | 18-1 单位页新增 + 编辑 + 删除反馈 | 课堂只做一个页面；其他模块用教师快照提供 |

每批实施时用这张表核对“重点/难点至少在必做或教师演示中出现”；若某项两项都没有，必须补进该批设计，不得默认删除。

### 6.5 12-1、19-1 的例外

12-1、19-1 已按 2 学时减时完成，本轮只更新教师 README、难度评分和验证记录的两栏记账，不补六段式学员手册。19-1 的 B 档统一为“三个指标 + 两张图 + 基本组合”，与设计文档早先草稿中的“两个指标 + 一张图”不一致处，以本口径为准。
