# 实训 3-1 与 4-1 四学时重设计

> 日期：2026-11-23
> 状态：待审核
> 范围：课次 3「后端开发框架」、课次 4「软件设计与建模」的实践部分；课次 12、19 的课时缩减登记
> 事实源：教材 `软件工程实践-2.0/03-后端开发框架 修改版.md`、`04-软件设计与建模.md`；教师工程参考 `实训工程参考/实训3-1/`、`实训4-1/`；课程计划 `docs/课程教学计划_院校版-1117.md`

## 一、背景与意图

学员的编码基础明显低于原设计假设：会读少量 Python，但没有独立写过类、装饰器、类型注解和 Web 服务；面对终端命令、`/docs` 操作、报错栈和文件拆分时，主要困难不是“不懂业务”，而是“不知道这一行在干什么、下一步点哪里”。

现有 3-1 与 4-1 各 2 学时（90 分钟）。3-1 要求从空白文件写出 45 行、五个端点、六种状态码、记录表和幂等说明；4-1 要求设计文档 + 六文件 + 五个接口 + 分页 + 422 + 两组一致性检查。教师参考自己把 4-1 标为“偏紧”，3-1 也没有余量讲语法。学员侧材料更薄：教材实训块每步只有“做什么 / 预期输出 / 做错会看到什么”，`分步实现指南.md` 属于教师版，学员版差异说明要求把它删掉；学员手里没有逐行解释和细节操作。

本次调整的目标不是把接口契约改简单，而是把**同样的核心任务拉长到 4 学时**，用多出来的时间做三件事：

1. 在每一步之前补“这一行语法是什么、为什么这样写”的讲解；
2. 把终端、`/docs`、请求构造、报错定位等操作细节写成可照做的步骤；
3. 削减与核心契约无关的书写负担（自选对象、完整设计文档、重复记录），把省下的时间还给理解和练习。

## 二、目标、非目标与反目标

### 2.1 目标

1. 3-1 结束时，全班能独立完成：从空文件启动应用、五个端点可调用、200/201/204/400/404 可复现、删除 204 无正文、能用自己的话解释幂等性。
2. 4-1 结束时，全班能独立完成：六文件齐备、五个接口可调用、200/201/204/400/404/422 可复现、设计文档三节齐全、两组一致性检查通过。
3. 学员材料做到“每一步可照做”：每步含目标、先看效果、语法卡片、完整代码与逐行解释、操作命令、检查点、常见错误。
4. 不破坏 3-1 → 4-1 → 5-1 的接缝；4-1 仍保留六文件、五个接口、`param.py` 与内存分页，5-1 可原样迁移。
5. 总学时维持 80，课次总数维持 24。

### 2.2 非目标

- 不改接口契约：资源仍为 `/departments`，字段仍为 `dept_code`、`full_name`、`address`，状态码分工不变。
- 不改存储方式：3-1 内存字典，4-1 dataclass + 内存列表，重启清空。
- 不改 5-1 及之后的工程内容；5-1 仍以 4-1 六文件为起点。
- 不在本轮细化 12-1、19-1 的完整内容；本轮只做课时缩减与必做/选做切分登记。
- 不新增运行依赖；不引入数据库、认证、JWT、pytest 学生必做内容。
- 不把教材改成完整教程；教材实训块保留任务与验收，逐行讲解放在学员手册。

### 2.3 反目标

- **不能**为了“讲语法”把五个端点或六文件砍掉，导致 5-1/6-1 无法承接。
- **不能**把学员手册写成“整段答案复制页”而不设检查点；每步必须有可观察的验证动作。
- **不能**用增加课后作业的方式变相保留原任务量；4 学时内的必做量必须真的下降。
- **不能**让 12-1、19-1 减时后仍按 4 学时的验收标准要求，必须同步降必做、移选做。

## 三、约束

1. **接缝约束**：4-1 → 5-1 的接缝表明确“六类模块文件不新建、不改名、不改写”，`param.py` 与内存分页由 5-1 原样复用。因此 4-1 不能删 `param.py`、不能删分页、不能把六个文件合并。
2. **契约约束**：`_shared/接口契约清单.md` 与 `duty-simplified` 是事实源；重复资源 400、删除 204 无正文、列表 `{items, total}` 不变。
3. **环境约束**：授课机为 ARM64 Ubuntu + Python 3.12、完全内网。现有工程参考的命令以 PowerShell 为主，与授课机不一致；本次学员手册必须给出 Linux bash 命令为主、PowerShell 对照为辅，并注明离线安装方式。
4. **课时约束**：1 学时 = 45 分钟；4 学时 = 180 分钟。教材正文、课程计划表、工程参考中的“2 学时 / 90 分钟”必须同步改净。
5. **材料约束**：学员材料不得包含教师自动测试、验证记录、教师完成态答案的“整包下载”；可以含教学用完整代码，但必须有“先自己做 3 分钟”的停顿和检查点。
6. **旧材料约束**：工作区中 `实训手册/` 已被删除；本次重设计需要重新建立学员侧目录，不能默认旧手册仍然存在。

## 四、方案选择与取舍

### 4.1 总体方案：A + 4 学时

- **A（选用）**：核心契约不减，削减周边负担，增加语法与操作讲解，用 4 学时完成。
- **B（未选）**：3-1 只做 3 个端点，把 PUT/DELETE 移到 4-1。问题：4-1 本来就有五个端点，移过去会让 4-1 第一次接触 PUT/DELETE 时同时面对六文件和分页，难度曲线更陡；且 5-1 的回归会缺 PUT/DELETE 的练习。
- **C（未选）**：把 3-1、4-1 各拆成两个 2 学时实训。问题：实训编号、教材章末结构、课程计划课次都要重排，改动面远大于本次目标。

### 4.2 学员材料放在哪里

- **选用**：重建 `实训手册/实训3-1/` 与 `实训手册/实训4-1/`，作为学员侧材料；`实训工程参考/` 继续做教师侧答案与验证。
- 未选：把逐行讲解直接扩进教材章末实训块。问题：教材会从“任务书”变成“教程”，篇幅膨胀，且教师/学员材料混在一起。
- 未选：把教师 `分步实现指南.md` 直接发给学生。问题：其中含自动测试、验证记录和完整答案，无法控制“先练后看”。

### 4.3 3-1 是否保留五个端点

**保留五个端点。** 理由是接缝与契约：5-1 的部门模块、6-1 的落库都假设五个接口已存在；砍端点会把难度后移，而不是降低。任务量的下降改由以下四项实现：

1. 记录表从“十行全填”降为“五种状态码各一行必填，其余选填”；
2. 幂等说明改为给句式框架的 100 字填空，不再要求从零组织；
3. 终端命令、`/docs` 操作、报错定位写成逐步照做，减少试错时间；
4. 不再要求学生自己猜字典和装饰器的写法，先讲语法再写代码。

### 4.4 4-1 是否保留六文件、分页与 `response_model`

**保留六文件、五个接口、`param.py`、内存分页、`response_model` 与 422。** 理由是 5-1 接缝与第 4 章“六类职责”不可简化项。任务量的下降改由以下四项实现：

1. 课堂统一使用单位示例，自选对象的完整改编转为课后；
2. 设计文档给“单位示例 + 空格待填”的模板，学生填接口清单、目录和一条规则性失败，不从零设计；
3. `Depends()` 与 `response_model` 按模板抄写并会验证，不要求推导机制；
4. starter 继续提供 `model.py`、`schema.py`、`param.py` 与路由骨架，学生只补 `crud.py`、`service.py` 和五个路由函数，书写量约 70–80 行（含空行）。

### 5.2 实训 3-1：四学时结构（180 分钟）

**一句话目标**：从空文件写出一个可运行的单位接口，理解自己写下的每一行。

| 阶段 | 内容 | 分钟 | 学员产物 / 检查点 | 语法与操作讲解点 |
| --- | --- | ---: | --- | --- |
| 0 | 环境与操作基础 | 15 | 能打开终端、确认 Python、知道文件保存在哪；依赖检查通过 | 终端当前目录、`python --version`、`pip install -r requirements.txt`（内网用 `pip install --no-index --find-links=<wheelhouse 路径> -r requirements.txt`）、UTF-8 保存、英文标点、4 空格缩进 |
| 1 | 最小应用与 `/health` | 25 | `/docs` 可打开，`/health` 返回 200 与 `{"status": "ok"}` | `from ... import ...`、`app = FastAPI()`、`@app.get`、`def`、`return`、字典字面量 |

| 3 | 列表端点：静态 → 字典 | 20 | 列表返回 D01，`total` 为 1 | 嵌套字典、`.values()`、`list()`、`len()`、为什么返回 `{items, total}` |
| 4 | 详情端点与 404 | 15 | D01 返回 200，D404 返回 404 与“单位不存在” | 路径参数 `{dept_code}`、函数参数、类型注解、`not in`、`raise`、`HTTPException` |

| 6 | 修改端点与 200/404 | 15 | 改 `full_name` 返回 200，`address` 保持；D404 返回 404 | `if "full_name" in data`、局部变量、字段赋值、只改传入字段 |
| 7 | 删除端点与 204/404 | 15 | 第一次 204 无正文；第二次 404 | `del`、204 不返回内容、先判断存在 |
| 8 | 验证记录与幂等说明 | 15 | 五种状态码各一行真实记录；100 字幂等说明 | `/docs` 的 Try it out / Execute、bash 与 PowerShell 请求对照、记录表填写、幂等句式 |
| 9 | 复核与提交 | 10 | 重启后仍可访问；提交 `main.py`、记录表、说明 | 停止与重启、`--reload`、提交清单 |
| | **合计** | **175 + 5 机动 = 180** | | |

**离线环境的 `/docs`**：授课机完全内网，FastAPI 默认的 Swagger UI 走公网 CDN，`/docs` 可能空白。阶段 0 必须先做一次打开测试；若空白，按 5.4 的备用方案执行，并把空白页当作环境问题处理，不计入学员错误。

**代码规模不变**：学员最终 `main.py` 约 45 行、五个端点；教师完成态与 `项目/main.py` 不变。

**学员手册每阶段的固定六段式**：

1. **本步目标**：一句话，说明这一步做完能看到什么。
2. **先看效果**：先运行/先看响应，再解释代码，避免“先读一大段代码”。
3. **语法卡片**：只讲本步出现的语法，每个点 1–3 句，配一个最小例子；不展开语言全貌。
4. **代码与逐行解释**：完整可复制代码 + 行号对照表（代码 / 意思 / 为什么需要）。
5. **操作与检查点**：精确命令、预期输出、2–3 个自检项；命令以 Ubuntu bash 为主，PowerShell 对照放折叠或旁栏。
6. **常见错误与求助**：现象 → 先查什么 → 怎么改；最后一行写“卡住时先做哪三件事”。

**必须覆盖的语法点清单（3-1）**：

- 导入：`from fastapi import FastAPI, HTTPException, status` 中每个名字的用途。
- 应用与路由：`app = FastAPI()`；`@app.get("/health")` 是“把下面的函数登记为某个方法和路径的处理函数”，不要求理解装饰器原理。
- 函数：`def 名字(参数):`、缩进、`return`；无返回值与返回 `None` 的区别。
- 字典：字面量、键、值、取值、`.get()`、`in`、`del`、`.values()`；`KeyError` 与 500 的关系。
- 列表：`list(...)`、`len(...)`、遍历。
- 条件：`if`、`not`、`or`、`in` / `not in`。
- 异常：`raise HTTPException(status_code=404, detail="单位不存在")`；`raise` 之后函数不再往下执行。
- 状态码常量：`status.HTTP_201_CREATED`、`status.HTTP_204_NO_CONTENT`。
- 请求体：`data: dict` 是什么；JSON 的 `null` 与 Python 的 `None`、`true` 与 `True` 的对应。
- 路径参数：`/departments/{dept_code}` 与函数参数同名。
- 操作：`uvicorn main:app --reload --port 8000` 中 `main`、`app`、`--reload`、`--port` 各是什么；`/docs` 如何展开端点、点 Try it out、改请求体、点 Execute、读 Response code 与 body；bash 的 `curl` 与 PowerShell 的 `Invoke-RestMethod` / `Invoke-WebRequest` 对照。
- 报错：`SyntaxError`、`IndentationError`、`NameError`、`KeyError`、`TypeError` 分别先看哪一行；服务端终端与浏览器响应的区别。

**验收调整**：

- 记录表必填五行：200（列表或详情）、201（新增）、204（删除且正文为空）、400（缺字段或重复编码）、404（详情/修改/删除任一）；其余行选填。
- 幂等说明给句式框架：GET 重复请求______；PUT 重复提交同一请求体______；DELETE 第一次______、第二次______、最终______；POST 重复执行______。判断依据必须是“服务器最终状态”，不是“响应码相同”。
- 新增口头检查：随机指一行代码，学生说出“这行在做什么”；不要求背诵。

### 5.3 实训 4-1：四学时结构（180 分钟）

**一句话目标**：把单位模块拆成六个职责文件，接通五个接口，并说清每个文件为什么存在。

| 阶段 | 内容 | 分钟 | 学员产物 / 检查点 | 语法与操作讲解点 |
| --- | --- | ---: | --- | --- |
| 0 | 起点与目录结构 | 10 | starter 能启动；`/docs` 暂无业务端点；能指出六个文件的位置 | 包与 `__init__.py`、`from app.modules...`、`from . import model`、目录树、启动目录 |
| 1 | 设计文档：单位对象 | 25 | 表结构、接口清单、模块目录三节填完；写出一条规则性失败 | 字段/类型/必填/主键、五动作表、参数来源、六文件目录 |
| 2 | `model.py`：dataclass 与内存表 | 20 | REPL 能创建、追加、遍历 `Department` | `@dataclass`、类与属性、`str`、`str \| None`、默认值、`list[Department]`、`TABLE` |
| 3 | `schema.py`：Pydantic 模型 | 20 | 能验证一个字典；缺字段时看到校验错误 | `BaseModel`、`Field(...)`、`min_length`、`max_length`、`default=None`、`model_dump()`、`model_validate()`、`ConfigDict(from_attributes=True)` |
| 4 | `crud.py`：五个存取函数 | 25 | 五个函数补全；REPL 能增、查、改、删 | `from . import model`、`append`、`remove`、`for`、`if`、`return None`、`setattr`、`data.items()` |
| 5 | `service.py`：规则与分页 | 30 | 五个服务函数补全；重复 400、不存在 404、分页切片正确 | `raise HTTPException`、列表切片 `items[start:start + page_size]`、`len()`、列表推导、`model_dump(exclude_unset=True)` |
| 6 | `param.py` + `controller.py` + `main.py` | 30 | `/docs` 出现五个单位端点；路径无 `/api/v1` | `APIRouter(prefix=..., tags=...)`、`Depends()`、`response_model`、`status_code`、`include_router(..., prefix="")` |
| 7 | 状态码验证与两组一致性 | 15 | 200/201/204/400/404/422 各出现一次；两组检查逐项打勾 | `/docs` 操作、分页参数、422 与 400 的区别、字段逐项对照、文件逐项对照 |
| 8 | 提交 | 5 | 设计文档、六文件代码、验证记录 | 提交清单、删除缓存目录 |
| | **合计** | **180** | | |

**学员书写量**：`crud.py` 约 20 行、`service.py` 约 35 行、`controller.py` 路由函数约 25 行；`model.py`、`schema.py`、`param.py` 由 starter 提供，学生读懂并做小幅修改。总书写量约 70–80 行（含空行），比原 90 分钟设计仍可控，但不再宣称“约 50 行”。

**必须覆盖的语法点清单（4-1）**：

- 包与导入：目录为什么要有 `__init__.py`；`from app.modules.department import controller as department_controller`；`from . import model` 中的 `.` 指当前包。
- 类与 dataclass：`class`、属性、构造参数、默认值、类型注解；`@dataclass` 帮我们生成了什么（不要求背生成的代码）。
- 类型：`str`、`int`、`str | None`、`list[Department]`；类型注解不参与运行，但帮助阅读与校验。
- Pydantic：`BaseModel`、`Field`、`...` 表示必填、`ge`/`le`/`min_length`/`max_length`、`model_dump()`、`exclude_unset=True`、`model_validate()`、`ConfigDict(from_attributes=True)`；校验失败为什么是 422 而不是 400。
- 列表与循环：`append`、`remove`、`for item in ...`、`if`、`return None`、`enumerate` 不要求。
- `setattr`：为什么 crud 用 `setattr(item, key, value)` 而不是给每个字段写一遍。
- 切片：`(page - 1) * page_size`、`items[start:start + page_size]`；`total` 为什么是切片前的长度。
- 列表推导：`[schema.DepartmentOut.model_validate(item) for item in page_items]` 的读法；不要求自己推导，能照写并解释即可。
- FastAPI：`APIRouter`、`prefix`、`tags`、`Depends()`、`response_model`、`status_code`、`include_router`；只要求会填、会验证，不要求解释依赖注入源码。
- 状态码：200/201/204/400/404/422 各自由谁产生；204 不能有正文。
- 操作与排错：`ModuleNotFoundError: app`、`ImportError`、`NotImplementedError`、`ValidationError`、`422` 的定位顺序；`python -c "..."` 自检命令怎么读。

**验收调整**：

- 设计文档使用“单位示例 + 空格待填”模板：表结构三行、接口清单五行、目录树一棵；学生补“字段是否必填”“成功状态码”“一条规则性失败”。
- 自选对象的完整改编转为课后扩展；课堂统一单位，允许学生改一个字段名或增加一个可选字段作为“自己的设计”。
- 两组一致性检查改成清单：字段 3 项、文件 6 项，逐项打勾并写一句依据。
- 验证记录必填六行：200、201、204、400、404、422；分页两行选填。
