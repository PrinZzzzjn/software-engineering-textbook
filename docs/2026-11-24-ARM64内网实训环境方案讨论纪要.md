## 一、结论摘要

| 问题 | 结论 |
| --- | --- |
| 当前方案是什么 | 每台授课机本地安装 Python 3.12 + venv，用 ARM64 wheelhouse 完全离线装依赖；Docker 章节另有镜像 tar + 离线 compose 方案（镜像尚未生成，暂缓）。 |
| 一定要 Python 3.12 吗 | 就当前现成方案和现成 wheelhouse 而言，是。Python 3.11 需重新下载 cp311 wheel；Python 3.8 不可行。 |
| Python 3.8 能用吗 | 不能。仅换 wheel 不够，需整条依赖链降级并改动全部代码、教材与验证记录。 |
| 每台电脑都要拷贝吗 | 环境必须每台机器本地装（实训要求本地写代码、跑测试、练 Git）；wheelhouse 和项目文件可只维护一份，通过共享目录或内网 pip 源分发，不必逐台拷 U 盘。 |

| 当前最大缺口 | Ubuntu 20.04 自带 Python 3.8，需准备 Python 3.12 的离线安装包；`/docs` 补丁和 wheelhouse 尚未在 ARM 实机验证。 |

## 三、当前非 Docker 实施方案

### 3.1 三层结构

1. **依赖层**：`pip download --platform manylinux2014_aarch64 --python-version 3.12 --abi cp312` 在联网准备机上交叉下载 wheel → 拷入内网 → `pip install --no-index --find-links=./wheelhouse-arm64 -r requirements.linux-arm64.lock.txt`。`--no-index` 保证 pip 不访问公网。
2. **环境层**：每台授课机本地建 venv；把 `sitecustomize.py` 预置进去解决 `/docs` CDN 空白问题。
3. **运行层**：学员在本地 starter 目录跑 `uvicorn main:app --reload --port 8000` 或 `streamlit run app.py`，浏览器访问 `127.0.0.1`；前后端分离机器用 `DUTY_API_BASE_URL` 指定后端地址。

### 3.2 授课机前置检查

```bash
uname -m                    # 预期 aarch64
python3.12 -V               # 预期 3.12.x
ldd --version | head -1     # glibc >= 2.17（Ubuntu 20.04 为 2.31，满足）
```

### 3.3 单机安装步骤

```bash
python3.12 -m venv venv
source venv/bin/activate
pip install --no-index --find-links=./wheelhouse-arm64 \
  -r requirements.linux-arm64.lock.txt

VENV_SITE=$(python -c "import site; print(site.getsitepackages()[0])")
cp sitecustomize.py "$VENV_SITE/"

python -c "import fastapi,uvicorn,sqlalchemy,pydantic,pytest,httpx,streamlit,pandas,requests; print('deps ok')"
python -m pytest 项目参考/duty-simplified/tests/test_smoke.py -q    # 预期 3 passed
```

若目标 venv 已有 `sitecustomize.py`，不要覆盖，改用 `.pth` 方式（见 `tools/offline-deps/README.md` 与 `_shared/offline_docs/README.md`）。

## 四、Python 版本讨论

### 4.1 为什么 3.8 装不上

逐个读取 56 个 wheel 的 `Requires-Python` 元数据后确认：

- 30 余个包直接要求 ≥3.10 或 ≥3.11，例如 fastapi 0.165（≥3.11）、starlette 1.10（≥3.11）、pydantic 2.14（≥3.10）、streamlit 1.67（≥3.11）、SQLAlchemy 2.1.9（≥3.11）、pandas 2.3.2（≥3.9）、pytest 9.2（≥3.10）、requests 2.34（≥3.10）、uvicorn 0.54（≥3.10）。
- 16 个 wheel 文件名带 `cp312`，二进制 ABI 与 3.8 不兼容（numpy、pandas、pyarrow、pillow、pydantic-core、uvloop、httptools、PyYAML 等）。
- 3.8 上最后可用的版本组合约在 2023 年前后：fastapi 0.9x + pydantic 1.10 + SQLAlchemy 1.4 + streamlit 1.3x + pandas 1.5 + numpy 1.24 + pytest 7.4；部分旧版未必有 aarch64 预编译 wheel，可能要源码编译。

### 4.2 即使装上，项目功能也会坏

1. **语法层**：教师工程、学员 starter、快照中普遍使用 `int | None`、`list[X]`、`dict[str, int]`（例如 [项目参考/duty-simplified/app/core/security.py](../项目参考/duty-simplified/app/core/security.py)）。这些写法在 3.8 是 `TypeError`；仅 7 个文件有 `from __future__ import annotations`，且 Pydantic 靠读取注解工作，加 future import 也未必可解。全仓库 1166 个 Python 文件需逐个改注解。
2. **库 API 层**：代码大量使用 Pydantic v2 独有 API——`ConfigDict`、`model_dump()`、`model_dump(exclude_unset=True)`、`model_validate()`。3.8 只能用 Pydantic v1，对应写法是 `class Config: orm_mode = True`、`dict()`、`from_orm()`。教材 [实训4-1 分步实现指南.md](../实训手册/实训4-1/分步实现指南.md) 专门讲解 `model_dump` 与 `str | None`，这些内容要重写。
3. **行为与验收层**：`TestClient` 行为、422 错误体结构、Streamlit 组件可用性均随版本变化，全部 `验证记录.md` 的测试数字和 [接口契约清单.md](../实训工程参考/_shared/接口契约清单.md) 要重跑复核。

结论：改 3.8 不是降级依赖，而是重做教材技术栈；本次讨论**不采用**。Python 3.11 也只是“重新下一套 cp311 wheel + 回归验证”的选项，没有现成收益。

### 4.3 推荐路径

- 在 Ubuntu 20.04 上离线安装 Python 3.12：联网的同型号 ARM 机器上用 deadsnakes PPA 下载 `.deb` 及依赖后离线 `dpkg -i`，或源码编译（较慢）。装好后现有 wheelhouse 直接用，代码零改动。
- 有系统升级计划时，Ubuntu 24.04 默认 Python 3.12，一步到位。
- Docker 封装 Python 3.12 运行环境的路线暂不在本次范围（镜像 tar 尚未准备）。

## 五、分发方式讨论

### 5.1 为什么必须本地环境

项目文件中没有任何集中部署设计。课程实训要求学生本地写代码、跑 `pytest`、练 Git（5-1 甚至要在本地制造和解决冲突）；第 8 章起令牌存于进程内 `TOKEN_STORE`，多用户共用服务端会互相干扰。因此“学生机只访问一台中央服务器就能做实训”不成立，每台机器需要有本地 Python 3.12 + venv + 项目副本。

### 5.2 可集中分发的部分

依赖包和项目源码只需维护一份，推荐两种方式（均为本次讨论建议，项目文档中尚未写入）：

- **方案 A：共享目录（最省事）**。把 `wheelhouse-arm64/`、锁文件、`sitecustomize.py`、项目目录放到内网文件服务器（Samba/NFS/Windows 共享），学生机挂载后：

  ```bash
  python3.12 -m venv venv
  source venv/bin/activate
  pip install --no-index --find-links=/mnt/course-offline/wheelhouse-arm64 \
    -r /mnt/course-offline/requirements.linux-arm64.lock.txt
  ```

- **方案 B：内网 PyPI 源（规模较大时）**。在服务器起 `pypiserver`：

  ```bash
  pypi-server -p 8080 ./wheelhouse-arm64
  ```

  学生机 `pip install --index-url http://<服务器IP>:8080/simple --trusted-host <服务器IP> -r requirements.linux-arm64.lock.txt`。`pypiserver` 本身需提前下载 wheel 放入环境。

注意：项目源码可由服务器分发，但**不能直接在共享目录上运行**——`__pycache__`、SQLite `duty.db`、Streamlit 缓存的多人并发写入会冲突。学生应拷到自己家目录再跑。
