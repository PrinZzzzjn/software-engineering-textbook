## 三、下游：13-1 → 15-1（前端实训）

前端可依赖的后端事实：

| 项 | 取值 |
| --- | --- |
| 基地址 | `http://127.0.0.1:8000`，无 `/api/v1` |
| 登录 | `POST /users/login` → `{access_token, token_type, user}`；成功后请求头 `Authorization: Bearer <token>` |
| 列表 | 五类列表均返回 `{items, total}`；分页参数 `page`、`page_size` |
| 删除 | 204，无响应体 |
| 权限 | 写接口与 `/users` 需要管理员；普通用户 403；无令牌 401 |
| 校验失败 | 422，`detail` 为字段错误数组 |
| 业务失败 | 400 / 404，`detail` 为字符串 |
| 统计 | 年度统计与时段分布均为只读；年份为 4 位字符串 |
| 文档 | `/docs`、`/openapi.json` 可打开；`/docs` 内网可能空白，接口本身不受影响 |

前端需要特别注意：

- 401、403、422 的 `detail` 形状不同（字符串 vs 数组），不要统一按字符串展示。
- 列表字段已白名单化，用户对象只有 `id`、`username`、`role`、`is_active`。
- 不存在 `POST /duty-records/batch`；批量能力只在 service 层，前端不调用。
- 执勤记录没有 PUT 更新接口；删除后按 204 处理。
