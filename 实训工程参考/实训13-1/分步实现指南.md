## 2. 安全：列表输出模型（约 30 分钟）

class DepartmentListOut(BaseModel):

    total: int

## 3. 错误分层与事务（约 25 分钟）

教材 13.2 的结论是：业务错误用 `HTTPException` 指定 400/404，422 交给 Pydantic，500 交给框架；一个业务动作一个事务。

### 3.1 提交收拢

在 `app/core/database.py` 加：

```python
def commit_or_rollback(db: Session) -> None:
    """一个业务动作一次提交；失败回滚并继续抛出，避免半批数据与脏会话。"""
    try:
        db.commit()
    except Exception:
        db.rollback()
        raise
```

各模块 `crud.py` 里的 `db.commit()` 改为 `commit_or_rollback(db)`；`delete` 也一样。

### 3.2 请求级回滚

```python
def get_db():
    """请求级会话：正常结束由各写操作自行提交；出现异常先回滚再向上抛。"""
    db = SessionLocal()
    try:
        yield db
    except Exception:
        db.rollback()
        raise
    finally:
        db.close()
```

### 3.3 批量写入

在 `app/modules/duty_record/service.py` 增加批量入口，单条创建复用它：

```python
def _validate_batch_overlap(rows) -> None:
    for index, current in enumerate(rows):
        for later in rows[index + 1:]:
            if current.workstation_id != later.workstation_id:
                continue
            if (
                current.start_time < later.end_time
                and current.end_time > later.start_time
            ):
                raise HTTPException(status_code=400, detail="同一批次内的执勤时段重叠")


def create_duty_records(db, rows):
    for row in rows:
        _validate_duty_record(db, row)
    _validate_batch_overlap(rows)
    return crud.create_many(db, rows)


def create_duty_record(db, data):
    return create_duty_records(db, [data])[0]
```

`crud.create_many` 一次 `add_all`、一次提交：

```python
def create_many(db: Session, rows):
    records = [DutyRecord(**row.model_dump()) for row in rows]
    db.add_all(records)
    commit_or_rollback(db)
    for record in records:
        db.refresh(record)
    return records
```

## 4. 重复与性能（约 20 分钟）

### 4.1 公共分页

新建 `app/core/pagination.py`：

```python
def paginate(query, offset: int, limit: int):
    total = query.count()
    items = query.offset(offset).limit(limit).all()
    return items, total
```

五个 `crud.list_page` 改为「过滤 → 排序 → `paginate`」：

```python
def list_page(db: Session, offset: int, limit: int, dept_code: str | None = None):
    query = db.query(Workstation)
    if dept_code:
        query = query.filter(Workstation.dept_code == dept_code)
    query = query.order_by(Workstation.workstation_id)
    return paginate(query, offset, limit)
```

抽取判据与第 7 章一致：换一个模型仍然一字不改的，可以抽；页码换算仍留在 service。

## 常见错误对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `TypeError: paginate() missing 1 required positional argument` | `list_page` 未传 `offset` 或 `limit` | 检查 service 的页码换算 |
| `NameError: name 'Session' is not defined` | 给 `commit_or_rollback` 加了注解但未导入 | `from sqlalchemy.orm import Session` |
| 列表 500，提示 `ResponseValidationError` | `response_model` 与返回字段不符 | 核对 `*ListOut` 的字段名 |
| 批量失败后仍有数据 | 先 `add` 后校验，或 `commit` 在循环内 | 改为先校验再一次提交 |
| 403 变成 401 | 令牌无效或请求头缺 `Bearer` | 检查登录返回与请求头 |
| 422 与 400 混淆 | 缺字段属 422，业务规则属 400 | 按语义分工，不改状态码凑前端 |
| 测试互相污染 | 用了固定编号与固定时间 | 用 uuid 后缀与错开的年份 |
