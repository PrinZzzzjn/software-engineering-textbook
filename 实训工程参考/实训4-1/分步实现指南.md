## 阶段 1：选对象与写字段（教材步骤 1）

### 操作

需求条目是“维护单位基本信息，供后续人员归属与执勤统计使用”。从中提取一个业务对象：**单位**，不要把对象扩大成“执勤管理系统”。

先写设计，不写代码：

| 项目 | 单位示例的决定 |
| --- | --- |
| 业务对象与使用者 | 单位；由执勤年鉴维护人员管理 |
| 模块名与一句话职责 | `department`；维护单位编码、全称与地址 |
| 主键 | `dept_code`，业务上唯一且稳定 |
| 字段 | `dept_code: str`、`full_name: str`、`address: str \| None` |
| 关联判断 | 当前快照无关联表；完整业务中单位 1—N 人员，外键应在人员表 |

再写五动作接口草案：GET 集合、GET 单个、POST 集合、PUT 单个、DELETE 单个；URL 只用 `/departments` 和 `/departments/{dept_code}`。新增一条规则“编码重复返回 400”，字段或分页非法返回 422，资源不存在返回 404。

将结果填入设计文档的表结构、接口清单、模块目录三节，并做第一次字段与文件核对。完整示例见 `设计文档.md`。

### 验证

逐项回答：

- 能否用一句话说清模块职责？
- 三个字段是否都有名称、类型、必填性，主键是否唯一？
- 五个接口是否都有方法、URL、参数来源与成功状态码？
- 是否写明至少一条规则性失败，而不是只写成功路径？

### 常见错误

- 对象选成“管理系统”或“单位管理页面”；应收窄到需要保存数据的“单位”对象。
- 把外键放进当前单位表以保存人员列表；一对多关系的外键应在“多”的一方。
- URL 写成 `/getDepartments` 或 `/departments/delete/D01`；动作由 HTTP 方法表达。

## 阶段 2：写 model 与 schema（教材步骤 2）

### 2.1 `app/modules/department/model.py`

用完整内容替换骨架。dataclass 只描述记录，`TABLE` 只保存记录；完成态从空表开始，便于重复验证。

```python
from dataclasses import dataclass


@dataclass
class Department:
    dept_code: str
    full_name: str
    address: str | None = None


TABLE: list[Department] = []
```

### 2.2 `app/modules/department/schema.py`

创建、更新、单条输出、分页输出分别建模。`exclude_unset` 在 service 更新时使用，因此更新模型允许只提交部分字段；输出模型的 `from_attributes=True` 允许读取 dataclass 属性。

```python
from pydantic import BaseModel, ConfigDict, Field


class DepartmentCreate(BaseModel):
    dept_code: str = Field(..., min_length=2, max_length=20)
    full_name: str = Field(..., min_length=2, max_length=100)
    address: str | None = Field(default=None, max_length=500)


class DepartmentUpdate(BaseModel):
    full_name: str | None = Field(default=None, min_length=2, max_length=100)
    address: str | None = Field(default=None, max_length=500)


class DepartmentOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    dept_code: str
    full_name: str
    address: str | None = None


class DepartmentPage(BaseModel):
    items: list[DepartmentOut]
    total: int
```

### 验证

```powershell
python -c "from app.modules.department import model, schema; item=model.Department('D01','一中队'); print(schema.DepartmentOut.model_validate(item).model_dump()); print(model.TABLE)"
```

预期输出：

```text
{'dept_code': 'D01', 'full_name': '一中队', 'address': None}
[]
```

再核对设计文档：三个表字段与 `DepartmentOut` 三字段的名称、类型、可空性一致。

### 常见错误

- 输入与输出只用一个模型；以后增加内部字段时容易误暴露，也无法分别约束创建与更新。
- 忘记 `ConfigDict(from_attributes=True)`，导致输出模型不能直接验证 dataclass 对象。
- 把 `address` 写成必填，和设计文档“可选”冲突。
- 模型字段改了而设计文档未改；先记录差异，再判断哪一方需要修正。

## 阶段 3：写 crud（教材步骤 3）

### `app/modules/department/crud.py`

五个函数只回答“怎样读写”。查不到返回 `None`，不要在这里抛 404；新增前也不查重。

```python
from . import model


def list_all() -> list[model.Department]:
    return model.TABLE


def get(dept_code: str) -> model.Department | None:
    for item in model.TABLE:
        if item.dept_code == dept_code:
            return item
    return None


def create(item: model.Department) -> model.Department:
    model.TABLE.append(item)
    return item


def update(item: model.Department, data: dict) -> model.Department:
    for key, value in data.items():
        setattr(item, key, value)
    return item


def delete(item: model.Department) -> None:
    model.TABLE.remove(item)
```

### 验证

```powershell
python -c "from app.modules.department import crud, model; print(crud.get('D01')); item=crud.create(model.Department('D01','一中队')); print(crud.get('D01')); crud.update(item, {'address':'一号楼'}); print(crud.list_all()); crud.delete(item); print(crud.list_all())"
```

预期依次看到：初始查不到为 `None`，创建后能取得对象，更新后地址为“一号楼”，删除后列表为空。该命令在独立进程执行，不会给后续服务留下数据。

### 常见错误

- 在 crud 中导入 `HTTPException` 或写“编码已存在”；业务判断必须移到 service。
- `get()` 找不到时直接抛异常，导致 service 无法统一决定 404。
- `update()` 用新对象替换列表元素，却未真正修改传入对象；按字段 `setattr` 即可。

## 阶段 4：写 service（教材步骤 4）

### `app/modules/department/service.py`

规则集中在这里。列表先计算切片再组装输出，`total` 是切片前的总数；创建查重返回 400，详情、更新、删除先确认存在，否则 404。

```python
from fastapi import HTTPException

from . import crud, model, schema


def list_departments(page: int, page_size: int) -> dict:
    items = crud.list_all()
    start = (page - 1) * page_size
    page_items = items[start : start + page_size]
    return {
        "items": [schema.DepartmentOut.model_validate(item) for item in page_items],
        "total": len(items),
    }


def get_department(dept_code: str) -> model.Department:
    item = crud.get(dept_code)
    if item is None:
        raise HTTPException(status_code=404, detail="单位不存在")
    return item


def create_department(data: schema.DepartmentCreate) -> model.Department:
    if crud.get(data.dept_code) is not None:
        raise HTTPException(status_code=400, detail="单位编码已存在")
    return crud.create(model.Department(**data.model_dump()))


def update_department(
    dept_code: str, data: schema.DepartmentUpdate
) -> model.Department:
    item = crud.get(dept_code)
    if item is None:
        raise HTTPException(status_code=404, detail="单位不存在")
    return crud.update(item, data.model_dump(exclude_unset=True))


def delete_department(dept_code: str) -> None:
    item = crud.get(dept_code)
    if item is None:
        raise HTTPException(status_code=404, detail="单位不存在")
    crud.delete(item)
```

### 验证

```powershell
python -c "from app.modules.department import schema, service; data=schema.DepartmentCreate(dept_code='D01', full_name='一中队'); service.create_department(data); print(service.get_department('D01')); print(service.list_departments(1, 10))"
```

预期能看到 D01 对象，以及包含一条 `items`、`total=1` 的分页字典。重复执行同一命令是在新进程中运行，仍从空表开始；若在同一进程再次新增 D01，应抛出 400。

### 常见错误

- service 只做转发，查重和存在性判断仍写在 controller；这会使六文件只有形式没有职责。
- 更新使用 `data.model_dump()`，未提交字段也被写成 `None`；必须使用 `exclude_unset=True`。
- `total` 写成 `len(page_items)`；第二页只剩一条时会错误得到 1，应为全表总数。
- 把查重写成 422；格式合法但业务不允许，应由 service 返回 400。

## 阶段 5：写 param 与 controller 五接口（教材步骤 5）

### 5.1 `app/modules/department/param.py`

默认值和范围集中在查询模型中。`page < 1`、`page_size < 1`、`page_size > 100` 或无法解析为整数时，FastAPI 在进入接口前返回 422。

```python
from pydantic import BaseModel, Field


class DepartmentQueryParams(BaseModel):
    page: int = Field(1, ge=1)
    page_size: int = Field(10, ge=1, le=100)
```

### 5.2 `app/modules/department/controller.py`

controller 只取参数、调用 service、返回结果。列表的 `Depends()` 不能漏，POST 要声明 201，DELETE 要声明 204 且不返回正文。

```python
from fastapi import APIRouter, Depends, status

from . import param, schema, service

router = APIRouter(prefix="/departments", tags=["单位"])


@router.get("", response_model=schema.DepartmentPage)
def list_departments(params: param.DepartmentQueryParams = Depends()):
    return service.list_departments(params.page, params.page_size)


@router.get("/{dept_code}", response_model=schema.DepartmentOut)
def get_department(dept_code: str):
    return service.get_department(dept_code)


@router.post(
    "", response_model=schema.DepartmentOut, status_code=status.HTTP_201_CREATED
)
def create_department(data: schema.DepartmentCreate):
    return service.create_department(data)


@router.put("/{dept_code}", response_model=schema.DepartmentOut)
def update_department(dept_code: str, data: schema.DepartmentUpdate):
    return service.update_department(dept_code, data)


@router.delete("/{dept_code}", status_code=status.HTTP_204_NO_CONTENT)
def delete_department(dept_code: str):
    service.delete_department(dept_code)
```

### 5.3 根 `main.py`

确认根入口与完成态一致。业务路径只由模块的 `/departments` 提供，根装配不再加版本前缀。`/health` 是任务允许的可选服务检查，不属于单位五接口。

```python
from fastapi import FastAPI

from app.modules.department import controller as department_controller

app = FastAPI(title="Duty API", version="0.1.0")

app.include_router(department_controller.router, prefix="")


@app.get("/health")
def health():
    return {"status": "ok"}
```

打开 <http://127.0.0.1:8000/docs>，预期看到“单位”分组下五个端点，另有应用级 `/health`。检查路径中没有 `/api/v1`，集合路径没有末尾斜杠。

### 常见错误

- 全部业务接口 404：检查根 `include_router` 和模块 `prefix`，不要自行添加 `/api/v1`。
- 列表 422：检查 `Depends()`、`DepartmentQueryParams` 以及查询参数名称。
- 新增 200：POST 装饰器缺 `status.HTTP_201_CREATED`。
- 删除 200 或有正文：DELETE 装饰器未声明 204，或函数返回了被删除对象。
- 输出结构不符合模型：检查每个路由的 `response_model`，不要只在函数注解上写返回类型。

## 阶段 6：验证状态码与提交（教材步骤 6）

### 6.1 手工验证

服务从空表启动后，在 `/docs` 按顺序执行。实际值必须如实填写，不得直接把预期列抄到实际列。

| 顺序 | 方法与 URL | 输入 | 预期结果 |
| ---: | --- | --- | --- |
| 1 | GET `/departments` | 无 | 200，`{"items": [], "total": 0}` |
| 2 | POST `/departments` | `{"dept_code":"D01","full_name":"一中队","address":"一号楼"}` | 201，返回三字段 |
| 3 | POST `/departments` | 与上一步相同 | 400，“单位编码已存在” |
| 4 | POST `/departments` | `{"dept_code":"D02"}` | 422，缺 `full_name` |
| 5 | POST `/departments` | 分别新增 D02“二中队”、D03“三中队” | 两次均 201 |
| 6 | GET `/departments?page=1&page_size=2` | 查询参数 | 200，D01/D02，`total=3` |
| 7 | GET `/departments?page=2&page_size=2` | 查询参数 | 200，仅 D03，`total=3` |
| 8 | GET `/departments?page=3&page_size=2` | 查询参数 | 200，`items=[]`，`total=3` |
| 9 | GET `/departments?page=0` | 查询参数 | 422，页码小于 1 |
| 10 | GET `/departments/D01` | 路径参数 | 200 |
| 11 | PUT `/departments/D01` | `{"full_name":"第一中队"}` | 200，编码和地址保持 |
| 12 | GET `/departments/D404` | 路径参数 | 404，“单位不存在” |
| 13 | DELETE `/departments/D01` | 路径参数 | 204，响应体为空 |
| 14 | DELETE `/departments/D01` | 路径参数 | 404，不能重复删除 |

课堂最低要求是 200、201、204、404、422 各出现一次；教师参考额外强制覆盖 400 和分页行为。

### 6.3 两组一致性复查与提交

1. 逐字段比对表结构、`DepartmentOut`、实际详情响应与列表 `items`：`dept_code`、`full_name`、`address` 一致。
2. 逐文件比对模块目录和磁盘：controller、service、crud、model、schema、param 齐全，`__init__.py` 另行存在。
3. 若发现差异，先写期望值和实际值，再判定是文档问题还是实现问题，不默认以某一方为准。
4. 提交设计文档、补全后的最小实现、自己的接口验证记录。

### 常见错误

- 只验证成功路径，漏掉 400、404、422 或删除后的空响应体。
- 在已有数据的服务上机械套用“空列表”预期；重启服务清空内存后再按顺序验证。
- 第二页只检查 `items`，漏查 `total` 必须仍为 3。
- 把 422 当作服务异常；它是请求不符合模型的正常拒绝。
- 为了“通过”而直接修改实际状态码；验证记录必须来自真实请求。
