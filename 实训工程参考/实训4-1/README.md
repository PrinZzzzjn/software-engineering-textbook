# 综合实训 4-1：接口与设计综合实践（教师用工程参考）

> 对应教材：第 4 章 4.2–4.5 与章末「◆ 综合实训 4-1」  
> 学时：4 学时，共 180 分钟  
> 课堂达标（B 档）：六文件 + 列表/新增两个接口，验证 200/201/400/422；详情/修改/删除与 204/404 保留为教师完整版参考  
> 示例对象：单位（`department`）  
> 交付：设计文档、六文件最小实现、接口验证记录

本目录是教师完整版，包含答案工程与实跑记录，不直接作为学生提交模板。学生从 `starter/` 开始，按 `实训手册/实训4-1/` 的分步指南学习；完成态代码以教材 4.5 为唯一事实源。

## 一、概览

| 项目 | 内容 |
| --- | --- |
| 主目标 | 把“对象 → 表 → 模块 → 接口 → 六文件”落成一致的设计与代码 |
| 验证目标（B 档） | 列表与新增两个接口可调用，200/201/400/422 均可复现；204/404 为教师完整版演示 |

| 组织形式 | 教师演示 + 学生独立完成 starter；课堂统一使用单位示例 |
| 数据方式 | `dataclass` + 内存列表 `TABLE`，进程重启后清空 |
| 完成态入口 | `项目/main.py` |

| 自动验证 | `项目/tests/test_api.py`，使用 FastAPI `TestClient` |

课堂只保留“六文件设计”一个主目标和“接口状态码”一个验证目标。自选对象的完整改编不占用课堂必做时间。

> **B 档口径（2026-11-23）**：课堂必做是六文件 + 列表/新增两个接口，验证 200/201/400/422；目标 2、4、5 中的详情/修改/删除、完整五接口、404/204 属于“完整达成（教师版）”，不计入课堂达标。

完成本实训后，学生应能：

1. 为一个业务对象写出字段、类型、主键与一句话模块职责；有关联时说明外键为何位于“多”的一方。
2. 写出列表、详情、新增、修改、删除五个接口的方法、URL、参数来源和成功状态码。
3. 说明 controller、service、crud、model 四层及 schema、param 两类边界的职责。
4. 用六文件实现五个接口，列表用 `Depends()` 注入分页参数，输出使用 `response_model`。
5. 区分输入校验失败 422、编码重复 400、资源不存在 404，并验证删除 204 无正文。
6. 完成“表字段 ↔ 接口返回字段”“模块目录 ↔ 六文件”两组一致性检查。

## 三、边界

- 只做单位模块的内存版五个接口，不引入其他业务模块。
- 不建 `app/core/`，不使用 SQLAlchemy、数据库文件、认证或权限。
- 不使用 `/api/v1` 前缀；完整路径就是 `/departments` 与 `/departments/{dept_code}`。
- 不实现排序和复杂筛选；分页只有 `page`、`page_size`。
- 运行依赖仅 `fastapi`、`uvicorn`；`httpx`、`pytest` 仅用于教师测试。
- 内存数据不作为持久化成果，重启清空属于预期行为。
- 自动测试由教师参考提供；第 12 章才系统讲测试，本课学生可在 `/docs` 手工验收。

## 四、准备

1. Python 3.10 及以上，可运行 `python`、`pip`；浏览器可访问本机服务。
2. 已学第 3 章 3.4–3.6：四个方法、输入模型、`HTTPException`。
3. 已读第 4 章 4.2–4.5，能说出五动作接口组与六类职责。
4. 教师课前在干净环境安装依赖并运行一次 `项目/tests/test_api.py`。
5. 学生复制 `starter/`，准备设计文档空白稿；不要在完成态 `项目/` 上直接填写答案。
6. 若使用虚拟环境，应建在系统临时目录或课程指定位置，不放进本仓库。

## 八、快速开始

在本目录执行：

```powershell
cd 项目
python -m pip install -r requirements.txt
python -m uvicorn main:app --port 8000
```

打开 <http://127.0.0.1:8000/docs>。另开 PowerShell 运行教师测试：

```powershell
python -m pip install httpx pytest
python -m pytest tests/test_api.py
```

也可在本实训根目录直接运行 `python -m pytest 项目/tests/test_api.py`。服务停止按 `Ctrl+C`；再次启动后内存为空。

## 十、排错

| 现象 | 先查什么 | 处理 |
| --- | --- | --- |
| `/docs` 打不开 | 是否在 `项目/` 或 `starter/` 内启动，端口是否被占用 | 用 `python -m uvicorn main:app --port 8000`，确认地址端口一致 |
| 所有业务接口 404 | `main.py` 是否挂 router，模块前缀是否为 `/departments` | `include_router(..., prefix="")`，不加版本前缀 |
| `ModuleNotFoundError: app` | 当前目录与包文件 | 回到含 `main.py` 的目录，补齐三个 `__init__.py` |
| starter 调用报 `NotImplementedError` | 是否仍在骨架中 | 按 TODO 补 crud、service 和 controller，属于预期起点 |
| 新增仍是 200 | POST 装饰器 | 声明 `status_code=status.HTTP_201_CREATED` |
| 删除是 200 或有正文 | DELETE 装饰器和函数返回 | 声明 204，只调用 service，不返回内容 |
| 重复编码变 422 | 是否把业务重复当字段格式 | service 查重并抛 `HTTPException(400)` |
| 缺字段却进入函数 | 请求体是否仍为 `dict` | 改用 `DepartmentCreate`/`DepartmentUpdate`，由 Pydantic 返回 422 |
| 分页非法却返回 200 | `DepartmentQueryParams` 与 `Depends()` | 检查 `ge=1`、`le=100`，列表签名使用模型注入 |
| 修改清空了未提交字段 | 是否直接 `model_dump()` | 更新时使用 `exclude_unset=True` |
| 输出出现内部字段 | 路由是否缺 `response_model` | 列表用 `DepartmentPage`，单条用 `DepartmentOut` |
| 重启数据消失 | 是否误以为已使用数据库 | 这是内存版预期；持久化留待第 6 章 |

## 十一、提交

学生提交三项：

1. 设计文档：参照 `设计文档.md` 的三节和两组检查，不抄结论代替自己的核对。
2. 最小实现：由 `starter/` 补全的六文件代码与根 `main.py`。
3. 接口验证记录：按方法、URL、输入、预期、实际、结论填写，400 也建议记录。

提交前删除 `__pycache__/`、`.pytest_cache/`，不要提交虚拟环境、数据库或 `.env`。教师的 `验证记录.md` 是本参考工程的实测凭证，不代替学生自己的记录。
