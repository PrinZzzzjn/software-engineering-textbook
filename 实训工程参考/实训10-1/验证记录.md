## 五、教材一致性核对

| 教材要求 | 工程落点 | 结论 |
| --- | --- | --- |
| 10.1 执勤记录表字段：人员、哨位、开始、结束、状态 | `duty_record/model.py` | 一致 |
| 10.1 人员与哨位是已存在的参照数据 | 10-1 新建哨位模块；人员沿用 9-1 | 一致（哨位为补全项，见 README 3.4） |
| 10.2 规则一「开始早于结束」 | `_validate_duty_record` 第 1 步 | 一致 |
| 10.2 规则二「人员与哨位必须存在」 | 第 2、3 步 | 一致 |
| 10.2 规则三「同一哨位时间不重叠」 | `find_overlap` + 第 4 步 | 一致 |
| 10.2 重叠条件严格不等号 | `start_time < end_time` 且 `end_time > start_time` | 一致；首尾相接 201 |
| 10.2 校验顺序：时间 → 人员 → 哨位 → 重叠 | `service.py` 语句顺序 | 一致；两条顺序用例锁定 |
| 10.3 四个落点与归属判据 | 规则清单七列 | 一致 |
| 10.4 业务失败 400、格式失败 422、不存在 404 | service 与 Pydantic | 一致 |
| 10.4 先校验后写入 | `create_duty_record` | 一致；失败无残留用例 |
| 实训 10-1 步骤 1–6 | 分步指南阶段 1–6 | 一致 |
| 接口契约（无 PUT、`{items,total}`、204 无正文） | controller | 与 `duty-simplified` 一致 |

差异记录（有意为之，非教材错误）：

1. 教材 10-1 假定哨位表已存在，但 9-1 实训链未包含；本实训补建最小哨位模块，并在 README 3.4 说明。
2. 9-1 起写接口统一管理员；`_shared/接口契约清单.md` 已同步补注，避免前端实训按「公开写」实现。
3. 执勤记录读接口保持公开，教材未要求收紧；如课堂需要，可作为课后扩展。
