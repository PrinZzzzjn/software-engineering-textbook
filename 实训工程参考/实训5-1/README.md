# 实训 5-1：项目初始化与版本控制（教师用工程参考）

> 对应教材：第 5 章 5.1–5.6 与章末「◆ 实训 5-1」  
> 学时：4 学时，共 180 分钟  
> 示例对象：单位（`department`）  
> 交付：可启动工程、更新后的设计文档、验证记录、可读 Git 历史

本目录是教师完整版，包含完成态、学员起点与真实实跑记录，不直接作为学生提交模板。学生复制 `starter/` 后补全根目录配置并亲自完成 Git 操作；六个模块文件直接复用综合实训 4-1，不重写业务实现。

## 一、概览

| 项目 | 内容 |
| --- | --- |
| 主目标 1 | 把 4-1 六文件产物补成可启动、可换机安装、配置边界清楚的工程 |
| 主目标 2 | 用 Git 完成两次初始提交、功能分支合并与一次冲突解决 |
| 综合验证 | `/health`、`/docs`、`/departments` 可访问，历史与忽略规则可检查 |
| 数据方式 | `dataclass` + 内存列表 `TABLE`，进程重启后清空 |
| 完成态入口 | `项目/main.py` |
| 学员起点 | `starter/起点说明.md` 与已完成的 4-1 `app/` |
| 教师冒烟 | 实训根目录 `verify_api.py`，使用 FastAPI `TestClient` |

本实训不另起业务模块。课堂增量是工程化与版本控制，而不是再写一次 CRUD。

## 二、目标

完成本实训后，学生应能：

1. 说明根入口、六类模块文件和根目录配置各自的职责，沿一条请求说清调用路径。
2. 使用 `include_router(..., prefix="")` 装配单位路由，验证 `/health` 200、`/docs` 200。
3. 创建虚拟环境并依据 `requirements.txt` 安装依赖，区分运行依赖与教师验证依赖。
4. 用 `.env.example` 提供配置示例，用 `.gitignore` 排除本机环境、密钥、数据库、日志与缓存。
5. 完成 Git 初始化、暂存和两次初始提交，写出能说明意图的提交信息。
6. 在 `feature/health-version` 上修改并合并 `/health`，再制造、识别并解决一次同处修改冲突。
7. 以磁盘和实际请求为准同步设计文档、README 与验证记录。

## 三、边界

- 以 4-1 完成态为起点，只迁移 `app/` 与六个模块文件；不新增、不重写业务模块文件。
- 根 `main.py` 只创建应用、提供 `/health` 并挂路由；单位接口完整路径没有 `/api/v1`。
- 不建数据库，不写 `create_all`，不导入 `app.core.database`，不生成 `*.db`。
- 不建 `app/core/`；`database.py` 第 6 章加入，`security.py` 第 8 章加入。
- 不在项目中建 `tests/`；第 12 章才系统加入。根目录 `verify_api.py` 仅供教师冒烟验收。
- 不加入认证、JWT、SQLAlchemy、复杂筛选或前端；五个单位接口行为与 4-1 保持一致。
- `.env.example` 可以纳入 Git；`.env`、虚拟环境、日志、数据库与缓存不得进入完成态快照。
- 内存数据重启清空是预期行为，不用数据库文件弥补本阶段尚未出现的职责。

## 四、准备

1. Python 3.10 及以上、Git 和浏览器可用，分别执行 `python --version`、`git --version` 检查。
2. 已完成综合实训 4-1，能说明六文件职责与五个接口；本参考直接提供其单位模块产物。
3. 保留自己的 4-1 设计文档和接口验证记录，本实训结束时要更新目录与启动证据。
4. 阅读教材 5.1–5.6，准备一份工程目录清单。
5. 学生复制 `starter/` 到可写的课程工作目录，不直接改教师 `项目/` 或起点原件。
6. 教师课前按 `验证记录.md` 复跑；课堂文档端口统一为 8000，本参考实测使用 8012 以避免冲突。

## 八、快速开始

在本目录执行，使用项目内的课堂虚拟环境；该目录已被 `.gitignore` 排除：

```powershell
Set-Location 项目
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn main:app --port 8000
```

打开 <http://127.0.0.1:8000/docs>，另开终端请求：

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8000/health
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8000/departments
```

教师冒烟需在虚拟环境中另装 `httpx`、`pytest`，然后在本实训根目录执行：

```powershell
python -m pip install httpx pytest
python verify_api.py
```

停止 uvicorn 按 `Ctrl+C`。Linux/macOS 激活命令为 `source venv/bin/activate`；PowerShell 激活受限时，直接使用 `venv\Scripts\python.exe` 调用 `pip` 与 `uvicorn`，不要关闭系统安全策略。

## 十、排错

| 现象 | 先查什么 | 处理 |
| --- | --- | --- |
| 服务起不来 | 当前目录、依赖、语法、8000 端口 | 在含 `main.py` 的项目根启动；查看完整 traceback，换端口仅用于排障 |
| `/docs` 打不开 | 服务进程与启动对象 | 使用 `python -m uvicorn main:app --port 8000`，确认访问同一端口 |
| 业务接口全 404 | 根装配与模块前缀 | 根用 `prefix=""`，模块用 `/departments`；不要加 `/api/v1` 或末尾斜杠 |
| `ModuleNotFoundError: app` | 当前目录和三个 `__init__.py` | 回到项目根执行，恢复 4-1 包文件 |
| `ModuleNotFoundError: app.core.database` | 是否误抄后续章节入口 | 删除数据库导入与 `create_all`；本章不需要该文件 |
| 虚拟环境未生效 | `sys.prefix` 与命令路径 | 激活后再安装；或直接使用 `venv\Scripts\python.exe` |
| 换机依赖装不齐 | 是否在正确目录、网络与 Python 版本 | 在清单所在目录执行 `python -m pip install -r requirements.txt` |
| `git status` 出现 venv 或 `.env` | `.gitignore` 路径和是否已跟踪 | 首次提交前修正规则；已跟踪时用 `git rm -r --cached venv` 等命令移除索引 |
| Git 提交无作者信息 | 本地 `user.name`、`user.email` | 只在当前仓库设置课程用身份，不改全局配置 |
| 合并后出现冲突标记 | `git status` 与冲突文件 | 保留目标内容，删除 `<<<<<<<`、`=======`、`>>>>>>>`，再 add 和 commit |
| 冲突解决后语法错误 | 是否残留标记或重复 return | 运行 `git diff --check`、`python -m py_compile main.py` 后再提交 |
| 重启后单位消失 | 是否误解内存存储 | 这是 4-1/5-1 预期；持久化到第 6 章实现 |

## 十一、提交

学生提交四项：

1. 更新后的设计文档：目录一节与本实训磁盘一致，标注 4-1 到 5-1 的变化。
2. 项目仓库：六文件、根入口、依赖、配置示例、忽略规则与 README；不含本机环境和密钥。
3. `git log --oneline --graph` 与 `git status` 输出：能辨认两次初始提交、功能分支和冲突合并。
4. 自己的验证记录：`/health`、`/docs`、`/departments` 实际状态码，依赖安装和冲突处理结论。

提交前用 `git ls-files` 检查跟踪清单。教师完成态、难度评分和实测记录用于备课与验收，不代替学生操作。

## 十二、扩展

以下均为课后扩展，不占 180 分钟必做时间：

1. 在另一台机器或新的临时目录只依据 README、requirements 与 `.env.example` 复现安装和启动。
