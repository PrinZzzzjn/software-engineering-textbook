# 实训 5-1 难度评分

## 量化结果

| 指标 | 结果 | 统计口径 |
| --- | --- | --- |
| 初评 | **D2 / L3 / 合理** | 与总计划 4.5 一致 |
| 实施校准 | **D2 / L3 / 合理** | 六文件原样迁移降低编码量，但 Git 状态与冲突协商仍达到 L3 |
| 学生新增有效代码与配置 | **17 行** | 根 main 7 行、requirements 2 行、`.env.example` 1 行、`.gitignore` 7 行；非空且非注释 |
| 学生新增/重建文件 | **5 个** | main、requirements、`.env.example`、`.gitignore`、项目 README；六文件只迁移不计新增 |
| 教师验证代码 | **另计，不布置学生编写** | 根 `verify_api.py` 是教师冒烟工具，不属于项目 tests |
| 完成态项目文件 | **14 个** | 5 个根文件 + app 内 9 个文件，含三个空 `__init__.py` |
| 主动掌握新概念 | **2 组** | 可复现工程（目录/venv/配置）与 Git 协作（提交/分支/冲突） |
| 预计用时 | **180 分钟** | 含 45 分钟排错，占 25%，符合 20%–30% 规则 |

代码量按学生需要新增或重建的有效代码、配置统计，README 与迁移的六文件不重复计入。17 行本身落在 D1 行数区间，但涉及 5 个文件，按总计划“行数与涉及文件”两项取较高等级，因此定为 **D2**。教师脚本只证明完成态可运行，不用它抬高学生编码等级。

教材初评曾把工程目录、虚拟环境/配置、Git 分列为 3 个接触点。实施时将前两项合并为“可复现工程”一个主目标，Git 为另一个主目标，避免同时开第三条主线；配置读取、版本锁定机制和复杂分支模型不要求课堂推导。

## 难度来源

1. **增量分散在根目录**：代码行数少，但学生要同时判断入口、依赖、配置示例、忽略规则和 README 的位置与职责，达到 D2 的文件跨度。
2. **迁移正确性依赖前置产物**：若使用本参考 starter，六文件已经包化，无改动即可运行；若自己的 4-1 仍残留应用对象或平铺导入，必须先按教材修正再迁移。
3. **Git 是有状态操作**：工作区、暂存区、本地仓库与分支指针共同决定结果，不能靠逐条背命令判断当前状态。
4. **冲突需要契约判断**：删除标记只是形式，最终健康响应保留哪些字段需要人工协商；这使学生达到含状态处理的 L3，而不是单纯文件复制。
5. **两类可运行证据不同**：TestClient 冒烟证明应用行为，uvicorn 真实请求证明进程与端口可用，验证记录必须分别呈现。

## 180 分钟分配是否成立

| 阶段 | 分钟 | 其中排错 | 必做产出 |
| --- | ---: | ---: | --- |
| 准备与起点检查 | 10 | 0 | 4-1 app 副本、Python/Git 版本 |
| 迁移与包检查 | 15 | 3 | `/departments` router 可导入 |
| 配置与入口 | 25 | 5 | 五个根文件、无数据库装配 |
| venv 与依赖 | 20 | 5 | 独立环境与安装输出 |
| Git 两次初始提交 | 30 | 7 | 忽略提交、工程提交、跟踪清单 |
| 分支合并与冲突 | 35 | 10 | 健康版本提交、真实冲突合并、历史图 |
| 启动与文档同步 | 20 | 5 | 三个地址实测、目录文档一致 |
| 出口验收 | 10 | 0 | 状态、历史、配置逐项核对 |
| 机动 | 15 | 10 | 集中排错与 5 分钟进度缓冲 |
| **合计** | **180** | **45** | 排错占 25% |

结论是**时间分配合法且总体合理**：教材六步共 145 分钟，准备、验收和机动补足到 180 分钟；45 分钟排错已经显式纳入，而不是课外追加。六文件无需重写给 Git 演练留出时间，35 分钟足以完成一次快进合并和一次确定性冲突。

成立条件是教师提供已包化的 4-1 starter、课前确认 Python/Git 可用、课堂不展开数据库或测试框架。若要求学生同时修复残缺 4-1、锁定全部依赖或完成跨机互验，180 分钟不再保证；这些内容转为课后或先修补救。时间不足时优先保留两次初始提交、功能分支和冲突合并，扩展项可全部删除。

## 合理性核对

- **前置齐全**：starter 含 4-1 六文件与包文件，无数据库、账号或额外数据前置。
- **失败可定位**：README 排错表覆盖导入、404、依赖、忽略规则、冲突和文档不一致。
- **验收可观测**：状态码、响应结构、Git 历史图、跟踪清单和安装输出均可留存。
- **教材可对应**：README 映射表覆盖 5.1–5.6 与六个实训步骤。
- **难度承接**：4-1 的 L3 分层调用直接复用，5-1 新增 Git 状态但不增加业务层复杂度；到 6-1 才上升为数据库与事务相关难度。
