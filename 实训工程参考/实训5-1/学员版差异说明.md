# 实训 5-1 学员版差异说明

学员版的目标不是再次完成 4-1，也不是从完成态反推答案，而是亲手补根目录配置并操作 Git。发放时以 `starter/` 为代码起点，配套学生任务说明、分步指引和空白验收记录。

## 学生需要亲自完成的内容

1. 复制 starter，在根目录新建 `main.py`、`requirements.txt`、`.env.example`、`.gitignore`、README。
2. 按教材写 `prefix=""` 与健康响应，不以旧手册 `/api/v1` 为答案。
3. 创建并激活虚拟环境，依据自己的清单安装依赖。
4. 初始化 main，先提交 `.gitignore` 再提交工程，检查跟踪清单。
5. 完成 `feature/health-version` 修改和合并，再与同伴或按教师脚本制造一次冲突，人工决定最终响应。
6. 真实启动 8000 端口，记录 `/health`、`/docs`、`/departments` 的实际结果，并同步 4-1 设计文档目录。

## 可以保留的脚手架与提示

- 可给出 `.gitignore` 的排除类别，不要求学生凭记忆背所有扩展名。
- 可给出确定性冲突的操作分支名与检查命令，但最终保留内容必须由学生根据目标契约决定。
- 可提供空白验证表和排错清单，不预填实际输出。
- 学生若使用自己的 4-1 产物，先核对包结构；若 controller 仍创建 FastAPI 或导入仍为平铺形式，应按教材迁移要求修正。使用本参考 starter 时则明确“无改动，仅迁移”。

## 回收与验收差异

学生提交自己的工作仓库、更新后的设计文档、真实 Git 历史图和验证记录，不要求与教师 Git 哈希、提交时间或临时健康字段相同。必须相同的是：六文件职责与接口契约、根空前缀、依赖/配置边界、无数据库与 tests、至少三次可读提交、一次分支合并和一次已解决冲突。
