# 实训 16-1 数据读取与展示项目案例

本实训把 15-1 的单位管理页从假数据接到真实后端：先跑通 `/health`，再接登录拿令牌，把地址、超时、请求头与错误收进 `api_client`，最后用 `GET /departments` 读列表、`POST /departments` 新增，并补齐加载、空、错误三种状态。完成态见 `项目/`，学员起点见 `starter/`，实跑证据见 `验证记录.md`。

## 三、边界与不变量

### 3.1 请求四要素与封装四统一

| 四要素 | 本工程写法 |
| --- | --- |
| 地址 | `API_BASE_URL` + 路径，路径与 `/docs` 一致，无 `/api/v1` |
| 方法 | 查用 `GET`，登录与新增用 `POST` |
| 参数 | 查询用 `params`，请求体用 `json` |
| 请求头 | `Authorization: Bearer <token>`，由 `_headers` 自动注入 |

封装只做四件事：地址、超时、请求头、错误。不加重试、缓存、并发，避免把客户端做成小框架。

### 3.2 接口契约

- 业务路径直接挂在根下：`/departments`、`/users/login`、`/health`；
- 列表响应固定 `{items, total}`，前端先取 `items`；
- 新增成功 201，重复编码 400，未认证 401，不存在 404，字段校验 422；
- `GET /departments` 是公开接口，无效令牌仍能读；401 主要在写接口出现。

### 3.3 三种状态的职责

| 状态 | 触发 | 界面 | 回答的问题 |
| --- | --- | --- | --- |
| 加载态 | 请求进行中 | `st.spinner` | 还要等多久 |
| 空态 | 成功但 `items=[]` | `st.info` | 为什么没有数据、下一步做什么 |
| 错误态 | 连不上、400、401、404、422 | `st.error + st.stop` | 哪一步失败、怎么修 |

空数据不是错误：`items=[]` 用 `st.info`，不能用 `st.error` 或 `st.stop`。

### 3.4 不做的范围

- 不做翻页 UI（只取第 1 页，每页 10 条）；
- 不做编辑、删除（18-1）；
- 不做多页导航与统一登录守卫（17-1）；
- 不引入 `components/`、`auth.py`，页面保持单文件；
- 不改教材正文与接口字段。

## 六、操作步骤

1. **跑通一次请求（10 分钟）**：`requests.get("http://127.0.0.1:8000/health")`，确认 200 与 `{"status": "healthy"}`；地址、端口、路径逐项核对。
2. **接登录（15 分钟）**：`st.form` 收集用户名与密码；`POST /users/login` 成功后把 `access_token` 与 `user` 放进 `session_state`，再 `st.rerun()`；未登录时 `st.stop()`。
3. **封装客户端（15 分钟）**：建 `config.py` 与 `api_client.py`；页面只调 `api.get` / `api.post`；401 清令牌，422 把列表 detail 压平。
4. **列表与三态（15 分钟）**：`GET /departments?page=1&page_size=10`，名称搜索用 `params` 传 `full_name`；加载用 spinner、空态用 info、错误用 error + stop；新增改 `POST`，成功用 flash + rerun 刷新。
5. **排错与自测（10 分钟）**：把 `API_PREFIX` 改成 `/api/v1` 制造 404，按顺序记录；再用无效令牌触发 401；最后跑 `verify_app.py`。

详细代码与排错见 [分步实现指南.md](分步实现指南.md)。

## 九、验收标准

| 验收项 | 判定方式 |
| --- | --- |
| 接口调用正确 | 四要素与后端 `/docs` 一致，路径无版本前缀 |
| 客户端统一 | 页面无完整 URL；地址、超时、请求头、错误四处收拢 |
| 登录闭环 | 登录失败有可读提示；令牌过期回到登录页 |
| 三态齐全 | 加载、空、错误都有界面反馈；空态不是 error |
| 新增与错误 | 201 成功刷新；400/401/422 均有可读提示 |
| 排错有据 | 至少一份按「状态码 → detail → `/docs` → 代码」的记录 |
| 自测 | `verify_app.py` 全过 |

## 十、常见问题与排错

| 现象 | 先查什么 |
| --- | --- |
| 连不上后端 | 后端是否启动；`API_BASE_URL` 与端口 |
| 404 | 是否多写 `/api/v1`；路径是否与 `/docs` 一致；资源名是否复数 |
| 401 但列表能看 | 列表是公开接口；401 只会在写接口出现 |
| 422 显示一串字典 | 是否把 `detail` 列表压平后再显示 |
| 表格有行无值 | 字段名是否与接口逐字一致；是否先取 `items` |
| 空数据显示成报错 | `items=[]` 是正常结果，应用 `st.info` |
| 新增成功但列表没变 | 是否在成功分支 `st.rerun()`；提示是否用 flash |
| 登录后马上回到登录页 | 令牌是否存进 `session_state`；是否被 401 清除 |
| 页面白屏 | 是否有未捕获异常；`st.stop()` 位置是否正确 |
