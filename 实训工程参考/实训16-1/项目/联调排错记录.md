# 实训 16-1 联调排错记录

> 目的：按教材 16.5 的顺序「状态码 → detail → `/docs` → 代码」，记录三次故意制造的失败与定位过程。
> 环境：Windows，Python 3.13.15，后端 13-1 项目跑在 8000，前端 Streamlit 8501。

## 一、404：路径多写了版本前缀

| 步骤 | 内容 |
| --- | --- |
| 现象 | 页面显示 `Not Found`，单位列表完全不出现 |
| 状态码 | 404 |
| detail | `Not Found` |
| `/docs` | 业务路径是 `/departments`，没有 `/api/v1` 前缀 |
| 代码 | `config.py` 的 `API_PREFIX` 被临时改成 `"/api/v1"` |
| 结论 | 地址拼错，不是令牌或字段问题；恢复 `API_PREFIX = ""` 后列表恢复 |
| 排查顺序 | 状态码 404 → detail 只说明资源不存在 → `/docs` 确认路径 → 回到 `config.py` |

## 二、401：令牌失效

| 步骤 | 内容 |
| --- | --- |
| 现象 | 页面先提示「登录已过期，请重新登录」，随后回到登录页 |
| 状态码 | 401 |
| 后端 detail | `令牌无效`（缺令牌时为 `未提供令牌`） |
| 页面 detail | `登录已过期，请重新登录`（`api_client` 统一改写） |
| `/docs` | `GET /departments` 是公开接口，读列表不会 401；`POST /departments` 要求管理员，才会校验令牌 |
| 代码 | 把 `session_state["access_token"]` 改成 `invalid-token`，再提交新增，模拟令牌过期 |
| 结论 | `_request` 捕获 401 后清除 `access_token`，页面写 `login_notice` 并重跑，登录页提示原因 |
| 排查顺序 | 状态码 401 → detail 指向登录态 → `/docs` 确认认证方式 → 检查 `_headers` 与令牌来源 |

## 三、422：字段超长

| 步骤 | 内容 |
| --- | --- |
| 现象 | 新增单位时页面显示「String should have at most 100 characters」，没有新增成功 |
| 状态码 | 422 |
| detail | FastAPI 返回列表，`api_client` 压平成一句话后显示 |
| `/docs` | `full_name` 约束为 1–100 |
| 代码 | 表单只校验非空，没有校验长度；输入 101 个「超」字 |
| 结论 | 前端校验不能替代后端校验；422 的列表 detail 必须先压平再显示 |
| 排查顺序 | 状态码 422 → detail 指出字段与约束 → `/docs` 核对 `max_length` → 前端补长度提示或直接展示后端信息 |

## 四、顺序总结

| 现象 | 先查什么 | 本次定位到的位置 |
| --- | --- | --- |
| 404 | 地址前缀、路径拼写、尾斜杠 | `config.API_PREFIX` |
| 401 | 是否登录、请求头、令牌是否过期 | `api_client._request` 的 401 分支 |
| 422 | 请求体字段名、类型、长度 | `DepartmentCreate` 的 `max_length=100` |

三次都没有先改业务代码：先确认请求发到哪、后端回了什么，再定位到具体文件。
