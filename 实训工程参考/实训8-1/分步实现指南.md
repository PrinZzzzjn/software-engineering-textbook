# 实训 8-1 分步实现指南

本指南按教材 8.1–8.4 的顺序，把 7-1 的落库工程改造成带登录认证的工程。每个阶段都给出完成态代码、检查点与常见错误。标注「完成态文件」的代码块与 `项目/` 中的同名文件逐字一致；标注「片段」的代码块只用于说明本阶段要补的部分，阶段结束时以完成态文件为准。

约定：

- 命令默认在 `项目/` 目录执行，端口用 8000；`验证记录.md` 的 8015 只用于教师隔离验证。

    db.commit()

## 阶段 3：密码盐哈希与内存令牌（30 分钟）

### 3.1 为什么不存明文

明文一旦泄露，所有账号立即失守；数据库备份、日志、误提交都可能泄露。哈希是单向的，校验时只能「重算再比较」，不能还原。盐保证相同密码得到不同结果，攻击者不能拿一张预计算表批量比对。

本阶段先写 `app/core/security.py` 的上半部分（片段，阶段 5 再补依赖与当前用户）：

```python
import hashlib
import secrets


ITERATIONS = 100_000


def get_password_hash(password: str) -> str:
    salt = secrets.token_hex(16)
    digest = hashlib.pbkdf2_hmac(
        "sha256", password.encode("utf-8"), bytes.fromhex(salt), ITERATIONS
    ).hex()
    return f"{salt}${ITERATIONS}${digest}"


def verify_password(plain_password: str, hashed_password: str) -> bool:
    salt, iterations, digest = hashed_password.split("$", 2)
    candidate = hashlib.pbkdf2_hmac(
        "sha256", plain_password.encode("utf-8"), bytes.fromhex(salt), int(iterations)
    ).hex()
    return secrets.compare_digest(candidate, digest)


# 令牌表：token -> user_id，内存字典，进程重启即清空
TOKEN_STORE: dict[str, int] = {}


def create_access_token(user_id: int) -> str:
    token = secrets.token_hex(16)
    TOKEN_STORE[token] = user_id
    return token


def resolve_token(token: str) -> int | None:
    return TOKEN_STORE.get(token)
```

存储格式固定为 `盐$迭代次数$摘要`：盐是 32 位十六进制，迭代次数是十进制数，摘要是 64 位十六进制。校验时用 `split("$", 2)` 拆开，绝不要按固定下标切片。

### 3.2 检查哈希与令牌

```powershell
python -c "from app.core.security import get_password_hash, verify_password, create_access_token, TOKEN_STORE; h1=get_password_hash('secret123'); h2=get_password_hash('secret123'); print(h1 != h2, verify_password('secret123', h1), verify_password('wrong', h1)); t=create_access_token(1); print(len(t), TOKEN_STORE[t])"
```

预期：`True True False` 与 `32 1`。如果第一项是 `False`，说明盐没有真正随机；如果第二项是 `False`，检查盐与迭代次数在注册与校验两处是否一致。

### 3.3 为什么用盐哈希与内存令牌，而不是 JWT

JWT 是一种自包含的签名令牌：服务端把用户 id、过期时间等放进载荷，签名后整体发给客户端；后续请求不再查服务端存储，只验签名。它的优势是跨服务、无状态、易横向扩展；代价是需要管理签名密钥与算法、令牌在过期前难以撤销、载荷可见（不能放敏感信息），还要处理算法混淆、密钥轮换等细节。

本阶段选择「随机令牌 + 服务端字典」：

- 规模匹配：单进程、单数据库、课堂项目，只有三个认证接口，没有跨服务验签需求。
- 可撤销：登出时从 `TOKEN_STORE` 删除键即可立即失效；禁用由 `get_current_user` 检查 `is_active` 即时拦截。签名令牌要做到同样效果，得额外维护黑名单。
- 可观察：令牌就是一个随机串，学生能直接看到「服务端登记了什么」，便于理解认证不是客户端自说自话。
- 依赖最少：只用 `secrets` 生成随机数，不需要签名库、密钥配置与算法选择。
- 安全边界清楚：令牌不携带角色，角色每次从数据库读，9-1 改角色后立即生效。

代价是服务端有状态：`TOKEN_STORE` 是进程内字典，**服务重启后旧令牌全部失效**，需要重新登录；多进程部署时每个进程各有一份，互相不认。这是本阶段已知且可接受的行为，处理办法写在阶段 7。等系统需要多实例或无状态网关时，再把令牌存储换成数据库/Redis，或改为带签名与过期的令牌。

同理，本阶段不引入第三方密码库，用标准库 `hashlib.pbkdf2_hmac` 做带迭代次数的慢哈希；盐、迭代次数、摘要都可见。生产系统还可选用 scrypt、argon2，并配合更严格的密码策略。

## 阶段 4：注册与登录接口（40 分钟）

### 4.1 请求与响应模型（完成态文件：`app/modules/user/schema.py`）

```python
from pydantic import BaseModel, ConfigDict, Field


class UserCreate(BaseModel):
    username: str = Field(..., min_length=1, max_length=100)
    password: str = Field(..., min_length=6, max_length=128)


class UserOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    username: str
    role: str
    is_active: int


class UserLogin(BaseModel):
    username: str = Field(..., min_length=1, max_length=100)
    password: str = Field(..., min_length=1, max_length=128)


class TokenOut(BaseModel):
    access_token: str
    token_type: str = "bearer"
    user: UserOut
```

要点：

- `UserCreate` 的 `min_length=6` 让短密码在进入业务层之前就返回 422。
- `UserOut` 不含 `password_hash`；`from_attributes=True` 允许直接返回 ORM 对象。
- `TokenOut` 嵌套 `UserOut`，登录响应天然只有三个顶层字段。
- `UserCreate` **没有** `role` 字段。Pydantic 默认忽略多余字段，客户端传 `role=admin` 也不会生效，服务端始终写 `normal`。
- `UserLogin` 的密码只要求非空，不套注册的 6 位限制：老账号即使密码短，也应能走到校验逻辑并得到 401，而不是 422。

### 4.2 业务逻辑（完成态文件：`app/modules/user/service.py`）

```python
from fastapi import HTTPException

from app.core.security import create_access_token, get_password_hash, verify_password
from app.modules.user import crud
from app.modules.user.model import User


def create_user(db, data) -> User:
    if crud.get_by_username(db, data.username):
        raise HTTPException(status_code=400, detail="用户名已存在")
    return crud.create(db, data.username, get_password_hash(data.password))


def login(db, data) -> dict:
    user = crud.get_by_username(db, data.username)
    if not user or not verify_password(data.password, user.password_hash):
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    token = create_access_token(user.id)
    return {"access_token": token, "token_type": "bearer", "user": user}


def create_admin(db, username: str = "admin", password: str = "admin123") -> User:
    """幂等创建管理员账号，供启动 seed 与后续章节使用。"""
    user = crud.get_by_username(db, username)
    if user:
        return user
    user = crud.create(db, username, get_password_hash(password))
    return crud.update(db, user, {"role": "admin"})
```

要点：

- 查重放在服务层，返回 400；数据库唯一约束是最后一道防线。
- 登录时「用户不存在」与「密码错误」共用同一句 401，避免泄露账号是否存在。
- 先校验再签发令牌；校验失败不留下任何令牌。
- `create_admin` 幂等：已存在直接返回，不覆盖密码、不重复插入。它是教材三个接口之外唯一的补充，用于满足 `admin/admin123` 的验收与 9-1 的账号管理。

### 4.3 先写两个路由（片段：`app/modules/user/controller.py` 的前半部分）

```python
from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session

from app.core.database import get_db
from app.modules.user import service
from app.modules.user.schema import TokenOut, UserCreate, UserLogin, UserOut

router = APIRouter(prefix="/users", tags=["用户"])


@router.post("", response_model=UserOut, status_code=201)
def register(data: UserCreate, db: Session = Depends(get_db)):
    return service.create_user(db, data)


@router.post("/login", response_model=TokenOut)
def login_endpoint(data: UserLogin, db: Session = Depends(get_db)):
    return service.login(db, data)
```

注意 `@router.post("")` 的空字符串：它让最终路径是 `/users`，不是 `/users/`。如果写成 `"/"`，集合路径就会多一个尾斜杠，客户端访问 `/users` 会被重定向，验收时容易误判。

## 阶段 5：当前用户与依赖注入（30 分钟）

### 5.1 补全 security.py（完成态文件：`app/core/security.py`）

```python
import hashlib
import secrets

from fastapi import Depends, HTTPException
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from sqlalchemy.orm import Session

from app.core.database import get_db


ITERATIONS = 100_000


def get_password_hash(password: str) -> str:
    salt = secrets.token_hex(16)
    digest = hashlib.pbkdf2_hmac(
        "sha256", password.encode("utf-8"), bytes.fromhex(salt), ITERATIONS
    ).hex()
    return f"{salt}${ITERATIONS}${digest}"


def verify_password(plain_password: str, hashed_password: str) -> bool:
    salt, iterations, digest = hashed_password.split("$", 2)
    candidate = hashlib.pbkdf2_hmac(
        "sha256", plain_password.encode("utf-8"), bytes.fromhex(salt), int(iterations)
    ).hex()
    return secrets.compare_digest(candidate, digest)


# 令牌表：token -> user_id，内存字典，进程重启即清空
TOKEN_STORE: dict[str, int] = {}


def create_access_token(user_id: int) -> str:
    token = secrets.token_hex(16)
    TOKEN_STORE[token] = user_id
    return token


def resolve_token(token: str) -> int | None:
    return TOKEN_STORE.get(token)


bearer_scheme = HTTPBearer(auto_error=False)


def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme),
    db: Session = Depends(get_db),
) -> dict:
    if credentials is None:
        raise HTTPException(status_code=401, detail="未提供令牌")
    user_id = resolve_token(credentials.credentials)
    if user_id is None:
        raise HTTPException(status_code=401, detail="令牌无效")
    from app.modules.user import crud

    user = crud.get_by_id(db, user_id)
    if user is None:
        raise HTTPException(status_code=401, detail="令牌无效")
    return {"id": user.id, "role": user.role}
```

要点：

- `HTTPBearer(auto_error=False)`：缺头或 scheme 不是 Bearer 时返回 `None`，由我们统一给 401。默认的 `HTTPBearer()` 在缺头时由框架返回 403，不符合本章「认证失败 401」的口径。
- 令牌只用来查 `user_id`；角色每次从数据库读，9-1 改角色后立即生效，不需要重新登录。
- 用户被删除时，令牌还在字典里也返回 401，避免拿一个不存在的用户继续操作。
- 函数内导入 `crud` 是为了避免 `security` 与 `user` 模块在导入期互相牵连；这是本项目采用的写法。

### 5.2 补全 controller（完成态文件：`app/modules/user/controller.py`）

```python
from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session

from app.core.database import get_db
from app.core.security import get_current_user
from app.modules.user import service
from app.modules.user.schema import TokenOut, UserCreate, UserLogin, UserOut

router = APIRouter(prefix="/users", tags=["用户"])


@router.post("", response_model=UserOut, status_code=201)
def register(data: UserCreate, db: Session = Depends(get_db)):
    return service.create_user(db, data)


@router.post("/login", response_model=TokenOut)
def login_endpoint(data: UserLogin, db: Session = Depends(get_db)):
    return service.login(db, data)


@router.get("/me")
def me(current_user: dict = Depends(get_current_user)):
    return current_user
```

`/me` 没有 `response_model`，因为 `get_current_user` 已经只返回 `{id, role}` 两个字段，直接返回即可。

## 阶段 7：课后扩展（不计入 180 分钟）

### 7.1 令牌过期

把字典值改为 `(user_id, expires_at)`：

```python
import time

TOKEN_STORE: dict[str, tuple[int, float]] = {}

def create_access_token(user_id: int, ttl_seconds: int = 3600) -> str:
    token = secrets.token_hex(16)
    TOKEN_STORE[token] = (user_id, time.time() + ttl_seconds)
    return token
```

`get_current_user` 取出后先判断 `expires_at < time.time()`，过期则 `pop` 并 401。注意同时修改 `resolve_token` 的返回类型与所有调用点。

### 7.2 登出

新增 `POST /users/logout`，依赖 `get_current_user` 或直接读 Bearer 头，从 `TOKEN_STORE` 删除当前令牌，返回 204。随后用同一令牌访问 `/me` 应 401。若要多端登录只登出当前端，不要把该用户的全部令牌清空。

### 7.3 用户名与密码策略

用户名限制为 3–20 位字母、数字、下划线，注册时统一小写；密码增加大小写、数字、符号要求。策略要同时写进 `UserCreate` 与 README，避免接口文档与实际行为不一致。

### 7.4 生产级密码存储

把 PBKDF2 的迭代次数调高，或改用 scrypt、argon2；把算法标识也存进 `password_hash`，便于以后升级。盐仍然每个用户独立，比较仍然用常量时间比较。

### 7.5 多进程与共享令牌

`uvicorn --workers N` 会启动多个进程，每个进程的 `TOKEN_STORE` 互不相通，表现为「有时 200、有时 401」。解决办法是把 `token -> user_id/expires_at` 放进数据库或 Redis，或者改用带签名与过期的无状态令牌。做出选择前先写清撤销、过期、跨服务验签三个需求。
