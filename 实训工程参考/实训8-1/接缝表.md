## 三、修改文件与装配

`main.py` 的具体变化：

1. 顶部新增：

   ```python
   from app.modules.user import controller as user_controller
   from app.modules.user import model as user_model  # noqa: F401  建表前先导入模型
   from app.modules.user import service as user_service
   ```

2. 路由从两个变为三个，均 `prefix=""`：

   ```python
   app.include_router(department_controller.router, prefix="")
   app.include_router(personnel_controller.router, prefix="")
   app.include_router(user_controller.router, prefix="")
   ```

3. 新增 `_seed_admin()`，在 `_seed_departments()`、`_seed_personnel()` 之后执行。它调用 `user_service.create_admin(db)`，已存在直接返回。
4. `Base.metadata.create_all(bind=engine)` 的位置不变，但由于三个模型都已导入，建表范围自动扩展到 `users`。

`app/core/database.py` 不变：`engine`、`SessionLocal`、`Base`、`get_db` 的接口与 7-1 完全一致，user 模块直接复用。

## 五、接口契约变化

| 接口 | 认证 | 成功 | 失败 | 备注 |
| --- | --- | --- | --- | --- |
| `POST /users` | 否 | 201 `{id, username, role, is_active}` | 400 用户名已存在；422 | 客户端传 `role` 被忽略 |
| `POST /users/login` | 否 | 200 `{access_token, token_type, user}` | 401 用户名或密码错误；422 | `user` 四字段，无密码哈希 |
| `GET /users/me` | Bearer | 200 `{id, role}` | 401 未提供令牌/令牌无效 | 角色每次从库读 |
| `GET /health` | 否 | 200 `{"status":"healthy"}` | — | 不变 |
| department 五个接口 | 否 | 同 7-1 | 同 7-1 | 不变 |
| personnel 五个接口 | 否 | 同 7-1 | 同 7-1 | 不变 |

注册路径是 `POST /users`（教材 8-3-3），不是 `/users/register`。集合路径不带尾斜杠；客户端访问带尾斜杠的路径可能被框架重定向，验收一律以无尾斜杠为准。

## 六、不兼容点（7-1 → 8-1）

1. **新增 401 语义**：只有 `/users/me` 需要 Bearer；旧接口仍公开。学生若把 401 套到旧接口，属于越界，会破坏 7-1 回归。
2. **users 表首次出现**：旧库启动后多一张表；这不是破坏性变更，但备份/比对表结构时会看到差异。
3. **令牌重启失效**：`TOKEN_STORE` 在进程内，重启后旧令牌全部 401；账号仍在，可重新登录。这是已知行为，不是 bug。
4. **注册路径与尾斜杠**：`POST /users`，无尾斜杠；旧资料里的 `/users/register` 口径作废。
5. **密码规则收紧**：注册密码 6–128 位；5 位返回 422。登录只要求非空，避免老账号被 422 挡住。
6. **角色不可由客户端指定**：`UserCreate` 没有 `role`，多余字段被忽略；服务端固定 `normal`，只有 seed 的 `create_admin` 写 `admin`。
7. **admin seed**：首次启动写入 `admin/admin123`；运行中删除 admin，不会自动重建，需重启或手工调用 `create_admin`。
8. **新增内部函数**：`service.create_admin`、`crud.update`、`param.UserQueryParams` 在 8-1 没有对外路由，供 9-1 复用；不影响接口契约。
9. **401 而非 403**：本实训不做权限判断，所有已登录用户对 `/me` 都返回自己的 `{id, role}`；403 留到 9-1。
10. **未实现登出**：令牌只能等进程重启或从服务端字典删除才失效；没有 `POST /users/logout`。

## 七、回归契约（8-1 必须保持）

以下内容在 8-1 中不可改变，9-1 若无明确要求也不应改变：

- department：`GET /departments` 返回 `{items, total}`，默认 `page=1`、`page_size=10`，按 `dept_code` 升序；`full_name` 模糊过滤，空串视为不过滤；创建 201、重复 400、详情 200/404、修改 200/404、删除 204/404。
- personnel：`GET /personnel` 返回 `{items, total}`，默认分页同上，按 `certificate_number` 升序；`name` 模糊过滤、`dept_code` 精确过滤，空串视为不过滤；创建 201、重复 400、单位不存在 400、详情 200/404、修改 200/400/404、删除 204/404。
- 两个列表的非法分页（`page<1`、`page_size<1`、`page_size>100`、非整数）返回 422；非法载荷返回 422。
- seed 数据 D001/D002、P001/P002 与字段值不变。
- 响应字段名、中文文案、固定排序不变。

| 预留点 | 9-1 预期 |

## 九、教材与旧手册口径修正

| 旧口径 | 本工程口径 | 原因 |
| --- | --- | --- |
| 路由带版本化前缀 | 统一 `prefix=""`，`/users` | 教材本版约束 |
| 集合路径带尾斜杠 | `/users`、`/departments`、`/personnel` 均无尾斜杠 | 避免依赖重定向，验收更稳定 |
| 用重定向排错项解释访问失败 | 不作为排错项；只要求写对路径 | 旧排错项已过期，容易误导 |
| 7-1 接缝表预告注册路径为 `/users/register` | 实际为 `POST /users` | 以教材 8-3-3 为准，本表更正 |
| 步骤 2 后 `/docs` 出现用户分组 | 步骤 2 只建表，不挂路由，`/docs` 暂不出现用户分组；步骤 4 挂 router 后才出现 | 无路由就没有分组，旧描述与实际不符 |
| 8-1 只交 user 模块 | 必须保留 department 与 personnel 全部行为 | 总计划 R1，为 10-1 铺垫 |
| 新增第三方密码/签名库 | 只用 `hashlib` 与 `secrets` | 教材边界与依赖最小化 |
