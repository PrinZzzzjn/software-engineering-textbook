# 实训 3-1 分步实现指南（教师版）

本指南把教材实训的六个操作步骤记为阶段 0–5。学生从 `starter/main.py` 开始，教师可用 `项目/main.py` 核对答案。下列 Python 代码块均为完成态文件的连续原文，不提供另一套实现。

## 阶段 0：读 starter 与列表契约（对应步骤 1，10 分钟）

### 代码

先在起点中定位内存字典和列表端点；完成态中的对应原文如下：

```python
DEPARTMENTS = {
    "D01": {"dept_code": "D01", "full_name": "一中队", "address": "一号楼"},
}


@app.get("/departments")
def list_departments():
    return {"items": list(DEPARTMENTS.values()), "total": len(DEPARTMENTS)}
```

字典键 `D01` 是唯一标识，字典值是一条单位记录；`items` 是记录列表，`total` 是当前记录数。

### 验证命令

在 `starter/` 目录执行：

```powershell
python -m pip install -r requirements.txt
uvicorn main:app --port 8000
```

另开 PowerShell：

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/departments" -Method Get
```

预期：启动成功，`/docs` 初始只有列表端点；响应含一条 D01，`total` 为 1。

### 常见错误

- 把内存字典当成可长期保存的数据载体：本阶段重启即恢复初始值，这是预期行为。
- 从错误目录执行 `uvicorn main:app`：先进入包含目标 `main.py` 的目录。
- 把列表直接返回为数组：本契约必须保留 `items` 与 `total` 两个键。

## 阶段 1：补 POST 与 PUT（对应步骤 2，30 分钟）

### 代码

先把起点第一行扩展为完成态的导入：

```python
from fastapi import FastAPI, HTTPException, status
```

在列表端点后补新增函数：

```python
@app.post("/departments", status_code=status.HTTP_201_CREATED)
def create_department(data: dict):
    dept_code = data.get("dept_code")
    full_name = data.get("full_name")
    if not dept_code or not full_name:
        raise HTTPException(status_code=400, detail="缺少必填字段")
    if dept_code in DEPARTMENTS:
        raise HTTPException(status_code=400, detail="单位编码已存在")
    DEPARTMENTS[dept_code] = {
        "dept_code": dept_code,
        "full_name": full_name,
        "address": data.get("address"),
    }
    return DEPARTMENTS[dept_code]
```

再补修改函数：

```python
@app.put("/departments/{dept_code}")
def update_department(dept_code: str, data: dict):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    item = DEPARTMENTS[dept_code]
    if "full_name" in data:
        item["full_name"] = data["full_name"]
    if "address" in data:
        item["address"] = data["address"]
    return item
```

新增必须声明 201；修改的路径参数定位记录，请求体只更新传入的 `full_name` 或 `address`。

### 验证命令

重启服务后，在 PowerShell 依次执行：

```powershell
$body = @{ dept_code = "D02"; full_name = "二中队"; address = "二号楼" } | ConvertTo-Json
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments" -Method Post -ContentType "application/json; charset=utf-8" -Body $body | Select-Object StatusCode, Content

$update = @{ full_name = "二中队（改）" } | ConvertTo-Json
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments/D02" -Method Put -ContentType "application/json; charset=utf-8" -Body $update | Select-Object StatusCode, Content
```

预期：新增状态码 201，修改状态码 200；随后 `GET /departments` 的记录数为 2，D02 详情显示新名称。重复实验前重启服务，避免 D02 已存在。

### 常见错误

- 新增返回 200：漏写 `status_code=status.HTTP_201_CREATED`。
- 修改不存在的编码却返回 200：函数入口缺少存在性检查。
- 修改把未提交字段清空：应使用 `if "字段名" in data`，只改传入字段。
- 编辑器已保存但行为未变：确认重启的是正在编辑的这份应用。

## 阶段 2：补详情、DELETE 与 404（对应步骤 3，20 分钟）

### 代码

详情端点先判断编码是否存在：

```python
@app.get("/departments/{dept_code}")
def get_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    return DEPARTMENTS[dept_code]
```

删除端点声明 204，成功路径不返回任何内容：

```python
@app.delete("/departments/{dept_code}", status_code=status.HTTP_204_NO_CONTENT)
def delete_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    del DEPARTMENTS[dept_code]
```

### 验证命令

确认阶段 1 已创建 D02，然后执行：

```powershell
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments/D02" -Method Get | Select-Object StatusCode, Content
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments/D02" -Method Delete | Select-Object StatusCode, Content
```

预期：详情为 200；第一次删除为 204，`Content` 为空。在 `/docs` 再删除一次 D02，预期为 404，响应正文中的 `detail` 为“单位不存在”。

### 常见错误

- 删除仍带 JSON 正文：成功分支多写了 `return ...`，删除它。
- 删除返回 200：装饰器没有声明 `status.HTTP_204_NO_CONTENT`。
- 第二次删除仍成功：没有先检查 `dept_code not in DEPARTMENTS`。
- 详情被列表端点覆盖：检查两个 GET 的路径是否分别写对。

## 阶段 3：制造失败并比较 400、404、422（对应步骤 4，15 分钟）

### 代码

本阶段不改实现，重点读懂新增函数入口的连续检查：

```python
    dept_code = data.get("dept_code")
    full_name = data.get("full_name")
    if not dept_code or not full_name:
        raise HTTPException(status_code=400, detail="缺少必填字段")
    if dept_code in DEPARTMENTS:
        raise HTTPException(status_code=400, detail="单位编码已存在")
```

当前请求体是普通字典，缺字段和编码重复由函数返回 400；不存在的资源由详情、修改或删除函数返回 404。教材 3.5 改用输入模型后，缺字段等输入校验在进入函数前由框架完成，状态码变为 422；编码重复仍需函数内判断。

### 验证命令

在 `/docs` 依次发送：

| 请求 | 输入 | 预期 |
| --- | --- | --- |
| `POST /departments` | `{"dept_code":"D03"}` | 400，`缺少必填字段` |
| `POST /departments` | `{"dept_code":"D01","full_name":"重复"}` | 400，`单位编码已存在` |
| `GET /departments/D404` | 无 | 404，`单位不存在` |
| `PUT /departments/D404` | `{"full_name":"不存在"}` | 404，`单位不存在` |

也可用以下 PowerShell 形式观察缺字段请求的状态码：

```powershell
$missing = @{ dept_code = "D03" } | ConvertTo-Json
try {
    Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments" -Method Post -ContentType "application/json" -Body $missing
} catch {
    $_.Exception.Response.StatusCode.value__
}
```

预期输出为 `400`。

### 常见错误

- 把所有失败都归为 400：资源不存在应为 404。
- 把 422 当成本阶段必达项：当前 `data: dict` 写法缺字段是 400，422 只作后续对照。
- 为制造重复编码而反复重启：重启会清空新增数据；直接用已有的 D01 即可。
- 客户端自动跟随重定向掩盖 307：集合路径不要添加末尾斜杠。

## 阶段 4：填写记录与幂等性说明（对应步骤 5，10 分钟）

### 代码

本阶段不修改 `main.py`，沿用阶段 0–2 的代码。记录表中的请求必须与真实操作一致，至少覆盖下列十行；预期列不是实际列，实际值必须请求后填写。

| 方法 | URL | 输入摘要 | 预期状态码 |
| --- | --- | --- | ---: |
| GET | `/departments` | 无 | 200 |
| GET | `/departments/D01` | 无 | 200 |
| GET | `/departments/D404` | 无 | 404 |
| POST | `/departments` | D02，字段完整 | 201 |
| POST | `/departments` | 再次提交 D02 | 400 |
| POST | `/departments` | 缺 `full_name` | 400 |
| PUT | `/departments/D02` | 修改 `full_name` | 200 |
| PUT | `/departments/D404` | 修改任意名称 | 404 |
| DELETE | `/departments/D02` | 无 | 204 |
| DELETE | `/departments/D02` | 无 | 404 |

幂等性说明的组织顺序：GET 重复读取不改变状态；PUT 重复提交同一正文得到相同最终记录；DELETE 第一次为 204、第二次为 404，但最终都是资源不存在，所以仍幂等；POST 重复执行可能新增记录，因此不幂等。

### 验证命令

逐行在 `/docs` 重发请求并记录实际值。教师完成态可同时运行自动测试交叉检查：

```powershell
cd 项目
python -m pip install httpx pytest
python -m pytest tests/test_api.py
```

预期：记录表五种状态码齐全，删除 204 行注明无正文，自动测试十项全部通过。

### 常见错误

- 只记成功路径：必须补 400 与 404。
- 把预期状态码直接抄成实际状态码：实际列只能来自真实响应。
- 忘记检查 204 正文：状态码正确并不代表无正文，需同时检查。
- 用“每次响应码相同”解释幂等：判断依据是服务器最终状态。

## 阶段 5：复核完整代码并提交（对应步骤 6，5 分钟）

### 代码

提交前与下面完成态逐段核对；此代码块与 `项目/main.py` 全文逐字一致：

```python
from fastapi import FastAPI, HTTPException, status

app = FastAPI()

DEPARTMENTS = {
    "D01": {"dept_code": "D01", "full_name": "一中队", "address": "一号楼"},
}


@app.get("/departments")
def list_departments():
    return {"items": list(DEPARTMENTS.values()), "total": len(DEPARTMENTS)}


@app.get("/departments/{dept_code}")
def get_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    return DEPARTMENTS[dept_code]


@app.post("/departments", status_code=status.HTTP_201_CREATED)
def create_department(data: dict):
    dept_code = data.get("dept_code")
    full_name = data.get("full_name")
    if not dept_code or not full_name:
        raise HTTPException(status_code=400, detail="缺少必填字段")
    if dept_code in DEPARTMENTS:
        raise HTTPException(status_code=400, detail="单位编码已存在")
    DEPARTMENTS[dept_code] = {
        "dept_code": dept_code,
        "full_name": full_name,
        "address": data.get("address"),
    }
    return DEPARTMENTS[dept_code]


@app.put("/departments/{dept_code}")
def update_department(dept_code: str, data: dict):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    item = DEPARTMENTS[dept_code]
    if "full_name" in data:
        item["full_name"] = data["full_name"]
    if "address" in data:
        item["address"] = data["address"]
    return item


@app.delete("/departments/{dept_code}", status_code=status.HTTP_204_NO_CONTENT)
def delete_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    del DEPARTMENTS[dept_code]
```
