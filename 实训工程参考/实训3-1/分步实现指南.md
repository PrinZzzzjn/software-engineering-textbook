# 实训 3-1 分步实现指南（教师版）

本指南按**代码递进**保留阶段 0–7，供教师核对答案；课堂 4 学时按**教学阶段** 0–9 组织，见下表与 `实训手册/实训3-1/分步实现指南.md`。学生从 `starter/main.py` 的空起点开始，自己写出最小应用与五个端点；教师可用 `项目/main.py` 核对答案。下列 Python 代码块按阶段递进，最终与 `项目/main.py` 全文一致。

## 阶段 0：最小应用（对应步骤 1，15 分钟）

### 代码

在空目录中新建 `main.py`：

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/health")
def health():
    return {"status": "ok"}
```

`FastAPI()` 创建应用对象；`@app.get("/health")` 把下方函数登记为 `GET /health` 的处理函数；返回值会自动转换为 JSON。

### 验证命令

在 `main.py` 所在目录执行：

```powershell
python -m pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

浏览器打开 `http://127.0.0.1:8000/docs`，应能看到 `/health`。另开 PowerShell：

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/health" -Method Get
```

预期：`status` 为 `ok`。

### 常见错误

- `ModuleNotFoundError: fastapi`：依赖未安装，执行 `pip install -r requirements.txt`。
- `Could not import module "main"`：当前目录没有 `main.py`，或启动命令不在文件所在目录。
- `/docs` 打不开：服务未启动或端口被占用。

## 阶段 1：列表端点（对应步骤 2，15 分钟）

### 代码

先让列表返回一条写死记录，确认契约：

```python
@app.get("/departments")
def list_departments():
    return {
        "items": [
            {"dept_code": "D01", "full_name": "一中队", "address": "一号楼"}
        ],
        "total": 1,
    }
```

验证通过后，把记录移入字典，列表改为读取字典：

```python
DEPARTMENTS = {
    "D01": {"dept_code": "D01", "full_name": "一中队", "address": "一号楼"},
}


@app.get("/departments")
def list_departments():
    return {"items": list(DEPARTMENTS.values()), "total": len(DEPARTMENTS)}
```

字典键 `D01` 是唯一标识，字典值是一条单位记录；`items` 是记录列表，`total` 是当前记录数。

### 验证命令

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/departments" -Method Get
```

预期：`items` 含一条 D01，`total` 为 1。

### 常见错误

- 直接返回数组：本契约必须保留 `items` 与 `total` 两个键。
- 把字典写成列表：后面无法按编码定位记录。
- 把 `total` 写死为 1：加入新记录后不会变化。

## 阶段 2：详情端点（对应步骤 3，10 分钟）

### 代码

先把导入扩展为：

```python
from fastapi import FastAPI, HTTPException
```

再补详情端点：

```python
@app.get("/departments/{dept_code}")
def get_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    return DEPARTMENTS[dept_code]
```

路径中的 `{dept_code}` 由同名函数参数接收；不存在时主动抛出 404，而不是让字典键报错。

### 验证命令

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/departments/D01" -Method Get
Invoke-RestMethod -Uri "http://127.0.0.1:8000/departments/D404" -Method Get
```

预期：D01 返回 200 与记录；D404 返回 404，`detail` 为“单位不存在”。

### 常见错误

- 不存在时直接取字典键，返回 500：先判断 `dept_code not in DEPARTMENTS`。
- 详情路径写成 `/departments`：与列表端点冲突。
- 忘记导入 `HTTPException`。

## 阶段 3：新增端点（对应步骤 4，15 分钟）

### 代码

先把导入扩展为：

```python
from fastapi import FastAPI, HTTPException, status
```

再补新增端点：

```python
@app.post("/departments", status_code=status.HTTP_201_CREATED)
def create_department(data: dict):
    dept_code = data.get("dept_code")
    full_name = data.get("full_name")
    if not dept_code or not full_name:
        raise HTTPException(status_code=400, detail="缺少必填字段")
    if dept_code in DEPARTMENTS:
        raise HTTPException(status_code=400, detail="单位编码已存在")
    DEPARTMENTS[dept_code] = {
        "dept_code": dept_code,
        "full_name": full_name,
        "address": data.get("address"),
    }
    return DEPARTMENTS[dept_code]
```

成功必须声明 201；缺字段与编码重复都在函数入口判断，返回 400。

### 验证命令

```powershell
$body = @{ dept_code = "D02"; full_name = "二中队"; address = "二号楼" } | ConvertTo-Json
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments" -Method Post -ContentType "application/json; charset=utf-8" -Body $body | Select-Object StatusCode, Content
```

预期：新增返回 201；随后列表记录数为 2。重复提交 D02 返回 400“单位编码已存在”；只提交 `dept_code` 返回 400“缺少必填字段”。

### 常见错误

- 新增返回 200：漏写 `status_code=status.HTTP_201_CREATED`。
- 缺字段返回 500：直接索引 `data["full_name"]`，应改用 `data.get(...)` 并检查。
- 重复编码被覆盖：先判断 `dept_code in DEPARTMENTS`，再写入。

## 阶段 4：修改端点（对应步骤 5，10 分钟）

### 代码

```python
@app.put("/departments/{dept_code}")
def update_department(dept_code: str, data: dict):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    item = DEPARTMENTS[dept_code]
    if "full_name" in data:
        item["full_name"] = data["full_name"]
    if "address" in data:
        item["address"] = data["address"]
    return item
```

修改的路径参数定位记录；请求体只更新传入的字段，未传入的字段保持不变。

### 验证命令

```powershell
$update = @{ full_name = "一中队（改）" } | ConvertTo-Json
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments/D01" -Method Put -ContentType "application/json; charset=utf-8" -Body $update | Select-Object StatusCode, Content
```

预期：修改返回 200，`full_name` 已更新，`address` 保持原值；修改 D404 返回 404。

### 常见错误

- 修改把未提交字段清空：应使用 `if "字段名" in data`，只改传入字段。
- 修改不存在的编码返回 200：函数入口缺少存在性检查。
- 请求体字段名与代码读取键名不一致。

## 阶段 5：删除端点（对应步骤 6，10 分钟）

### 代码

```python
@app.delete("/departments/{dept_code}", status_code=status.HTTP_204_NO_CONTENT)
def delete_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="单位不存在")
    del DEPARTMENTS[dept_code]
```

删除成功声明 204，成功路径不返回任何内容。

### 验证命令

```powershell
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments/D02" -Method Delete | Select-Object StatusCode, Content
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/departments/D02" -Method Delete | Select-Object StatusCode, Content
```

预期：第一次删除 204 且 `Content` 为空；第二次删除 404。

### 常见错误

- 删除仍带 JSON 正文：成功分支多写了 `return ...`。
- 删除返回 200：装饰器没有声明 `status.HTTP_204_NO_CONTENT`。
- 第二次删除仍成功：没有先检查 `dept_code not in DEPARTMENTS`。

## 阶段 6：验证与记录（对应步骤 7，10 分钟）

### 代码

本阶段不修改 `main.py`，沿用阶段 0–5 的代码。记录表中的请求必须与真实操作一致，至少覆盖下列十行；预期列不是实际列，实际值必须请求后填写。

| 方法 | URL | 输入摘要 | 预期状态码 |
| --- | --- | --- | ---: |
| GET | `/departments` | 无 | 200 |
| GET | `/departments/D01` | 无 | 200 |
| GET | `/departments/D404` | 无 | 404 |
| POST | `/departments` | D02，字段完整 | 201 |
| POST | `/departments` | 再次提交 D02 | 400 |
| POST | `/departments` | 缺 `full_name` | 400 |
| PUT | `/departments/D02` | 修改 `full_name` | 200 |
| PUT | `/departments/D404` | 修改任意名称 | 404 |
| DELETE | `/departments/D02` | 无 | 204 |
| DELETE | `/departments/D02` | 无 | 404 |

幂等性说明的组织顺序：GET 重复读取不改变状态；PUT 重复提交同一请求体得到相同最终记录；DELETE 第一次为 204、第二次为 404，但最终都是资源不存在，所以仍幂等；POST 重复执行可能新增记录，因此不幂等。

### 验证命令

逐行在 `/docs` 重发请求并记录实际值。教师完成态可同时运行自动测试交叉检查：

```powershell
cd 项目
python -m pip install httpx pytest
python -m pytest tests/test_api.py
```

预期：记录表五种状态码齐全，删除 204 行注明无正文，自动测试十一项全部通过。

### 常见错误

- 只记成功路径：必须补 400 与 404。
- 把预期状态码直接抄成实际状态码：实际列只能来自真实响应。
- 忘记检查 204 正文：状态码正确并不代表无正文，需同时检查。
- 用“每次响应码相同”解释幂等：判断依据是服务器最终状态。

## 阶段 7：复核完整代码并提交（对应步骤 8，5 分钟）
