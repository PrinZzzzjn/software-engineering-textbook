# 实训 9-1 学员版差异说明

本文件说明学员从 8-1 完成态拿到 9-1 起点后，哪些内容**保留**、哪些**删除**、哪些**替换**、哪些**新增**，避免把旧手册里「所有数据接口都公开」的写法带进来。

## 一、保留（不要改）

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 盐哈希 | `app/core/security.py` 的 `get_password_hash` / `verify_password` | 仍是随机盐 + SHA-256，不换算法 |
| 令牌存取 | `TOKEN_STORE`、`create_access_token`、`resolve_token` | 仍是内存字典，重启失效；不改签名令牌 |
| 认证依赖 | `get_current_user` | 仍负责「取令牌 → 查令牌 → 查用户 → 查 `is_active` → 返回 `{id, role}`」 |
| 注册契约 | `POST /users` | 201，字段 `id/username/role/is_active`；重复 400、短密码 422 |
| 登录契约 | `POST /users/login` | 200，`access_token/token_type/user`；错误 401 |
| 当前用户 | `GET /users/me` | 无令牌 401，有令牌 200 `{id, role}` |
| 管理员 seed | `main.py` 的 `_seed_admin()` | `admin/admin123` 幂等写入，不覆盖已有用户 |
| 三张表 | `department`、`personnel`、`user` 的 `model.py` | 字段不变，不新增 `disabled`，不迁移 |
| 六文件体例 | 每个模块 `controller/service/crud/param/schema/model` | 继续使用，不拆新层 |
| 7-1 查询 | department/personnel 的列表、详情、分页、过滤、排序 | 路径、字段、错误码全部不变 |
| 运行配置 | `requirements.txt`、`.env.example`、`.gitignore`、`DATABASE_URL` | 不新增依赖，不改数据库地址规则 |
| 错误文案 | 用户名已存在、用户名或密码错误、未提供令牌、令牌无效、各模块 400/404/422 | 不改写，避免前端与测试回归 |

## 二、删除（旧写法不再适用）

| 删除项 | 旧位置 | 删除理由 |
| --- | --- | --- |
| 「用户列表暂不实现 / 占位」的说明 | 8-1 的 `user/param.py` 注释与旧手册 | 9-1 要正式实现列表 |
| 「department/personnel 写接口匿名可用」的示例 | 7-1 手册与旧验收 | 写接口已收归管理员，匿名示例会得到 401 |
| 「权限只在前端隐藏按钮」的说法 | 旧前端章节 | 后端必须执行授权；前端隐藏只是体验 |
| 把 403 当成「未登录」的处理 | 旧前端拦截器 | 401 才是未登录/令牌失效；403 是无权限 |
| 「禁用只是把字段改成 0」的简化说法 | 旧账号管理草稿 | 还要在登录时检查，禁用后不能签发令牌；`get_current_user` 也检查 `is_active`，旧令牌立即失效 |
| 在函数体里复制 `if role != "admin"` 的写法 | 旧示例 | 统一用依赖，避免八个入口各写一遍 |
| 直接返回 ORM 用户对象的写法 | 旧列表草稿 | 会带出 `password_hash`；必须手工组装四项 |

## 三、替换（同一位置换实现）

| 位置 | 8-1 / 旧写法 | 9-1 写法 |

| `app/modules/user/schema.py` | 注册、输出、登录、令牌 | 追加 `UserPage` 与 `UserUpdate`，用 `Literal` + `| None` |
| `app/modules/user/controller.py` | 注册、登录、`me` | 追加 `GET /users`、`PUT /users/{user_id}`；列表用装饰器依赖，修改用参数依赖 |
| `app/modules/department/controller.py` | 所有接口公开 | POST/PUT/DELETE 挂管理员依赖；GET 保持公开 |
| `app/modules/personnel/controller.py` | 所有接口公开 | POST/PUT/DELETE 挂管理员依赖；GET 保持公开 |

## 四、新增（8-1 没有的内容）

| 新增 | 位置 | 学员要能解释 |
| --- | --- | --- |
| 管理员依赖 | `security.py` | 为什么 401 由认证层产生、403 由授权层产生 |
| 用户列表 | user 五文件 | 为什么返回 `{items, total}`、为什么不能带 `password_hash`、为什么固定 `id` 排序 |
| 用户修改 | user 四文件 | 为什么只允许两个字段、为什么 422 在函数前、为什么 404 先于 400 |
| 禁用登录 | `service.login` | 为什么检查在签发令牌之前、为什么返回 401「账号已禁用」 |
| 权限回收 | department/personnel controller | 为什么只加一个依赖参数就够、为什么读接口不加 |
| 权限矩阵 | README 与验收 | 三种身份 × 八个管理入口的状态码必须能背下来并实测 |
| 接缝意识 | 接缝表 | 旧接口从匿名 200 变成 401/403，前端第 15 章起必须带令牌 |

## 五、学员操作顺序

1. 先跑通起点：注册、登录、`me`、两个旧列表；确认 `GET /users` 是 404。
2. 加管理员依赖，用一个临时路由或下一阶段的列表验证 401/403/200。
3. 做列表：参数 → crud → service → controller；先验字段，再验分页。
4. 做修改：schema → service → controller；先验 200，再验 404/400/422，最后验禁用登录。
5. 做权限回收：department 三个写接口 → personnel 三个写接口；每加一个就用手工矩阵验一次。
6. 跑回归：8-1 三个用户接口 + 7-1 两个查询 + 23 项测试。
7. 最后写运行记录，不要先写文档再补代码。

## 六、不要带进 9-1 的旧习惯

- 不要用 `HTTPBearer()` 默认行为作为管理员依赖：匿名会得到 403，和 401 语义冲突。
- 不要把角色写进令牌：改角色后旧令牌不生效，且需要额外刷新机制。
- 不要在列表里 `return db.query(User).all()`：字段过滤与分页都会失控。
- 不要在修改里 `model_dump()` 全量写回：未传字段会被 `None` 覆盖。
- 不要只改教材点名的两个 department 接口：personnel 与 PUT 会留下同类越权。
- 不要为了让旧前端「不报错」而撤掉依赖：9-1 的验收就是旧接口出现 401/403。
- 不要把「禁用」实现成删除用户：8-1 的 `is_active` 已存在，删除会破坏登录与历史关联。
- 不要把课后扩展塞进 90 分钟：修改角色的全部校验与完整禁用流程明确不计入必做。
