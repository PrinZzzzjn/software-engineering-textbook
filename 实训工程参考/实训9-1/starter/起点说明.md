# 实训 9-1 学员起点说明

本目录是**实训 8-1 的完成态**：users 表、`app/core/security.py`、注册/登录/`me` 与 admin seed 都已就位；department 与 personnel 的查询、分页、过滤、排序和 CRUD 也全部可用。`admin/admin123` 由启动 seed 幂等写入，`TOKEN_STORE` 仍在进程内，重启后旧令牌失效、账号保留。

本实训要在**不破坏 8-1 注册/登录/`me` 与 7-1 查询行为**的前提下，完成账号管理与权限回收。这里不给答案代码，请按教材 9.1–9.4 与任务书完成。

## 本实训要达成的四件事

1. 在认证依赖之上新增管理员依赖：未登录 401，已登录但非管理员 403。
2. 新增管理员专属的用户列表，分页 `page` / `page_size`，响应 `{items, total}`，条目不含密码哈希。
3. 新增管理员专属的用户修改，只允许改 `role` 与 `is_active`；用户不存在 404，管理员禁用自己 400，非法值 422。
4. 回收 department 与 personnel 的写接口权限，读接口保持公开。

## 接口契约（验收口径）

| 场景 | 状态码 | 关键字段 / 文案 |
| --- | --- | --- |
| 列表成功 | 200 | `{items, total}`；条目 `id`、`username`、`role`、`is_active` |
| 列表分页非法 | 422 | `page < 1`、`page_size < 1`、`page_size > 100`、非整数 |
| 修改成功 | 200 | 返回修改后的四项用户字段 |
| 目标用户不存在 | 404 | `用户不存在` |
| 管理员禁用自己 | 400 | `不能禁用自己` |
| 角色/状态非法 | 422 | `role` 仅 `admin`/`normal`；`is_active` 仅 0/1 |
| 匿名访问管理接口 | 401 | `未提供令牌` 或 `令牌无效` |
| 普通用户访问管理接口 | 403 | `权限不足` |
| 被禁用账号登录 | 401 | `账号已禁用` |

任何响应都不得出现 `password_hash`。注册、登录、`me` 的字段与 8-1 完全一致。

## 起点检查

在已安装依赖的环境中，于本目录执行：

```powershell
python -c "from app.modules.user.controller import router; print(router.prefix)"
python -m uvicorn main:app --port 8000
```

第一条预期输出 `/users`。启动后，`GET /departments` 与 `GET /personnel` 应各返回 2 条 seed 数据；`GET /users` 应是 404；`admin/admin123` 应能登录。这些都是起点状态。

`tests/test_api.py` 是 8-1 留下的教师测试，可用于确认改造前后注册、登录、`me` 与旧查询行为未变。本实训不要求扩展测试，教材第 12 章才系统讲测试；但建议每次改完都跑一次：

```powershell
python -m pytest tests -q
```

注意：这份 8-1 测试里的 department/personnel **写用例是按匿名 201/200/204 写的**。一旦完成权限回收，这些用例会因 401/403 失败，属于**预期的接缝变化**，不是回归。9-1 的验收以任务书的权限矩阵与教师提供的 9-1 测试为准；不要把 8-1 的写用例改回匿名通过。
