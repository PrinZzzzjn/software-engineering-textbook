# 实训 20-1 分步实现指南

按教材实训 20-1 的四步展开。命令都在 `项目/` 根目录执行；起点是 19-1 的完成态 `项目/`。本实训不改业务页面结构，重点是「按路径证明能用、按顺序定位问题、把错误收口、把交付说清」。

## 0. 起点检查（约 20 分钟）

先启动后端（13-1 项目）：

```powershell
cd ..\..\实训13-1\项目
python -m uvicorn main:app --port 8000
```

浏览器打开 <http://127.0.0.1:8000/health>，应返回 `{"status": "healthy"}`。

再启动 19-1 前端：

```powershell
cd ..\..\实训19-1\项目
python -m streamlit run app.py
```

**验收**：侧边栏五个页面可切换；单位页能新增、编辑、删除；统计页 P001 + 2026 显示 2 天、16 小时、3 条，折线与柱状图正常。

## 1. 按路径联调（约 45 分钟）

### 1.1 先写清单，再动手

联调不是「把页面点一遍」。每步先写期望，再记录实际；没有期望，失败了也看不出来。十步清单：

| 步骤 | 操作 | 期望 | 实际 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | 未登录直接访问单位页 | 被守卫拦住，提示登录 | | |
| 2 | 用管理员账号登录 | 进入首页，侧边栏显示当前用户 | | |
| 3 | 打开单位管理 | 列表显示，分页正常 | | |
| 4 | 搜索「测试1」 | 只显示匹配的单位 | | |
| 5 | 新增一个单位 | 列表出现新记录 | | |
| 6 | 编辑该单位名称 | 列表显示新名称 | | |
| 7 | 删除该单位 | 二次确认后列表少一条 | | |
| 8 | 打开数据统计 | 指标卡与图表有数据 | | |
| 9 | 切换人员或年份 | 指标与图表跟着变 | | |
| 10 | 退出登录 | 回到登录页，子页面再次被拦截 | | |

### 1.2 先主流程，后边角

主流程走完再补三条边角，缺一条都不算联调完成：

1. **未登录**：直接输入子页面地址，应停在登录页；
2. **空结果**：搜索一个不存在的名称，应显示 `st.info` 而不是报错；
3. **重复提交**：同一编码连续提交两次，第二次应给出「已存在」。

### 1.3 失败先记录

失败时不要立刻改代码。先把「哪一步、期望什么、实际什么、页面显示什么、后端日志是什么」记下来，全部走完后按影响排序：先修主流程，再修提示，最后修样式。

**做错会看到什么**：只测单个页面 → 页面各自通过，串起来却断在登录态或刷新；只测正常路径 → 权限、空数据、重复提交的问题留到验收才暴露。

**验收**：十步全部有「期望 / 实际 / 结论」，至少一条边角记录；失败项能指出发生在哪一步。

## 2. 排查问题（约 40 分钟）

### 2.1 固定顺序

```text
现象 → 状态码 → detail / 返回体 → 后端日志 → 定位页面/接口/字段 → 修复并重跑清单
```

状态码是第一线索：

| 状态码 | 含义 | 先查什么 |
| --- | --- | --- |
| 401 | 没登录 / 登录过期 | 令牌是否存在，请求头是否带上 |
| 403 | 登录了但没权限 | 当前角色与接口权限 |
| 404 | 资源不存在 | 路径与主键是否已被删除 |
| 422 | 参数校验失败 | 字段名、类型、长度、必填 |
| 500 | 后端异常 | 后端日志与堆栈，不要先改前端 |

401 与 403 要分清：一个是「没证件」，一个是「证件不够级别」。500 的根因在后端，前端只负责提示「稍后重试」。

### 2.2 两条真实排查记录

**记录 A：422 提示是一串英文列表**

1. 现象：新增单位时单位名称超长，页面提示一长串 `[{'type': 'string_too_long', ...}]`；
2. 状态码：422；
3. detail：FastAPI 返回的是列表，不是字符串；
4. 日志：后端正常，属于参数校验；
5. 定位：`api_client._request` 没有把列表压平；
6. 修复：`detail = "；".join(item.get("msg", item) for item in detail)`，页面再由统一组件加「提交内容有误」前缀。

**记录 B：删除后提示「登录已过期」，但刚登录过**

1. 现象：点删除没有删掉，页面回到登录页；
2. 状态码：401；
3. detail：「令牌无效」；
4. 日志：后端收到的是旧令牌；
5. 定位：前端在测试时手动改过 `session_state`，令牌没有同步；
6. 修复：401 统一由 `show_api_error` 清会话并 `st.rerun()`，页面不再各写一套。

### 2.3 没有状态码的问题

| 现象 | 先查什么 |
| --- | --- |
| 页面不渲染 | 是否有未捕获异常；`st.stop()` 是否在异常分支里 |
| 数据不更新 | 是否 `st.rerun()`；取数是否在写操作之前 |
| 样式异常 | `config.toml` 是否重启；是否重复注入 CSS |
| 图表空白 | 数据结构/字段名是否与接口一致 |
| 页面卡顿 | 是否在循环里发请求；是否一次取太多 |

**做错会看到什么**：一上来就改代码 → 改错层；把 500 当前端问题 → 越改越乱。

**验收**：至少一条完整排查记录，能指出问题在前端、接口还是字段。

## 3. 统一错误（约 35 分钟）

### 3.1 新建错误组件

新建 `components/errors.py`：

```python
import streamlit as st

import api_client as api


def show_api_error(exc: api.ApiError) -> None:
    status_code = getattr(exc, "status_code", -1)
    detail = getattr(exc, "detail", str(exc))

    if status_code == 401:
        st.session_state.clear()
        st.session_state["login_notice"] = "登录已过期，请重新登录"
        st.rerun()
    elif status_code == 403:
        st.error("当前账号没有权限执行该操作")
    elif status_code == 404:
        st.error("数据不存在，可能已被删除")
    elif status_code == 422:
        st.error(f"提交内容有误：{detail}")
    elif status_code == 500:
        st.error("服务器开小差了，请稍后重试或联系管理员")
    elif status_code == 0:
        st.error(f"无法连接后端服务：{detail}")
    else:
        st.error(detail)
```

三个要点：

1. 401 必须走统一入口：先清会话，再写入 `login_notice`，然后 `st.rerun()`；
2. 500 不显示 `detail`，堆栈留在后端日志；
3. 空数据不是错误，仍用 `st.info`。

### 3.2 页面改成一行

取数失败：

```python
try:
    data = api.get("/departments", params=params)
except api.ApiError as exc:
    show_api_error(exc)
    st.stop()
```

写操作失败：

```python
except api.ApiError as exc:
    show_api_error(exc)
```

五个页面、十七处 `except api.ApiError` 全部改完；页面里不再出现 `st.error(exc.detail)`。

### 3.3 登录页的 401 不并入

登录接口的 401 表示「账号或密码错误」，不是令牌过期。它仍由 `auth.render_login()` 单独提示，避免一登录失败就被清会话逻辑带走。

**做错会看到什么**：401 仍各页各写 → 有的回登录页、有的只弹一行红字；500 把 `detail` 拼进提示 → 用户看到英文堆栈与服务器路径。

**验收**：五页异常都调用 `show_api_error`；令牌失效后回登录页并提示「登录已过期」；422 提示带「提交内容有误」，500 提示不含堆栈。

## 4. 整理与展示（约 40 分钟）

### 4.1 交付清单

| 类别 | 内容 |
| --- | --- |
| 代码 | 前端项目，可运行 |
| 截图 | 登录、列表、新增/编辑/删除、统计 |
| 联调记录 | 十步清单的通过情况 |
| 错误处理 | 401/403/404/422/500 各一条 |
| 已知问题 | 还没解决的问题 + 原因 + 规避办法 |
| 说明 | 如何启动、依赖、测试账号 |

### 4.2 已知问题也要写

已知问题不是扣分项，藏起来才是。写法：什么情况下会出问题、目前怎么规避、计划何时处理。

本工程的已知问题示例：

- 403 没有自然触发路径（后端只有管理员账号），只能用注入方式验证提示；
- 500 同样没有自然触发路径，前端只保证提示可读，根因看后端日志；
- 统计页明细在前端按年份过滤，跨年记录的口径以接口说明为准。

### 4.3 三分钟展示四段

| 段落 | 内容 | 参考时长 |
| --- | --- | ---: |
| 1 | 一句话说明做了什么 | 20 秒 |
| 2 | 演示主流程：登录 → 新增 → 编辑 → 删除 → 统计 | 90 秒 |
| 3 | 说一个排查过的故障：现象 → 原因 → 改法 | 45 秒 |
| 4 | 说一个已知问题或下一步 | 25 秒 |

展示的重点不是「功能多」，而是「能说清边界」。演示只走一条顺利路径，验收还要看联调记录、错误记录与已知问题。

**做错会看到什么**：展示变成功能罗列 → 三分钟讲不完，听者记不住边界。

**验收**：交付清单六类齐全；三分钟计时演练一次，四段都有内容。

## 常见错误对照

| 报错/现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面空白 | 异常未捕获，或 `st.stop()` 前已渲染一半 | 先看 `app.exception` 与后端日志 |
| 状态错乱 | `session_state` 键冲突 | 一个页面一套前缀，切换时重置页码 |
| 重复提交 | 按钮未禁用，或提交后没 `st.rerun()` | 提交成功后清表单并重跑 |
| 401 反复弹 | 清会话后没有回登录页 | 在 `show_api_error` 里统一 `st.rerun()` |
| 404 没有提示 | 页面仍直接 `st.error(exc.detail)` | 改为 `show_api_error(exc)` |
| 422 显示列表 | detail 未压平 | 在 `api_client` 里拼接 `msg` |
| 500 显示堆栈 | 提示里拼了 `detail` | 500 固定提示，细节进日志 |
| 提示泄露令牌 | 把请求头或整段异常拼进提示 | 只显示业务原因 |
| 空结果显示成报错 | 把空列表当异常 | 空数据用 `st.info` |
| 联调只测正常路径 | 缺未登录、空结果、重复提交 | 按十步清单补三条边角 |
