## 二、新增文件

### `app/core/__init__.py`

空文件。作用只是让 `core` 成为包，缺少它时 `from app.core.database import ...` 会报 `ModuleNotFoundError`。

### `app/core/database.py`

```python
import os

from sqlalchemy import create_engine
from sqlalchemy.orm import declarative_base, sessionmaker

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./duty.db")

engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

| 名字 | 职责 | 谁使用 |
| --- | --- | --- |
| `engine` | 连接目标与连接池 | `main.py` 的 `create_all` |
| `SessionLocal` | 造请求级会话 | `get_db`、`main.py` 的 seed |
| `Base` | 声明式模型父类与元数据 | `model.py`、`main.py` |
| `get_db` | 每请求开会话、结束后关闭 | `controller.py` 的 `Depends` |

## 三、实质修改文件

### `model.py`：`dataclass` + `TABLE` → ORM

5-1 的模型是普通数据类，数据放在模块级列表 `TABLE`；6-1 的模型继承 `Base`，数据由数据库持有。

| 项目 | 5-1 | 6-1 |
| --- | --- | --- |
| 模型定义 | `@dataclass class Department` | `class Department(Base)` |
| 存储位置 | `TABLE: list[Department]` | `departments` 表 |
| 主键 | 代码约定 `dept_code` | `primary_key=True` |
| 字段长度 | Pydantic 校验 | `String(20/100/500)` + Pydantic 校验 |
| 模块常量 | `TABLE` 被 crud 直接引用 | 无 `TABLE`，只能通过 `Session` 访问 |

### `crud.py`：列表操作 → `Session`

| 函数 | 5-1 | 6-1 |
| --- | --- | --- |
| 查询单个 | `for d in model.TABLE` | `db.query(Department).filter(...).first()` |
| 列表 | 直接返回内存列表 | `order_by(...).offset(...).limit(...).all()` + `count()` |
| 新增 | `model.TABLE.append(...)` | `db.add(...)` + `commit()` + `refresh()` |
| 修改 | 直接改对象字段 | `setattr` + `commit()` + `refresh()` |
| 删除 | `model.TABLE.remove(...)` | `db.delete(...)` + `commit()` |

新增的 `list_page(db, offset, limit)` 返回 `(items, total)`；`total` 与 `items` 分开计算，供 service 组装。

### `main.py`：增加建表与 seed

新增内容：

- 导入 `Base`、`SessionLocal`、`engine`；
- 导入 `app.modules.department.model`，让 `Base.metadata` 认识 `departments`；
- `Base.metadata.create_all(bind=engine)`；
- `_seed_departments()`：D001 一中队 / D002 二中队，逐条查存在性，已存在则跳过；
- 路由仍以 `prefix=""` 挂载，路径保持 `/departments`。

### `requirements.txt`

版本策略与 `duty-simplified` 一致，不锁死小版本；`pytest`、`httpx` 只在教师验证环境安装。

### `.gitignore`

## 四、接线级修改

### `service.py`

- 每个函数第一个参数改为 `db`，并传给 crud。
- 列表用 `offset = (page - 1) * page_size`，把 `items` 与 `total` 组装成字典。
- 修改使用 `data.model_dump(exclude_unset=True)`。
- 业务规则不变：重复编码 400，查不到 404。

### `controller.py`

- 五个接口都增加 `db: Session = Depends(get_db)`。
- 列表参数仍由 `DepartmentQueryParams = Depends()` 注入。
- 列表不再声明 `response_model`；POST/GET/PUT 仍返回 `DepartmentOut`。
- 路径、状态码与 5-1 完全一致：201/200/204/400/404/422。

### `schema.py`

| 5-1 | 6-1 | 原因 |
| --- | --- | --- |
| `DepartmentCreate`（`min_length=2`） | `DepartmentCreate`（`min_length=1`） | 对齐教材 6-2-2 |
| `DepartmentUpdate` | 删除 | 修改接口与新增同构，body 需要 `dept_code` |
| `DepartmentOut` | 增加 `from_attributes=True` | 从 ORM 对象读取字段 |
| `DepartmentPage` | 删除 | 列表直接返回 `{items, total}` 字典 |

### `param.py`

`DeptQuery` 改名为 `DepartmentQueryParams`，字段仍为 `page=1`、`page_size=10`、`ge=1`、`le=100`。改名的目的是与教材 6-3-1 和后续 personnel 参数类保持一致。

## 五、删除

没有删除文件。删除的是内存版遗留物：

- `model.TABLE` 常量；

## 六、不兼容点

1. **内存字典消失**：数据不再保存在模块级列表里，任何 `TABLE` 引用都失效；进程重启不再自动清空。
2. **数据持久化**：数据写入 `duty.db`。验证「重新开始」必须删除数据库文件，不能靠重启；测试必须使用临时数据库，否则会污染开发数据。
3. **分页参数进入契约**：5-1 的列表没有分页参数；6-1 的 `page`/`page_size` 由 Pydantic 校验，`page=0`、`page_size=0` 返回 422。前端如果仍按「一次拿全量」调用，需要适配 `items`。
4. **模型校验变化**：`PUT` 与 `POST` 同构，body 必须带 `dept_code` 与 `full_name`；5-1 那种只传 `full_name` 的局部更新会得到 422。
5. **会话接线**：service 与 crud 不再能无参数直接调用；任何直接调用都要先造 `Session`，并在结束时关闭。controller 之外没有全局 session。
6. **环境变量读取方式**：`DATABASE_URL` 从系统环境变量读取，`.env.example` 仍只有 `DEBUG=True`；本章不引入 `python-dotenv`，把值写进 `.env` 不会自动生效。
7. **依赖增加**：运行依赖多一个 `sqlalchemy`；只装 5-1 的 `fastapi`、`uvicorn` 会在导入模型时报错。
8. **测试位置**：6-1 完成态新增 `tests/test_api.py`，但它只用于教师验证；学生提交物不要求测试，教材第 12 章才正式引入。
9. **不变的契约**：`/health`、`/departments` 路径、无 `/api/v1`、五个成功状态码、错误码含义均与 5-1 一致。

## 七、6-1 → 7-1 预告

7-1 在 6-1 之上新增 personnel 模块，复用本实训的数据库与分页骨架。

### 预计新增

- `app/modules/personnel/` 六文件：`model.py`、`schema.py`、`param.py`、`crud.py`、`service.py`、`controller.py`；
- `main.py` 导入 personnel 模型、`include_router`，`create_all` 自动建表；
- personnel 表字段：`person_code` 主键、`full_name`、`dept_code`（外键语义）、`rank` 等，具体以教材第 7 章为准。

### 预计修改

| 文件 | 修改 |
| --- | --- |
| `personnel/param.py` | 在 `page`、`page_size` 之外增加可选过滤（如 `full_name`、`dept_code`） |
| `personnel/crud.py` | 复用 `list_page` 的分页骨架，在 `query` 上追加 `filter`，`count()` 必须在过滤之后 |
| `personnel/service.py` | 组装 `{items, total}`；新增时先校验 `dept_code` 是否存在，不存在返回 400 |
| `personnel/controller.py` | 沿用 `Depends(get_db)` 与固定状态码 |
| `main.py` | 导入新模型并挂载路由，仍用 `prefix=""` |
| `tests/` | 增加过滤、排序、分页与 400 校验用例（教师验证） |

### 复用点

- `app/core/database.py` 不改，personnel 直接复用同一个 `engine`、`SessionLocal`、`Base`、`get_db`。
- `list_page` 的「固定排序 → `offset` → `limit` → `count`」次序不变；排序字段可按教材改为 `person_code` 或其他固定字段，前端仍不传 `sort_by`。
- 422（输入）、400（业务/外键）、404（不存在）、204（删除）的分层不变。

### 7-1 的不兼容预警

- 列表查询从「只分页」变为「过滤 + 分页」，`total` 的语义是**过滤后的总数**；如果先 `count()` 再 `filter`，总数会偏大。
- 新增 personnel 时，`dept_code` 不存在应返回 400，而不是让数据库外键异常变成 500。
- 排序字段一旦改变，前端依赖的顺序会变；必须在接口文档中写死，不接受前端传入。
- `main.py` 的模型导入必须包含 personnel，否则 `create_all` 不会创建新表。
