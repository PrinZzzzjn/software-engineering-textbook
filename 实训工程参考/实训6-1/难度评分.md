## 二、等级判定

### 代码行数：落在 D2 区间

约 150 行有效代码，按总计划的行数区间属于 D2（101–200 行）。

### 涉及文件数：落在 D4 区间

学生实际触碰 12 个文件，落入 D4 的 11–20 个文件区间。按总计划「行数与文件数取较高等级」的口径，本项目定为 **D4**。这与 5-1 的判定方式一致：5-1 只有 17 行新增代码，但涉及 5 个文件，按较高等级定为 D2。

### 认知负荷：L4

| 维度 | 表现 |
| --- | --- |
| 新机制数量 | ORM 映射、请求级 Session 生命周期、建表时序、分页查询与总数、持久化与幂等 seed |
| 跨文件耦合 | 五个文件同时改签名或依赖，任一不同步就 500；错误可能出现在任何一层 |
| 错误可观察性 | 422/400/404/204 可由接口直接观察；但「数据为何没落库」「为何重启后消失」需要读日志、查 `duty.db`、比对启动目录 |
| 与前置实训的跨度 | 5-1 是单进程内存字典，6-1 引入外部状态与事务边界，属于机制级跨越 |

综合为 **L4**。L5 的特征是并发、跨进程一致性与不可逆数据迁移，本实训不涉及。

## 三、新概念数与拆分建议

教材本章引入的新概念清单：

1. **ORM 与请求级 Session**：`Base`、模型类、`Session`、`get_db` 的 `yield/finally` 生命周期。
2. **建表与持久化时序**：模型必须先导入，`create_all` 才认识表；数据落在 `duty.db`，重启后仍在。
3. **分页查询**：`page`/`page_size` → `offset`/`limit`，固定 `order_by`，`count()` 返回 `total`。
4. **幂等初始化**（选做）：seed 逐条查存在性，或拆成独立 init 脚本。
5. **错误分层**（复习）：422 输入校验、400 业务规则、404 资源不存在、204 无正文；4-1、5-1 已出现，不按全新概念计。

按原始条目计为 3–4 个新概念，**超过「单次实训新概念≤2 个」的规则**。建议按以下方式处理：

- **推荐方案（保持 4 学时）**：课堂只把「ORM/Session/建表」合并为概念组 A，「分页查询」作为概念组 B，合计 2 组；seed 幂等与分页边界降为选做，不纳入课堂新授。这样在必做范围内满足 ≤2。
- **严格方案（拆成两次）**：6-1A「落库」2 学时，只做 `database.py`、`model.py`、`crud.py`、`main.py` 建表与 seed，验收重启持久化；6-1B「分页」2 学时，补 `param.py`、`service` 的 `offset` 与 `controller` 列表，验收分页与 422。6-1B 直接复用 6-1A 工程。
- **不推荐**：把 seed 拆分、分页边界、personnel 预告全部塞进 180 分钟；这会把新概念推到 5 个以上，且挤掉排错时间。

## 五、必做与选做切分

### 必做（构成及格线）

1. **落库推导**：说明 `engine`、`SessionLocal`、`Base`、`get_db` 的职责；新增 `app/core/database.py`。
2. **建表与模型**：`model.py` 改为 ORM；`main.py` 导入模型并 `create_all`；seed 幂等。
3. **department 全流程**：新增 201、重复 400、详情 200/404、修改 200、删除 204 无正文、重复删除 404。
4. **分页基础**：`page`/`page_size`、`{items, total}`、固定 `dept_code` 升序；非法值 422。
5. **持久化证据**：真实停止并重启进程，同一条记录仍在。
6. **错误分层**：能解释 422/400/404 各自由谁产生。

### 选做（不占必做时间）

1. **seed 与 init 脚本拆分**：应用启动只建表，初始化独立执行。
2. **分页边界**：越界页、`page_size` 上限调整、`total` 与过滤次序。
3. **personnel 模块预告**：复制六文件、外键存在性校验、过滤与排序留到第 7 章。
4. **备份与索引**：`duty.db` 备份方式，`dept_code` 主键索引依据。

## 六、合理性核对

| 核对项 | 判断 |
| --- | --- |
| 前置知识是否够用 | 5-1 已给出六文件分层、Pydantic 校验与五个接口；6-1 只替换存储，前置够用。若学生 5-1 未完成，180 分钟不够。 |
| 失败是否可定位 | 422/400/404/204 可直接由接口观察；落库失败可查 `duty.db`、启动目录与 uvicorn 日志。 |
| 验收是否可观察 | 八条状态码 + 分页 JSON + 重启前后同一条记录 + `git ls-files` 卫生检查。 |
| 教材映射是否完整 | 6.1 两组代码、6.2 表与 CRUD、6.3 分页、6.4 错误分层均有落点，见 `README.md` 教材映射表。 |
| 难度是否连续 | 3-1 建立分层 → 4-1 完善校验与错误码 → 5-1 单位模块 → 6-1 落库；6-1 是机制升级，不是重复劳动。 |
| 是否有超纲内容 | 无 users、认证、权限、`/api/v1`、测试框架要求；personnel 只作预告。 |

## 七、结论

**D4 / L4 / 重**。重的原因不是代码行数，而是：12 个文件的接线面、外部状态（SQLite 文件）、请求级 Session 生命周期、分页与总数的查询口径，以及「重启后是否仍在」这类必须实跑才能确认的验收。若严格按「单次新概念≤2」执行，建议拆成 6-1A（落库）与 6-1B（分页）两次；若保持 4 学时，必须把 seed/init 拆分与分页边界明确列为选做，并保留 44 分钟排错时间。
