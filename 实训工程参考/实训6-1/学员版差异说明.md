# 实训 6-1 学员版差异说明

> 完整版：教师用 `实训6-1/`（含完成态、教师测试、实跑记录）  
> 学员版：从 5-1 完成态出发的任务书 + 起点 + 验收模板  
> 原则：保留判断支架，删除答案代码；学生必须自己完成落库与分页。

## 一、总体差异

| 维度 | 完整版 | 学员版 |
| --- | --- | --- |
| 起点 | `starter/` 与 5-1 完成态 | 同左，保留 |
| 目标工程 | `项目/` 完成态，可直接启动 | 不提供；学生把 `starter/` 复制为工作副本后自行改造 |
| 代码 | 每个阶段完整文件 | 只给签名、关键行提示与伪代码，核心实现留空 |
| 测试 | `tests/test_api.py` 13 项，pytest 全绿 | 不提供自动测试；只给八条手工检查清单 |
| 验证 | `验证记录.md` 真实输出 | 提供空白记录模板，由学生填写实际结果 |
| 难度/接缝 | `难度评分.md`、`接缝表.md` | 删除；仅保留“要改哪 4 处”的起点说明 |
| 文档 | 教师视角，含课堂时间与排错预算 | 学生视角，保留目标、边界、步骤、验收、排错、提交 |

## 二、删除内容

| 删除项 | 原因 |
| --- | --- |
| `项目/` 整个完成态 | 直接给出答案，学生只需复制，无法形成落库推导 |
| `项目/tests/test_api.py` | 教材第 12 章才正式引入测试；本实训只要求手工验证八条 |
| `验证记录.md` 的真实输出 | 学生应记录自己的运行结果，不能照抄教师环境 |
| `难度评分.md` | 备课信息，对学生是干扰 |
| `接缝表.md` | 含完整变更清单与下游预告，等于提前给出改造路线 |
| `学员版差异说明.md` | 教师内部文档，不进入学生包 |
| 分步指南中的完整代码块 | 替换为骨架与关键行提示，避免“抄写即完成” |
| 6-1 项目 README 中的教师 pytest 命令与完成态目录树 | 替换为学生工作副本的目录树与手工验证命令 |

## 四、替换内容

| 完整版 | 学员版替换为 | 替换理由 |
| --- | --- | --- |
| `app/core/database.py` 完整 13 行 | 文件骨架：导入、`DATABASE_URL`、`engine`、`SessionLocal`、`Base`、`get_db` 的 TODO 与注释 | 学生要自己写出会话生命周期 |
| `model.py` 完整 ORM | 字段表 + “继承 Base、声明 `__tablename__`、主键/必填/长度”的提示 | 保留表结构判断，删除可直接抄的类 |
| `crud.py` 完整 29 行 | 五个函数签名与“用 query/add/commit/refresh/delete”的提示 | 学生要自己完成 Session 读写 |
| `main.py` 完整 34 行 | 在 5-1 的 main 上标出三处插入点：导入模型、`create_all`、seed | 保留建表时序这一关键认知 |
| `service.py` 完整 25 行 | 保留业务规则清单（重复 400、查不到 404）与 `offset` 公式，函数体留空 | 业务判断不能由代码代劳 |
| `controller.py` 完整 27 行 | 保留路由表与 `Depends(get_db)` 提示，函数体留空 | 学生要理解依赖注入 |
| `schema.py`/`param.py` 完整代码 | 字段与边界表 + “是否保留 DepartmentUpdate/DepartmentPage”的讨论题 | 让学生自己判断契约变化 |

| 教师实测的 `13 passed`、`duty.db 12288 字节` | 空白“实际结果”列 | 学生必须自己跑出数据 |

## 五、学员版建议目录

```text
实训6-1-学员版/
├── README.md                 # 任务书（目标、边界、时间、步骤、验收、排错、提交、扩展、教材映射）
```

## 六、评分口径（学员版）

| 等级 | 标准 |
| --- | --- |
| 及格 | 完成 4 处改造；五个接口可用；列表含 `items`/`total`；新增 201、详情 200/404、删除 204/404；重启后数据仍在 |
| 良好 | 在上述基础上，`page=0`/`page_size=0` 返回 422；重复编码 400；固定排序正确；`requirements.txt` 与 `.gitignore` 同步 |
| 优秀 | 能解释 `engine`/`Session`/`Base`/`get_db` 的分工；能说明 422/400/404 的层次；完成 seed/init 拆分或分页边界之一；仓库无数据库、缓存与环境文件 |

不要求提交自动测试；不要求与教师完成态代码逐字一致，但接口路径、状态码、字段与分页契约必须一致。若学生使用不同实现（例如把 `offset` 计算放在 crud），只要行为正确、边界一致即可。

## 七、不可删除的教学支架

以下内容即使压缩学员版也必须保留，否则学生会退化为“照着抄”：

1. 起点说明中的 4 处改动清单（只给位置与目标，不给代码）。
2. 表结构三字段与约束表。
3. 状态码契约与错误分层表。
4. 分页公式与 `{items, total}` 的响应形状。
5. 八条手工检查清单与重启持久化步骤。
6. 排错表的“现象 → 先查什么 → 处理方向”。
7. 教材 6.1–6.4 与代码号映射，方便学生回读。
8. 提交前的 `git ls-files` 卫生检查。

## 八、教师使用建议

- 课前把 `starter/` 与任务书发给学生，明确“不得修改教师完成态”。
- 课堂只演示 `engine`/`Session` 的职责与 `create_all` 的时序，不演示完整六文件抄写。
- 验收时随机抽取一条记录重启，避免学生只在 TestClient 里验证。
- 对进度快的学生，追加 seed/init 拆分或分页边界；对进度慢的学生，保证“四个接口 + 重启持久化”先完成。
