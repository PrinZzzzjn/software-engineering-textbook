# 实训 6-1 分步实现指南

本指南对应教材实训 6-1 的三步：建库与建表、department 读写全流程、验证与提交。示例固定为单位模块（department）。全部命令以 Windows PowerShell 为准，文档端口统一为 8000。

**代码一致性约定**：本指南中标注为「完整文件」的代码块与 `项目/` 对应文件逐字一致。阶段 1–2 完成后应用只能确认 `/health` 与数据库；阶段 3 把四个接线文件补齐后，五个单位接口才全部可用。这是分阶段施工的正常中间态。

## 阶段 1：数据库基础设施（20 分钟）

### 1.1 新建包文件

在 `app/` 下新建 `core/` 目录，并放一个空的 `__init__.py`。没有它，`from app.core.database import ...` 会报 `ModuleNotFoundError`。

### 1.2 `app/core/database.py`（完整文件）

```python
import os

from sqlalchemy import create_engine
from sqlalchemy.orm import declarative_base, sessionmaker

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./duty.db")

engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)
Base = declarative_base()


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

四个名字各管一件事：`engine` 知道数据库文件在哪、怎么连；`SessionLocal()` 每次造出一个请求级 `Session`；`Base` 是表模型的父类；`get_db` 把 session 交给接口，接口结束后在 `finally` 关闭。

### 验证

```powershell
python -c "from app.core.database import engine, SessionLocal, Base; print(engine.url)"
```

预期输出：

```text
sqlite:///./duty.db
```

此时还没有建表，`duty.db` 也未必立刻出现；`create_engine` 不主动连接。

### 常见错误

- 少了 `app/core/__init__.py`，导入报 `ModuleNotFoundError: No module named 'app.core'`。
- 把 `DATABASE_URL` 写死成 `D:\...\duty.db`；换机后路径失效。应使用环境变量与相对路径回落。
- 删掉 `connect_args={"check_same_thread": False}`；FastAPI 的线程池与 SQLite 同连接协作时会报线程错误。
- 把 `DATABASE_URL` 写进 `.env` 就以为会生效；本章没有 `python-dotenv`，应用只读系统环境变量。

## 阶段 2：模型、输入输出与建表（25 分钟）

### 2.1 `app/modules/department/model.py`（完整文件）

删除 `@dataclass` 与 `TABLE`，改为：

```python
from sqlalchemy import Column, String

from app.core.database import Base


class Department(Base):
    __tablename__ = "departments"

    dept_code = Column(String(20), primary_key=True)
    full_name = Column(String(100), nullable=False)
    address = Column(String(500), nullable=True)
```

`primary_key=True` 是主键，`nullable=False` 是必填，`String(100)` 是长度上限。三者都在写入时由数据库检查，是最后一道防线。

### 2.2 `app/modules/department/schema.py`（完整文件）

```python
from pydantic import BaseModel, ConfigDict, Field


class DepartmentCreate(BaseModel):
    dept_code: str = Field(..., min_length=2, max_length=20)
    full_name: str = Field(..., min_length=2, max_length=100)
    address: str | None = Field(default=None, max_length=500)


class DepartmentUpdate(BaseModel):
    full_name: str | None = Field(default=None, min_length=2, max_length=100)
    address: str | None = Field(default=None, max_length=500)


class DepartmentOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    dept_code: str
    full_name: str
    address: str | None = None


class DepartmentPage(BaseModel):
    items: list[DepartmentOut]
    total: int
```

与 5-1 的差别：`DepartmentCreate` 的字段长度与 4.5 保持一致；`DepartmentUpdate` 只列允许修改的字段，主键 `dept_code` 不在其中；输出模型增加 `from_attributes=True`，让 Pydantic 能从 ORM 对象读取字段；`DepartmentPage` 把 `items` 与 `total` 的返回结构写进模型，列表接口用它声明 `response_model`。

### 2.3 `main.py`（完整文件）

```python
from fastapi import FastAPI

from app.core.database import Base, SessionLocal, engine
from app.modules.department import controller as department_controller
from app.modules.department import model as department_model  # noqa: F401  建表前先导入模型

app = FastAPI(title="Duty API", version="0.1.0")


@app.get("/health")
def health():
    return {"status": "healthy"}


app.include_router(department_controller.router, prefix="")

# 建表只创建缺失的表；表已存在时重复调用不会清空数据
Base.metadata.create_all(bind=engine)


def _seed_departments() -> None:
    """写入两个教学演示单位；逐条先查存在性，重复启动不会重复写入。"""
    db = SessionLocal()
    try:
        for code, name, address in [
            ("D001", "一中队", "一号营区"),
            ("D002", "二中队", "二号营区"),
        ]:
            exists = (
                db.query(department_model.Department)
                .filter(department_model.Department.dept_code == code)
                .first()
            )
            if not exists:
                db.add(
                    department_model.Department(
                        dept_code=code, full_name=name, address=address
                    )
                )
        db.commit()
    finally:
        db.close()


_seed_departments()
```

建表三行不能省：导入 `Base` 与 `engine`、导入模型、`Base.metadata.create_all(bind=engine)`。`create_all` 只识别**已经导入**的模型，所以模型导入不是装饰。

seed 逐条先查存在性，重复启动不会重复插入；这与 `create_all` 的「表已存在则跳过」是同一思路。

## 阶段 3：读写接线（60 分钟）

本阶段四个文件必须一起完成：`crud.py` 与 `service.py` 改签名后，`controller.py` 若不同步修改，列表请求会因参数不匹配而 500。

### 3.1 `app/modules/department/crud.py`（完整文件）

```python
from sqlalchemy.orm import Session

from app.modules.department.model import Department


def get_by_code(db: Session, dept_code: str):
    return db.query(Department).filter(Department.dept_code == dept_code).first()


def list_page(db: Session, offset: int, limit: int):
    items = (
        db.query(Department)
        .offset(offset)
        .limit(limit)
        .all()
    )
    total = db.query(Department).count()
    return items, total


def create(db: Session, data):
    department = Department(**data.model_dump())
    db.add(department)
    db.commit()
    db.refresh(department)
    return department


def update(db: Session, department, data: dict):
    for key, value in data.items():
        setattr(department, key, value)
    db.commit()
    db.refresh(department)
    return department


def delete(db: Session, department):
    db.delete(department)
    db.commit()
```

`list_page` 用 `offset`、`limit` 取当前页，`total` 单独 `count()`，是本页之外的全量条数；固定 `order_by` 留到第 7 章 7.4。`create` 提交后 `refresh`，保证返回的对象带上数据库里的最终值。

### 3.2 `app/modules/department/service.py`（完整文件）

```python
from fastapi import HTTPException

from app.modules.department import crud


def list_departments(db, params):
    offset = (params.page - 1) * params.page_size
    items, total = crud.list_page(db, offset, params.page_size)
    return {"items": items, "total": total}


def create_department(db, data):
    if crud.get_by_code(db, data.dept_code):
        raise HTTPException(status_code=400, detail="单位编码已存在")
    return crud.create(db, data)


def get_department(db, dept_code: str):
    department = crud.get_by_code(db, dept_code)
    if not department:
        raise HTTPException(status_code=404, detail="单位不存在")
    return department


def update_department(db, dept_code: str, data):
    department = crud.get_by_code(db, dept_code)
    if not department:
        raise HTTPException(status_code=404, detail="单位不存在")
    return crud.update(db, department, data.model_dump(exclude_unset=True))


def delete_department(db, dept_code: str) -> None:
    department = crud.get_by_code(db, dept_code)
    if not department:
        raise HTTPException(status_code=404, detail="单位不存在")
    crud.delete(db, department)
```

业务规则仍留在 service：重复编码 400、查不到 404。crud 不判断业务规则，只执行查询与写入。

### 3.3 `app/modules/department/param.py`（完整文件）

```python
from pydantic import BaseModel, Field


class DepartmentQueryParams(BaseModel):
    page: int = Field(default=1, ge=1)
    page_size: int = Field(default=10, ge=1, le=100)
```

`ge=1` 让 `page=0`、`page_size=0` 在进入函数前返回 422；`le=100` 防止一次拉取过多记录。

### 3.4 `app/modules/department/controller.py`（完整文件）

```python
from fastapi import APIRouter, Depends, status
from sqlalchemy.orm import Session

from app.core.database import get_db
from app.modules.department import service
from app.modules.department.param import DepartmentQueryParams
from app.modules.department.schema import (
    DepartmentCreate,
    DepartmentOut,
    DepartmentPage,
    DepartmentUpdate,
)

router = APIRouter(prefix="/departments", tags=["单位"])


@router.get("", response_model=DepartmentPage)
def list_departments(
    params: DepartmentQueryParams = Depends(),
    db: Session = Depends(get_db),
):
    return service.list_departments(db, params)


@router.post("", response_model=DepartmentOut, status_code=status.HTTP_201_CREATED)
def create_department(data: DepartmentCreate, db: Session = Depends(get_db)):
    return service.create_department(db, data)


@router.get("/{dept_code}", response_model=DepartmentOut)
def read_department(dept_code: str, db: Session = Depends(get_db)):
    return service.get_department(db, dept_code)


@router.put("/{dept_code}", response_model=DepartmentOut)
def update_department(
    dept_code: str, data: DepartmentUpdate, db: Session = Depends(get_db)
):
    return service.update_department(db, dept_code, data)


@router.delete("/{dept_code}", status_code=status.HTTP_204_NO_CONTENT)
def delete_department(dept_code: str, db: Session = Depends(get_db)):
    service.delete_department(db, dept_code)
```

controller 只声明路由、依赖与响应模型；`db: Session = Depends(get_db)` 让 FastAPI 在每个请求前开 session、请求结束后关闭。列表参数由 `DepartmentQueryParams = Depends()` 从 `?` 后读取，边界在进入函数前完成校验。

### 常见错误

- 列表参数不匹配：`service.list_departments` 已改签名，controller 仍按 `(page, page_size)` 调用，请求 500。
- 忘记 `db: Session = Depends(get_db)`，service 收到 `None` 或缺少参数。
- 列表只有 `items` 没有 `total`：service 没有组装 `crud.list_page` 的第二个返回值。
- 翻页顺序不稳定：本章的 `list_page` 还没带 `order_by`；第 7 章 7.4 会补固定排序键。
- 修改接口报 422：PUT 的 body 仍按新增格式提交；本参考的 PUT 用 `DepartmentUpdate`，只传要改的字段即可。
- 删除返回 200：路由仍用默认状态码；应声明 `status_code=status.HTTP_204_NO_CONTENT`。

## 阶段 4：九条测试清单与错误分层（25 分钟）

服务仍在 8000 端口运行时，逐条执行。PowerShell 5 对 4xx 会抛异常，用 `try/catch` 读状态码。

```powershell
$base = "http://127.0.0.1:8000"

# 1. 列表 200，含 items/total
(Invoke-WebRequest -UseBasicParsing "$base/departments").StatusCode
(Invoke-RestMethod "$base/departments").total

# 2. 新增 201
$new = @{ dept_code = "D003"; full_name = "三中队"; address = "三号营区" } | ConvertTo-Json
(Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$base/departments" -ContentType "application/json" -Body $new).StatusCode

# 3. 重复编码 400
try { Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$base/departments" -ContentType "application/json" -Body $new } catch { $_.Exception.Response.StatusCode.value__ }

# 4. 缺字段 422
$bad = @{ dept_code = "D004" } | ConvertTo-Json
try { Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$base/departments" -ContentType "application/json" -Body $bad } catch { $_.Exception.Response.StatusCode.value__ }

# 5. 详情 200
(Invoke-WebRequest -UseBasicParsing "$base/departments/D003").StatusCode

# 6. 不存在 404
try { Invoke-WebRequest -UseBasicParsing "$base/departments/D999" } catch { $_.Exception.Response.StatusCode.value__ }

# 7. 分页 200，page=0 与 page_size=0 为 422
Invoke-RestMethod "$base/departments?page=1&page_size=2"
try { Invoke-WebRequest -UseBasicParsing "$base/departments?page=0" } catch { $_.Exception.Response.StatusCode.value__ }
try { Invoke-WebRequest -UseBasicParsing "$base/departments?page_size=0" } catch { $_.Exception.Response.StatusCode.value__ }

# 8. 修改 200；修改不存在的编码 404
$put = @{ full_name = "三中队（改）"; address = "三号营区" } | ConvertTo-Json
(Invoke-WebRequest -UseBasicParsing -Method Put -Uri "$base/departments/D003" -ContentType "application/json" -Body $put).StatusCode
$put_missing = @{ full_name = "三中队（改）" } | ConvertTo-Json
try { Invoke-WebRequest -UseBasicParsing -Method Put -Uri "$base/departments/D999" -ContentType "application/json" -Body $put_missing } catch { $_.Exception.Response.StatusCode.value__ }

# 9. 删除 204 无正文；重复删除 404
$deleted = Invoke-WebRequest -UseBasicParsing -Method Delete -Uri "$base/departments/D003"
"status=$($deleted.StatusCode) body=$($deleted.Content)"
try { Invoke-WebRequest -UseBasicParsing -Method Delete -Uri "$base/departments/D003" } catch { $_.Exception.Response.StatusCode.value__ }
```

预期状态码依次为 200、201、400、422、200、404、200/422/422、200/404、204 且 `body` 为空、404。

### 错误分层核对

| 情况 | 状态码 | 产生位置 | 本次触发方式 |
| --- | --- | --- | --- |
| 缺字段、类型不对、长度超限 | 422 | 输入模型校验，进入函数前 | `POST` 只带 `dept_code` |
| 编码重复 | 400 | `service.create_department` | 同编码 `POST` 两次 |
| 资源不存在 | 404 | `service.get/update/delete_department` | `GET/DELETE /departments/D999` |
| 未捕获异常 | 500 | 框架兜底 | 不应由正常业务路径触发 |

### 常见错误

- 重复编码返回 500：service 没先查重，数据库唯一约束抛异常。
- 详情 404 变成 500：查不到时直接访问空对象字段，没有先抛 `HTTPException(404)`。
- 422 与 400 混淆：422 是格式/边界问题，400 是业务规则问题。
- 删除 204 却带正文：处理函数返回了内容；204 处理函数不返回正文。
- 重复删除返回 204：删除前没有查存在性。

### 常见错误

- 只在 TestClient 中通过就声称持久化成功；必须真实停止并重启进程。
- 重启后数据消失：仍在使用内存版 `crud.py` 或启动目录不同，读写到了另一个 `duty.db`。
- `duty.db` 进入提交：用 `git rm --cached duty.db` 移出索引，并确认 `.gitignore` 生效。
- 把 `pytest`、`httpx` 写进运行依赖；它们只属于教师验证环境。
