# ARM64 内网离线安装说明

> 适用：课堂完全内网封闭的 ARM64 Ubuntu 授课机
> 配套文件：`wheelhouse-arm64/`、`python-images-arm64.tar`、`duty-images-arm64.tar`、`Dockerfile.*.offline`、`docker-compose.offline.yml`
> 完整背景见仓库根 `tools/offline-deps/README.md`

## 0. 授课机环境检查（必须先做）

```bash
uname -m                    # 预期：aarch64
ldd --version | head -1     # 预期：glibc >= 2.17
python3.12 -V               # 预期：Python 3.12.x
docker version              # 第 22-24 章需要；预期有输出
docker compose version      # 预期有输出
```

- 若 `uname -m` 不是 `aarch64`：用错了机器，ARM64 轮子装不上。
- 若没有 Python 3.12：cp312 轮子全部不匹配，必须先装 3.12（内网需提前准备 Python 3.12 安装包）。
- 若 `docker` 不存在：第 22-24 章无法实跑，需先离线安装 Docker Engine（提前准备 docker 的 .deb 安装包）。

## 1. 非 Docker 实训（第 3-20 章）：wheelhouse 安装依赖

把 `wheelhouse-arm64/` 和 `requirements.linux-arm64.lock.txt` 拷到授课机同一目录，然后：

```bash
cd <课程目录>/tools/offline-deps
python3.12 -m venv venv
source venv/bin/activate
pip install --no-index --find-links=./wheelhouse-arm64 -r requirements.linux-arm64.lock.txt
```

验证：

```bash
python -c "import fastapi,uvicorn,sqlalchemy,pydantic,pytest,httpx,streamlit,pandas,requests; print('deps ok')"
cd 项目参考/duty-simplified
python -m pytest tests/test_smoke.py -q        # 预期 3 passed
uvicorn main:app --reload --port 8000          # 浏览器访问 /health、/docs
```

> `--no-index` 保证 pip 完全不访问公网；不要用教材里的 `pip install -r requirements.txt` 原命令。
> 前端默认请求 `http://127.0.0.1:8000`；后端在别的机器时设 `DUTY_API_BASE_URL=http://<后端IP>:8000`。

## 2. Docker 实训（第 22-24 章）：加载离线镜像

把 `python-images-arm64.tar` 和 `duty-images-arm64.tar` 拷到授课机，加载：

```bash
docker load -i python-images-arm64.tar
docker load -i duty-images-arm64.tar
```

验证镜像架构为 arm64：

```bash
docker image inspect --format '{{.Architecture}}' duty-backend:1.0    # 预期 arm64
docker image inspect --format '{{.Architecture}}' duty-frontend:1.0   # 预期 arm64
```

## 3. 一键启动前后端（内网，不构建）

把 `docker-compose.offline.yml` 拷到授课机，在同目录执行：

```bash
docker compose -f docker-compose.offline.yml up -d
```

验证：

```bash
docker compose -f docker-compose.offline.yml ps          # 两个服务均 healthy
curl http://127.0.0.1:8000/health                         # {"status":"healthy"}
# 浏览器访问 http://<授课机IP>:8501
```

停止：

```bash
docker compose -f docker-compose.offline.yml down
```

## 4. 若必须在授课机重新构建镜像（备用）

正常用 `load` + `compose.offline.yml` 即可。若镜像损坏需重建：

1. 把 `wheelhouse-arm64/` 复制为各项目目录下的 `wheelhouse/`：
   ```bash
   cp -r wheelhouse-arm64 项目参考/duty-simplified/wheelhouse
   cp -r wheelhouse-arm64 项目参考/duty_frontend/wheelhouse
   ```
2. 把 `Dockerfile.backend.offline` 放到 `duty-simplified/`（覆盖原 Dockerfile），`Dockerfile.frontend.offline` 放到 `duty_frontend/`。
3. 在 ARM64 机器上构建：
   ```bash
   docker build -t duty-backend:1.0 项目参考/duty-simplified
   docker build -t duty-frontend:1.0 项目参考/duty_frontend
   ```
   > 必须在 ARM64 机器上 build；x86 机器 build 出的镜像在 ARM 上跑不起来。

## 5. 内网常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pip install` 报找不到包 | wheel 平台不匹配或漏包 | 确认用 `--find-links` 指向 arm64 wheelhouse；核对 56 个包齐全 |
| `docker load` 后镜像架构是 amd64 | 用了 x86 构建的镜像 tar | 必须用 arm64 镜像 tar（见阶段 0 产出） |
| `/docs` 页面空白 | Swagger UI 走公网 CDN | `/openapi.json` 正常；可用 `swagger-ui-bundle` 本地化（见 tools/offline-deps README 第 6 节） |
| 前端连不上后端 | DUTY_API_BASE_URL 不对 | compose 内用 `http://backend:8000`；非 compose 用 `http://127.0.0.1:8000` 或后端 IP |
| 容器启动后无数据 | 首次启动 seed 失败 | 后端镜像首次启动自动建表+seed；检查 `docker logs` 有无报错 |
