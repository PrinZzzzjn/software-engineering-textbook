## 二、等级判定

### 代码行数：落在 D3 区间

学生新增/改写约 215 行，按总计划的行数区间属于 D3（201–400 行）。

### 涉及文件数：落在 D3 区间

学生实质触碰 10 个代码文件，落入 D3 的 6–10 个文件区间。行数与文件数都取 D3，不需要按「较高等级」上调。

### 认知负荷：L4

| 维度 | 表现 |
| --- | --- |
| 新机制数量 | 参数模型复用、过滤条件拼装；分页与固定排序是 6-1 的复习，不按全新机制计 |
| 跨文件耦合 | 过滤字段从 `param.py` 经 `service.py` 传到 `crud.py`，任一处漏改就出现「筛选无效」；personnel 六文件同构复制，需逐处替换语义 |
| 错误可观察性 | `total` 与 `items` 是否同源可直接观察；但「筛选后总数不变」「翻页重复」不会抛异常，需要构造请求比对 |
| 与前置实训的跨度 | 6-1 已落库与分页，7-1 从「一个模块能查」升级为「两个模块一致地查」，属于复用判断与第二个模块的协同 |
| 业务依赖 | personnel 新增与修改要校验 `dept_code` 是否存在，跨模块读取单位表；返回 400 而非让数据库异常变 500 |

综合为 **L4**。L5 需要全链路联调或不可逆数据迁移，本实训不涉及；L3 只需要单模块跨层调用，覆盖不了「两个模块 + 回归」的协同面。

## 三、新概念数与拆分建议

本实训按必做范围只保留两个新概念：

1. **参数模型复用**：在 `param.py` 中同时声明分页边界与过滤字段，由 `Depends()` 注入；第二个模块沿用同一形状与同一参数名。
2. **过滤条件拼装**：在 `crud.list_page` 中按可选参数追加 `filter`，并保证 `filter` 在 `count()` 之前，使 `total` 与 `items` 同源。

以下内容不作为课堂新授，列为复习或课后扩展：

- 固定排序：6-1 已按 `dept_code` 固定，本实训只要求保留并复制到 `certificate_number`。
- 422/400/404/204 分层：3-1 至 6-1 已反复出现。
- 多字段组合过滤：代码上会自动累加条件，但课堂只验证单条件，组合验证留课后。
- 分页边界：越界页、上限调整留课后。
- 教材 7.5 的 `app/core/pagination.py`：留课后，用于讨论「模块内同构」与「公共件」的取舍。

按「单次实训新概念≤2 个」的规则，本实训在必做范围内刚好满足。若把组合过滤、分页边界与公共分页件同时塞进课堂，新概念会升到 4–5 个，90 分钟必然挤掉排错与回归。

## 五、必做与选做切分

### 必做（构成及格线）

1. **重复识别**：并排两个 `list_page`，至少指出三处结构相同，并把模型、过滤、排序列为模块语义。
2. **参数边界**：department 的 `param.py` 增加 `full_name`；两个模块的 `page=0`、`page_size=0` 均为 422。
3. **过滤与计数**：department 的 `full_name` 模糊过滤生效；`filter` 在 `count()` 之前；未命中返回 200 与空 `items`。
4. **固定排序**：department 按 `dept_code`、personnel 按 `certificate_number`；逐页比对无重复。
5. **personnel 复用演练**：六文件齐备；列表分页与单条件过滤可用；新增 201、重复 400、详情 200/404、删除 204/404。
6. **回归**：不带过滤参数时，department 的 `items`/`total` 与 6-1 一致。

### 选做（不占必做时间）

1. **多字段组合过滤**：`name` 与 `dept_code` 同时传入的验证与语义讨论。
2. **分页边界**：越界页、`page_size` 上限、`total` 与过滤次序的更多用例。
3. **公共分页件**：按 7.5 抽出 `app/core/pagination.py`，比较维护成本。
4. **排序白名单**：为 department 增加受控的 `sort_by`，比较与固定键的适用边界。

## 六、合理性核对

| 核对项 | 判断 |
| --- | --- |
| 前置知识是否够用 | 6-1 已给出落库、`Session`、分页与固定排序；7-1 只加过滤与第二个模块，前置够用。若 6-1 未完成，90 分钟不够。 |
| 失败是否可定位 | 422 与 400 可直接观察；`total` 偏大可通过「筛选命中数」比对；翻页重复可通过逐页编码比对。 |
| 验收是否可观察 | 两个模块的列表 JSON、过滤命中/未命中、422、增删改查状态码、6-1 回归表均可由请求复现。 |
| 教材映射是否完整 | 7.1–7.5 与实训四步都有落点；7.5 公共件明确列为课后扩展，没有假装在课内完成。 |
| 难度是否连续 | 6-1 单模块落库与分页 → 7-1 两个模块一致查询 → 8-1 认证；7-1 是复用判断的升级，不是重复 6-1。 |
| 是否有超纲内容 | 无 users、认证、权限、`/api/v1`、`sort_by`、测试框架要求；组合过滤与公共件均为选做。 |

## 七、结论

**D3 / L4 / 偏紧**。偏紧的原因不是代码量，而是 90 分钟内要同时完成「理解过滤与计数次序」「把变化收敛到 param/crud」「复制第二个模块并保持状态码一致」「回归 6-1」四件事。personnel 六文件虽是同构复制，但每份都要替换模型、主键、过滤字段与排序键，漏一处就出现行为偏差。

取舍建议：

- **保持 90 分钟（推荐）**：课堂只做「参数模型 + 过滤 + 固定排序」主目标；personnel 至少完成列表分页与单条件过滤，完整增删改查可作为课后补齐。组合过滤、分页边界、`app/core/pagination.py` 明确移出必做。
- **进度落后时**：先保证 department 的过滤与计数次序、personnel 的列表可用；personnel 的修改/删除可延后，但不能删 department 的回归。
- **拆成两次（严格方案）**：7-1A「查询参数与过滤」2 学时，只改 department；7-1B「第二个模块复用」2 学时，复制 personnel 并做回归。这样每次新概念不超过 2 个，排错时间可回到 25% 以上。
- **不推荐**：在 90 分钟内同时讲组合过滤、分页边界、公共分页件与排序白名单；这会把课堂变成四个并列主题，学生没有时间验证 `total` 与 `items` 是否同源。
