# 实训 7-1 学员版差异说明

> 完整版：教师用 `实训7-1/`（含完成态、23 项教师测试、实跑记录）  
> 学员版：从 6-1 完成态出发的任务书 + 起点 + 验收模板  
> 原则：保留「重复识别 → 参数收拢 → 过滤计数 → 固定排序 → 回归」的判断支架，删除答案代码；学生必须自己完成第二个模块的复制与替换。

## 一、总体差异

| 维度 | 完整版 | 学员版 |
| --- | --- | --- |
| 起点 | `starter/` 与 6-1 完成态 | 同左，保留 |
| 目标工程 | `项目/` 完成态，可直接启动 | 不提供；学生把 `starter/` 复制为工作副本后改造 |
| 代码 | 每个阶段完整文件 | 只给字段表、函数签名、关键行提示与 TODO，核心实现留空 |
| 测试 | `tests/test_api.py` 23 项，pytest 全绿 | 不提供 7-1 新测试；starter 中的 6-1 测试保留为回归工具，学生不扩展 |
| 验证 | `验证记录.md` 真实输出 | 提供空白记录模板，由学生填写实际结果 |
| 难度/接缝 | `难度评分.md`、`接缝表.md` | 删除；起点说明只保留「要改哪几处」 |
| 文档 | 教师视角，含课堂时间与排错预算 | 学生视角，保留目标、边界、步骤、验收、排错、提交 |

## 四、替换内容

| 完整版 | 学员版替换为 | 替换理由 |
| --- | --- | --- |
| `department/param.py` 完整 7 行 | 字段表 + 「分页边界写在 `Field`、过滤字段用列名」的提示 | 学生要自己决定边界与过滤字段 |
| `department/crud.py` 完整 `list_page` | 函数签名 + 「建 query → 加 filter → count → order_by → offset/limit」的步骤提示 | 学生要自己写出计数次序 |
| `department/service.py` 完整列表函数 | `offset` 公式与 `{items, total}` 组装提示，函数体留空 | 业务换算不能由代码代劳 |
| personnel 六文件完整代码 | 字段表、路由表、文件职责表、函数签名与 TODO | 学生要完成「复制后替换语义」 |
| `main.py` 完整 76 行 | 在 6-1 的 main 上标出四处插入点：导入 personnel 模型、挂路由、seed、seed 调用顺序 | 保留建表时序与 seed 依赖这一关键认知 |
| 23 项教师测试 | 手工验证清单 + 空白回归记录表 | 避免把测试框架提前引入 |
| 教师实测的 `23 passed`、8014 响应 | 空白「实际结果」列 | 学生必须自己跑出数据 |
| 完整版 90 分钟排错预算 | 学生版只给「卡住时先查什么」，不公布分钟数 | 避免学生按教师节奏机械等待 |

## 六、评分口径（学员版）

| 等级 | 标准 |
| --- | --- |
| 及格 | department 的 `full_name` 过滤生效，`total` 随过滤变化；`page=0` 返回 422；personnel 列表能分页并按 `certificate_number` 排序；启动后 `/personnel` 可用 |
| 良好 | 在上述基础上，personnel 过滤命中/未命中正确；新增 201、重复 400、详情 200/404、修改 200、删除 204/404；新增人员校验单位存在；department 的 6-1 行为未回归 |
| 优秀 | 能解释「结构可收拢、语义留模块」；能说明 `filter` 为什么必须在 `count()` 之前；完成组合过滤、分页边界或 `app/core/pagination.py` 之一；仓库无数据库、缓存与环境文件 |

不要求提交自动测试；不要求与教师完成态逐字一致，但接口路径、状态码、字段、过滤语义、固定排序与 `{items, total}` 契约必须一致。若学生把 `offset` 计算放在 crud，或把过滤参数改名，只要行为正确且文档同步，也可接受。

## 七、不可删除的教学支架

以下内容即使压缩学员版也必须保留，否则学生会退化为「照着抄」：

1. 起点说明中的 4 处改动清单（只给位置与目标，不给代码）。
2. department 与 personnel 的字段表、主键与长度约束。
3. 「三处结构相同、三处模块语义」的对比表。
4. 过滤语义：模糊/精确、空串不筛选、未命中 200 + 空列表。
5. 「`filter` 必须在 `count()` 之前、`total` 与 `items` 同源」的判断。
6. 固定排序键与「不接受前端 `sort_by`」的理由。
7. 状态码契约与 422/400/404 的分层。
8. 改造前后同一组请求的回归清单。
9. 排错表的「现象 → 先查什么 → 处理方向」。
10. 教材 7.1–7.5 与代码号映射，方便学生回读。

## 八、教师使用建议

- 课前把 `starter/` 与任务书发给学生，明确「不得修改教师完成态」。
- 课堂只演示「重复与差异」和「计数次序」两处判断，不演示 personnel 六文件逐行抄写。
- 让先完成的学生运行 starter 的 13 项测试，确认 department 未回归；不要让他们提前改写测试。
- 验收时随机抽取一个过滤值与一个越界参数，避免学生只验证“正常路径”。
- 对进度快的学生，追加组合过滤、分页边界或公共分页件；对进度慢的学生，保证 department 过滤与 personnel 列表先完成。
- 不把 `app/core/pagination.py` 作为及格线；它体现的是复用边界的进一步判断，不是本实训的最低要求。
