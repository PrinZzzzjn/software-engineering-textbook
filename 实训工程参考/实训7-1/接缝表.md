## 二、新增：personnel 六文件

### `model.py`

```python
class Personnel(Base):
    __tablename__ = "personnel"

    certificate_number = Column(String(20), primary_key=True)
    name = Column(String(100), nullable=False)
    dept_code = Column(String(20), nullable=False)
    rank = Column(String(50), nullable=True)
```

与 department 的差异：

| 项目 | department | personnel |
| --- | --- | --- |
| 主键 | `dept_code`（单位编码） | `certificate_number`（证件号，字符串） |
| 业务字段 | `full_name`、`address` | `name`、`dept_code`、`rank` |
| 排序键 | `dept_code` | `certificate_number` |
| 过滤字段 | `full_name` 模糊 | `name` 模糊、`dept_code` 精确 |
| 跨模块依赖 | 无 | 新增/修改时校验 `dept_code` 存在 |

`dept_code` 只作为普通列保存，没有数据库外键；存在性由 service 检查，保持与 `duty-simplified` 一致。

### `param.py`

```python
class PersonnelQueryParams(BaseModel):
    page: int = Field(default=1, ge=1)
    page_size: int = Field(default=10, ge=1, le=100)
    name: str | None = None
    dept_code: str | None = None
```

分页字段与 department 同名同边界；过滤字段使用 personnel 表的列名。`None` 与空串都表示不筛选。

### `crud.py`

`list_page(db, offset, limit, name=None, dept_code=None)` 的顺序固定为：

```text
建 query → 追加 filter（name、dept_code）→ count → order_by(certificate_number) → offset → limit
```

两个过滤条件都在 `count()` 之前，因此 `total` 是过滤后的总数。

### `service.py`

列表部分与 department 同构：`offset = (page - 1) * page_size`，透传过滤字段，返回 `{items, total}`。业务规则：

- 证件号已存在 → 400「证件号已存在」；
- 新增或修改时 `dept_code` 不存在 → 400「所属单位不存在」；
- 查询、修改、删除不到 → 404「人员不存在」。

单位存在性复用 `department.crud.get_by_code`，只读单位表。

### `controller.py`

`APIRouter(prefix="/personnel", tags=["人员"])`，五个接口的路径、状态码与 department 一致：

| 方法 | 路径 | 成功 | 失败 |
| --- | --- | --- | --- |
| GET | `/personnel` | 200 `{items, total}` | 422 |
| POST | `/personnel` | 201 | 400、422 |
| GET | `/personnel/{certificate_number}` | 200 | 404 |
| PUT | `/personnel/{certificate_number}` | 200 | 400、404、422 |
| DELETE | `/personnel/{certificate_number}` | 204 无正文 | 404 |

### `department/crud.py`

6-1：

```python
def list_page(db: Session, offset: int, limit: int):
    items = db.query(Department).order_by(Department.dept_code).offset(offset).limit(limit).all()
    total = db.query(Department).count()
    return items, total
```

7-1：

```python
def list_page(db: Session, offset: int, limit: int, full_name: str | None = None):
    query = db.query(Department)
    if full_name:
        query = query.filter(Department.full_name.contains(full_name))
    total = query.count()
    items = query.order_by(Department.dept_code).offset(offset).limit(limit).all()
    return items, total
```

变化点：查询对象只建一次；过滤在计数之前；`total` 与 `items` 同源。固定排序键不变。

## 四、不兼容点

1. **列表查询参数扩展**：department 增加 `full_name`，personnel 增加 `name`、`dept_code`。旧请求不带这些参数时行为不变；带参数时 `total` 的语义是**过滤后的总数**，不再等于全表条数。前端若用 `total` 计算页数，必须使用同一个过滤条件。
2. **personnel 主键为字符串编码**：没有整数 `id`，详情、修改、删除的路径参数都是 `certificate_number`。按字符串排序时 `P10` 会排在 `P2` 前；若业务需要自然序，应在编码上补零或改用可排序格式，而不是改前端排序。
3. **新增表**：`personnel` 表由 `create_all` 补建。旧 `duty.db` 只有 `departments` 时，启动后会自动多出 `personnel`；不需要手工迁移，也不会清空旧数据。
4. **跨模块业务校验**：新增或修改人员时，`dept_code` 不存在返回 400，而不是让数据库异常变成 500。前端要把 400 当作可提示的业务错误处理。
5. **personnel 的排序键**：固定为 `certificate_number`，不是 `dept_code`。同一单位多人时，按证件号升序稳定分页；若照抄 department 的 `dept_code` 排序，翻页会不稳定。
6. **测试基线变化**：6-1 是 13 项，7-1 是 23 项。学生若保留 starter 的 13 项测试，新增用例不会自动出现；教师验收以 7-1 的 23 项为准。
7. **契约外的新增过滤**：`/personnel` 的 `name` 过滤是本实训为演示模糊匹配增加的参数，接口契约清单中只列了 `dept_code`。文档与前端需按本实训的扩展说明处理，不要误以为 `name` 在所有章节都存在。
8. **不变的部分**：`/health`、`/departments`、`/personnel` 路径，无 `/api/v1`，五个成功状态码与错误码含义，department 的字段与固定排序，`app/core/database.py` 的四个名字，均与 6-1 一致。
