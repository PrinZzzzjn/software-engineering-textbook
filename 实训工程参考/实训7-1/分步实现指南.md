# 实训 7-1 分步实现指南

本指南对应教材实训 7-1 的四步：找重复与差异、集中参数边界、修正计数次序、固定排序并回归。示例固定为 department 与 personnel 两个模块，先在 department 上完成改造并验证，再把同一套写法复制到 personnel。全部命令以 Windows PowerShell 为准，文档端口统一为 8000。

**代码一致性约定**：本指南中标注为「完整文件」的代码块与 `项目/` 对应文件逐字一致。阶段 2 会让 `param.py` 先接受 `full_name`，但 `crud.py` 尚未使用它；阶段 3 接通过滤后，这个参数才真正生效。这是分阶段施工的正常中间态。

## 阶段 1：并排识别重复与差异（10 分钟）

把 6-1 的 department `list_page` 与教材代码 7-1-1 并排看：

```python
def list_page(db, offset: int, limit: int):
    items = (
        db.query(模型)
        .order_by(固定排序列)
        .offset(offset)
        .limit(limit)
        .all()
    )
    total = db.query(模型).count()
    return items, total
```

共同骨架包括接收 `offset` 与 `limit`、取当前页、单独计数后返回二元组；固定排序是本章要补上的差异（6-1 没有 `order_by`）。真正不同的只有三处：

| 差异 | department 的取值 | 复制到 personnel 时改成 |
| --- | --- | --- |
| 查询哪张表 | `Department` | `Personnel` |
| 按哪一列排序 | `dept_code` | `certificate_number` |
| 是否带过滤 | 本实训新增 `full_name` 模糊过滤 | `name` 模糊、`dept_code` 精确 |

结论要写成一句话：**分页与计数是结构，模型、过滤字段、排序列是各模块语义**。结构可以照抄，语义必须逐个替换，不能整段复制后不改。

再回答教材例 7-2 的四个判断：

1. 按主键查一条记录：可以收拢，模型与主键名作为参数。
2. 分页查询多条并计数：可以收拢，`count`、`offset`、`limit` 对每个模型相同。
3. 新增单位前检查 `dept_code` 是否重复：留在单位模块。
4. 新增人员前检查 `dept_code` 是否存在：留在人员模块。

判据只有一条：换一个模型仍一字不改的才可收拢；需要知道“当前是单位还是人员”的，留在模块内。

常见错误：

- 把「带过滤的分页」与「不带过滤的分页」当成完全一样，直接复制，结果第二个模块的 `total` 统计了全表。
- 把「单位编码唯一」「人员必须属于某单位」塞进公共函数，公共代码从此认识具体业务。
- 只比较函数体，不比较参数来源；过滤字段来自 `param.py`，不是函数内部凭空出现。

## 阶段 2：把参数边界集中到 `param.py`（10 分钟）

### 2.1 `app/modules/department/param.py`（完整文件）

```python
from pydantic import BaseModel, Field


class DepartmentQueryParams(BaseModel):
    page: int = Field(default=1, ge=1)
    page_size: int = Field(default=10, ge=1, le=100)
    full_name: str | None = None
```

三个字段放在同一个模型里：分页边界 `ge=1`、`le=100` 写在类型声明上，过滤字段 `full_name` 可空。FastAPI 通过 `Depends()` 注入并校验，`page=0`、`page_size=0`、`page_size=101` 在进入函数前就得到 422，service 不必再写边界判断。

`full_name` 用 `None` 表示“没有筛选”。空串也视为没有筛选，这一判断放在 `crud.py` 里，阶段 3 处理。

### 验证

服务启动后：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/departments?full_name=一"
try { Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8000/departments?page=0" } catch { $_.Exception.Response.StatusCode.value__ }
try { Invoke-WebRequest -UseBasicParsing "http://127.0.0.1:8000/departments?page_size=0" } catch { $_.Exception.Response.StatusCode.value__ }
```

预期：`full_name` 请求仍是 200 且返回全部 2 条（本阶段只收参数，尚未过滤）；两个越界请求都返回 `422`。

### 常见错误

- 只在 service 里写 `if page < 1: raise ...`；参数边界应集中在模型声明。
- 给 `page_size` 不设上限；调用方传 `100000` 会一次取走整张表。
- 过滤字段用 `dept_name` 之类自造名字；过滤参数应使用表的列名，前端和文档才对得上。
- 给 `full_name` 设 `min_length=1`；空串应表示“不筛选”，不能返回 422。

## 阶段 3：过滤条件拼装与计数次序（15 分钟）

本阶段两个文件一起改：`crud.list_page` 增加过滤参数，`service.list_departments` 把 `params.full_name` 传下去。

### 3.1 `app/modules/department/crud.py`（完整文件）

```python
from sqlalchemy.orm import Session

from app.modules.department.model import Department


def get_by_code(db: Session, dept_code: str):
    return db.query(Department).filter(Department.dept_code == dept_code).first()


def list_page(db: Session, offset: int, limit: int, full_name: str | None = None):
    query = db.query(Department)
    if full_name:
        query = query.filter(Department.full_name.contains(full_name))
    total = query.count()
    items = (
        query.order_by(Department.dept_code)
        .offset(offset)
        .limit(limit)
        .all()
    )
    return items, total


def create(db: Session, data):
    department = Department(**data.model_dump())
    db.add(department)
    db.commit()
    db.refresh(department)
    return department


def update(db: Session, department, data: dict):
    for key, value in data.items():
        setattr(department, key, value)
    db.commit()
    db.refresh(department)
    return department


def delete(db: Session, department):
    db.delete(department)
    db.commit()
```

三个要点：

1. `query = db.query(Department)` 先建一个查询对象；过滤、计数、排序、取页都从这同一个对象派生。
2. `if full_name:` 在 `count()` 之前追加 `filter`。`contains` 生成 `LIKE '%值%'`，实现模糊匹配；`None` 与空串都跳过，不产生无意义条件。
3. `total = query.count()` 必须在过滤之后、`offset` 之前；这样 `total` 与 `items` 描述同一批数据。

### 3.2 `app/modules/department/service.py`（完整文件）

```python
from fastapi import HTTPException

from app.modules.department import crud


def list_departments(db, params):
    offset = (params.page - 1) * params.page_size
    items, total = crud.list_page(db, offset, params.page_size, params.full_name)
    return {"items": items, "total": total}


def create_department(db, data):
    if crud.get_by_code(db, data.dept_code):
        raise HTTPException(status_code=400, detail="单位编码已存在")
    return crud.create(db, data)


def get_department(db, dept_code: str):
    department = crud.get_by_code(db, dept_code)
    if not department:
        raise HTTPException(status_code=404, detail="单位不存在")
    return department


def update_department(db, dept_code: str, data):
    department = crud.get_by_code(db, dept_code)
    if not department:
        raise HTTPException(status_code=404, detail="单位不存在")
    return crud.update(db, department, data.model_dump(exclude_unset=True))


def delete_department(db, dept_code: str) -> None:
    department = crud.get_by_code(db, dept_code)
    if not department:
        raise HTTPException(status_code=404, detail="单位不存在")
    crud.delete(db, department)
```

service 只做三件事：把页码换算成 `offset`、把过滤字段透传给 crud、把二元组组装成 `{items, total}`。业务规则（重复编码 400、查不到 404）仍留在这里。controller 不需要改：它只声明 `DepartmentQueryParams = Depends()` 并透传。

### 验证

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/departments?full_name=一"
Invoke-RestMethod "http://127.0.0.1:8000/departments?full_name=不存在"
Invoke-RestMethod "http://127.0.0.1:8000/departments?full_name=中队&page=1&page_size=1"
```

预期：

- `full_name=一`：`total=1`，只含 D001。
- `full_name=不存在`：HTTP 200，响应为 `{"items":[],"total":0}`，不是 404。
- `full_name=中队&page=1&page_size=1`：`items` 1 条，`total` 仍为 2，说明计数用的是过滤后的查询。

### 常见错误

- 先 `total = db.query(Department).count()` 再 `filter`：列表 1 行、页脚却写 2 条，前端会算出多一页。
- 把 `if full_name:` 写成 `if full_name is not None:`：空串会进入 `LIKE '%%'`，虽然结果碰巧相同，但“未筛选”与“筛选空值”混在一起。
- 过滤无命中时抛 404：列表没有记录不是“资源不存在”，应返回 200 与空 `items`。
- service 忘了传 `params.full_name`：参数被模型收下却没有参与查询，页面看起来“筛选无效”。
- 在 crud 里重新 `db.query(Department)` 计数：虽然结果可能对，但两次查询对象不一致，后续加条件时容易漏。

## 阶段 4：固定排序与 department 四条检查（15 分钟）

### 4.1 固定排序键

`order_by` 已在上面的 `crud.py` 中：department 按 `dept_code` 升序。它必须留在 `offset`、`limit` 之前。没有 `order_by` 时，数据库不承诺两次查询返回相同行序，翻到第 2 页可能看到第 1 页出现过的记录。

教材 7.4 还给出排序列白名单：

```python
sort_fields = {
    "dept_code": Department.dept_code,
    "full_name": Department.full_name,
}
column = sort_fields.get(sort_by, Department.dept_code)
query = query.order_by(column.asc())
```

本实训不落地这段代码。目前的单位、人员两个模块，列表都只有一个默认顺序，固定键代码更少、接口也少一个参数。只有当确实需要用户切换多列排序时，才引入白名单；无论哪种，都不能把前端字符串直接拼进 `order_by`。

### 4.2 department 四条检查

服务运行时逐条执行（PowerShell 5 对 4xx 会抛异常，用 `try/catch` 读状态码）：

```powershell
$base = "http://127.0.0.1:8000"

# 1. 列表 200，含 items/total
(Invoke-RestMethod "$base/departments").total

# 2. 过滤命中与未命中
Invoke-RestMethod "$base/departments?full_name=一"
Invoke-RestMethod "$base/departments?full_name=不存在"

# 3. 分页切片与固定顺序
Invoke-RestMethod "$base/departments?page=1&page_size=1"
Invoke-RestMethod "$base/departments?page=2&page_size=1"
Invoke-RestMethod "$base/departments?page=3&page_size=1"

# 4. 非法参数 422
try { Invoke-WebRequest -UseBasicParsing "$base/departments?page=0" } catch { $_.Exception.Response.StatusCode.value__ }
try { Invoke-WebRequest -UseBasicParsing "$base/departments?page_size=0" } catch { $_.Exception.Response.StatusCode.value__ }
```

预期：第 1 页 D001、第 2 页 D002、第 3 页空 `items` 且 `total=2`；两次非法参数均为 422。连续翻页时同一编码不重复出现。

### 常见错误

- 为了加过滤把 `order_by` 删掉；过滤与排序是两件事，都要保留。
- 把 `order_by` 放在 `offset` 之后；SQLAlchemy 会报错或顺序不符合预期。固定顺序是 `filter` → `count` → `order_by` → `offset` → `limit`。
- 让前端传 `sort_by` 却不做白名单；不存在字段返回 500，不该参与排序的列也可能被暴露。
- 看到第 3 页为空就以为分页坏了；`page` 超过总页数返回空 `items` 是正常行为，`total` 仍应是过滤后的总数。

## 阶段 5：personnel 六文件复用演练（20 分钟）

这一阶段只做“同构复制”。先建 `app/modules/personnel/__init__.py`（空文件），再依次放六个文件。每写一个文件，先回答“它对应 department 的哪个文件、哪几处必须改”。

### 5.1 复制对照表

| 文件 | 从 department 复制后改什么 |

注意：本阶段虽然两个过滤条件可以同时传，但课堂只验证单条件；组合过滤是 `README.md` 第十二节的课后扩展。

### 5.6 `app/modules/personnel/service.py`（完整文件）

```python
from fastapi import HTTPException
from sqlalchemy.orm import Session

from app.modules.department.crud import get_by_code as get_dept_by_code
from app.modules.personnel import crud


def _ensure_dept_exists(db: Session, dept_code: str):
    if not get_dept_by_code(db, dept_code):
        raise HTTPException(status_code=400, detail="所属单位不存在")


def list_personnel(db, params):
    offset = (params.page - 1) * params.page_size
    items, total = crud.list_page(
        db, offset, params.page_size, params.name, params.dept_code
    )
    return {"items": items, "total": total}


def create_personnel(db, data):
    if crud.get_by_certificate_number(db, data.certificate_number):
        raise HTTPException(status_code=400, detail="证件号已存在")
    _ensure_dept_exists(db, data.dept_code)
    return crud.create(db, data)


def get_personnel(db, certificate_number: str):
    personnel = crud.get_by_certificate_number(db, certificate_number)
    if not personnel:
        raise HTTPException(status_code=404, detail="人员不存在")
    return personnel


def update_personnel(db, certificate_number: str, data):
    personnel = crud.get_by_certificate_number(db, certificate_number)
    if not personnel:
        raise HTTPException(status_code=404, detail="人员不存在")
    payload = data.model_dump(exclude_unset=True)
    if "dept_code" in payload:
        _ensure_dept_exists(db, payload["dept_code"])
    return crud.update(db, personnel, payload)


def delete_personnel(db, certificate_number: str) -> None:
    personnel = crud.get_by_certificate_number(db, certificate_number)
    if not personnel:
        raise HTTPException(status_code=404, detail="人员不存在")
    crud.delete(db, personnel)
```

列表部分与 department 的 service 形状一致：换算 `offset`、透传过滤字段、组装二字段。业务规则属于 personnel：证件号重复 400、新增或改单位时校验 `dept_code` 存在、查不到 404。`_ensure_dept_exists` 复用 department 的 `get_by_code`，只读单位表，不修改它。

from app.core.database import get_db
from app.modules.personnel import service

from app.modules.personnel.schema import PersonnelCreate, PersonnelOut

router = APIRouter(prefix="/personnel", tags=["人员"])


@router.get("")

### 5.8 `main.py`（完整文件）

```python
from fastapi import FastAPI

from app.core.database import Base, SessionLocal, engine
from app.modules.department import controller as department_controller
from app.modules.department import model as department_model  # noqa: F401  建表前先导入模型
from app.modules.personnel import controller as personnel_controller
from app.modules.personnel import model as personnel_model  # noqa: F401  建表前先导入模型

app = FastAPI(title="Duty API", version="0.1.0")


@app.get("/health")
def health():
    return {"status": "healthy"}


app.include_router(department_controller.router, prefix="")
app.include_router(personnel_controller.router, prefix="")

# 建表只创建缺失的表；表已存在时重复调用不会清空数据
Base.metadata.create_all(bind=engine)


def _seed_departments() -> None:
    """写入两个教学演示单位；逐条先查存在性，重复启动不会重复写入。"""
    db = SessionLocal()
    try:
        for code, name, address in [
            ("D001", "一中队", "一号营区"),
            ("D002", "二中队", "二号营区"),
        ]:
            exists = (
                db.query(department_model.Department)
                .filter(department_model.Department.dept_code == code)
                .first()
            )
            if not exists:
                db.add(
                    department_model.Department(
                        dept_code=code, full_name=name, address=address
                    )
                )
        db.commit()
    finally:
        db.close()


def _seed_personnel() -> None:
    """写入两个教学演示人员；所属单位由 _seed_departments 先写入。"""
    db = SessionLocal()
    try:
        for number, name, dept_code, rank in [
            ("P001", "张伟", "D001", "一级值班员"),
            ("P002", "李娜", "D002", "二级值班员"),
        ]:
            exists = (
                db.query(personnel_model.Personnel)
                .filter(personnel_model.Personnel.certificate_number == number)
                .first()
            )
            if not exists:
                db.add(
                    personnel_model.Personnel(
                        certificate_number=number,
                        name=name,
                        dept_code=dept_code,
                        rank=rank,
                    )
                )
        db.commit()
    finally:
        db.close()


_seed_departments()
_seed_personnel()
```

建表前必须导入两个模型，`create_all` 才认识两张表。seed 的顺序不能颠倒：人员依赖单位编码，先写 D001/D002 再写 P001/P002。两段 seed 都逐条查存在性，重启不会重复写入。

### 常见错误

- 忘了在 `main.py` 导入 personnel 模型，报 `no such table: personnel`。
- 先 seed 人员再 seed 单位，人员写入时单位还不存在。
- personnel 的排序键仍写 `dept_code`，同一单位多人时顺序不稳定；应按 `certificate_number`。
- 详情路径仍用 `{dept_code}` 或函数参数名仍叫 `dept_code`；personnel 的主键是字符串编码 `certificate_number`。
- 新增人员不校验单位，直接写入，之后按 `dept_code` 过滤时出现“孤儿”记录。
- 把 `name` 过滤写成精确匹配；教材要求姓名模糊，`contains` 才与 department 的 `full_name` 写法一致。
- 复制 service 时漏改 `detail` 文案或异常文案，接口仍能用，但验收对不上。
