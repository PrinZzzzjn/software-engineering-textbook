## 1. 实现新增（约 40 分钟）

### 1.1 先定三步

新增、编辑、删除都走同一套顺序：

```text
前端校验（必填/长度/时间先后） → 调 POST/PUT/DELETE → 成功 set_flash + st.rerun()
```

成功后**不要**手动 `append` 列表；`st.rerun()` 会让脚本重跑，取数代码在操作之前，自然拿到后端最新数据。

### 1.2 单位页新增

沿用 17-1 的表单，补上成功后回到第 1 页与 flash：

```python
with st.form("create_department", clear_on_submit=True):
    dept_code = st.text_input("单位编码 *", key="new_dept_code")
    full_name = st.text_input("单位名称 *", key="new_full_name")
    address = st.text_input("地址", key="new_address")
    submitted = st.form_submit_button("提交", type="primary", key="submit_dept")

if submitted:
    if not dept_code.strip() or not full_name.strip():
        st.error("单位编码和单位名称不能为空")
    else:
        try:
            api.post("/departments", json={...})
        except api.ApiError as exc:
            if exc.status_code == 401:
                st.session_state["login_notice"] = exc.detail
                st.rerun()
            st.error(exc.detail)
        else:
            st.session_state["dept_page"] = 1
            set_flash(f"已新增单位 {code} - {name}")
            st.rerun()
```

`clear_on_submit=True` 在提交后清空表单，避免同一份数据被连点两次。

### 1.3 新建三个业务页

- `pages/3_人员管理.py`：先取单位下拉，再查 `/personnel`；新增字段为 `certificate_number`、`name`、`dept_code`、`rank`；
- `pages/4_哨位管理.py`：新增字段为 `workstation_id`、`name`、`dept_code`、`is_active`（复选框映射 0/1）；
- `pages/5_执勤记录.py`：先取人员与哨位下拉，再用 `date_input` + `time_input` 组合出起止时间：

```python
start_dt = datetime.combine(start_date, start_time)
end_dt = datetime.combine(end_date, end_time)
if start_dt >= end_dt:
    st.error("开始时间必须早于结束时间")
else:
    api.post("/duty-records", json={
        "personnel_certificate_number": ...,
```

**做错会看到什么**：提交两次 → 表单未清空或按钮未禁用；新增后列表没变 → 忘了 `st.rerun()`。

**验收**：四页都能新增；刷新或换页后新记录仍在；单位页新增后回到第 1 页。

## 2. 实现编辑（约 45 分钟）

### 2.1 回填：value 只在第一次创建时生效

```python
options = {f"{d['dept_code']} - {d['full_name']}": d for d in items}
selected = options[st.selectbox("选择单位", list(options.keys()), key="dept_edit_select")]
code = selected["dept_code"]

with st.form(f"edit_department_{code}"):
    st.text_input("单位编码（不可修改）", value=code, disabled=True)
    edit_name = st.text_input(
        "单位名称 *",
        value=selected.get("full_name", ""),
        key=f"edit_dept_name_{code}",
    )
    edit_address = st.text_input(
        "地址",
        value=selected.get("address") or "",
        key=f"edit_dept_address_{code}",
    )
    save = st.form_submit_button("保存修改", type="primary", key="dept_save")
```

两条规则：

1. 输入框 `key` 带上对象标识；切换单位时 key 变化，相当于新建组件，值重新从 `value` 取；
2. 主键（单位编码、证件号、哨位编号）创建后不可改，输入框 `disabled=True`。

### 2.2 保存：PUT 传完整字段

```python
if save:
    try:
        api.put(f"/departments/{code}", json={
            "dept_code": code,
            "full_name": edit_name.strip(),
            "address": edit_address.strip() or None,
        })
    except api.ApiError as exc:
        st.error(exc.detail)
    else:
        set_flash(f"已保存单位 {code}")
        st.rerun()
```

人员与哨位的编辑同理：`PUT /personnel/{cert}`、`PUT /workstations/{id}`，body 传完整字段。执勤记录没有 `PUT`，页面不提供编辑。

### 2.3 保留当前页

编辑成功后**不要**改页码；`st.rerun()` 后仍按 `session_state["dept_page"]` 取数，用户停在原来的页。

**做错会看到什么**：编辑 A 后切到 B，表单还是 A → 输入框 `key` 没带对象标识；保存后跳回第 1 页 → 保存分支里误改了页码。

**验收**：切换不同对象时表单跟着换值；保存后仍停在原页；列表显示新值。

## 3. 实现删除与反馈（约 40 分钟）

### 3.1 二次确认

```python
with st.expander("删除单位（危险操作）"):
    st.caption(f"将删除：{code} - {selected['full_name']}")
    confirm = st.checkbox("我确认要删除该单位", key=f"dept_delete_confirm_{code}")
    if st.button("删除", type="primary", disabled=not confirm, key="dept_delete"):
        try:
            api.delete(f"/departments/{code}")
        except api.ApiError as exc:
            st.error(exc.detail)
        else:
            set_flash(f"已删除单位 {code}")
            st.rerun()
```

`expander` 默认收起，减少误触；未勾选时按钮禁用；删除失败显示原因（404 已被删除等）。

### 3.2 flash 反馈

```python
def set_flash(message: str) -> None:
    st.session_state["_flash"] = message


def show_flash() -> None:
    message = st.session_state.pop("_flash", None)
    if message:
        st.toast(message, icon="✅")
```

页面顶部调用一次 `show_flash()`。为什么不能直接 `st.success` 再 `st.rerun()`？因为 `st.success` 画在当前这次渲染上，紧接着的重跑会丢掉它；先存 `session_state`，重跑后再显示，取出即清除，才不会重复。

### 3.3 删除后页空回退

取到列表后加一条保护：

```python
if not items and page > 1:
    st.session_state["dept_page"] = page - 1
    st.rerun()
```

**做错会看到什么**：删除后列表没变 → 没有重跑；第二次删除得到 404 → 前端只删了行，没有重新取数；删完最后一条停在空页 → 没有页空回退。

**验收**：未确认时不能删除；确认后记录消失；删空当前页时自动回退一页。

## 4. 保持状态（约 35 分钟）

### 4.1 初始化只做一次

```python
if "dept_page" not in st.session_state:
    st.session_state["dept_page"] = 1
if "dept_page_size" not in st.session_state:
    st.session_state["dept_page_size"] = DEFAULT_PAGE_SIZE
if "dept_keyword" not in st.session_state:
    st.session_state["dept_keyword"] = ""
```

不要把 `dept_page = 1` 写在每次重跑都会执行的位置；用户翻到第 3 页，下一次重跑又被设回 1。

### 4.2 筛选变化重置页码

```python
signature = f"{keyword.strip()}|{page_size}"
if st.session_state.get("dept_query_signature") != signature:
    st.session_state["dept_query_signature"] = signature
    st.session_state["dept_page"] = 1
```

人员页与执勤记录页的签名还要带上单位/人员/哨位筛选值。

### 4.3 退出登录清空会话

`auth.py` 的退出按钮：

```python
if st.button("退出登录", width="stretch", key="logout"):
    st.session_state.clear()
    st.rerun()
```

## 常见错误对照

| 报错/现象 | 原因 | 处理 |
| --- | --- | --- |
| 提交两次 | 表单未 `clear_on_submit`，按钮未禁用 | 新增表单加 `clear_on_submit=True` |
| 编辑串行 | 输入框 `key` 没带对象标识 | `key=f"edit_dept_name_{code}"` |
| 编辑后列表没变 | 成功后没重跑，或手动改了前端列表 | `st.rerun()`，让后端返回最新数据 |
| 提示一闪而过 | `st.success` 后立刻 `st.rerun()` | 用 flash：先存 `session_state`，重跑后显示 |
| 提示每次都出现 | `show_flash` 没有 `pop` 清除 | 取出即删除 |
| 翻页后总回第 1 页 | 页码初始化写在每次重跑都执行的位置 | `if "dept_page" not in st.session_state` 包住 |
| 搜索后空白页 | 筛选变化没重置页码 | 签名变化时把页码设为 1 |
| 删空当前页后空白 | 没做页空回退 | `if not items and page > 1: page -= 1` |
| 换账号看到旧数据 | 退出登录没清会话 | `st.session_state.clear()` |
| 执勤记录不能改 | 后端无 `PUT` | 删除后重建，或改后端契约（本章不做） |
| 删除单位后人员还在 | 后端未做关联校验与级联 | 页面提示先清理关联数据；契约差异见 `验证记录.md` |
