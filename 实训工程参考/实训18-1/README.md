# 实训 18-1 数据编辑与页面状态项目案例

本实训在 17-1 多页前端上补齐写操作：单位页增加编辑与删除，新增人员、哨位、执勤记录三个业务页；所有写操作按「校验—提交—刷新」三步实现，危险操作先二次确认，成功反馈用 flash 跨重跑保留，页码与筛选放进 `session_state`。完成态见 `项目/`，实跑证据见 `验证记录.md`。

## 二、教学目标与教材映射

1. 按「前端校验—提交接口—成功重跑」三步实现新增、编辑与删除，成功后不手动改列表。
2. 说明取数为什么必须放在操作之前，以及页码、每页条数、筛选条件怎样放进 `session_state`。
3. 用 `value` 回填编辑表单，用带对象标识的 `key` 避免切换对象后串值，用 `clear_on_submit` 避免重复提交。
4. 用 `expander` + 勾选 + 禁用按钮实现二次确认，用 flash message 让成功提示跨重跑显示一次。
5. 解释 `session_state` 的初始化、读取、修改、清理四个阶段，并排查常见的状态错位。

## 三、边界与不变量

### 3.1 目录与职责

| 位置 | 职责 | 本工程做法 |
| --- | --- | --- |
| `app.py` | 入口、登录门禁、首页导航说明 | 列出五个页面；不含业务表格 |
| `auth.py` | 登录、登出、`require_login` | 与 17-1 逐字一致 |
| `api_client.py` | 地址、超时、令牌、错误四统一 | 与 17-1 一致；`put` / `delete` 本实训首次使用 |
| `components/table.py` | `render_table` 与 `pagination_bar` | 四页共用，不改接口 |
| `components/feedback.py` | `set_flash` / `show_flash` | 新增；消息取出即清除 |
| `pages/` | 每个文件一个页面 | 五页；一页一类任务 |
| `config.py` | 基地址、前缀、超时、默认分页 | 不改 |

### 3.2 写操作三步

- **校验**：只做必填、长度、时间先后等不查库的检查；重复编码、关联存在、时段冲突交给后端；
- **提交**：调用 `POST` / `PUT` / `DELETE`；失败显示 `detail`，401 回登录；
- **刷新**：成功后 `set_flash(...)` + `st.rerun()`，由脚本重新向后端取数，不 `append`、不改前端列表。

### 3.3 页面状态归属

| 状态 | 放哪 | 本工程做法 |
| --- | --- | --- |
| 列表数据 | 后端 | 每次重跑重新取；写成功后不手改 |
| 页码、每页条数、筛选 | `session_state` | `if "xxx" not in st.session_state` 只初始化一次 |
| 编辑表单 | 组件状态 + 对象标识 key | `key=f"edit_dept_name_{code}"`，切换单位重新取值 |
| 操作反馈 | `session_state["_flash"]` | 写入后重跑，`show_flash()` 取出显示并清除 |
| 登录态 | `session_state` | 退出登录 `st.session_state.clear()` |

### 3.4 状态联动规则

- 筛选条件或每页条数变化时，页码重置为 1；
- 删除当前页最后一条后，若当前页为空且页码大于 1，页码回退一页；
- 新增成功后回到第 1 页，保证新记录在排序后的首页可见；
- 编辑成功后不清页码与筛选，用户仍停在原位置。

### 3.5 不做的范围

- 不做图表与主题美化（19-1）；
- 不做统一错误提示组件与交付清单（20-1）；
- 不新增后端接口，不改字段与状态码；
- 执勤记录后端无 `PUT`，本页不提供编辑，只做新增与删除；
- 不改教材正文；差异记录在 `验证记录.md`。

## 六、操作步骤

1. **实现新增（40 分钟）**：保留单位页「新增单位」区，按三步提交；新建 `pages/3_人员管理.py`、`pages/4_哨位管理.py`、`pages/5_执勤记录.py`，每页都先取下拉数据，再用 `st.form(clear_on_submit=True)` 收集字段；成功后回到第 1 页并 `st.rerun()`。
2. **实现编辑（45 分钟）**：三个可改资源各加一个「编辑」区；先用 `selectbox` 选中当前页对象，再用 `value` 回填；主键输入框 `disabled=True`；输入框 `key` 带对象标识；保存走 `PUT`，成功后保留当前页。
3. **实现删除（40 分钟）**：每个删除区放在 `expander` 中，先勾选「我确认」再启用按钮；删除成功后 `set_flash` + `st.rerun()`；当前页为空时页码回退一页。
4. **保持状态（35 分钟）**：页码、每页条数、筛选进 `session_state`，初始化只做一次；筛选变化重置页码；`show_flash()` 放在页面顶部，取出即清除；用无效令牌提交一次，确认 401 回登录并清除会话。

## 九、验收标准

| 验收项 | 判定方式 |
| --- | --- |
| 写操作三步 | 新增、编辑、删除都有校验、提交与成功后的重跑 |
| 编辑回填 | 切换对象后输入框跟着换值，不串行 |
| 无重复提交 | 新增表单 `clear_on_submit=True`；删除按钮确认前禁用 |
| 二次确认 | 未勾选时删除按钮禁用，勾选后才可点 |
| 状态保持 | 编辑后仍在原页；搜索变化回到第 1 页；删空当前页页码回退 |
| 反馈一次 | flash 取出即清除，不每次重跑重复提示 |
| 守卫与 401 | 五个子页面未登录被拦截；写接口 401 回登录并清会话 |
| 自测 | `verify_app.py` 97 项全过 |

## 十、常见问题与排错

| 现象 | 先查什么 |
| --- | --- |
| 重复提交 | 新增表单是否 `clear_on_submit=True`；按钮是否可连点 |
| 编辑串行 | 输入框 `key` 是否带对象标识；`value` 是否只在首次创建时生效 |
| 编辑后列表没变 | 成功后是否 `st.rerun()`；取数是否在操作之前 |
| 成功提示一闪而过 | 是否直接 `st.success` 后 `st.rerun()`；改用 flash |
| 提示每次都出现 | `show_flash()` 是否 `pop` 取出后清除 |
| 翻页后回到第 1 页 | 页码是否每次重跑都被赋值为 1；初始化是否用 `if ... not in` 包住 |
| 搜索后停在不存在的页 | 筛选变化时是否把页码重置为 1 |
| 删除当前页最后一条后空白 | 是否做「页空回退一页」 |
| 换账号看到上一账号数据 | 退出登录是否 `st.session_state.clear()` |
| 执勤记录改不了 | 后端没有 `PUT /duty-records/{id}`；删除后重建 |
| 删除单位后人员还在 | 后端不做级联删除；先处理该单位下的人员与哨位 |
