# 实训 15-1 单位管理页项目案例

本实训在第 14 章的单页骨架上，用假数据完成一个可运行的单位管理页：指标、表格、搜索、空态、新增表单同页协作，覆盖输入、展示、交互、容器四类组件。完成态见 `项目/`，学员起点见 `starter/`，实跑证据见 `验证记录.md`。

## 二、教学目标与教材映射

完成本实训后，学生应能：

1. 把页面拆成指标区、筛选区、表格区、新增区，并为每个区域选对组件。
2. 用 `st.form` 把多个输入与提交按钮包成一个事务式交互，填写期间不重跑。
3. 用 `st.column_config` 让表格可读：中文列名、合理列宽、隐藏行号。
4. 先过滤再渲染，空结果给 `st.info` 而不是空表或报错。
5. 用 `st.session_state` 保存假数据，新增后重跑仍能看到。

## 三、边界与不变量

### 3.1 四类组件的最低覆盖

| 类别 | 本工程使用 | 位置 |
| --- | --- | --- |
| 输入 | `st.text_input`、`st.checkbox` | 筛选区、新增表单 |
| 展示 | `st.metric`、`st.dataframe`、`st.info`、`st.error`、`st.success` | 指标区、列表区、新增区 |
| 交互 | `st.button`、`st.download_button`、`st.form_submit_button` | 筛选区、列表区、新增区 |
| 容器 | `st.columns`、`st.tabs`、`st.form` | 全页 |

### 3.2 数据契约

假数据字段与接口契约逐字一致：`dept_code`、`full_name`、`address`。不得为了界面好看改成 `code`、`name`、`addr`，否则 16-1 接接口时要全页改名。

### 3.3 状态与重跑

- 假数据只存一份：`st.session_state.departments`。
- 首次运行做深拷贝，避免修改种子常量。
- 新增成功用「写 flash → `st.rerun()` → 重跑后显示」的顺序，保证表格当次就能看到新增行。
- 清空搜索用按钮回调 `on_click`，不在控件实例化后直接改其 `session_state`。

### 3.4 不做的范围

- 不接后端、不做登录、不做权限、不做分页。
- 不做响应式与主题定制；这些留给后续章节。
- 不引入除 `streamlit`、`pandas` 之外的依赖。

## 六、操作步骤

1. **列组件清单（15 分钟）**：把页面分成指标区、筛选区、表格区、新增区，写出「区域—组件—类别」，确认四类都有。
2. **搭输入区（20 分钟）**：搜索用 `st.text_input`；新增用 `st.form` 包住三个输入与 `st.form_submit_button`。填写过程中页面不应重跑。
3. **搭展示区（20 分钟）**：三个 `st.metric`；`st.dataframe` + `column_config` 配中文列名、列宽，`hide_index=True`。
4. **交互与空态（15 分钟）**：先读控件值过滤，再渲染；结果为空用 `st.info`；「清空搜索」用 `on_click` 回调。
5. **整合与自测（10 分钟）**：新增写回 `session_state`；按「空结果、超长文本、重复提交」三条路径各走一遍；跑 `verify_app.py`。

详细代码与排错见 [分步实现指南.md](分步实现指南.md)。

## 十、常见问题与排错

| 现象 | 先查什么 |
| --- | --- |
| 输入框总被清空 | 是否放进 `st.form`；是否设置了 `clear_on_submit` |
| 表单提交后没刷新 | 提交分支是否重新读取 `session_state` |
| 按钮点击后代码每次都执行 | 执行代码是否放在 `if st.button(...)` 或回调里 |
| 表头还是英文 | `column_config` 的键与字段名是否逐字一致 |
| 日期显示成数字 | 是否先 `pd.to_datetime` |
| 表格列顺序乱 | 是否显式指定列 |
| 空结果整页报错 | 是否在过滤后直接取第一行；补空态分支 |
| 新增后当次看不到 | 表格是否先于新增渲染；用 flash + `st.rerun()` |
| 假数据与接口字段不一致 | 按契约用 `dept_code`、`full_name`、`address` |

## 十二、课后扩展

1. 把表格渲染与新增表单各抽成一个函数；第二次出现重复时再抽，抽完重跑 `verify_app.py`。
2. 用真实 `GET /departments` 替换假数据，记录字段差异（第 16 章）。
3. 换场景：用哨位（编号、名称、所属单位、启用状态）重做组件选型，注意哨位没有地址，新增时要选所属单位。
4. **复习任务**：回看第 14 章 14.2 的「脚本即页面」与本节 15.5 的重跑模型，说明为什么 `st.form` 能减少重跑。
