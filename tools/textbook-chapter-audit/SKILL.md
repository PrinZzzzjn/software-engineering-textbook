# textbook-chapter-audit

按项目内《教材写法诊断规则·上册：章节骨架》《教材写法诊断规则·下册：行文方式》逐章审查，产出落盘报告，默认不改正文。

## Overview

核心原则：**先骨架，后行文；先证据，后建议；报告落盘，正文不动。**

审查不是“挑几个明显问题”。它必须产出三件固定物：本章路线、三级标题对照、逐条可定位的问题清单。时间紧、章节长、问题很多都不改变输出形状。

## When to Use

- 对 `软件工程实践-2.0/NN-*.md` 单章做骨架与行文审查；
- 为某章生成三级标题“现有/应删/应增/应改名”对照；
- 用两份诊断规则做逐章复查或全书轮审。

不适用：实际改写章节、设计整本大纲、只核代码或只出习题。若用户同时要求修改，先完成报告，再进入改写请求。

## Required References

开始之前必须读取：

1. `docs/2026-11-24-教材写法诊断规则-上册-章节骨架.md`
2. `docs/2026-11-24-教材写法诊断规则-下册-行文.md`
3. 三级标题 v2 规范：优先 `docs/unuesd/三级标题规范_2.0_草案.md`；若不存在，用 Glob 搜索 `*三级标题规范*` 与 `*三级标题清单*`，在报告备注中写实际路径。仍找不到才停止。
4. `references/report-template.md`（本 skill 内，报告格式权威）

上册与下册缺失时停止：不要凭记忆替代规则。三级标题规范仍标“待签字”不是停止理由，按用户已确认的全书统一口径执行，并在备注说明状态。

## Input

- 章号或章文件路径。章号 N 解析为 `软件工程实践-2.0/NN-*.md`，NN 两位补零。
- 可选：审查范围（仅骨架 / 仅行文 / 仅三级标题）。未指定则三项全做。
- **局部审查仍使用完整报告模板**：未审查的章节写“不适用：本次仅审查 X”，不删除章节；本章路线是必填项，不因局部审查省略。

允许读取前章、后章、`00-教材设计.md`、`术语表.md`、`98-参考答案.md` 做交叉核对，但只用于证据，不把邻章正文整章复制进上下文。跨章冲突若超出本章范围，记入“未核事项/需主编裁决”，不继续全书追查。

## Workflow

1. **定位与登记**：确定章文件路径；打印 `▶ 审查第 N 章：<章标题>`。
2. **读取规则**：分别读取上册、下册、三级标题规范和报告模板，逐项确认存在。缺失时按 Required References 处理。
3. **读取目标章**：读取目标章全文；按需要读取少量邻章或配套文件做证据核对。
4. **先写路线**：在报告中先填“本章路线”四句——上一章止步于哪一步、本章接手什么、本章产出什么可核对物、下一章为什么接手下一步。每句附位置或原文证据。写不出时：路线判定写“不完整”，在骨架问题清单中列为高风险；逐节主线表写“受阻：路线不完整，暂不做逐节判定”，但继续填写模板其余章节，未核事项写明受阻原因。
5. **骨架审查**：按上册 S1–S11 与检查表逐节检查。对每处问题给出原文章节号与原文证据。特别注意章首落点、机制/应用分合、概念分合、正文代码详略、跨章重复。
6. **三级标题对照**：逐 `## x.y` 节填表：现有标题 / 处理（保留、改名、合并、删除、新增）/ 新标题 / T1、T2、T3 依据。无标题的节也要显式判断“不设”及理由。不要把粗体标签自动等同为三级标题；按 T1/T2/T3 判定。示范例题、独立习题、实训模板、章末组件属于正式教学组件，不纳入 `x.y.N`；T 列写“不适用（教学组件）”，不写 ✓。
7. **行文审查**：按下册 B1、B2、B3、B4、A、C 分类，逐条引用原句。每条必须回答终极判定问题：“删掉它，读者会不会少知道一件他此刻能用上的事？”
8. **落盘报告**：写入 `docs/章节审查/NN-章审查.md`，严格使用 `references/report-template.md` 的标题与字段。目录不存在时创建。同一章重审时覆盖该文件，并在报告头注明“重审”与日期。
9. **机械验收**：写完后重新读取报告文件，确认六个二级标题、本章路线四句、三级标题对照表、骨架/行文问题清单都存在；缺失就补齐后再回报。此步不可省略。
10. **回报对话**：固定四行——文件路径；骨架发现条数与首要问题；标题对照覆盖数与首要建议；行文发现条数与首要问题。完整内容在文件里。

## Non-negotiables

- 默认不改章节正文。用户明确要求修改时，报告完成后另起任务。
- 时间压力、篇幅压力、用户催促均不减少输出字段；可缩减每条建议的文字，不可省略章节路线、三级标题表、问题清单。
- 每条问题必须有：位置、类型、原文证据、判定结论、建议。没有原文证据的“总体感觉”不写入报告。
- 三级标题判断必须使用 T1/T2/T3，不以“字数够不够”“其他章有没有”为理由；正式教学组件按例外处理。
- 跨章引用只需定位与核对相关段落，不整章读取邻章；项目级问题只记录，不擅自裁决。
- 目录 `docs/章节审查/` 只存审查报告；不写章节原文的副本。
- 未完成第 9 步机械验收，不得声称报告完成。

## Rationalizations

| Excuse | Reality |
|---|---|
| “时间紧，先给 5 条重点” | 报告模板是交付物；可精简措辞，不可省字段。 |
| “只审行文，不用写路线和标题表” | 局部审查仍用完整模板；未审部分写“不适用”。 |
| “三级标题规范还没签字，先不判断” | 用户已明确全书统一；按 v2 判据给出对照，并在备注说明状态。 |
| “没有粗体标签就不必设三级标题” | 是否设题看 T1/T2/T3，不看现有是否是粗体。 |
| “这个问题很明显，不用引用原文” | 无证据即无发现；审查报告要可复核。 |
| “跨章冲突太大，这章先别报” | 记录证据与需主编裁决事项；审查不等于替主编拍板。 |
| “顺手把正文改了更高效” | 审查与改写是两个交付物；默认只落报告。 |

## Red Flags - STOP

- 报告缺少“本章路线”或“三级标题对照表”；
- 写完后没有重新读取报告文件做机械验收；
- 用“建议增强逻辑性/可进一步打磨”等无证据措辞；
- 因篇幅或 Deadline 跳过任何模板章节；
- 直接修改 `软件工程实践-2.0/NN-*.md` 而没有单独要求。

出现任一项，回到报告模板补齐后再回报。

## Output

落盘路径固定：`docs/章节审查/NN-章审查.md`。对话回报固定四行，见 Workflow 第 10 步。
