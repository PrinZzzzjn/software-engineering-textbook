# 前言

软件工程课堂上常见这样一幕：学生能写出一段跑得通的代码，却说不清它该放在项目的哪个位置、由谁维护、改动一处会牵动哪些地方。能运行与可交付之间，隔着一整套工程方法。本书要补的正是这一段。

## 编写背景

应用型院校的软件开发课程，大多以语法与框架入门，学生做完几个小练习，仍没有经历过一次完整的系统开发：需求从谁那里来、接口怎么约定、数据如何落地、测试与部署由谁负责。进入工作岗位后，这些空缺会以另一种方式补上——返工、联调、交接时的返工。本书把这些环节提前放进课堂。

全书以“工程化交付”为主线：每个阶段都要求留下可检查的产物——需求条目、验收标准、表结构、接口契约、测试用例、可运行的镜像——并说明这些产物为什么必须存在、在什么条件下可以简化。教材不追求覆盖全部软件工程理论，只把从需求到部署这条主干走通、走透。

## 本书的读者

本书面向有一点点 Python 基础、但几乎没有项目经验的读者：会写基本语法，没经历过多人协作、长期维护、上线运行的完整系统。阅读本书不需要预先学习 SQL、HTTP 或 Git，这些内容会在用到时从零讲起。本书也适合作为企业新员工的技术入门读物，以及软件开发课程的教学用书。


## 结构与体例

全书 24 章，按软件开发的推进顺序分为四篇：软件工程基础与需求分析、后端服务开发、前端界面构建、软件部署与系统交付。章与课次一一对应，可按课次顺序讲授，也可按篇组织专题教学。

各章体例统一。章首以「本章要解决的问题」提出一个贯穿全章的问题，随后的小节围绕它逐步展开；讲解之后是「示范例题」，给出完整解答，供读者照着做；章末是「独立习题」，只留题目，用于检验是否真正掌握。实践类章末附「实训」块，按任务目标与验收、课前准备、操作步骤、排错清单、提交与验收、课后扩展六段组织，可直接作为课堂实践任务使用。

代码在书中标注语言与编号，关键文件标出文件名；章末列出本章完整代码的位置，按步骤操作即可复现。独立习题的参考答案属教师用材料，不随学生用书发放。
