# 第 19 章 界面优化与数据可视化

同一份统计数据，可以做成两个完全不同的页面：一个只是把表格铺开，另一个却能让人一眼看出重点。功能没有变，差别来自信息的组织方式。

工具本身不决定可读性，选择与组合才决定。

## 本章要解决的问题

**Streamlit 提供哪些样式、布局与图表工具？怎样用它们把统计数据组织成可读的仪表盘？**

想改颜色，却不知道主题配置有哪些键；想画图，却不确定用哪个函数、参数怎么传。工具没认全，例子只能照抄，换一份数据就不知道怎么改。

本章关心的是：样式、布局与图表各自解决什么问题，又怎样组合起来，把一组统计数据组织成一眼能读的仪表盘。

## 本章学习目标

读完第 19 章并完成实训后，你应该能：

1. 说明 Streamlit 主题配置的常用键，写出 `.streamlit/config.toml` 并说明生效方式。
2. 用 `st.container(border=True)`、`st.columns(gap=...)` 与 `st.divider()` 组织仪表盘的卡片与区块，说明 `subheader`、`caption` 的作用。
3. 使用 `st.metric` 的常用参数展示指标卡，并说明 `delta`、`format`、`icon` 的作用。
4. 使用 `st.line_chart`、`st.bar_chart` 等内置图表，说明 `x`、`y`、`color`、`height` 等常用参数。
5. 把主题、卡片、指标与图表组合成一个可读的仪表盘，并用信息层级的判据检查它。

## 19.1 主题与视觉统一

Streamlit 的主题是一组全局生效的视觉参数，配置一次，所有页面共用（Streamlit 官方文档）。它不需要写 CSS：在项目根目录的 `.streamlit/config.toml` 中写 `[theme]` 节，重启服务后生效。常用键如下：

| 键 | 作用 | 常用取值 |
| --- | --- | --- |
| `base` | 明色或暗色基底 | `"light"` / `"dark"` |
| `primaryColor` | 按钮、链接、选中态 | 十六进制颜色，如 `#0F766E` |
| `backgroundColor` | 页面底色 | 十六进制颜色，如 `#F8FAFC` |
| `secondaryBackgroundColor` | 卡片、侧边栏底色 | 十六进制颜色，如 `#FFFFFF` |
| `textColor` | 正文颜色 | 十六进制颜色，如 `#0F172A` |
| `font` | 字体族 | `"sans serif"` / `"serif"` / `"monospace"` |

**代码 19-1-1** · `.streamlit/config.toml`（主题配置，TOML）

```toml
[theme]
base = "light"
primaryColor = "#0F766E"
backgroundColor = "#F8FAFC"
secondaryBackgroundColor = "#FFFFFF"
textColor = "#0F172A"
font = "sans serif"

[browser]
gatherUsageStats = false
```

**主色定在哪里**

`primaryColor` 是主色，按钮、链接与选中态都用它；`backgroundColor` 与 `secondaryBackgroundColor` 分开，页面浅灰、卡片纯白，层次自然出来；`textColor` 要保证与背景的对比度，普通正文至少 4.5:1（WCAG 2.1 AA）。这些键写在 `[theme]` 下，键名拼错时对应的样式不会生效。

运行时也可以边调边看：在页面右上角菜单中打开 Settings → Theme，调整颜色与字体并即时预览，把最终值写回 `config.toml`。改完配置文件必须重启 Streamlit，主题才会重新加载。

**主题之外才用 CSS**

主题覆盖大多数颜色、字体与底色需求。少数主题表达不了的细节（例如某个组件内部的特殊间距）才用 CSS：`st.markdown("<style>...</style>", unsafe_allow_html=True)` 可以注入样式，代价是升级框架时可能失效、每个页面都要维护。**先用主题，再考虑 CSS，最后才做像素级定制。**

> 💡 **易错点**：改完 `config.toml` 不重启，页面颜色不变；或把键名写成 `primary_color`，主题不报错但也不生效。改完先看按钮与底色是否变化，再继续往下做。

## 19.2 指标与统计口径

`st.metric` 用来显示一个关键数字，常用参数如下：

| 参数 | 作用 |
| --- | --- |
| `label` | 指标名称 |
| `value` | 指标值，数字或字符串 |
| `delta` | 与上期的差值，自动显示正负 |
| `delta_color` | `"normal"` / `"inverse"` / `"off"`，控制差值颜色 |
| `format` | 数字格式，如 `"%d"`、`"%.1f"` |
| `icon` | 图标，帮助快速识别 |
| `border` | 加卡片边框 |
| `help` | 悬停时显示的说明 |

**一排指标卡的写法**

上述是 `st.metric` 的常用参数；完整列表以所用 Streamlit 版本的官方文档为准。

**代码 19-1-2** · 示例代码（Python）

```python
m1, m2, m3, m4 = st.columns(4)
m1.metric("总执勤天数", yearly["total_duty_days"], icon="📅", border=True)
m2.metric("总执勤时长（小时）", yearly["total_duty_hours"], icon="⏱️", border=True, format="%.1f")
m3.metric("执勤记录数", distribution["total_records"], icon="🏅", border=True)
m4.metric("高峰时段数", len(distribution["peak_hours"]), icon="📈", border=True)
```

`st.columns(4)` 先分成四列，每个指标卡占一列。`format` 只影响显示，不改变数据；天数用整数、时长保留一位小数，格式统一，不必每次换算。指标卡的数取自统计接口返回的字段，例如 `total_duty_days`、`total_duty_hours`、`total_records`；手填的数字与后端对不上，是仪表盘最常见的事故。一个页面通常选 3–5 个“一眼要看到”的数字，每个都要有明确口径。

> 💡 **易错点**：把指标值手填成固定数字。页面上看起来完整，但后端数据一变就对不上；指标卡必须从统计接口读，口径与第 11 章一致。

## 19.3 图表选型与数据形状

Streamlit 的图表接口分两类：

| 类型 | 接口 | 用途 |
| --- | --- | --- |
| 内置图表 | `st.line_chart`、`st.bar_chart`、`st.area_chart`、`st.scatter_chart`、`st.map` | 快速画常见趋势、对比、分布与地图 |
| 集成图表 | `st.altair_chart`、`st.plotly_chart`、`st.pyplot`、`st.vega_lite_chart` | 需要复杂交互或精细控制时 |

**内置图表与集成图表**

本章用内置图表；饼图、直方图等内置接口没有的图形，用集成图表（如 Altair、Plotly、Matplotlib）绘制。`st.line_chart` 与 `st.bar_chart` 的常用参数如下：

| 参数 | 作用 |
| --- | --- |
| `data` | DataFrame 或数组，通常由接口返回的列表转换而来 |
| `x` | 横轴列名；省略时用 DataFrame 的索引 |
| `y` | 纵轴列名，可传一个或多个 |
| `color` | 颜色列或固定颜色；本章用主色的邻近色 |
| `height` | 图表高度，如 `260` |
| `width` | 图表宽度，`"stretch"` 表示填满容器 |
| `x_label` / `y_label` | 横轴、纵轴标题 |
| `horizontal` | 仅 `st.bar_chart`：横向柱状图 |
| `stack` | `st.bar_chart` / `st.area_chart`：是否堆叠 |

上述是内置图表的常用参数；`st.scatter_chart` 还有 `size`，`st.map` 使用 `latitude` / `longitude`，完整列表以所用 Streamlit 版本的官方文档为准。

**代码 19-1-3** · 示例代码（Python）

```python
time_rows = distribution["time_distribution"]
df_time = pd.DataFrame(time_rows).set_index("hour")
df_time.index.name = "小时"
st.line_chart(df_time, y="count", color="#0D9488", height=260, width="stretch")

month_rows = yearly["duty_by_month"]
df_month = pd.DataFrame(month_rows).set_index("month")
df_month.index.name = "月份"
st.bar_chart(df_month, y="days", color="#0D9488", height=260, width="stretch")
```

图表要的是“表格”：把 JSON 列表转成 `DataFrame`，用 `set_index` 把小时或月份设为横轴，用 `y=` 指定纵轴列；也可以不设索引，改用 `x="hour", y="count"`。`color` 用主色的邻近色，同一页面只用一个图表色；`height` 控制高度，`width="stretch"` 让图表填满所在容器。

图表类型应与数据形状匹配（Cleveland & McGill, 1984）：

| 目的 | 内置接口 | 说明 |
| --- | --- | --- |
| 比大小 | `st.bar_chart` | 分类之间比较 |
| 看趋势 | `st.line_chart`、`st.area_chart` | 时间序列 |
| 看分布 | `st.scatter_chart`；直方图用集成图表 | 两个变量的关系或数据分布 |
| 看占比 | 饼图用集成图表（Altair/Plotly/Matplotlib） | 内置接口没有饼图 |

选错图表，数据再准也读不出来。例如用饼图比较 12 个月的天数，用户很难看出差异；用折线图看“单位排名”也不合适。图表必须配标题和口径说明，例如“按执勤开始时间的小时统计”；空数据要提示，不要画一张空图；图表下方提供“查看数据表”，方便读屏与核对。

> 💡 **易错点**：图表类型按“好看”选，而不是按“要回答的问题”选。先写下这张图要回答的一句话（比大小、看趋势、看分布、看占比），再选接口；写不出来，说明这张图不该放。

## 19.4 仪表盘与信息层级

**仪表盘的骨架**

把主题、布局、指标与图表组合起来，就是一个仪表盘。下面是一个统计页的骨架（`distribution` 与 `yearly` 分别取自 `/analytics/duty-time-distribution` 与 `/analytics/staff-duty-yearly`，`df_detail` 是明细记录）：

**代码 19-1-4** · 示例代码（Python）

```python
import pandas as pd
import streamlit as st

st.set_page_config(page_title="执勤数据仪表盘", page_icon="📊", layout="wide")

with st.sidebar:
    year = st.selectbox("年份", [2025, 2026])
    # 后续取数时把 year 放进查询参数

m1, m2, m3, m4 = st.columns(4)
m1.metric("总执勤天数", yearly["total_duty_days"], icon="📅", border=True)
m2.metric("总执勤时长（小时）", yearly["total_duty_hours"], icon="⏱️", border=True, format="%.1f")
m3.metric("执勤记录数", distribution["total_records"], icon="🏅", border=True)
m4.metric("高峰时段数", len(distribution["peak_hours"]), icon="📈", border=True)

left, right = st.columns(2, gap="medium")
with left:
    with st.container(border=True):
        st.subheader("24 小时分布")
        st.caption("按执勤开始时间的小时统计")
        df_time = pd.DataFrame(distribution["time_distribution"]).set_index("hour")
        st.line_chart(df_time, y="count", color="#0D9488", height=260)

with right:
    with st.container(border=True):
        st.subheader("月度分布")
        st.caption("按月份统计的执勤天数")
        df_month = pd.DataFrame(yearly["duty_by_month"]).set_index("month")
        st.bar_chart(df_month, y="days", color="#0D9488", height=260)

st.divider()
st.subheader("明细")
st.dataframe(df_detail, width="stretch", hide_index=True)
```

`st.set_page_config(layout="wide")` 让页面使用整幅宽度；`st.sidebar` 放全局筛选；四个 `st.metric` 组成总览；两张图分别回答趋势与对比；`st.dataframe` 提供明细。所有组件仍按调用顺序从上到下排列，容器只改变分组。

**卡片、间距与区块标题**

容器的类型与选型见 15.5，页面区域见 17.3；这里只补仪表盘需要的样式参数。仪表盘的可读性主要靠分组，不靠配色。`st.container(border=True)` 给一组内容加边框与内边距，相当于一张卡片；`st.columns(2, gap="medium")` 控制两栏间距，`vertical_alignment="center"` 让并排的卡片在垂直方向对齐；`st.subheader()` 做区块标题，`st.caption()` 补一句口径说明；`st.divider()` 在总览与明细之间画一条分隔线。这些参数都不改变数据逻辑，只影响分组与留白。卡片最多套两层——卡片里再套卡片，分组反而看不清。

工具会用之后，再回到判断标准：界面优化是否帮助用户更快完成任务（Nielsen, 1994）。把所有元素都加上颜色、渐变与动画，不改变分组与顺序，页面仍然难读；反过来，主题、卡片、指标与图表用对了，即使配色朴素，信息也能一眼找到。

**信息层级在仪表盘上的落点**

信息层级（第 17 章 17.4）指页面的阅读顺序与用户的任务顺序一致。仪表盘的任务顺序是“先看总量，再看变化，最后查明细”，所以按“总览 → 趋势 → 明细”排列（Few, 2006），首屏只回答一个问题，其余信息下钻。

用 17.4 的四个手段逐项检查：

- **分组**：指标一行、图表两栏、明细单独成区；
- **对齐**：指标卡与图表共用列边界，图表同宽；
- **对比**：指标数字最重，图表标题次之，明细最轻；
- **顺序**：先总览后明细。

十秒测试在仪表盘上的版本是：用户能否在十秒内说出“总量多少、变化如何、明细在哪”。指标卡堆满首屏、图表缺标题与口径、明细抢在图表前面，都是层级失衡。

| 改动 | 用到的工具 |
| --- | --- |
| 统一主色与字体 | `[theme]` |
| 区域分组、卡片 | `st.container(border=True)`、`st.columns` |
| 关键数字 | `st.metric` |
| 趋势与对比 | `st.line_chart`、`st.bar_chart` |
| 明细数据 | `st.dataframe` |

常见问题如下表：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面很“花” | 主色不止一个，或图表色与主题不一致 | 收拢到一个主色 |
| 图表读不出来 | 图表类型与数据不匹配，或缺口径说明 | 按“要回答的问题”重选接口，补标题与口径 |
| 指标卡数字对不上 | 指标值手填，没有来自统计接口 | 改为从接口取数 |
| 空数据画了一张空图 | 没判断 `items` 是否为空 | 先判断空数据，用 `st.info` 提示 |
| 窄屏图表溢出 | 用了固定宽度 | 用比例列与 `width="stretch"` |

> 💡 **易错点**：只改颜色，不改分组与顺序。颜色不能代替分区；先用容器与列把区域分开，再调主题。

#### 例 19-2：用指标卡与内置图表展示统计数据

**题目**：有一段按小时统计的 `rows = [{"hour": 0, "count": 3}, ...]` 和按月份统计的 `months = [{"month": "1月", "days": 12, "hours": 48}, ...]`。请用 `st.metric` 从 `months` 计算并显示总执勤天数与总时长，用 `st.line_chart` 画小时分布、`st.bar_chart` 画月度分布；说明 `x`、`y`、`color`、`height` 各起什么作用。

**解**：

**代码 19-2-2** · 示例代码（Python）

```python
import pandas as pd
import streamlit as st

st.metric("总执勤天数", sum(m["days"] for m in months), icon="📅", border=True)
st.metric("总执勤时长（小时）", sum(m["hours"] for m in months), icon="⏱️", border=True, format="%.1f")

df_hour = pd.DataFrame(rows).set_index("hour")
st.line_chart(df_hour, y="count", color="#0D9488", height=260)

df_month = pd.DataFrame(months).set_index("month")
st.bar_chart(df_month, y="days", color="#0D9488", height=260)
```

`y` 指定要画的数值列；`x` 省略时使用 DataFrame 的索引（这里是 `hour` 与 `month`），也可以写成 `x="hour"`；`color` 固定图表色；`height` 控制高度。两张指标卡的数字由 `months` 求和得到，`format` 只影响显示，页面上的数始终与给定数据一致。

### 三、操作步骤

1. **配置主题**
   - 做什么：改 `.streamlit/config.toml` 的常用键
   - 操作：设置 `base`、`primaryColor`、`backgroundColor`、`textColor`、`font`，重启 Streamlit
   - 预期输出：→ 全站颜色与字体统一
   - 做错会看到什么：颜色没变；确认是否重启、键名是否拼对
2. **做指标卡**
   - 做什么：用 `st.columns` 与 `st.metric` 做一行指标卡
   - 操作：设置 `label`、`value`、`format`、`icon`、`border`
   - 预期输出：→ 3–5 个关键数字一眼可见、格式统一
   - 做错会看到什么：数字手填、格式混乱；改为从接口取数并统一 `format`
3. **画图表**
   - 做什么：用 `st.line_chart` 与 `st.bar_chart` 画趋势与对比
   - 操作：把数据转成 `DataFrame`，设置 `x` 或索引、`y`、`color`、`height`
   - 预期输出：→ 图表类型与数据形状匹配
   - 做错会看到什么：图表空白；检查 `data` 是否为 `DataFrame`、`x`/`y` 列名是否存在
4. **组合仪表盘**
   - 做什么：用 `st.sidebar`、`st.columns`、`st.container` 组合页面
   - 操作：按总览—趋势—明细排列，保留改进前后截图
   - 预期输出：→ 页面层级清楚、窄屏可用
   - 做错会看到什么：容器嵌套过多、固定宽度溢出；减少嵌套，改用比例列与 `width="stretch"`

### 四、排错清单

| 现象 | 先查什么 |
| --- | --- |
| 主题不生效 | 是否重启、键名是否拼对 |
| 指标卡数字对不上 | 是否手填、是否来自接口 |
| 图表空白或报错 | `data` 是否为 `DataFrame`、`x`/`y` 列名是否存在 |
| 图表太窄或溢出 | 是否用比例列与 `width="stretch"` |
| 卡片层次乱 | 容器嵌套是否过多、主色是否统一 |

## 本章小结

**核心结论**：

1. **主题**配置写在 `.streamlit/config.toml` 的 `[theme]` 节，常用键有 `base`、`primaryColor`、`backgroundColor`、`secondaryBackgroundColor`、`textColor`、`font`；改完必须重启 Streamlit。
2. **卡片与区块**用 `st.container(border=True)`、`st.columns(gap=...)`、`st.subheader()`、`st.caption()`、`st.divider()` 组织；容器只负责摆放，卡片靠边框与留白形成分组。
3. **指标卡**用 `st.metric`，常用参数有 `label`、`value`、`delta`、`delta_color`、`format`、`icon`、`border`、`help`；数字必须来自统计接口。
4. **图表**有内置接口（`st.line_chart`、`st.bar_chart`、`st.area_chart`、`st.scatter_chart`、`st.map`）与集成接口（Altair、Plotly、Matplotlib）；内置图表的常用参数有 `data`、`x`、`y`、`color`、`height`、`width`。
5. 把主题、布局、指标与图表组合成仪表盘：`sidebar` 放筛选，指标卡给总览，图表给趋势与对比，`st.dataframe` 给明细；再用信息层级（总览—趋势—明细、首屏一问）检查排列是否成立。

把这章压缩成一句话：**先用对 Streamlit 的主题、布局、指标与图表接口，再谈怎样把它们排得更好读。**
