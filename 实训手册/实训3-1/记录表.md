# 实训 3-1 状态码记录表

> 填法：每做一次真实请求，立刻填一行。“实际状态码”必须来自响应，不能抄“预期状态码”。

| 序号 | HTTP 方法 | URL | 输入摘要 | 预期状态码 | 实际状态码 | 响应体是否为空 | 结论 |
| ---: | --- | --- | --- | ---: | ---: | --- | --- |
| 1 | GET | `/departments` | 无 | 200 |  | 否 |  |
| 2 | POST | `/departments` | 完整记录 | 201 |  | 否 |  |
| 3 | POST | `/departments` | 重复编码 | 400 |  | 否 |  |
| 4 | DELETE | `/departments/{dept_code}` | 无 | 204 |  | 是 |  |

## 三、幂等说明（100 字以内）

按下面四句填，判断依据写“服务器最终状态”：

> GET 重复请求______，因为______。
>
> PUT 重复提交同一请求体______，因为______。
>
> DELETE 第一次______，第二次______，但最终______，所以______。
>
> POST 重复执行______，因为______。

参考答案要点（不要直接抄，先自己写）：

- GET 读多少次都不改数据，幂等。
- PUT 重复提交同一请求体，最终记录一样，幂等。
- DELETE 第一次 204、第二次 404，响应码不同，但最终都是资源不存在，所以幂等。
- POST 重复执行可能新增多条，不幂等。

## 四、自检

- [ ] 五行必填都有真实状态码
- [ ] 204 行的“响应体是否为空”填“是”
- [ ] 400 与 404 各至少一行
- [ ] 幂等说明四句都填了
- [ ] 没有把预期列抄到实际列
