# 实训 3-1 代码分步实现指南

本指南以部门为例，把 starter 从“只有一个 GET 列表”补到“五个端点全部可用”。字段与资源名可按自选对象替换，方法与状态码的对应关系不变。

## 零、起点

```python
from fastapi import FastAPI

app = FastAPI()

DEPARTMENTS = {
    "D01": {"dept_code": "D01", "full_name": "一中队", "address": "一号楼"},
}


@app.get("/departments")
def list_departments():
    return {"items": list(DEPARTMENTS.values()), "total": len(DEPARTMENTS)}
```

启动后打开 `/docs`，只有 `GET /departments` 一个端点。本实训补另外四个。

## 阶段 1：补详情接口与 404

```python
from fastapi import HTTPException


@app.get("/departments/{dept_code}")
def get_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="部门不存在")
    return DEPARTMENTS[dept_code]
```

`dept_code` 是路径参数，用来定位单个资源。查不到时用 `HTTPException(404)` 结束请求，不返回空对象。

**检查点**：`GET /departments/D01` 返回 200；`GET /departments/D404` 返回 404。

## 阶段 2：补新增接口与 201

```python
from fastapi import status


@app.post("/departments", status_code=status.HTTP_201_CREATED)
def create_department(data: dict):
    dept_code = data.get("dept_code")
    full_name = data.get("full_name")
    if not dept_code or not full_name:
        raise HTTPException(status_code=400, detail="缺少必填字段")
    if dept_code in DEPARTMENTS:
        raise HTTPException(status_code=400, detail="部门编码已存在")
    DEPARTMENTS[dept_code] = {
        "dept_code": dept_code,
        "full_name": full_name,
        "address": data.get("address"),
    }
    return DEPARTMENTS[dept_code]
```

请求体用字典接收，字段检查写在函数入口。缺字段与编码重复都属于业务判断，返回 400；第 3 章 3.5 改用 Pydantic 后，缺字段会变成 422。

**检查点**：新增返回 201；重复编码返回 400；缺字段返回 400。

## 阶段 3：补修改接口与 200

```python
@app.put("/departments/{dept_code}")
def update_department(dept_code: str, data: dict):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="部门不存在")
    item = DEPARTMENTS[dept_code]
    if "full_name" in data:
        item["full_name"] = data["full_name"]
    if "address" in data:
        item["address"] = data["address"]
    return item
```

路径参数定位资源，请求体提供要改的字段。只改传入的字段，未传的保持原值。

**检查点**：修改返回 200；修改不存在的编码返回 404。

## 阶段 4：补删除接口与 204

```python
@app.delete("/departments/{dept_code}", status_code=status.HTTP_204_NO_CONTENT)
def delete_department(dept_code: str):
    if dept_code not in DEPARTMENTS:
        raise HTTPException(status_code=404, detail="部门不存在")
    del DEPARTMENTS[dept_code]
```

成功时函数不返回内容，装饰器声明 204；响应没有正文。再次删除同一编码，资源已不存在，返回 404。

**检查点**：第一次删除 204 且无正文；第二次删除 404。

## 阶段 5：在 `/docs` 验证五种状态码

| 请求 | 预期 |
| --- | --- |
| `GET /departments` | 200 |
| `GET /departments/D01` | 200 |
| `GET /departments/D404` | 404 |
| `POST /departments`，提交完整字段 | 201 |
| 重复提交同一 `dept_code` | 400 |
| `POST /departments`，缺 `full_name` | 400（手写检查） |
| `PUT /departments/D01` | 200 |
| `PUT /departments/D404` | 404 |
| `DELETE /departments/D02` | 204，无正文 |
| 再次 `DELETE /departments/D02` | 404 |

把结果填入记录表。若出现 500，按第 3 章 3.2 的责任表判断该由谁拒绝。

## 阶段 6：幂等性说明

- 重复 `GET` 结果不变。
- 重复 `PUT` 同一正文，最终记录相同。
- 第一次 `DELETE` 返回 204，第二次返回 404；两次执行后服务器状态相同，都是“该部门不存在”。**幂等看服务器状态，不看响应码。**
- 重复 `POST` 会再次创建，或因编码重复返回 400；服务器状态可能改变，因此 POST 不幂等。

## 每阶段都要问的三个问题

1. 这个方法对应的成功状态码是什么？GET / PUT 200，POST 201，DELETE 204。
2. 参数放在哪里？定位用路径参数，新增与修改的数据放请求体。
3. 失败由谁拒绝？资源不存在用 `HTTPException(404)`；字段检查在进入业务逻辑前完成。
