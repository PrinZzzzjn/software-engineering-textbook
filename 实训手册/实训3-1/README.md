## 六、操作步骤

### 步骤 1：读 starter（10 分钟）

- 做什么：打开 `starter/main.py`，确认已有一条 GET 列表与一个内存字典。
- 预期输出：能说出字典的键是什么、值与字段如何对应。
- 做错会看到什么：把字典当成数据库，试图写入文件；本实训只要求内存存储。

### 步骤 2：补 POST 与 PUT（30 分钟）

- 做什么：按 3.4 的写法补新增与修改；新增返回 201，修改返回 200。
- 预期输出：`/docs` 中能看到两个新端点，新增后列表多一条，修改后详情变化。
- 做错会看到什么：新增仍返回 200；检查装饰器的 `status_code` 参数。

### 步骤 3：补 DELETE 与 404（20 分钟）

- 做什么：补删除接口，成功返回 204 且不返回正文；删除不存在的资源返回 404。
- 预期输出：第一次删除 204，第二次删除 404。
- 做错会看到什么：204 仍带 JSON 正文；检查函数是否返回了内容。

### 步骤 4：在 `/docs` 制造 400 与 404（15 分钟）

- 做什么：提交缺字段或类型不符的正文，观察当前写法返回 400；访问不存在的编码，观察 404。
- 预期输出：能说清 400 与 404 的分工。
- 做错会看到什么：把所有失败都归为 400；回到 3.2 的责任表。

### 步骤 5：填写记录表（10 分钟）

- 做什么：把五个端点的正常与失败请求逐行填入 [记录表.md](记录表.md)。
- 预期输出：200、201、204、404、400 各至少一行。
- 做错会看到什么：只记录了成功路径；补齐失败两行。

### 步骤 6：提交（5 分钟）

- 做什么：整理代码与记录表，按教师要求提交。
- 预期输出：代码可重新启动，记录表与 `/docs` 行为一致。

## 十、排错清单

| 现象 | 先查什么 |
| --- | --- |
| 所有接口 404 | 装饰器路径是否与访问路径一致；是否漏写方法 |
| 新增返回 307 | URL 末尾斜杠不一致；统一集合地址的写法 |
| 删除返回 200 且带正文 | 装饰器是否声明 `status_code=204`；函数是否返回了内容 |
| 重复删除返回 200 | 是否先判断资源存在，再执行删除 |
| 修改后字段未变 | 请求体字段名与代码读取的键是否一致 |
| 字段错误返回 500 | 是否直接索引不存在的键；改用 `data.get(...)` 或模型 |
