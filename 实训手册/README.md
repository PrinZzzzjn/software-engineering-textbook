# 实训手册

本目录收录与《软件工程实践》（2.0）教材配套的实训手册。教材从第 3 章起在章末设置 ◆ 实训块；本手册将每个实训块展开为可直接在课堂使用的材料。

## 一、体例

每次实训对应一个目录，目录内包含：

| 文件 | 作用 |
| --- | --- |
| `README.md` | 实训手册正文：目标、课前准备、时间安排、操作步骤、验收、排错、提交 |
| `分步实现指南.md` | 代码从空目录到可验证实现的逐阶段说明；仅在实训要求写代码时提供 |
| `设计文档模板.md` | 学生填写的设计文档骨架；仅在实训产出设计文档时提供 |
| `记录表.md` | 课堂记录表；仅在实训含状态码验证时提供 |
| `验收记录.md` | 启动、目录、历史与排除项的核对表；仅在实训含验收记录时提供 |
| `starter/` 或 `项目/` | 可运行的最小项目或完成后的完整工程；仅在实训要求写代码时提供 |

编写约定：

1. 目录名等于教材中的实训编号，例如 `实训4-1`、`实训5-1`。
2. 概念讲解留在教材正文，手册只回答“做什么、怎么做、怎么验收”；需要时回指教材节号。
3. 手册不以“可直接提交的答案”为目的。教材第 4 章要求业务对象自选、字段与路径自行确定；`starter/` 与《分步实现指南》中的单位示例只演示机制与流程，学生须替换为自选对象并自行设计。
4. 命令、预期输出与状态码以教材和 `项目参考/` 的验证结果为准；因操作系统或依赖版本产生的差异，统一写入各手册的排错清单。
5. 案例背景统一取教材主案例《执勤电子年鉴》（单位、人员、哨位、执勤记录）。示例字段以 `项目参考/duty` 的代码为准；接口写法以教材第 4 章 4.4 的约定为准，参考项目中的早期写法（单数资源名、删除返回 200）不作为判定依据，并在排错清单中列为“已知不同”。

## 三、时间与分组建议

- **分组**：独立完成。4-1 的设计文档互查、5-1 的仓库互查均改为课后扩展，不占用课堂时间。
- **时间**：分钟数取自对应教材实训块。3-1 合计 90 分钟（2 学时），优先保住五个端点与五种状态码；4-1 合计 90 分钟（2 学时），时间不足时优先保住设计与六个文件；5-1 与 6-1 各 180 分钟（4 学时）：5-1 优先保住 Git 历史与分支，6-1 优先保住注册、登录与 `/me`。
- **场地**：每人一台可运行 Python 的机器；3-1、4-1、6-1 需要浏览器打开 `/docs`，5-1 另需终端与已安装的 Git。
