# 实训 4-1 接口验证记录表

> 填法：每做一次真实请求，立刻填一行。“实际状态码”必须来自响应，不能抄“预期状态码”。

## 一、必填六行

| 序号 | HTTP 方法 | URL | 输入摘要 | 预期状态码 | 实际状态码 | 响应体是否为空 | 结论 |
| ---: | --- | --- | --- | ---: | ---: | --- | --- |
| 1 | GET | `/departments` | 无 | 200 |  | 否 |  |
| 2 | POST | `/departments` | 完整记录 | 201 |  | 否 |  |
| 3 | DELETE | `/departments/{dept_code}` | 无 | 204 |  | 是 |  |
| 4 | POST | `/departments` | 重复编码 | 400 |  | 否 |  |
| 5 | GET | `/departments/D404` | 无 | 404 |  | 否 |  |
| 6 | POST | `/departments` | 缺 `full_name` | 422 |  | 否 |  |

> 第 3 行删除前先新增一条；第 4 行重复提交第 2 行的编码；第 6 行只提交 `dept_code`。

## 四、自检

- [ ] 六行必填都有真实状态码

- [ ] 400 与 422 各一行，能说出区别
- [ ] 分页行的 `total` 是全量条数
