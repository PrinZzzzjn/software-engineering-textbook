# 综合实训 4-1 实训手册：接口与设计综合实践

> **对应教材**：第 4 章《软件设计与建模》章末 ◆ 综合实训 4-1
> **课次**：课次 4（2 学时 · 实践）｜前置：第 2 章需求条目与验收标准；第 3 章 3.4–3.6；第 4 章 4.1–4.6
> **交付**：设计文档、六文件实现代码、接口验证记录

## 一、实训概览

| 项目 | 内容 |
| --- | --- |
| 实训编号 | 综合实训 4-1 |
| 实训名称 | 接口与设计综合实践 |
| 对应教材 | 第 4 章；同时使用第 3 章的四方法与输入模型 |
| 课次与学时 | 课次 4 · 2 学时 · 实践（90 分钟） |
| 组织形式 | 独立完成 |
| 场地与工具 | 可运行 Python 的计算机；浏览器；`/docs` 页面 |

本实训先为自选业务对象写出表结构、接口组与模块目录，再用六文件实现五个接口，验证设计中的状态码是否落地。

## 二、学习目标与验收标志

### 2.1 本课结束后应能做到

| 编号 | 学习目标（能做什么） | 对应第 4 章目标 | 达标要点 |
| --- | --- | --- | --- |
| L1 | 说出需求到设计文档的翻译顺序，并为自选对象列出字段与主键 | 1、2 | 顺序为对象 → 表 → 模块 → 接口 → 目录；主键唯一且必填 |
| L2 | 写出一张表结构：字段、类型、主键；有一对多关系时说明外键位置 | 2 | 外键在“多”的一方，并能说出查询与修改的理由 |
| L3 | 写出五个标准接口的方法、URL、参数来源与成功状态码，并给出一条规则性失败 | 4 | URL 是名词、方法是动作、状态码表结果；能区分 422 与 400 |
| L4 | 按业务能力划出模块，用一句话写职责，画出六个文件的目录 | 3、5 | 一句话能说清职责；六个文件各就其位 |
| L5 | 用六文件实现五个接口，跑通 200、201、204、404、422 | 6 | 每个状态码都能指出由哪一层产生 |

步骤与目标的对应：步骤 1–2 支撑 L1、L2；步骤 3–5 支撑 L3、L4；步骤 6 支撑 L5。

### 2.2 验收标志

| 目标 | 验收标志 |
| --- | --- |
| 表结构设计 | 字段、类型、主键清楚；有一对多关系时，外键放在“多”的一方并说明理由 |
| 模块模板 | 一句话说清模块职责；模块对应一个文件夹；六个文件齐备 |
| 接口组设计 | 五个标准动作的方法、URL、参数来源、成功状态码齐全；至少一条规则性失败的说明 |
| 六文件实现可运行 | `controller` / `service` / `crud` / `model` / `schema` / `param` 齐备，五个接口均可调用；`/docs` 可打开 |
| 状态码验证 | 200、201、204、404、422 至少各出现一次，并记录实际结果 |
| 设计文档 | 表结构、接口清单、模块目录三节齐全；两组一致性检查通过 |

验收标志衡量交付物，学习目标衡量能力；两者冲突时以学习目标为准。例如记录表填满，但说不出 422 为什么由模型而不是接口函数拒绝，L5 仍记为未达成。

## 六、操作步骤

### 步骤 1：选对象与写字段（10 分钟）

- 做什么：确定业务对象，列出 3–5 个字段与主键，判断是否存在关联对象。
- 预期输出：一条能说清“这个对象是什么、谁在用”的说明，以及字段清单。
- 做错会看到什么：对象选得太大（如“管理系统”）；缩到一个业务对象，再继续。

### 步骤 2：写 model 与 schema（15 分钟）

- 做什么：打开 starter 的 `app/modules/department/`，把 `model.py` 的字段换成自选对象；把 `schema.py` 的输入、输出与更新模型换成对应字段。
- 预期输出：字段名、类型与约束能直接对应设计文档的表结构。
- 做错会看到什么：输入与输出共用一个模型；内部字段出现在输出里；拆成两个模型。

### 步骤 3：写 crud（20 分钟）

- 做什么：补全 `crud.py` 的 `list_all`、`get`、`create`、`update`、`delete` 五个函数，只做存取。
- 预期输出：`crud.py` 中不出现 `HTTPException`，也不判断规则。
- 做错会看到什么：把“编码重复”写进 `crud`；移到 `service`。

### 步骤 4：写 service（15 分钟）

- 做什么：补全 `service.py` 的五个函数；编码重复返回 400，资源不存在返回 404。
- 预期输出：`controller` 调用 `service` 后即可得到结果或异常。
- 做错会看到什么：`service` 只做转发、没有任何判断；把规则补回这一层。

### 步骤 5：写 param 与 controller 五个接口（20 分钟）

- 做什么：`param.py` 的 `DepartmentQueryParams` 已给出；在 `controller.py` 登记五个接口，列表用 `Depends()` 注入参数，删除声明 204。
- 预期输出：`/docs` 出现五个端点；列表 200、详情 200、新增 201、修改 200、删除 204。
- 做错会看到什么：删除返回 200 或带正文；检查 `status_code=204` 与函数返回值。

### 步骤 6：验证状态码与提交（10 分钟）

- 做什么：在 `/docs` 制造 200、201、204、404、422；填写记录表；核对表字段与接口返回、模块目录与六个文件两组对应。
- 预期输出：五种状态码都出现；每组对应都能指出具体依据。
- 做错会看到什么：所有错误都返回 500 或 200；按第 3 章 3.2 的状态码责任表判断该由谁拒绝。

## 十、排错清单

| 现象 | 先查什么 |
| --- | --- |
| `/docs` 打不开 | 服务是否启动、启动文件是否为 `main:app` |
| 接口全 404 | `include_router` 的两段前缀是否都写、模块 `prefix` 是否正确 |
| `ModuleNotFoundError: app.modules` | 包目录是否缺 `__init__.py`、是否在 `starter/` 目录执行 |
| 新增返回 200 | 装饰器是否声明 `status_code=201` |
| 删除返回 200 或带正文 | 装饰器是否声明 `status_code=204`；函数是否返回了内容 |
| 重复删除仍返回 204 | 是否先判断资源存在 |
| 字段错误返回 500 | 是否直接索引不存在的键；先用模型校验 |
| 输出带出内部字段 | 是否声明 `response_model` |
| 重启后数据消失 | 内存存储的正常行为；数据库在第 6 章引入 |
| 422 与 400 混用 | 输入不符合约定交 422；业务规则不满足交 `HTTPException(400)` |

## 十一、提交要求

提交三项：**设计文档**、**六文件实现代码**、**接口验证记录**。

设计文档按 [设计文档模板.md](设计文档模板.md) 编写；验证记录按 [记录表.md](记录表.md) 填写，表头为：方法 / URL / 输入 / 预期状态码 / 实际状态码 / 结论。

发现差异时，不应默认修改某一方；先记录期望值与实际值，再判断是设计文档有误还是实现偏离。
