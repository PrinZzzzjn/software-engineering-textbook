# 综合实训 4-1 代码分步实现指南

> **定位**：演示从空目录到一个可验证的最小实现的完整过程，每个阶段结束时代码都可运行。以执勤电子年鉴中的“工位”为例。
> **使用者**：教师课堂演示；学生对照自查。提交的代码必须替换为自己选定的业务对象。
> **与 starter 的关系**：`starter/` 相当于本文第 2 阶段末的骨架，另有两处占位函数；第 3、4 阶段就是把这两处占位补完。
> **与教材步骤的关系**：第 1–4 阶段对应操作步骤 5（实现最小后端），第 5 阶段对应步骤 6（验证状态码）。

## 零、开始之前

**文件**：本实训只建两个文件；第 5 章把它们迁入模块目录，模块其余四个文件到第 8 章补。

```text
starter/            ← 自己新建一个目录，名称随意
├── main.py         ← 应用与接口
└── schemas.py      ← 第 2 阶段起才需要
```

**启动**（在 `main.py` 所在目录执行）：

```bash
uvicorn main:app --reload
```

**验证入口**：浏览器打开 `http://127.0.0.1:8000/docs`。每个阶段结束都从这里发出请求，对照下文的状态码。

**一条约定**：每阶段只增加一件事，并在 `/docs` 里确认它生效后再进入下一阶段。跳过验证，后面出错时无法判断是哪一步引入的。

## 阶段 1：最小应用——先把 200 跑通

**目标**：路由挂载成功，`/docs` 出现“工位”分组，列表接口返回空集合。

**为什么先做这一步**：接口全 404 是初学者最常见的问题，原因几乎都在前缀与挂载。先让列表接口返回 200，就把“应用能启动、路由能到达”这件事单独验证掉了。

**main.py**

```python
from fastapi import APIRouter, FastAPI

app = FastAPI(title="工位接口（阶段 1）")
router = APIRouter(prefix="/api/v1/workstations", tags=["工位"])


@router.get("/")
def list_workstations():
    return {"items": [], "total": 0}


app.include_router(router)
```

**验证**

| 请求 | 预期 | 说明 |
| --- | --- | --- |
| `GET /api/v1/workstations/` | 200，`{"items": [], "total": 0}` | 接口通了，还没有数据 |
| `POST /api/v1/workstations/` | **405** | 路径存在，但未注册 POST 方法 |
| `GET /api/v1/workstations/WS-001` | **404** | 该路径尚未注册 |

**做错会看到什么**

- 全 404：`APIRouter` 的 `prefix` 与 `include_router` 未同时写，或路径单复数不一致。
- 405 不等于 404：405 表示路径已注册、方法不对；404 表示路径不存在。分清两者，能直接定位问题在方法还是路径。

**设计对照**：本阶段实现设计文档接口清单的第 1 行（查询集合）。

## 阶段 2：加模型——让输出可控

**目标**：引入 `schemas.py`，列表返回两条示例记录；响应只包含输出模型声明的字段。

**为什么此时才加模型**：接口先通，再加约束，出错时能判断是新代码的问题还是原有路由的问题。模型一次加三件事：输入能进什么、输出能出什么、`/docs` 显示什么。

**schemas.py**（新建）

```python
from pydantic import BaseModel, Field


class WorkstationCreate(BaseModel):
    workstation_id: str = Field(..., min_length=2, max_length=20)
    workstation_name: str = Field(..., min_length=2, max_length=50)
    dept_code: str = Field(..., min_length=2, max_length=10)
    category_code: str | None = None
    remark: str | None = None


class WorkstationOut(BaseModel):
    workstation_id: str
    workstation_name: str
    dept_code: str
    category_code: str | None = None
    remark: str | None = None


class WorkstationListOut(BaseModel):
    items: list[WorkstationOut]
    total: int
```

**main.py**

```python
from fastapi import APIRouter, FastAPI

from schemas import WorkstationListOut

app = FastAPI(title="工位接口（阶段 2）")
router = APIRouter(prefix="/api/v1/workstations", tags=["工位"])

items = [
    {
        "workstation_id": "WS-001",
        "workstation_name": "一号值班台",
        "dept_code": "D01",
        "category_code": "C01",
        "remark": None,
        "is_deleted": False,
    },
    {
        "workstation_id": "WS-002",
        "workstation_name": "二号值班台",
        "dept_code": "D02",
        "category_code": "C02",
        "remark": None,
        "is_deleted": False,
    },
]


@router.get("/", response_model=WorkstationListOut)
def list_workstations():
    return {"items": items, "total": len(items)}


app.include_router(router)
```

**验证**

| 请求 | 预期 | 说明 |
| --- | --- | --- |
| `GET /api/v1/workstations/` | 200，`total` 为 2 | 数据进入响应 |
| 响应的第一条 | 无 `is_deleted` 字段 | `response_model` 按模型过滤，未声明的字段不输出 |

`is_deleted` 是故意放进 `items` 的：它代表内部字段。若响应里出现了它，说明 `response_model` 没写或写错——这正是第 3 章 3.5 所说的过度数据暴露。

**此时与 starter 的关系**：starter 的列表接口就是这一阶段；它另外放了新增与查询单个两个占位函数，返回固定值。下一阶段开始替换占位。

## 阶段 3：新增——201 与 422

**目标**：新增接口写入 `items`，成功返回 201；请求体缺字段时由 Pydantic 返回 422。

**改动位置**：`main.py` 的 import 行，以及在 `app.include_router(router)` 之前新增函数。

**改动一：import**

```python
from schemas import WorkstationCreate, WorkstationListOut, WorkstationOut
```

**改动二：新增函数**

```python
@router.post("/", status_code=201, response_model=WorkstationOut)
def create_workstation(data: WorkstationCreate):
    items.append(data.model_dump())
    return data
```

**验证**

| 请求 | 预期 | 说明 |
| --- | --- | --- |
| `POST /api/v1/workstations/`，请求体含 `workstation_id`、`workstation_name`、`dept_code` | 201，返回新记录 | 新增成功 |
| `POST` 后再查列表 | `total` 加 1 | 记录确实写入了 |
| `POST` 缺 `workstation_id` | **422** | 进入函数前被模型拒绝 |
| `POST` 用已存在的 `WS-001` | **201**（此时不拦截） | 重复编号的处理留到阶段 5 |

**做错会看到什么**

- 新增返回 200：`status_code=201` 未写或写错位置（应写在装饰器参数里）。
- 缺字段仍返回 201：`data: WorkstationCreate` 未声明模型，FastAPI 把请求体当普通字典。
- 列表里看不到新记录：函数返回了数据但没有执行 `items.append`。

**讲解点**：422 不是函数抛出的，而是请求体按模型解析失败时由框架返回的。函数体只处理模型表达不了的规则。

## 阶段 4：查询单个——404

**目标**：用路径参数定位一条记录；找不到时返回 404，而不是 200 或 500。

**改动位置**：`main.py` 的 import 行，以及在文件末尾、`app.include_router(router)` 之前新增函数。

**改动一：import**

```python
from fastapi import APIRouter, FastAPI, HTTPException
```

**改动二：新增函数**

```python
@router.get("/{workstation_id}", response_model=WorkstationOut)
def get_workstation(workstation_id: str):
    for item in items:
        if item["workstation_id"] == workstation_id:
            return item
    raise HTTPException(status_code=404, detail="工位不存在")
```

**验证**

| 请求 | 预期 | 说明 |
| --- | --- | --- |
| `GET /api/v1/workstations/WS-001` | 200，返回该记录 | 路径参数命中 |
| `GET /api/v1/workstations/WS-999` | **404**，`detail` 为“工位不存在” | 规则性失败 |
| `GET /api/v1/workstations/` | 仍为 200 | 集合路径不受影响 |

**做错会看到什么**

- 任何编号都返回 200：没有在找不到时 `raise HTTPException`，函数返回了占位数据。
- 返回 500：直接访问了不存在的键，或抛出未处理的异常；失败分支必须显式抛出 `HTTPException`。
- 访问集合路径变成 404：集合路径与单个路径的尾斜杠写法不一致，客户端实际请求的路径与注册的路径差一级；检查两个装饰器的路径是否统一（集合用 `"/"`，单个用 `"/{workstation_id}"`），请求时保持一致。

**此时完成度**：200、201、404、422 四种状态码已在代码中全部具备。剩下去 `/docs` 逐一验证并填写记录表。

## 阶段 5：可选——规则性失败 400 与收尾

**目标**：为“编号重复”补一条业务规则，返回 400；完成记录表与两组一致性检查。

**说明**：教材要求在设计文档中写出至少一条规则性失败的说明，不要求实现。实现了，就在记录表多加一行；未实现，设计文档中注明“本次未实现”即可。

**改动**：把阶段 3 的 `create_workstation` 替换为：

```python
@router.post("/", status_code=201, response_model=WorkstationOut)
def create_workstation(data: WorkstationCreate):
    for item in items:
        if item["workstation_id"] == data.workstation_id:
            raise HTTPException(status_code=400, detail="工位编号已存在")
    items.append(data.model_dump())
    return data
```

**验证**

| 请求 | 预期 | 说明 |
| --- | --- | --- |
| `POST` 已存在的 `WS-001` | **400**，`detail` 为“工位编号已存在” | 参数格式正确，业务不允许 |
| `POST` 新编号 | 201 | 正常新增 |
| `POST` 缺字段 | 422 | 与 400 分属两种责任 |

**为什么不是 422**：请求体格式完全合法，只是业务规则不允许，因此不能用模型校验的 422；也不应落到 500。

**收尾三步**

1. 在 `/docs` 中制造 200、201、404、422（若做了本阶段，再加 400），逐行填 [记录表.md](记录表.md)。
2. 核对两组对应：表字段与接口返回字段；模块目录与六个文件。
3. 整理三项交付物：设计文档、`main.py` + `schemas.py`、记录表。

## 阶段与产物对照

| 阶段 | 新增能力 | 可验证状态码 | 对应教材步骤 | 对应 starter |
| --- | --- | --- | --- | --- |
| 1 | 路由挂载、空列表 | 200 | 步骤 5 前段 | 无（starter 从阶段 2 起） |
| 2 | 输入/输出模型、输出过滤 | 200 | 步骤 5 前段 | 列表接口已实现 |
| 3 | 新增写入 | 201、422 | 步骤 5 后段 | POST 占位待替换 |
| 4 | 路径参数与 404 | 200、404 | 步骤 5 后段 | GET 单个占位待替换 |
| 5 | 规则性失败（可选） | 400 | 步骤 6 | 无（可选扩展） |

## 每阶段都要问的三个问题

1. 这一步对应设计文档的哪一行？答不出，说明设计文档与代码已经脱节。
2. 这一步新增或改变了哪个状态码？它由谁拒绝——模型、业务规则，还是框架？
3. 如果删掉这一步，哪条验收标志会不成立？
