## 开始之前：这份实训难在哪

3-1 是“一个文件写五个端点”；4-1 是“把同一件事拆到六个文件”。难的不是业务，而是三件事：

1. **文件之间怎么连**：谁导入谁，`from . import model` 里的 `.` 是什么。
2. **每一层管什么**：controller 只收参数，service 管规则，crud 管读写，model 管结构，schema 管输入输出，param 管查询参数。
3. **两类失败怎么分**：字段格式不对由 Pydantic 返回 422；编码重复由 service 返回 400。

每阶段末尾都有检查点；检查点不过，不进入下一阶段。


### 语法卡片

**包与目录。** `app/` 是一个包，`app/modules/` 是子包，`app/modules/department/` 是单位模块包。每个包目录下要有一个 `__init__.py`；它可以是空文件，作用是把目录标记为包。

**绝对导入。** 从项目根目录开始写完整路径：

```python
from app.modules.department import controller as department_controller
```

意思是：从 `app/modules/department` 包里取出 `controller`，并给它起别名 `department_controller`。

**相对导入。** 在同一个包内部，用 `.` 表示“当前包”：

```python
from . import model
```

意思是：从当前包（`department/`）导入 `model.py`。这样模块改名或移动时，不用改一堆绝对路径。

**启动目录。** `uvicorn main:app` 要求终端当前目录就是 `main.py` 所在目录；否则会报 `Could not import module "main"`。

### 代码与逐行解释

目录结构：

```text
starter/
├── main.py

└── app/
```

### 语法卡片：设计里的四个词

**字段与类型。** 字段是“要存什么”，类型是“它是什么形态”。本实训只有三种：

| 类型 | 写法 | 例子 |
| --- | --- | --- |

**参数来源。** 同一个接口的数据可能来自三个位置：

| 来源 | 用在哪 | 例子 |

| 查询参数 | 过滤、分页 | `?page=1&page_size=10` |

## 阶段 2：`model.py`：dataclass 与内存表（20 分钟）

### 本步目标

读懂 `model.py`：用 `dataclass` 描述一条单位记录，用 `TABLE` 列表保存所有记录。

### 先看效果

```bash
python -c "from app.modules.department import model; item=model.Department('D01','一中队'); print(item); model.TABLE.append(item); print(model.TABLE)"
```

预期：

```text
Department(dept_code='D01', full_name='一中队', address=None)
[Department(dept_code='D01', full_name='一中队', address=None)]
```

### 语法卡片

**`@dataclass`。** 写在 `class` 上面，告诉 Python：“这个类主要是装数据的，帮我自动生成初始化方法。”没有它，`Department('D01','一中队')` 不能这样直接传参数。

**类与属性。** `class Department:` 定义一个类；下面缩进的 `dept_code: str` 是属性声明。

**类型注解。** `dept_code: str` 表示这个属性应该是字符串；`address: str | None = None` 表示它可以是字符串或 `None`，默认是 `None`。

**`list[Department]`。** 表示“装 `Department` 的列表”。`TABLE: list[Department] = []` 是模块级变量，所有函数共享这一份列表，相当于内存里的“表”。

### 代码与逐行解释

<!-- file: app/modules/department/model.py -->
```python
from dataclasses import dataclass


@dataclass
class Department:
    dept_code: str
    full_name: str
    address: str | None = None


TABLE: list[Department] = []
```

| 行 | 代码 | 在做什么 | 为什么需要 |
| --- | --- | --- | --- |
| 1 | `from dataclasses import dataclass` | 导入装饰器 | 下面要用 `@dataclass` |
| 4 | `@dataclass` | 自动生成初始化方法 | 可以直接 `Department('D01','一中队')` |
| 5 | `class Department:` | 定义记录类型 | 一条单位记录 |
| 6–7 | `dept_code: str`、`full_name: str` | 两个必填字段 | 无默认值，创建时必须给 |
| 8 | `address: str \| None = None` | 可选字段 | 不给就是 `None` |
| 11 | `TABLE: list[Department] = []` | 内存表 | crud 往这里 append/remove |

> 起点 `starter` 里可能带一条 D01 初始记录，方便你先看到数据。为了和完成态一致，把 `TABLE` 改成空列表 `[]`；需要数据时用 POST 新增。

### 操作与检查点

1. 打开 `model.py`，确认 `@dataclass` 在 `class` 上面。
2. 运行上面的 `python -c`，能看到 `Department(...)`。
3. 把 `TABLE` 改成 `[]`，再运行一次，列表为空。

检查点：

- [ ] `@dataclass` 没漏
- [ ] `address` 默认是 `None`
- [ ] `TABLE` 是列表，不是字典
- [ ] `python -c` 能创建并打印记录

### 常见错误与求助

| 现象 | 先查什么 | 怎么改 |
| --- | --- | --- |
| `TypeError: Department() takes no arguments` | 有没有 `@dataclass` | 补上装饰器 |
| `NameError: Department` | 导入路径 | `from app.modules.department import model` |
| 所有记录共用同一个默认值 | 默认值是不是可变对象 | 用 `None`，在函数里再创建 |
| `ModuleNotFoundError` | 目录与 `__init__.py` | 确认在 `starter/` 启动，三个 `__init__.py` 都在 |

## 阶段 3：`schema.py`：Pydantic 模型（20 分钟）

### 本步目标

读懂四个模型：创建、更新、单条输出、分页输出。知道字段校验失败为什么是 422，而编码重复是 400。

### 先看效果

```bash
python -c "from app.modules.department import schema; data=schema.DepartmentCreate(dept_code='D01', full_name='一中队'); print(data.model_dump())"
```

预期：

```text
{'dept_code': 'D01', 'full_name': '一中队', 'address': None}
```

再试缺字段：

```bash
python -c "from app.modules.department import schema; schema.DepartmentCreate(dept_code='D01')"
```

预期：抛出 `ValidationError`，提示 `full_name` 缺失。FastAPI 会把它转成 422 响应。

### 语法卡片

**`BaseModel`。** Pydantic 的模型基类；继承它，字段就会在创建时被检查。

**`Field(...)`。** 给字段加约束。`...` 表示必填；`min_length`、`max_length` 限制长度；`default=None` 表示可选。

**`model_dump()`。** 把模型转成普通字典，方便传给 crud 或 `Department(**...)`。

**`exclude_unset=True`。** 只导出“调用方真正传了的字段”，没传的不导出。更新时用它，避免把没传的字段清空。

**`model_validate()`。** 把 dataclass 或字典验证成输出模型；配合 `ConfigDict(from_attributes=True)` 可以读取对象属性。

**422 与 400。** 字段缺失、类型不对、长度不合法，由 Pydantic 在进入函数前拒绝，返回 422；编码重复是业务规则，进入 service 后由 `HTTPException(400)` 拒绝。

### 代码与逐行解释

<!-- file: app/modules/department/schema.py -->
```python
from pydantic import BaseModel, ConfigDict, Field


class DepartmentCreate(BaseModel):
    dept_code: str = Field(..., min_length=2, max_length=20)
    full_name: str = Field(..., min_length=2, max_length=100)
    address: str | None = Field(default=None, max_length=500)


class DepartmentUpdate(BaseModel):
    full_name: str | None = Field(default=None, min_length=2, max_length=100)
    address: str | None = Field(default=None, max_length=500)


class DepartmentOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    dept_code: str
    full_name: str
    address: str | None = None


class DepartmentPage(BaseModel):
    items: list[DepartmentOut]
    total: int
```

| 模型 | 用途 | 关键点 |
| --- | --- | --- |
| `DepartmentCreate` | POST 请求体 | 三个字段；两个必填 |
| `DepartmentUpdate` | PUT 请求体 | 都可不填；只更新传入字段 |
| `DepartmentOut` | 单条响应 | `from_attributes=True` 读 dataclass |
| `DepartmentPage` | 列表响应 | `items` 是输出模型列表，`total` 是整数 |

### 操作与检查点

1. 运行创建模型的 `python -c`，看到三个字段。
2. 运行缺字段的 `python -c`，看到 `ValidationError`。
3. 运行输出模型：

```bash
python -c "from app.modules.department import model, schema; item=model.Department('D01','一中队'); print(schema.DepartmentOut.model_validate(item).model_dump())"
```

预期：

```text
{'dept_code': 'D01', 'full_name': '一中队', 'address': None}
```

检查点：

- [ ] 能说出 `Create` / `Update` / `Out` / `Page` 各自的用途
- [ ] 知道 `...` 表示必填
- [ ] 知道缺字段是 422，不是 400
- [ ] 知道 `exclude_unset=True` 用在哪

### 常见错误与求助

| 现象 | 先查什么 | 怎么改 |
| --- | --- | --- |
| 输入输出共用一个模型 | 是否只有一个 `Department` 模型 | 拆成 Create/Update/Out/Page |
| `model_validate` 报错 | 是否忘了 `from_attributes=True` | 在 `DepartmentOut` 加 `model_config` |
| 缺字段返回 400 | 是否还在用手写 `data.get` | 4-1 改用模型，缺字段由框架返回 422 |
| 更新把没传字段清空 | 是否用了 `model_dump()` | 改成 `model_dump(exclude_unset=True)` |

## 阶段 4：`crud.py`：五个存取函数（25 分钟）

### 本步目标

补全五个函数，只做“读写数据”，不判断业务规则。查不到返回 `None`，不抛 404。

### 先看效果

```bash
python -c "from app.modules.department import crud, model; print(crud.get('D01')); item=crud.create(model.Department('D01','一中队')); print(crud.get('D01')); crud.update(item, {'address':'一号楼'}); print(crud.list_all()); crud.delete(item); print(crud.list_all())"
```

预期依次是 `None`、D01 对象、含地址“一号楼”的列表、空列表。

### 语法卡片

**`from . import model`。** 从当前包导入 `model` 模块，后面用 `model.TABLE`、`model.Department`。

**`append` / `remove`。** `list.append(item)` 加到末尾；`list.remove(item)` 删除这个对象。

**`for item in model.TABLE:`。** 逐个检查列表里的记录。

**`return None`。** 查不到时返回 `None`，让 service 决定要不要抛 404。

**`setattr(item, key, value)`。** 按字段名设置属性。等价于 `item.full_name = value`，但字段名在变量里时只能用 `setattr`。

**`data.items()`。** 一次取出字典的键和值。

### 代码与逐行解释

<!-- file: app/modules/department/crud.py -->
```python
from . import model


def list_all() -> list[model.Department]:
    return model.TABLE


def get(dept_code: str) -> model.Department | None:
    for item in model.TABLE:
        if item.dept_code == dept_code:
            return item
    return None


def create(item: model.Department) -> model.Department:
    model.TABLE.append(item)
    return item


def update(item: model.Department, data: dict) -> model.Department:
    for key, value in data.items():
        setattr(item, key, value)
    return item


def delete(item: model.Department) -> None:
    model.TABLE.remove(item)
```

| 函数 | 在做什么 | 不做什么 |
| --- | --- | --- |
| `list_all` | 返回整个表 | 不分页、不排序 |
| `get` | 按编码找一条，找不到返回 `None` | 不抛 404 |
| `create` | 加到表里 | 不查重 |
| `update` | 按传入字段改 | 不判断字段是否合法 |
| `delete` | 从表里移除 | 不判断是否存在 |

### 操作与检查点

按“先看效果”的命令跑一遍。如果你看到的不是 `None`，说明 `TABLE` 里还有初始数据；先清空再试。

## 阶段 5：`service.py`：规则与分页（30 分钟）

### 本步目标

补全五个服务函数：列表做分页；创建查重返回 400；详情、修改、删除先确认存在，不存在返回 404。`crud` 只负责读写，规则都放在这一层。

### 先看效果

```bash
python -c "from app.modules.department import schema, service; data=schema.DepartmentCreate(dept_code='D01', full_name='一中队'); service.create_department(data); print(service.get_department('D01')); print(service.list_departments(1, 10))"
```

预期：先看到 D01 对象，再看到 `{'items': [...], 'total': 1}`。在同一个进程里再次新增 D01，应抛出 400。

### 语法卡片

**`raise HTTPException(status_code=400, ...)`。** 编码重复是业务规则不允许，用 400；资源不存在用 404。它们都在函数内主动抛出。

**切片。** `items[start : start + page_size]` 取出从 `start` 开始、长度为 `page_size` 的一段。`start = (page - 1) * page_size`。

**`len(items)` 与 `len(page_items)`。** `total` 必须是切片前的总数，不是当前页的条数。第二页只剩一条时，`total` 仍然是全表条数。

**列表推导。** `[schema.DepartmentOut.model_validate(item) for item in page_items]` 的意思是：把当前页每条 dataclass 转成输出模型，组成列表。读法是“对 page_items 里的每个 item，做 model_validate”。

**`model_dump(exclude_unset=True)`。** 更新时只导出调用方真正传了的字段；没传的字段不出现在字典里，`crud.update` 就不会改它。

**`model.Department(**data.model_dump())`。** `**` 把字典拆成关键字参数，等价于 `Department(dept_code=..., full_name=..., address=...)`。

### 代码与逐行解释

<!-- file: app/modules/department/service.py -->
```python
from fastapi import HTTPException

from . import crud, model, schema


def list_departments(page: int, page_size: int) -> dict:
    items = crud.list_all()
    start = (page - 1) * page_size
    page_items = items[start : start + page_size]
    return {
        "items": [schema.DepartmentOut.model_validate(item) for item in page_items],
        "total": len(items),
    }


def get_department(dept_code: str) -> model.Department:
    item = crud.get(dept_code)
    if item is None:
        raise HTTPException(status_code=404, detail="单位不存在")
    return item


def create_department(data: schema.DepartmentCreate) -> model.Department:
    if crud.get(data.dept_code) is not None:
        raise HTTPException(status_code=400, detail="单位编码已存在")
    return crud.create(model.Department(**data.model_dump()))


def update_department(
    dept_code: str, data: schema.DepartmentUpdate
) -> model.Department:
    item = crud.get(dept_code)
    if item is None:
        raise HTTPException(status_code=404, detail="单位不存在")
    return crud.update(item, data.model_dump(exclude_unset=True))


def delete_department(dept_code: str) -> None:
    item = crud.get(dept_code)
    if item is None:
        raise HTTPException(status_code=404, detail="单位不存在")
    crud.delete(item)
```

| 函数 | 规则 | 关键点 |
| --- | --- | --- |
| `list_departments` | 分页 | `total` 是切片前总数；`items` 是当前页 |
| `get_department` | 不存在 404 | 先 `crud.get`，再判断 `None` |
| `create_department` | 重复 400 | 先查重，再创建 |
| `update_department` | 不存在 404；只改传入字段 | `exclude_unset=True` |
| `delete_department` | 不存在 404 | 先查，再删 |

| 现象 | 先查什么 | 怎么改 |
| --- | --- | --- |
| service 只做转发 | 查重和存在判断是否还在 controller | 规则移到 service |
| 更新把没传字段清空 | 是否用了 `model_dump()` | 改成 `exclude_unset=True` |
| `total` 第二页变成 1 | 是否用了 `len(page_items)` | 改成 `len(items)` |

## 阶段 6：`param.py` + `controller.py` + `main.py`（30 分钟）

### 本步目标

补全查询参数模型和五个路由，挂到根应用上。完成后 `/docs` 出现五个单位端点。

### 先看效果

启动后打开 `http://127.0.0.1:8000/docs`，应看到“单位”分组下的五个端点；路径都是 `/departments`，没有 `/api/v1`，集合路径没有末尾斜杠。

### 语法卡片

**`APIRouter(prefix="/departments", tags=["单位"])`。** 创建一个路由器；`prefix` 是这一组路由的共同前缀，`tags` 是 `/docs` 里的分组名。

**`@router.get("")`。** 集合路径用空字符串，因为前缀已经是 `/departments`；不要写 `"/"`，否则会变成 `/departments/`，请求 `/departments` 可能被重定向（307）。

**`Depends()`。** 让 FastAPI 在进入函数前准备好查询参数模型；`params: param.DepartmentQueryParams = Depends()` 表示“把查询参数按这个模型解析”。本阶段只要求会照写、会验证，不要求解释依赖注入源码。

**`response_model=...`。** 声明响应按哪个模型输出；它会过滤字段，并让 `/docs` 显示响应结构。

**`status_code=...201/204`。** POST 声明 201；DELETE 声明 204，且函数不返回内容。

**`include_router(..., prefix="")`。** 把模块路由挂到应用上；模块自己已经带 `/departments`，根应用不再加版本前缀。

### 代码与逐行解释

<!-- file: app/modules/department/param.py -->
```python
from pydantic import BaseModel, Field


class DepartmentQueryParams(BaseModel):
    page: int = Field(1, ge=1)
    page_size: int = Field(10, ge=1, le=100)
```

| 字段 | 默认值 | 约束 | 非法时 |
| --- | ---: | --- | --- |
| `page` | 1 | `ge=1`（≥1） | 422 |
| `page_size` | 10 | `ge=1`、`le=100`（1–100） | 422 |

<!-- file: app/modules/department/controller.py -->
```python
from fastapi import APIRouter, Depends, status

from . import param, schema, service

router = APIRouter(prefix="/departments", tags=["单位"])


@router.get("", response_model=schema.DepartmentPage)
def list_departments(params: param.DepartmentQueryParams = Depends()):
    return service.list_departments(params.page, params.page_size)


@router.get("/{dept_code}", response_model=schema.DepartmentOut)
def get_department(dept_code: str):
    return service.get_department(dept_code)


@router.post(
    "", response_model=schema.DepartmentOut, status_code=status.HTTP_201_CREATED
)
def create_department(data: schema.DepartmentCreate):
    return service.create_department(data)


@router.put("/{dept_code}", response_model=schema.DepartmentOut)
def update_department(dept_code: str, data: schema.DepartmentUpdate):
    return service.update_department(dept_code, data)


@router.delete("/{dept_code}", status_code=status.HTTP_204_NO_CONTENT)
def delete_department(dept_code: str):
    service.delete_department(dept_code)
```

### 语法卡片：422 与 400 怎么分

- 422：请求不符合模型。字段缺失、类型不对、长度不合法、`page=0`。由 Pydantic 在进入函数前拒绝。
- 400：字段格式没问题，但业务规则不允许。例如编码重复。由 service 主动 `HTTPException(400)`。
- 404：资源不存在。由 service 主动 `HTTPException(404)`。

### 两组一致性检查

1. **表字段 ↔ 响应字段**：逐项对照 `dept_code`、`full_name`、`address` 在表结构、`DepartmentOut`、实际详情响应里是否一致。
2. **目录 ↔ 磁盘文件**：六个职责文件 + 三个 `__init__.py` 是否都在；每个文件是否只做自己的事。

发现不一致时，先写“期望值 / 实际值”，再判断是文档问题还是实现问题，不要默认改某一方。

### 操作与检查点

## 完成之后

回看这条链：

```text
请求 → controller → service → crud → model/TABLE
                ↘ schema / param
```

- `param` 管查询参数，`schema` 管输入输出，`model` 管记录结构，`crud` 管读写，`service` 管规则，`controller` 管路由。

- 六文件不是形式：改字段校验找 `schema`，改业务规则找 `service`，改存储找 `crud`，改路径找 `controller`。
