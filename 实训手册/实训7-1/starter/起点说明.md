# 实训 7-1 学员起点说明

本目录是**实训 6-1 的完成态**：department 已经落库，列表能按 `page`、`page_size` 分页并返回 `{items, total}`，固定按 `dept_code` 升序；`app/core/database.py` 提供 `engine`、`SessionLocal`、`Base`、`get_db`；启动时建表并幂等写入 D001、D002。

本实训要在这个工程上做两件事：让 department 的列表支持过滤，再把同一套查询写法复制出 personnel 模块。这里不给答案代码，请按教材 7.1–7.5 与任务书完成。

## 需要完成的 4 处

1. **department 增加过滤**
   - 在 `app/modules/department/param.py` 的分页参数之外增加 `full_name`，保持 `page`、`page_size` 的边界不变。
   - 在 `crud.list_page` 中按 `full_name` 做模糊过滤；过滤条件必须加在 `count()` 之前，空串视为不筛选。
   - service 把过滤字段透传给 crud；controller 与 schema 不需要改。

2. **新增 personnel 模块**
   - 新建 `app/modules/personnel/` 与空 `__init__.py`，按 department 的六文件职责放置 `model.py`、`schema.py`、`param.py`、`crud.py`、`service.py`、`controller.py`。
   - 表名 `personnel`，四个字段：
     - `certificate_number`：字符串主键，长度 20；
     - `name`：必填，长度 100；
     - `dept_code`：必填，长度 20；
     - `rank`：可空，长度 50。
   - 路由前缀 `/personnel`，详情、修改、删除都以 `certificate_number` 作为路径参数。
   - 列表过滤：`name` 模糊、`dept_code` 精确；排序固定按 `certificate_number` 升序。
   - 业务规则：新增或修改时校验 `dept_code` 是否存在，不存在返回 400；证件号重复返回 400；查不到返回 404。
   - 分页、`{items, total}`、422/400/404/204 的分工与 department 保持一致。

3. **让应用认识新模块**
   - `main.py` 在 `create_all` 之前导入 personnel 模型；挂载 personnel 路由时仍用 `prefix=""`，路径中不出现 `/api/v1`。
   - seed 增加 P001、P002 两条人员；必须先写单位再写人员，单位编码分别落在 D001、D002，重复启动不重复写入。

4. **回归 6-1 的 department**
   - 不带过滤参数时，department 的 `items` 与 `total` 必须与 6-1 完全一致。
   - 逐一验证详情 200/404、新增 201/400、修改 200、删除 204 无正文、重复删除 404。
   - 用同一组请求比对改造前后的响应；不能只验证新模块。

## 起点检查

在已安装依赖的环境中，于本目录执行：

```powershell
python -c "from app.modules.department import controller; print(controller.router.prefix)"
python -m uvicorn main:app --port 8000
```

第一条预期输出 `/departments`。第二条启动后，`GET /departments` 应返回 2 条 seed 数据；此时还没有 `/personnel`，访问它会得到 404，这是起点状态，不是错误。

`tests/test_api.py` 是 6-1 留下的教师测试，可用于确认改造前后 department 行为未变；本实训不要求扩展测试，教材第 12 章才系统讲测试。

- 不要新建 `users` 表、`security.py`、认证、令牌或权限（第 8、9 章）。

- 不要新建 `app/core/pagination.py`；公共分页是课后扩展，本实训先保证两个模块各自写法一致。
