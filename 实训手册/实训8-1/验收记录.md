## 三、接口验证

要求：七个分支全部实际请求；URL 与方法须与下表一致。

| 序号 | 方法 | URL | 输入 | 预期 | 实际 | 结论 |
| ---: | --- | --- | --- | ---: | ---: | --- |
| 1 | POST | `/api/v1/users` | `{"username":"alice","password":"secret123"}` | 201，响应无 `password_hash` | [ ] |  |
| 2 | POST | `/api/v1/users` | 同上，重复提交 | 400，`用户名已存在` | [ ] |  |
| 3 | POST | `/api/v1/users` | `{"username":"bob","password":"123"}` | 422，`string_too_short` | [ ] |  |
| 4 | POST | `/api/v1/users/login` | `alice` 与正确密码 | 200，含 `access_token`、`token_type` 与 `user` | [ ] |  |
| 5 | POST | `/api/v1/users/login` | `alice` 与错误密码 | 401，`用户名或密码错误` | [ ] |  |
| 6 | GET | `/api/v1/users/me` | 不带请求头 | 401，`未提供令牌` | [ ] |  |
| 7 | GET | `/api/v1/users/me` | `Authorization: Bearer <token>` | 200，`{"id": 1, "role": "normal"}` | [ ] |  |

补充检查：

- [ ] 第 1 行的响应体中没有 `password_hash`
- [ ] 第 4 行拿到的令牌可直接用于第 7 行
- [ ] 第 4 行的 `user` 含 `id`、`username`、`role`、`is_active`，且不含 `password_hash`
- [ ] 任意拼接一个无效令牌访问 `/me`，返回 401
