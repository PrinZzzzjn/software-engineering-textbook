# 实训 5-1 代码分步实现指南

本指南演示如何把 4-1 的六文件产物迁入完整工程，再补上依赖、虚拟环境、配置与 Git。以单位模块为例；自选资源的目录名与路径自行替换。

## 零、起点

4-1 结束后，项目已经是一个可运行的单文件应用加六文件模块：

```text
starter/
├── main.py
└── app/modules/dept/
    ├── controller.py
    ├── service.py
    ├── crud.py
    ├── model.py
    ├── schema.py
    └── param.py
```

`main.py` 负责创建应用与挂路由；六个文件负责一个资源的五个接口。本实训把它变成一个有依赖清单、配置、忽略规则与 Git 历史的工程。

## 阶段 1：迁移六文件（15 分钟）

### 1.1 建目录

```bash
mkdir -p app/modules/dept
touch app/__init__.py app/modules/__init__.py app/modules/dept/__init__.py
```

Git 不跟踪空目录，`__init__.py` 同时承担“让目录进入仓库”的作用。

### 1.2 复制六文件

把 4-1 的六个文件复制到 `app/modules/dept/`，文件名不变：

```text
app/modules/dept/
├── __init__.py
├── controller.py
├── service.py
├── crud.py
├── model.py
├── schema.py
└── param.py
```

### 1.3 删除 controller 中的应用对象

`controller.py` 只保留路由与接口：

```python
from fastapi import APIRouter, Depends, status

from . import param, schema, service

router = APIRouter(prefix="/departments", tags=["单位"])

# 以下五个接口与 4-1 相同，不再重复列出
```

`app = FastAPI()` 移到根目录 `main.py`。模块的 `router.prefix` 只写 `"/departments"`，`"/api/v1"` 由入口提供。

### 1.4 检查点

```bash
python -c "from app.modules.dept import controller; print(controller.router.prefix)"
```

输出 `/departments`。若报 `ModuleNotFoundError`，先确认三个 `__init__.py` 都在。

## 阶段 2：装配根目录 main.py（10 分钟）

```python
from fastapi import FastAPI

from app.modules.dept import controller as dept_controller

app = FastAPI(title="Duty API", version="0.1.0")


@app.get("/health")
def health():
    return {"status": "healthy"}


app.include_router(dept_controller.router, prefix="/api/v1")
```

`main.py` 只做两件事：创建应用、挂路由。数据库建表在第 8 章加入，本章不写 `create_all`。

启动验证：

```bash
uvicorn main:app --reload --port 8000
```

访问 `/health` 与 `/docs`，再访问 `/api/v1/departments/`，三者均应为 200。

**做错会看到什么**：接口全 404，说明模块 `prefix` 与 `include_router` 的 `prefix` 少写了一段；`/docs` 打不开，说明启动文件不是 `main:app`。

## 阶段 3：虚拟环境与依赖（20 分钟）

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# Linux / macOS
source venv/bin/activate
pip install -r requirements.txt
```

`requirements.txt`：

```text
fastapi
uvicorn[standard]
pydantic
```

正式项目应锁定版本，例如 `fastapi==0.110.0`；教学环境先使用机房统一安装的版本。

**做错会看到什么**：提示符前没有 `(venv)`，说明虚拟环境未激活；此后安装的依赖会进入系统 Python。

## 阶段 4：Git 初始化（30 分钟）

先写 `.gitignore`，再初始化仓库：

```gitignore
venv/
__pycache__/
*.pyc
.env
*.db
logs/
.pytest_cache/
```

```bash
git init -b main
git add .gitignore
git commit -m "chore: add gitignore"
git add .
git commit -m "chore: init fastapi project"
```

先单独提交 `.gitignore`，后续 `git add .` 才不会带入 `venv/` 与 `.env`。

**做错会看到什么**：`git status` 出现 `venv/`，说明忽略规则未生效；已跟踪时用 `git rm -r --cached venv`。

## 阶段 5：分支开发与合并（35 分钟）

```bash
git switch -c feature/health-version
# 修改 main.py 中 /health 的返回值
git add main.py
git commit -m "feat: add service version to health"
git switch main
git merge feature/health-version
```

若制造冲突，文件中会出现三组标记：

```text
<<<<<<< HEAD
当前分支的内容
=======
要合并进来的内容
>>>>>>> feature/health-version
```

保留所需内容，删除三组标记，`git add` 标记为已解决，再 `git commit`。

**做错会看到什么**：冲突标记未删除，代码会带语法错误；提交前用 `git diff` 检查。

## 阶段 6：验证与提交（20 分钟）

- `/health` 200、`/docs` 200、五个接口可调用。
- `git log --oneline` 至少 3 条，信息说明做了什么。
- `git ls-files` 中无 `venv/`、`.env`、`*.db`、`logs/`。
- 设计文档的目录一节与磁盘一致。
- 填写验收记录，完成出口检查。

## 阶段与产物对照

| 阶段 | 产物 | 对应教材 |
| --- | --- | --- |
| 1 | `app/modules/<模块>/` 六文件 | 5.1 |
| 2 | 根目录 `main.py` | 5.1 |
| 3 | `venv/` 与 `requirements.txt` | 5.5 |
| 4 | `.gitignore` 与首次提交 | 5.3 |
| 5 | 分支与合并记录 | 5.4 |
| 6 | 验证记录与交付 | 5.5–5.6 |

## 每阶段都要问的三个问题

1. 这个文件回答什么问题？入口只装配，模块六文件各管一类职责。
2. 换一台机器，靠什么复现？依赖清单、`.env.example`、`.gitignore` 与版本控制四者缺一不可。
3. 这次提交只包含一项改动吗？一次提交只做一件事，回退时才能精确撤销。
